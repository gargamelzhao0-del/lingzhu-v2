1. 设备请求开启
设备发送：
{
  "type": "audio_mode_request",
  "request_id": "device_open_001",
  "mode": "meeting",
  "state": "enabled"
}
云端批准：
{
  "type": "audio_mode_request_ack",
  "request_id": "device_open_001",
  "ok": true,
  "mode": "meeting",
  "state": "enabled"
}
设备收到 ok:true 后，直接进入会议模式并持续上传全部音频。
2. 设备请求关闭
设备停止采集、发送完已采集音频后发送：
{
  "type": "audio_mode_request",
  "request_id": "device_close_001",
  "mode": "meeting",
  "state": "disabled"
}
云端完成音频收尾后回复：
{
  "type": "audio_mode_request_ack",
  "request_id": "device_close_001",
  "ok": true,
  "mode": "meeting",
  "state": "disabled"
}
3. 云端要求设备开启
云端发送：
{
  "type": "device_command",
  "command": "set_audio_mode",
  "request_id": "cloud_open_001",
  "mode": "meeting",
  "state": "enabled"
}
设备真正启动会议采集后回复：
{
  "type": "device_command_ack",
  "request_id": "cloud_open_001",
  "command": "set_audio_mode",
  "ok": true,
  "mode": "meeting",
  "state": "enabled"
}
4. 云端要求设备关闭
云端发送：
{
  "type": "device_command",
  "command": "set_audio_mode",
  "request_id": "cloud_close_001",
  "mode": "meeting",
  "state": "disabled"
}
设备停止采集并发送完剩余音频后回复：
{
  "type": "device_command_ack",
  "request_id": "cloud_close_001",
  "command": "set_audio_mode",
  "ok": true,
  "mode": "meeting",
  "state": "disabled"
}


5. 设备在播报中开启会议模式

设备点击开启会议模式
设备应立即在本地将当前播报淡出，同时发送：
{
  "type": "audio_mode_request",
  "request_id": "device_open_001",
  "mode": "meeting",
  "state": "enabled",
  "interrupt_current_turn": true
}
含义：
type：设备请求改变音频模式。
request_id：设备为本次开启操作生成的唯一编号。
mode：请求进入会议模式。
state：请求开启。
interrupt_current_turn:true：要求云端取消该设备当前正在执行的对话，包括停止生成回复和停止继续下发 TTS 音频。
设备本地同时执行：
当前播报以约 200 ms 淡出。
停止播放后续到达的旧对话音频。
暂时不上传会议音频，等待云端批准。
6. 云端完成打断并批准开启
云端取消当前对话、停止 TTS 下发并建立会议接收状态后回复：
{
  "type": "audio_mode_request_ack",
  "request_id": "device_open_001",
  "ok": true,
  "mode": "meeting",
  "state": "enabled",
  "current_turn_cancelled": true
}
含义：
request_id：必须与设备请求中的值相同。
ok:true：云端允许设备进入会议模式。
state:enabled：会议模式已经被云端接受。
current_turn_cancelled:true：旧对话和后续 TTS 下发已经被取消。
设备收到这条消息后，直接开始会议模式并持续上传全部音频。
