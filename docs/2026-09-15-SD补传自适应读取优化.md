# SD 补传自适应读取优化

## 问题与基线

本轮基线为用户确认的默认速度测试版，独立目录 `C:/tmp/nuwax-sd-event-20260915`。会话 `meeting_20260915_76f279a7_297701` 的 7 个分段已完整提交，7626 帧共 152.52 秒音频，5,079,812 字节上传用时 15.869 秒，平均 **312.61 KiB/s**。

日志中 99.65% 的读取字节回退到 PSRAM 路径，604 次因分配后内部空闲量低于 16 KiB 放弃内部缓冲。原实现固定申请 8192 字节数据加校验状态，只检查请求大小，不能利用略小的可用空间。分配开销或并发内存使用的具体占比，旧日志尚不足以区分。

事件交接已降低数据等待，但采音压力等待增加。代码还存在一个调度问题：尝试阻塞等待就清空累计工作预算，即使通知恰好到达、实际只等待极短时间，也会重置预算。

## 实现

- 读取块以 512 字节扇区为单位，在 512～8192 字节之间选择。预检查同时考虑内部总余量、最大连续 DMA 空间、校验状态和 128 字节分配裕量。
- 分配后仍检查至少 16 KiB 内部空闲量；不足时释放，结合实测开销缩小重试。每次读取最多尝试 3 次，失败仍走原 PSRAM/SD DMA 适配路径。缓冲只在一次有界读取和校验期间持有。
- 读取函数返回实际校验通过的字节数。预读和串行路径均按该数值推进；读短、读失败或校验失败返回零可发布字节，防止缩块后错位、重复或跳过音频。
- 奇数字节断点继续使用适配路径跨到下一扇区边界，随后恢复自适应内部读取。协议包大小、请求与会话标识规则、CRC、持久化 ACK 和删除条件保持现有约束。
- 事件等待至少持续一个系统节拍，才允许清空工作预算；短等待继续累计。分配耗时也纳入工作预算，保留 64 KiB/20 ms 主动让步以及采音压力保护。
- 新增 `offline replay adaptive read` 日志，记录缩块次数、容量范围、分配拒绝与分配后余量拒绝次数，以及最近一次余量拒绝前后的空闲量。旧 `fallback slices` 仍表示最终回退次数；新 `*_rejects` 表示尝试失败次数，可能重试后成功，二者不能直接相加。
