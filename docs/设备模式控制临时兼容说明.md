# 会议／监控模式控制兼容说明

适用版本：7.0.209 起，保留 7.0.208 的开关兼容规则。继续使用现有 `device_command / set_audio_mode`、`device_command_ack` 和 `audio_mode_request`，不新增字段。

云端与设备采用新的重连约定：云端不再用 `meeting disabled`、`monitoring disabled` 等初始化状态命令覆盖设备。新连接就绪后，由设备上报实际状态；用户主动开关及会议／监控切换仍使用原控制命令。

## 开启与关闭

`state=enabled` 表示开启该模式，`state=disabled` 表示关闭该模式。控制请求的 `audio_session_id` 可以省略，开启、关闭均不以场次 ID 是否匹配作为执行条件。

| 场景 | 设备处理 |
| --- | --- |
| 尚未开启，开启请求没有 ID 或为空 | 设备生成新的录音场次 ID，实际开始录音后回传该 ID |
| 尚未开启，请求携带合法且未使用的 ID | 原样用作录音场次 ID |
| 请求 ID 不适合作为 SD 场次 ID，或已被历史录音使用 | 生成新 ID；历史录音不改名、不覆盖 |
| 已在该模式，再收到开启请求 | 保持当前录音和场次 ID，回传 already_active 及实际 ID |
| 收到关闭请求，没有 ID、ID 过期或与当前场次不同 | 关闭该模式的当前录音，完成必要封存后回复成功 |
| 已关闭，再收到关闭请求 | 返回已关闭状态 |
| 切换会议／监控 | 校验新录音身份、存储及资源，再停止原模式、封存尾文件、启动目标模式；不等待旧音频上传 |

控制解析器仍拒绝非字符串、超过 47 字节、转义 NUL、重复 JSON 字段等畸形输入。设备实际录音 ID 仍须符合 1～35 字符的字母、数字、下划线或短横线约束；不会把旧控制文本直接当作文件路径。

## 断线与重复请求

- 每次云端连接就绪后同步两种模式：会议中上报 meeting=enabled、monitoring=disabled；监控中相反；普通对话时两者均为 disabled。运行中的模式携带原 audio_session_id，关闭状态不带场次 ID。无卡正在运行的模式沿用原开启／恢复请求，不在实时采集循环中另加发送。
- 有卡录音断线后继续使用原录音 ID；每个连接使用新的同步 request_id，同次重试沿用原 request_id。云端按上报更新当前状态；旧场次 begin／commit／session_end 只处理数据，不覆盖当前开关状态。
- 首次发送失败按 1、2、4、8、10 秒退避，之后每 10 秒重试，直到该状态成功发出或连接／状态变化。成功发出后的回执等待预算为 5 秒，最多成功发送 3 次。回执失败、丢失或超时不停止录音，也不阻止后续开关；同步回执本身不抢占聆听或播放。
- 设备不对重连后的关闭命令增加过滤或五秒等待。明确的 device_command(state=disabled) 仍立即进入原关闭流程；因此云端必须遵守“不下发初始化开关状态命令”的约定。
- 同一请求的重试仍受原执行期限、连接代际、局部停止代际及有限的近期去重缓存约束，不能无限期延长命令或复活近期已结束的开启请求。这不是跨重启、无限历史的请求去重。
- 每次新操作使用新的 request_id；传输重试沿用原 request_id。旧录音补传不用于重新开启模式。

## 回执与音频归属

只有实际进入采集才回复开启成功，关闭等待本地必要封存，不等待音频补传。SD、OTA、配网、资源冲突或超时等真实失败仍返回失败。

成功开启 ACK 中的 audio_session_id 是设备实际使用的录音 ID。云端若需要关联业务记录，应读取该值；旧控制请求没有 ID 时，不能假定自己预先知道上传 ID。也可在上传 begin 时，按已认证设备身份和录音 ID 创建场次。

audio_begin、Binary、audio_commit、audio_session_end 及其 ACK 格式和校验不变。SD 文件头、Binary 头和上传消息仍使用实际录音 ID；提交与结束确认不得跨文件或跨场次匹配。

无卡的实时音频及离线处理继续原流程。旧配置项 CONFIG_NUWAX_SD_LEGACY_CONTROL_COMPAT 仅保留配置兼容，不再决定开关是否要求场次 ID。
