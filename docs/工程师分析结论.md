  → 回声未被消除 → 设备声残留
  → nearend_blend 混入的原始mic中带有回声 → 设备声穿透
关键代码： live_aec.c:1386-1390


c
if (copied < (chunk / 2U)) {  // 参考丢失

78%的帧走了这条路径，AEC核心完全没有执行。 回声残留必然大。

人声音量波动来自参考状态的交替： 参考正常→人声可听，参考丢失→人声被压。而78%的帧都在"被压"状态。

修正路径（基于S29真实数据）
第一步：解决参考丢失（78%→目标20%以下）
当前问题： ADAPTIVE_REF_MIN_CORR_Q15=6000 阈值太高，自适应参考搜索找不到有效偏移（adaptive_ref=0，一次都没触发）。

c

    if (metrics.corr_q15 > best_corr) { ... }
当前 MIN_CORR_Q15=6000 但日志中 mic_ref_corr_q15 在1000-5000之间波动。自适应参考搜索根本找不到满足阈值的偏移，导致从未触发。

修正：

ADAPTIVE_REF_MIN_CORR_Q15: 6000 → 1500（恢复到原始值）
同时增加稳定性约束：新偏移必须连续3帧被选中才切换
第二步：解决 ref_inactive/ref_missing 时的过度衰减
当前问题： REF_MISSING_ATTENUATE_Q15=2048(6.25%)，即使有hint也只到 24576(75%)，然后 dual_restore 恢复后仍只有37.5%。

修正：

REF_MISSING_ATTENUATE_Q15: 2048 → 24576(75%)（和无hint时hint提升后的值一致）
REF_INACTIVE_ATTENUATE_Q15: 2048 → 24576(75%)
参考丢失时不应默认重压，应该走旁路（append_bypass_chunk），让原始信号通过，依赖后续的nearend_blend和dual_restore恢复
第三步：解决 dual_guard 过度拦截
当前问题： cleanref_hintsplit 分支的 nearend_blend_dual_evidence() 拦住了201次blend。

修正：

NEAREND_BLEND_DUAL_BALANCE_Q15: 22000 → 28000
NEAREND_BLEND_DUAL_DIFF_AVG_ABS: 450 → 200
NEAREND_BLEND_DUAL_DIFF_PEAK: 1600 → 600
或直接移除dual guard（推荐）
第四步：修正 human-first hint 误判
当前问题： hint 在无人基线中也大量触发。

修正：

在 dual_mic_human_first_hint 中增加 AEC ref 相关性检查：当 ref 活跃且 MIC 信号能量高时，才产生 strong hint
ref_inactive 状态时不产生 hint（防止误判设备声）
