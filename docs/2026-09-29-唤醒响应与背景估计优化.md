# 7.0.110 唤醒响应与背景估计优化

## 范围

保留本地唤醒、云端问候、播放完成后收音、连续对话流程。没有替换问候为提示音，也没有提前上传问候期间的麦克风声音。没有改变协议、唤醒词列表、会议/监控、充电或 OTA 菜单接管逻辑。

## 改动

1. 已建立问候 turn guard、visual round 且连接 epoch 有效后，在发送请求前通过既有异步 UI 状态通道发布 THINKING。它表示已唤醒、正在等待问候，不表示已开始收音。请求失败仍进入原有收音恢复路径；超时、断线沿用既有回收流程。首帧和播放结束仍按原 generation 校验处理。
2. 背景估计改为 8 个 128 ms 最小值桶的低分位估计。疑似语音短时限制背景值上升，最长 3.5 秒；持续新背景最终仍会被学习，降低背景可正常跟踪。采集断续清除历史和语音持有状态，保留已有背景基准，避免恢复首帧人声直接变成背景。
3. 候选日志新增最近约半秒的语音时长、总采样时长、语音平均幅度及 shadow 判定。shadow 只做对照，不参与实际放行，也不要求用户重复呼叫。真实准入仍使用原有模型分数、语音证据、幅度比例和削波限制。
4. sdkconfig.defaults 模型阈值统一为 0.09，与正式构建及最终分数门槛一致。MultiNet 编译时校验两者相等，防止构建配置漂移。0.100 的 strong 分档仍是诊断分类，不新增强分数无条件放行。

## 验证

- 实际 C 背景算法：轻声持续输入不抬高自身门槛，持续更响背景有界学习，环境变安静、瞬时冲击、采集断续、毫秒计数回绕。
- 实际 C 证据算法：近期语音与窗口内较早语音区分；shadow 拒绝不会改变现有准入。
- 提取真实问候函数执行：先建立所有权再发布反馈、随后发送；guard/visual/epoch 失败不显示反馈；发送失败释放所有权；模拟发送时立即响应。
- 既有唤醒证据测试及五个缺陷变体、唤醒采集/监督、对话及产品回归。
- 最终 ELF 检查实际阈值、源码新鲜度、唤醒任务静态栈帧和 OTA 身份。

新增固定结构，无新常驻任务、模型或 PCM 留存。背景估计可改善部分轻声漏唤醒，但也可能改变讨论声下的通过分布，需要真机正负样本对比，不能以主机测试宣称识别率已提高或误触发已降低。

## 真机日志

```text
wake feedback requested revision=wake-response-v1 ... wake_to_feedback_ms=... capture_started=0
wake candidate diagnostics revision=wake-response-v1 score=... noise=... rise_held=... recent_voice_ms=... recent_total_ms=... recent_signal_avg=... evidence_age_ms=... shadow=... enforced=0
```

`wake_to_feedback_ms` 是提交 UI 状态的耗时，不是屏幕实际亮出新画面的耗时。目标为确认后约 150 ms 可见，需真机录像/显示日志验证；菜单或 OTA 覆盖时不强行抢占屏幕。

shadow=pass 也不是“确认无人声误唤醒”，只是近期声学条件满足。评分低于模型自身门槛的结果不会成为这里的候选日志；评估漏唤醒仍需人工标注呼叫次数。

上一轮约 3.79 秒的 playback_begin 到首帧等待不由本次设备改动解决。继续使用现有云端问候，语音首响速度仍依赖云端首帧。

建议在相同位置和音量下测试普通/轻声/远距离呼叫，记录成功数与尝试数；另记录讨论、电视、敲击噪声的暴露时长与误唤醒次数。不要只看模型分数，不能把同一段重复播放当作独立声学样本。
