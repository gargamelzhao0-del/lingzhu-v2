       "params": {
         "name": "self.ui.set_emotion",

           "emotion": "happy"
         }
       }

   }

   旧文档写成 `payload.tool + payload.arguments`，不符合当前设备解析逻辑，已修正。

## 产品路线裁决：智能打断由“设备端精判”调整为“设备端音频前端 + 云端精判”

结论：**采纳产品负责人新方向。后续不再把 ESP32S3 设备端作为智能打断最终判别器来追求极致本地精判。设备端目标调整为稳定实时音频前端：稳定采集、轻量降噪、尽量降低回声/杂音、保留语音细节、上传可被云端精确对齐的音频与播放引用；云端负责精确 AEC、人声/声纹/语义判断和最终打断裁决。**

本裁决不否定前面 P3/P5/P6 的价值，但改变其定位：

- P3/P5/P6 不再承担“本地最终判断用户是否要打断”的产品责任。
- P3/P5/P6 继续作为设备端音频健康、候选采集、播放期间上传、时序对齐和 fallback 诊断能力。
- 本地 gray cancel 阈值/voice class 不再继续作为主线反复调参目标。
- 004-4E 的“修本地 narrow class 精确 fixture”不再作为下一步主线开发任务；保留其问题记录，但不继续投入本地精判闭环。

新的职责边界：

### 设备端必须负责

1. **稳定采集**
   - 唤醒状态下，无论设备播报还是空闲，都能连续采集麦克风音频。
   - 播放期间不能因为 TTS 输出、UI、网络、缓冲等导致采集断流。
   - 必须保留 `500-1000ms` pre-roll，避免用户开头被截掉。
   - 上报丢帧、队列溢出、read timeout、write failure、heap/DMA 等质量指标。

2. **轻量净化**
   - 允许做底噪、风扇、低频嗡声、键盘尖峰等轻量过滤。
   - 不允许激进降噪、强 VAD 截断或强压缩破坏用户声纹、ASR 和云端 AEC 所需细节。
   - 原则：宁可带一点噪声上传，也不要把用户人声细节在设备端抹掉。

3. **回声参考与时序元数据**
   - 每段上传音频必须能和当前 TTS 播放数据对齐。
   - 设备端必须上报 `playback_id`、`audio_session_id`、播放开始/停止时间、淡出/duck 时间、音量、采样率、帧序号、上传帧时间戳。
   - 如设备端有本地 playback PCM/reference ring，也应提供 ref slot / ref RMS / underrun / delay_samples 等诊断字段。

4. **本地执行**
   - 云端返回 `duck` 时，设备端快速降低播放音量。
   - 云端返回 `cancel_turn` 时，设备端平滑淡出当前播报。
   - 设备端继续录完整 follow-up utterance。

### 云端负责

1. 精确 AEC：使用云端保存的真实 TTS PCM/reference 与设备上传音频做时间对齐和回声消除。
2. 人声判断：区分人声、键盘、风扇、媒体声、短促噪声。
3. 声纹/目标说话人：对绑定用户或授权用户做相似度权重判断。
4. 语义意图：结合流式 ASR partial 判断是否为打断、纠正、换题、停止、补充。
5. 最终裁决：输出 `continue / record_only / duck / cancel / followup_listen` 等动作。

工程影响：

- 当前不要继续烧录或真人测试 004-4E。
- 下一步先下发设备端“音频前端化审计与云端契约”任务，明确设备端已有能力、缺口和最小改动路径。
- 之后再分阶段开发：稳定采集/pre-roll → 播放引用元数据 → 轻量降噪 → 云端决策动作执行。

这里定义为“临时目标输出音量百分比”，不是“当前音量乘以 30%”。例如用户音量 20%，duck 后就是 30% 这个绝对值会变大，这是不对的。因此实际执行必须取：

```text
duck_target = min(current_volume_percent, CONFIG_NUWAX_P6_GRAY_CONFIRM_DUCK_VOLUME_PERCENT)
```

如果当前音量为 20%，duck 到 20% 不产生变化。为保证测试可见，host 测试时建议把播报音量设为 35% 或 40%；如果仍按 20% 测，duck 行为可能只记录不改变音量。后续可改为“当前音量比例”，但本轮不扩展。

这是当前阶段兼顾 ASR 首包延迟和误触发安全的保守值。日志必须输出 `gray_to_confirm_ms` 或 `gray_to_reject_ms`。
