# 7.0.212 SD 录音完整性诊断

本版针对 11 月 2 日 15:28 会议中途停止的问题。7.0.211 日志已经证实：写入后同步、重新打开文件读取，得到的 CRC 与写入端记录不符。重复读取仍不符，设备因此保护停录。现有证据不能区分内存、文件系统缓存、驱动读写链路和 SD 介质，不能直接归因为卡坏。

本版增加定位证据，并补上封口头尾的独立检查。没有取消 CRC 保护，没有修改云端/App 协议或上传吞吐配置。

## 检查位置

| 位置 | 检查与结果 |
| --- | --- |
| 生产者入队 | 对完整 NA 帧计算 CRC，随队列槽一起交付；没有改变音频帧格式 |
| 写入之前 | 重算队列数据 CRC；有差异则停止本场并报告 `frame_queue_crc` |
| 写入期间 | PSRAM 中保留长度字和帧的写前副本；`fwrite` 返回后再算源数据 CRC，发现变化报告 `frame_write_crc` |
| 写入 SDK | 在原 DMA 适配器内记录最近扇区写入 CRC；失败的写入不能作为有效见证。其他任务的写入同样更新记录 |
| 独立读回 | 沿用首帧、每 100 帧及封口前的只读独立句柄检查。与写前副本逐块比较，保留首个差异读块；原应用 CRC 仍独立决定成功或失败 |
| 扇区出现差异 | 仅首次差异，在原 FatFs 卷锁内借用私有内部 DMA 缓冲，直接复读该 LBA 作比较。使用私有卡描述符和 200 ms 命令期限；不修改原 SDK 返回值、errno 或读写数据 |
| 文件封口 | 文件写入时间头、尾部并关闭后，用新只读句柄检查文件大小及首尾各 512 B。CRC/大小差异各允许一次独立重试；持续失败保留 `.part`，禁止发布上传 |

确定性的完整性故障优先于较早遗留的 I/O 错误标签，避免保护停录被旧标签遮住；快照内存分配失败时，这条分类和停录规则也照常执行。

扇区见证表只有 256 项，冲突最多探测 8 项；不知道的扇区和被替换的条目明确计数。覆盖不足不能作为“磁盘正确”的证明。没有逐帧或逐扇区串口日志。

## 故障证据

故障日志以 `SD integrity fault revision=212`、`SD integrity difference`、`SD integrity IO` 标识，包括场次、物理文件编号、文件偏移、队列/写前/写后 CRC、批次 CRC、首个差异位置、扇区 LBA、写入/读回/独立复读 CRC。

第一份故障快照先冻结在 RAM，后续关闭、恢复和新场次不能覆盖尚未保存的快照。只有录音、采集任务、写盘任务、场次和补传均空闲、介质恢复流程成功后，才尝试写入：

```text
/sdcard/sd_integrity/evidence_0.bin
/sdcard/sd_integrity/evidence_1.bin
/sdcard/sd_integrity/evidence_2.bin
/sdcard/sd_integrity/evidence_3.bin
```

创建使用排他方式；已有 `.bin` 和未写完的 `.part` 都占用槽位，不覆盖、不删除旧文件。每份快照最多尝试保存 4 次，诊断写盘命令期限为 750 ms。失败后保留 RAM 快照；普通录音的 CRC 保护继续工作。证据不会进入音频补传或任何云端请求。

每份文件是 512 B 小端头、写前批次副本、首个差异读块，最大 67,720 B。四槽有效内容上限 270,880 B，另有文件系统分配开销。证据含本地录音字节。突然断电前尚未保存的 RAM 快照会丢失；文件系统或卡故障也可能导致无法保存。

头部签名 `NWXDIA2\0`，版本 1；头部前 508 B 和两个数据区分别有 CRC。解析工具会检查签名、版本、长度和 CRC，再输出定位信息：

```powershell
& 'C:\Espressif\tools\python\v6.0\venv\Scripts\python.exe' `
  tools/analyze-sd-integrity-evidence.py 'D:\sd_integrity\evidence_0.bin'
```

阶段：1 为队列内容变化，2 为写入期间源数据变化，3 为录音记录独立读回失败，4 为封口首尾失败，5 为封口长度失败。扇区复读与最后一次写入 CRC 相同，说明需继续查普通读回路径；复读也不同，说明需继续查写入持久化及底层读写链路。两种结果均不能独立证明 SD 卡的物理故障。

## 资源与兼容性

- ESP32-S3 实际类型大小：批次快照 68,616 B、扇区观察器 6,456 B，128 个队列槽合计增加 1,024 B，共增加 76,096 B PSRAM，不含分配器开销。
- 故障复读临时使用 512 B 内部 DMA，保留现有 16 KiB 内存底线。没有新增任务或持续占用内部 DMA。
- 快照分配失败不会阻止原有录音和独立 CRC 校验；正常上传连接、TLS 参数、预读缓冲和分块协议不变。
- 原 `96 B` 文件头、`32 B` 文件尾和 NA 帧格式不变。场次标识、状态控制、离线恢复、FIFO、文件 ACK 后删除及八小时限制沿用原逻辑。界面代码未修改。
- 补正上一版资源说明：7.0.211 新增的独立读回 stdio 缓冲实际为 **16,384 B**，原说明写成 8,192 B。该版本程序实际分配正确；本次更正只涉及报告，不改动 7.0.211 二进制或 SHA。

## 验证界限

宿主机测试执行生产诊断代码、底层观察器和实际写盘函数，注入队列变化、写入中变化、读回变化、文件头尾与长度变化，检查证据冻结、保存边界、扇区覆盖及私有命令期限。会议、监控各八小时采用逻辑时钟和实际文件读写，逐文件检查音频帧序号、时间与 CRC；不是设备持续运行八小时。

实机异常的最终原因、整机长期稳定性及 500 KiB/s 吞吐必须由后续实机日志和网关记录确认。本版不能修复已有损坏的音频字节，不能承诺以后不再保护停录。不要为了清除故障而格式化卡，保留原文件和证据更有助于定位。
