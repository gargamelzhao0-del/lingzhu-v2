# Nuwax AI Partner 7.0 — 音频全双工优化方案

> 文档版本：v1.0  
> 创建日期：2026-07-08  
> 适用范围：设备端音频处理管线优化（播放时采集 + AEC + 人声保真上传）

---

## 一、目标

设备播放时同步采集音频，设备端 AEC 消除设备播报回声，过滤出保真清晰的人声上传云端 ASR。

---

## 二、当前架构诊断

**架构方向正确，实际效果受配置参数限制。** 核心问题不在于架构，而在于几个关键参数值使得人声恢复机制失效、VAD 门控过于保守。

### 2.1 现有管线（可运行的）

```
原始人声 + 回声
  → live_aec 核心 (ESP AFE AEC)
    → 残余回声消除 (residual_cancel)
    → 近端混合 nearend_blend (当前 raw_mix=0，无效)
    → 双麦近端恢复 dual_restore (guard 极严，实际极少触发)
    → 近端楼层恢复 nearend_floor_restore
  → audio_cleaner (HPF + Notch + quiet_gate)
  → VAD 门控 (播放门控)
  → PCM16 上传至云端
```

### 2.2 五个核心问题

| # | 问题 | 位置 | 严重度 | 现状描述 |
|---|------|------|--------|---------|
| 1 | nearend_blend 无效 | `NEAREND_RAW_MIX_Q15=0` | 🔴 高 | AEC 消除回声后人声被衰减，但完全不把原始人声混回来。被 AEC 衰减的人声永久丢失 |
| 2 | 参考丢失时过度衰减 | `REF_MISSING_ATTENUATE_Q15=2048`(6.25%) | 🔴 高 | 软件参考缓冲区历史数据不足时，麦克风信号被压到 6.25%，此时如果用户说话完全听不见 |
| 3 | 播放门控门槛过高 | `DURING_PLAYBACK_MIN_AVG_ABS=650`, `PEAK=1800` | 🟡 中 | 比普通 VAD(400/1500)高 62.5%。安静说话(avg≈500)被判定为非语音，该帧直接不上传 |
| 4 | 评分系统衰减过快 | 每帧减1分，正常对话节奏(4-5帧一个词)净减分 | 🟡 中 | 分数持续下降到0，即使用了正常音量说话，门控评分也不够 |
| 5 | quiet_gate 播放时门限过低 | 播放+live_aec 时用 base 值(90/420)，noise floor 动态调整被跳过 | 🟡 中 | AEC 残留回声(avg≈100-300)穿透 gate 不被衰减，当作有效信号上传 |

## 三、优化方案

### P0 — 立即执行（影响人声保留，改4处）

#### 1. 开启 nearend_blend，恢复被 AEC 衰减的人声

| 配置项 | 当前值 | 改为 | 含义 |
|--------|-------|------|------|
| `CONFIG_NUWAX_LIVE_AEC_NEAREND_RAW_MIX_Q15` | 0 | **2048** | AEC 输出中混入 6.25% 原始麦克风信号 |
| `CONFIG_NUWAX_LIVE_AEC_STRONG_NEAREND_RAW_MIX_Q15` | 0 | **4096** | 强近端时混入 12.5% 原始麦克风信号 |

- **文件**：`sdkconfig` 第1033行、第1036行（或 `menuconfig` → `Component config → Nuwax AI Partner → Live AEC`）
- **原理**：raw_mix=0 时 `apply_nearend_blend()` 函数第780行直接 return，完全不执行混合。改为 2048 后，公式为 `out = out × (1-raw_mix) + mic × raw_mix`，部分人声被恢复
- **验证方法**：播放时说话，检查 `nearend_blend_chunks` 统计计数器是否递增（`live_aec_t` 结构体第47行）

#### 2. 降低参考丢失时的衰减

| 配置项 | 当前值 | 改为 | 含义 |
|--------|-------|------|------|
| `CONFIG_NUWAX_LIVE_AEC_REF_MISSING_ATTENUATE_Q15` | 2048 | **4096** | 参考丢失时从 6.25% 衰减提升到 12.5% |

- **文件**：`sdkconfig` 第1023行
- **背景**：代码 `live_aec.c:1227-1232` 中，如果有 `strong_nearend_preserve_hint`（双麦检测到近端），衰减会自动提升到 `REF_MISSING_HINT_ATTENUATE_Q15`（8192=25%）。但基础值 2048 过低，无双麦提示时人声被严重压制
- **验证方法**：播放开始瞬间或播放间隙说话，检查 `ref_missing_attenuated_chunks` 计数

#### 3. 双麦候选直接贡献播放门控资格

- **文件**：`main/nuwax_ai_partner_main.c` 第3090-3094行附近
- **改动内容**：在 `playback_gate_candidate = playback_nearend_candidate` 的判断中增加条件：
  ```c
  /* 修改前 */
  playback_gate_candidate = playback_nearend_candidate;
  
  /* 修改后 */
  playback_gate_candidate = playback_nearend_candidate ||
      (playback_gate_score_frames >= 3 && playback_dual_mic_candidate);
  ```
- **原理**：当前双麦候选只给评分系统 +1 分（`playback_gate_score_update` 第2390行），但不直接决定 `playback_gate_candidate`。这浪费了双麦的空间信息能力。当评分 ≥3 且双麦候选有效时，允许 gate 打开
- **涉及常量**：`NUWAX_PLAYBACK_GATE_SCORE_PER_AEC_CANDIDATE=2`, `NUWAX_PLAYBACK_GATE_SCORE_PER_DUAL_CANDIDATE=1`（第124-125行）

#### 4. 移除评分衰减

| 宏定义 | 当前值 | 改为 | 位置 |
|--------|-------|------|------|
| `NUWAX_PLAYBACK_GATE_SCORE_DECAY_PER_FRAME` | 1 | **0** | `nuwax_ai_partner_main.c` 第126行 |

- **原理**：当前每帧 -1 分，正常对话节奏（4-5帧一个词）下得分净减少。假设说话帧 +2 分，后 3-4 帧各 -1 分，每轮净减少 1-2 分，分数持续下降到 0。移除衰减后，只要有候选出现就能维持或增加分数
- **替代方案**：如不希望完全取消衰减，可改为每 **2-3帧** 减1分，或仅在 `score_frames > 15` 时启用衰减

### P1 — 强烈建议（提升 VAD 准确率，改3处）

#### 5. 降低播放门控能量门槛

| 宏定义 | 当前值 | 改为 | 位置 |
|--------|-------|------|------|
| `NUWAX_DURING_PLAYBACK_NEAREND_MIN_AVG_ABS` | 650 | **550** | `nuwax_ai_partner_main.c:88` |
| `NUWAX_DURING_PLAYBACK_NEAREND_MIN_PEAK` | 1800 | **1600** | `nuwax_ai_partner_main.c:89` |

- **对比**：普通 VAD 门槛为 400/1500（`mic_level.c:47-58`），降幅约 15%。550/1600 在保持一定回声抑制能力的同时，显著降低误拒率
- **强能量门槛**（`STRONG_AVG_ABS=1100`, `STRONG_PEAK=3200`）保持不变，用于高置信度场景

#### 6. 调整 quiet_gate 播放时门限

- **文件**：`main/conversation/audio_cleaner.c` 第506-524行
- **改动一**：将播放 + live_aec 时的 quiet 门限从 base 值(90/420)提升到 **180/700**
  ```c
  /* 修改前 */
  #if CONFIG_NUWAX_LIVE_AEC_ENABLE
      quiet_avg = base_quiet_avg;       // 90
      quiet_peak = base_quiet_peak;     // 420
  #else
      quiet_avg = max_u32(quiet_avg, 220);
      quiet_peak = max_u32(quiet_peak, 900);
  #endif
  
  /* 修改后 */
  #if CONFIG_NUWAX_LIVE_AEC_ENABLE
      quiet_avg = max_u32(base_quiet_avg, 180);  // 180
      quiet_peak = max_u32(base_quiet_peak, 700); // 700
  #else
      // 保持不变
  #endif
  ```
- **改动二**：取消第518-520行的 `!playback_active` 限制，使播放时 noise floor 动态调整也生效
  ```c
  /* 修改前 */
  #if CONFIG_NUWAX_LIVE_AEC_ENABLE
      && !playback_active
  #endif
  
  /* 修改后：移除 && !playback_active */
  ```
- **原理**：当前注释 "Keep the gate conservative so low-level near-end speech is not crushed" 意图正确，但 90/420 门限过低导致 AEC 残留回声穿透。AEC 处理后残留回声在 avg≈100-300 量级，180 是一个合理平衡点。同时启用 noise floor 动态调整（`noise_floor_avg_abs × 2 + 30`，上限 `quiet_avg × 2`），使门限能适应环境噪声变化

#### 7. 调整播放后处理门控门槛

| 宏定义 | 当前值 | 改为 | 位置 |
|--------|-------|------|------|
| `NUWAX_DURING_PLAYBACK_POST_MIN_AVG_ABS` | 900 | **700** | `nuwax_ai_partner_main.c:96` |
| `NUWAX_DURING_PLAYBACK_POST_MIN_PEAK` | 2500 | **2000** | `nuwax_ai_partner_main.c:97` |

- **原理**：播放结束后扬声器振膜惯性造成短暂残余回声（约 10-50ms），但当前 900/2500 门槛过高，导致播放结束后的短暂间隙内用户说话被误拒

### P2 — 可选优化（增强噪声抑制）

#### 8. 提高参考不活跃时的衰减值

| 配置项 | 当前值 | 改为 |
|--------|-------|------|
| `CONFIG_NUWAX_LIVE_AEC_REF_INACTIVE_ATTENUATE_Q15` | 2048 | **8192** |

- **文件**：`sdkconfig` 第1024行
- **原理**：参考信号存在但电平低时（用户播放音量小或播放间隙），当前 2048(6.25%) 的衰减过度压制了近端人声。代码默认值（`live_aec.c:63-64`）为 32768（不衰减），sdkconfig 强制 2048 可能是为了安全。改为 8192(25%) 保留一定衰减但不至于压死人声

#### 9. 引入基频检测 VAD

- **依赖库**：`esp-dsp 1.7.0`（已在 `dependencies.lock` 中）
- **方法**：利用 `dsps_fft2r_fc32` 对每帧音频做 FFT，检测 80-400Hz 范围是否有周期性分量（基频）
- **原理**：有基频 → 人声，无基频 → 噪声/回声残留/TTS。这是区分人声和 TTS 残留的最可靠方法
- **参考实现**：对 960 样本帧（60ms @16kHz）做 1024 点 FFT，在频域检测 5-25 号 bin 的峰值和间隔规律
- **优先级**：建议完成 P0+P1 后评估效果，再决定是否实施

| 级别 | 数量 | 改动类型 | 涉及文件 | 预估代码行数 |

## 五、优化后预期效果

| 场景 | 当前效果 | 优化后预期 |
|------|---------|-----------|
| 播放 + 大音量说话 | 人声被 AEC 衰减 50-90%，双麦恢复偶发 | 人声保留 60-80%，残留回声可控 |
| 播放 + 正常音量说话 | VAD 不触发，帧不上传 | VAD 触发，人声保留 50-70% |
| 播放 + 安静说话 | 门控挡住，不上传 | 门控降低后得以通过 |
| 播放间隙（振膜惯性期） | 门控挡住，不上传 | 门控降低后短间隙内人声得以通过 |
| 无播放 + 安静 | 人声经过 HPF/Notch/quiet_gate，基本可懂 | 不变（本方案不涉及此场景） |

## 六、验证方法

### 6.1 统计计数器检查

通过日志观察以下计数器在播放时的行为：

| 计数器 | 结构体字段 | 预期行为 |
|--------|-----------|---------|
| nearend_blend_chunks | `live_aec.nearend_blend_chunks` | 播放时说话应持续递增（当前不递增） |
| dual_restore_chunks | `live_aec.dual_restore_chunks` | 双麦恢复触发次数 |
| ref_missing_attenuated_chunks | `live_aec.ref_missing_attenuated_chunks` | 参考丢失时衰减处理的次数 |
| playback_gate_candidate_frames | `main.c` 局部变量 | 播放门控候选帧数 |
| attenuated_quiet_frames | `audio_cleaner.stats.attenuated_quiet_frames` | quiet_gate 衰减次数 |

### 6.2 主观测试

1. 播放一段 TTS 音频（中等音量）
2. 在播放过程中以正常音量说话
3. 检查云端收到的音频是否包含清晰的人声，无明显回声残留
4. 在播放间隙轻声说话，检查是否被正确采集
