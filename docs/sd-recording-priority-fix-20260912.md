# SD 录音优先修复与验收记录

## 问题与实现

2026-09-12 测试的在线会议采集 2500 帧，网关归档只有 2485 帧；尾号 17
归档内部缺少 15 帧。独立 WebSocket 并不隔离 SD 文件系统竞争。

1. 两种补传传输统一采用录音优先准入。归档活跃、离线采集活跃、关闭中、
   writer 正在写入或队列未排空时，不启动补传任务。正在运行的任务在目录扫描、
   CRC 验证、分片读盘和提交删除前重新检查，主动返回 NOT_FINISHED。
   每次校验只推进一条记录；已发出的片段保留接收端断点，不删除未确认文件。
2. ACK 等待每 100 ms 检查录音和连接状态，录音开始时释放补传任务资源；
   独立网关建连也接入已有取消回调。TCP/DNS 的实际取消时延受传输实现约束。
3. 非阻塞采集路径保留：不以阻塞录音线程或扩大内部堆缓存来掩盖丢帧。
   镜像拒收按秒限频记录 sequence、queue、free_slots；关闭镜像记录 accepted/
   rejected，writer 完成收尾后记录 dropped_frames、degraded、complete、err。
   admission 成功不等于持久化成功，最终以 writer 关闭结果和文件帧序号为准。
4. 网关提交时记录首尾 sequence、缺失帧数和不连续次数，CRC 正确但存在缺帧
   的历史归档仍允许保存，以免丢失已有音频。complete 不替代帧连续性检查。
5. 网关每秒原子替换报告，并在 commit 后立即更新；不再依赖连接关闭。
   报告同时保存 pending 的 nextOffset 和 totalBytes。
6. 增加会话级监督进程：子进程退出后 2 秒重启、记录退出码，每次运行使用独立
   日志/报告，保持归档目录不变。显式 Stop 会停止子进程并禁止重启。
7. 补传 worker 因录音或 SD 存储忙返回 `ESP_ERR_NOT_FINISHED` 时发布重试边沿；
   连接 owner 在录音收尾、队列排空后立即清除旧退避并重新调度，不再把“本轮已
   启动”误当成“本轮已完成”。

录音停止且 SD 收尾后由现有后台调度重试，begin 返回持久化偏移后继续发送。
会议持续录音期间延迟补传；监控在当前人声归档关闭、存储空闲后可以补传。
没有开发用户可见的 SD 状态，也没有改变正式云端的业务消息路由。

会议/监控控制器在 WebSocket 断开时会保留离线接管标记，UI 同步在该标记消费前
将离线接管显示为 ACTIVE，避免状态栏开关误显示为关闭；本地用户仍可显式关闭离线
会议/监控并终止录音。

## 硬件复测

1. 保留历史 backlog，开始新会议：正在补传应主动退出，SD 队列不再受持续补传
   读盘竞争；停止会议后自动续传。核对 writer dropped_frames=0 和网关帧连续性。
2. 模拟断网录音后恢复联网，结束会议：确认离线文件 begin 的偏移、commit 和
   设备删除日志；旧尾号 19 的 `.part` 初始持久化偏移为 193536。
3. 实测监控有声/静音切换及真正断开 Wi-Fi 的恢复。
4. 进行实际 8 小时离线录音；主机容量模拟不能替代长时实机录音验证。

当前修改不能补回旧文件已缺失的 15 帧，也不能保证慢卡/坏卡永不丢帧；需要新固件
实测确认调度效果。内部堆历史最低 187 字节、NVS 压缩和 UI/唤醒延迟仍需后续日志
检查。本次未降低内存安全阈值、未清空 NVS；UI 仅增加离线接管状态同步，未修改
通用 UI 动画调度。

## 2026-09-14 八小时测试复盘

设备恢复联网后曾成功连接网关，但补传 worker 在在线会议重新启动时返回
`ESP_ERR_NOT_FINISHED`，随后同一连接没有立即重新发起 `begin`；网关报告因此为
`begins=0/chunks=0/commits=0`。本次新增重试边沿针对该场景，必须由下一次固件
实测确认 `begin` 在 SD 收尾后出现并完成全批次提交。
