# 补传 800 KiB/s 目标：分路测量固件

## 结论

上一轮网关端完成 6.5164 MiB / 19.437 s，整体约 **343.31 KiB/s**。800 KiB/s 需要约 2.33 倍，当前没有实测证据证明可达。本轮先消除读、发送并行带来的归因歧义，交付可烧录的测量固件；尚未获得本轮硬件速度或长期稳定性结果。

## 本轮行为

- 每次测试补传任务中，首个从 offset=0 开始、容量为 128 KiB 的合适窗口，先完整读入并校验，再发送、等待原有持久化 ACK。该 ACK 前预读线程不读下一窗口，因此能分别观察读取和发送吞吐。使用真实归档数据，没有合成音频或额外协议消息。
- 后续窗口恢复现有双缓冲、逐块发布。小归档、断点续传、低内存降级及线程创建失败不执行这次隔离测量。
- 新增 SD 事件入队到任务取出延迟统计，并重复输出实际 SD 时钟。SDK 原件不修改：测试构建使用经 SHA 验证的生成副本，保留原来的队列、超时和中断切换行为。
- 保留 CRC、序号、ACK 后删档、录音抢占、唤醒积压退让、内部内存保留量、40 MHz 验证失败回退 20 MHz，以及 RNNT 增容修复。正式云端协议不变。

诊断窗口人为停止读/发重叠，会给首个符合条件的段增加有限耗时；不能将该段和普通流水段直接比较。该路径只用于 SD 测试网关的窗口补传。驱动事件计时只在测试网关构建开启。

## 日志如何解释

| 日志 | 用途与边界 |
| --- | --- |
| `SD replay clock` | `actual_khz` 为控制器实际时钟读数；`negotiated_khz` 不是实际时钟的替代值。 |
| `offline replay lane probe` | `read_KiBps` 包含读取、校验、让出及调度；`tx_ack_KiBps` 包含组包、发送、让出、ACK 和可能的重试。两者不是裸 SD / Wi-Fi 带宽。 |
| `offline SD event profile` | `empty_lag_*` 仅统计进入等待前队列为空的事件，从中断入队时间戳到任务取出后的时间戳。可能含队列竞争和调度延迟，不能直接等同纯调度延迟。 |
| `queued_on_entry` | 调用接收前队列已非空的次数；这些事件不计入 `empty_lag_*`，避免将正常积压当成唤醒延迟。 |
| `receive_wait_ms` | 成功接收事件所花时间，包含等待中断及恢复执行；和 SD 命令总耗时重叠，不能相加。 |
| `offline window transfer` / `offline segment total` | 普通流水段和完整段耗时，需与网关持久化完成时间一起衡量最终吞吐。 |

驱动计数是控制器级累计值的段前后差分，可能包含该时间段的文件系统元数据访问。统计过程中使用原子计数，不在 ISR 内打印或分配内存。空队列检查与接收不是一个原子操作，因此该分组是诊断线索，不是精确的调度跟踪。

128 KiB 以 800 KiB/s 传输只允许 **160 ms**。若单独读取或发送持续明显超过这个量级，应先优化对应路径；若两路单独足够快而流水慢，应检查并行争用和唤醒负载。即使短窗口两路都超过 800，也不能保证完整上传达到 800，需要考虑并行争用、段切换及最终提交。

## 验证结果

- 完整 ESP-IDF 6.0 工程构建成功；应用分区剩余约 30%。
- 离线录音、模拟 8 小时预算、监控 SD 捕获、ACK 重试、CRC/序号、断点续传、内存降级、目录分页、SD 40/20 MHz 回退回归通过。
- 新增诊断窗口测试覆盖成功、ACK 丢失重传、错误 offset、超时耗尽、断线、连接代次变化、录音抢占；读错误/短读和完整窗口发布前抢占也能退出并回收线程。
- ESP-IDF ROM CRC 参考实现下的补传测试通过；SD 事件边界、时间戳回绕和 SDK SHA 防护检查通过。
- 最终构建确认两个 SD 源文件来自生成副本，私有头文件优先级正确；RNNT 修复两个内部调用点的最终 ELF 检查通过。
- 相比 `nuwax-sd40-fallback-20260916`，镜像增加 1152 字节，静态 DIRAM 增加 32 字节。SD 事件队列默认 4 项，每项新增一个 uint32 字段，另有少量预读上下文开销；没有新增音频大缓冲。
