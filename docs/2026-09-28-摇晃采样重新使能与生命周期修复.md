# 7.0.103 摇晃采样、重新使能与生命周期修复

对应审查：[功能门槛与逻辑质量深度审查](2026-09-28-功能门槛与逻辑质量深度审查.md)。本轮修复 G01/G02/G03；G04 完成维护操作之间的准入复查与耗时分项，完整异步隔离仍开放。不改变云端协议、语音唤醒阈值0.09、OTA最低电量5%、正式云端路由及现有表情。

## 1. 修复内容与前后效果

| 问题 | 修复前 | 修复后 |
| --- | --- | --- |
| 周期性总线争用 | 共享I2C零等待，固定周期可能反复碰到忙；锁忙和真实读取超时混淆 | 共享总线最多等待10 ms，再执行原10 ms传输预算；私有控制锁保持零等待。忙返回NOT_FINISHED，真实传输错误保留原错误；端到端≥50 ms仍拒绝样本、不突发追赶。 |
| 有意摇晃漏识别 | 忙碌跳过也清空重力基线，下一有效帧再丢一次动作证据 | 短忙碌保留基线与既有有效峰；仅使用真实采样观察，超过150 ms缺口仍清空候选。450 mg、四次交替峰、500–1500 ms动作跨度保持原值。 |
| 摇晃后不重新使能 | 每次失败清空300 ms连续静止计时；周期性短缺口可长期阻止下一次摇晃 | 在最长1 s证据窗口内累计至少300 ms相邻有效静止区间；缺失区间不计时，实际运动/真实读取故障清空静止证据，仍满足4 s冷却。 |
| 启动失败误报 | 子任务先失败，创建者随后覆盖成running=true | 原子STOPPED→STARTING，由子任务发布RUNNING或FAILED；启动者不再覆盖就绪状态。 |
| 失败后再次start | 可能被旧句柄阻止，或清空后丢失静态栈/TCB指针 | 传感器初始化失败在本次启动中为终态，保留一次静态分配，重复start拒绝且不重新分配；没有保存已退出任务的句柄。内存/任务创建失败释放资源并允许重试。 |
| 连续慢维护 | 音量保存期间已有交互到达，仍紧接着写诊断NVS；耗时统计漏掉音量保存 | 音量保存后重新检查会话/资源/命令队列/UI门禁；忙则推迟诊断。总耗时包含音量，并输出volume_ms与diagnostic_ms。 |

共享总线10 ms是配置的等待预算，不是实机绝对耗时保证；任务调度仍可能增加墙钟时间，摇晃worker保留50 ms过旧样本过滤。新方案没有增设任务、采样队列或每帧堆分配。

传感器初始化失败没有新增自动重试：避免在FreeRTOS idle尚未回收时复用静态栈。此时设备保留普通对话，只禁用本次启动中的摇晃；需要重新启动才再次初始化传感器。is_running只表示真正完成初始化，不把任务创建成功当作传感器ready。

## 2. 回归设计

- `tools/test-shake-gap.py`：直接执行生产策略及抽取的真实采样循环。覆盖原有各轴/斜向、不同频率和相位、拿起/转动/轻微走动/单次碰撞、时间回绕、过旧采样、真实故障、共享交互门禁；新增周期性20%忙碌缺口、静止后第二次摇晃、稀疏证据不累计、1 s窗口过期、真实运动清空证据与旧静止计数不跨轮次复用。
- `tools/test-shake-startup.py`：从当前生产文件抽取状态结构、初始化前段、start和is_running。覆盖创建返回前/后的成功和失败、创建期间再次start、两次分配分别失败、任务创建失败、十次重复启动不增加保留分配。调度桩不替代FreeRTOS实机调度验证。
- `tools/test-qmi-poll.py`及`tools/test-interaction-boundaries.py`：区分私有锁忙、共享锁忙和真实传输超时；验证预算、输出有效性及锁释放。
- `tools/test-diagnostic-idle-gate.py`：新增音量保存期间配网请求/UI操作到达的情况，证明不继续串接诊断写入；覆盖扬声器/OTA功能开关组合。
- 多项错误变体必须被拒绝：忙碌清空基线、丢失时段当静止、无限静止证据窗口、失败被发布为ready、失败重试丢失资源、取消交互门禁等。

合成60组周期缺口动作全部通过不代表实机100%召回率。真实硬件上必须同时观察误触与漏触，不能只测用力摇晃。

## 3. G04 保留边界

本轮没有将NVS维护搬到新任务：仅凭一次空闲快照跨任务启动Flash操作，可能与新音频/配网/OTA资源接管竞态。新增二次准入可以阻止已到达的请求被额外诊断写入拖延，但不能中止已开始的NVS事务，不能消除单次慢写，也不提供30 s落盘保证。

后续独立工作是：在保持Flash guard及音频所有权的前提下，为维护操作建立明确的请求、领取、取消和完成协议。此项仍记为开放风险，不将本轮的小修复描述为完整异步隔离。
