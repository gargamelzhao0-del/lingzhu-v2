# SD 补传事件唤醒与稳定性诊断

## 基线与判断

会话 `meeting_20260915_76f279a7_296412` 的 7838 帧、7 个分段已在测试网关验证完整。5,221,004 字节上传用时 15.727 秒，平均 324.20 KiB/s。校验耗时降低，但 SD 读取和流水线等待仍占较大比例；22.12% 的读取字节走了 PSRAM 回退路径。

当前代码的预读、发送交接依赖 `vTaskDelay(1)` 轮询。在 100 Hz 系统节拍下，数据已经就绪仍可能等到下一节拍；每个 8 KiB 发布块都可能遇到这种延迟。改用事件通知能消除这部分额外等待，但不会消除真实的 SD I/O 耗时或提高 SD 时钟。

## 本次修改

- 使用两个静态二值信号量通知数据就绪及 ACK 窗口释放，存储随预读上下文分配在 PSRAM，不新增常驻内部 DMA 缓冲。
- 原子变量仍负责数据发布和窗口所有权，事件只负责唤醒。通知先于等待到达时保持有效，多次通知可以合并；消费者每次醒来重新检查条件。
- 只有持久化 ACK 后才能复用窗口；读取错误通知发送任务退出。取消唤醒正在等待空闲窗口的读任务，仍需等它停止后才能关闭文件、释放信号量与缓冲。
- 无进展时最多每 20 ms 检查取消和连接 epoch。保留采音压力保护、工作预算让步、每个窗口后的让步和有界 SD 读取。已排队的通知不会直接清空工作预算。
- 记录缓冲回退的四类原因：`unaligned`、`reserve`、`allocation`、`post_reserve`，数值为读取切片次数。尚未根据猜测降低 16 KiB 内部内存余量或提高 SD 时钟。

版本标记为 `handoff=event`。比较下一轮时需关注整轮网关速度、`data_wait_ms`、`sd_read_ms`、回退原因和采音丢块指标；当前没有实机提速比例保证。

## 重启诊断

上一轮 MultiNet7 RNNT 内部空指针的底层原因尚未证实。本次没有将定时销毁模型当作根因修复，也没有修改识别阈值或模型算法。

独立诊断版启用 UART ELF 崩溃转储，关闭详细转储日志和整堆捕获，不另设常驻转储栈。崩溃转储保留故障任务寄存器和栈，并限制其他任务数量；不保证包含 PSRAM 中完整的 RNNT 私有对象。转储会延长崩溃后重启前的串口输出时间，正常运行不发送转储。

链接 MAP 实测诊断版相对上一轮增加 2020 字节 DIRAM 静态占用，其中包含 SDK 为转储将每核 ISR 栈从 1536 调整至 2096 字节的开销。此开销可能增加 SD 缓冲回退，因此默认速度测试版关闭转储，诊断版单独保存。两个版本不能直接用于归因事件交接的提速幅度。诊断选项保存在 `sdkconfig.sd-replay-diagnostic.defaults`，适用于追加到独立构建的配置列表。

默认版最终 MAP 对比确认 DIRAM 静态占用增量为 0，ISR 栈恢复为 1536 字节。默认版和诊断版均构建通过；默认版独立镜像及同版 ELF/MAP 另存于 `C:/tmp/nuwax-sd-event-20260915`。

每分钟记录模型 generation、实例年龄、帧数、内部与 PSRAM 空闲量及任务栈余量。可烧录版本需一并保存 ELF/MAP，避免再次用不同版本 ELF 解析旧地址。

## 验证及使用

测试记录：`../tmp/replay-event-offline-tests.log`、`../tmp/replay-event-window-final-tests.log`、`../tmp/replay-event-rom-tests.log`。覆盖完整性、续传、ACK 丢失重试、生产者消费者交接、取消、连接变化、读取失败、低内存路径，以及信号提前到达、合并和资源回收。构建信息见 `../tmp/replay-event-build-result.json`。

工程根目录烧录：

```powershell
powershell -ExecutionPolicy Bypass -File tools/flash-sd-replay-test.ps1 -Port COM11
```

使用同版 ELF 监听串口，启动监听不会主动重启设备：

```powershell
powershell -ExecutionPolicy Bypass -File tools/monitor-sd-replay-test.ps1 -Port COM11
```

若要复现并抓取 MultiNet 重启，改用诊断版，烧录和监听均指定同一目录：

```powershell
powershell -ExecutionPolicy Bypass -File tools/flash-sd-replay-test.ps1 -Port COM11 -BuildDir C:\tmp\nuwax-sd-event-diagnostic-20260915
powershell -ExecutionPolicy Bypass -File tools/monitor-sd-replay-test.ps1 -Port COM11 -BuildDir C:\tmp\nuwax-sd-event-diagnostic-20260915
```

保留完整日志，诊断版尤其需要保留 `CORE DUMP START` 到 `CORE DUMP END` 区间。监视器使用 `Ctrl+T`、`Ctrl+L` 切换日志保存，`Ctrl+]` 退出。若后续构建覆盖默认目录，应将监听脚本的 `-BuildDir` 指向设备实际烧录的独立固件目录。

上一轮 324.20 KiB/s 对照固件目录：`C:/tmp/nuwax-sd-before-event-20260915`，已保存六个镜像及同版 ELF/MAP。
