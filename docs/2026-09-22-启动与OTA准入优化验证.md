# 启动与 OTA 准入优化验证

## 依据与范围

依据 2026-09-22 提供的开机日志（附件 `73d457f3-cadf-41c7-9048-5cc95587c3e4`）。原固件 7.0.98：11.37 秒开始连接 Wi-Fi，15.22 秒取得 IP，18 秒云端应用就绪；同版本 OTA 在音频暂停后才拒绝；唤醒任务在前 40 秒启动 6 次。稳态渲染约 39.28 FPS，启动最长 UI handler 321.91ms。

本轮不改变表情、菜单布局、音频上传协议、正式云端地址、关机安全屏障或电池阈值。固件版本号仍为 7.0.98；以 ELF SHA 和启动标记区分本轮串口测试版本。正式 OTA 发布必须使用高于运行固件的版本号。

## 已实施

### 1. OTA 在取得音频所有权之前校验版本

`nuwax_ota_device.c` 增加统一版本比较，在 WebSocket 命令入队前检查，并在控制器接受队列任务时再次检查。保留传输层已有校验。

- 同版本、旧版本及仅 build metadata 不同的版本不进入升级流程。
- 拒绝时沿用 ACK 格式，返回 `rejected / version_not_newer`，不显示升级画面、不暂停唤醒、不写入新的升级事务。
- 重复任务和未确认结果仍优先按原来的幂等处理逻辑处理，不绕过已有事务。
- 新版本仍需通过认证、回滚状态、电量、音频忙、分区和关机互斥等检查。
- 客户端应把拒绝 ACK 作为本次任务的拒绝结果；未接受的任务不会产生已执行升级的成功结果。

### 2. 调整启动顺序，保留 Flash 保护

旧流程在第一次唤醒就绪后调用 `refresh_saved_wifi_list_ui()`。它读取 NVS，进入 `wifi_nvs_open()` 的 Flash 保护，从而停止刚启动的唤醒任务；当扬声器尚未持有共享音频板时，还可能引起音频板拆建。

新顺序：

1. 配网服务退出后，读取 Wi-Fi 历史列表。
2. 在没有唤醒采集任务时预处理已保存 STA 配置。
3. 加载唤醒模型。
4. 完成 AEC 预检，并释放预检资源。
5. 初始化扬声器，保持共享音频板。
6. 启动唤醒，检查内部 RAM/DMA 余量。
7. 按现有内存门限启动后台联网。

`nuwax_wifi_prepare_boot_config()` 与正式连接路径共用 STA 配置构造函数；实际连接时仍重新核对驱动配置，匹配才跳过重复配置及 Flash 保护。预处理失败继续走原有连接重试路径。

预处理不会关联 AP，不修改已连接、正在连接、处于配网所有权下或模拟离线的 STA。保留 NVS/配置写入保护，未以取消保护换取速度。未将模型构建、AEC 内存峰值与 WPA3 认证同时启动。

效果目标是消除可避免的启停和配置写入，不承诺唤醒任务永远只启动一次：实际唤醒词更新、升级、配网及内存不足时仍可能需要合法切换。DHCP 约 3.2 秒的等待也不由本轮代码直接消除。

### 3. I²C 长事务归属诊断

原日志最长等待 156.5ms、持锁 162.3ms、锁超时 6 次，仅有全局总量，无法确认具体来源。检查代码后，电量计命令之间的必要延时已在共享锁之外；编解码器锁覆盖的是单次代理操作。没有证据支持直接缩短硬件超时或取消互斥。

增加 `long_holds`（持锁超过 10ms 的次数）、`wait_task`、`hold_task`、`timeout_task`。固定大小字段，无动态分配；继续由电池任务低频输出，不在共享事务锁内逐条打印。

这项是诊断补全，加上减少重复编解码器初始化带来的总线负载下降。**不能据此宣称 162ms 长事务或 6 次锁超时已经消失**；必须根据下一轮日志的任务归属继续判断。任务名用于定位调用链，不等同于某个外设已经故障。

## 实机验收

1. 开机应出现 `boot optimization revision=20260922-startup-v1`、`boot STA configuration prepared before wake`。
2. 正常已配网冷启动，连接阶段应出现 `Wi-Fi STA configuration unchanged; reuse without Flash fence`；检查编解码器完整初始化次数是否减少。
3. 下发与当前相同版本的合法 OTA 命令，应出现 `OTA rejected before audio reservation: version_not_newer`；此次命令不应出现 OTA 音频暂停或升级画面。
4. 使用合法新版本验证正常升级、失败恢复和升级后启动确认；本轮仅编译和主机检查不能代替这些设备测试。
5. 对比取得 IP、云端就绪时间、UI 最大停顿、音频健康、内部内存低水位；同一网络多次冷启动，避免以一次 DHCP 快慢判定效果。
6. 收集 `I2C totals` 与 `I2C contention`，同时操作触摸、摇晃和对话，检查长事务归属。保留锁超时与显示停顿是否同一时段的证据。
7. 回归断网恢复、会议/监控、SD 补传及长按关机。沿用上一轮未完成的故障注入和板级实测清单。

本轮不自动烧录设备；实机帧率、触摸体验、联网改善幅度与长时间稳定性均需烧录后验证。
