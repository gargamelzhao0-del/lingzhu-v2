# SD 补传速度与稳定性修复（7.0.210）

本轮基于 7.0.209 修改设备发送链路。保留会议、监控控制及重连状态同步，云端/App 消息、二进制包、存储格式和确认规则不变。

## 修改范围

### TLS 发送期限

- 新帧尚未进入 TLS 时，可以暂缓或取消，连接保持可用。
- TLS 接收过输入后，保留该帧缓冲、原始输入跨度及 `WANT_READ`/`WANT_WRITE` 方向，完成当前帧后再交接。
- 实际 BIO 写出或 TLS 返回已接受字节，才更新最后进展时间；单纯重试、被唤醒不算进展。
- 无进展期限为 2.5 秒。后台发送仍有总期限：250ms I/O 预算加最多 8 秒完成预算，并由心跳剩余期限进一步收紧。
- 收到本地前台取消请求后，独立的 2.5 秒交接期限只设置一次，不因后续进展续期。
- 超出期限仍无法完整结束 TLS 帧时，断开该连接，保留未确认文件，之后按原协议重试。不能遗弃半帧后继续在原连接发送其他消息。

这些数值是失败边界，不是每包固定等待时间。网络正常时立即继续发送。

### TCP 空间释放与发送准入

正式云端共享连接复用已有 `tcp_output` 封装，观察 ACK、可用发送空间及对端窗口变化，更新事件序号并唤醒唯一的补传发送任务。保留 SDK 的原始返回值、数据所有权、拥塞控制和重传规则。

事件信号量在运行期间一直有效。等待前后均核对所属连接、代次和事件序号，ACK 恰好发生在检查与等待之间不会丢失；旧文件或已关闭连接的迟到信号不会被当成新进展。TCP PCB 指针不保存到工作线程。

`WANT_WRITE` 优先等进展事件，最多 20ms 检查一次期限和取消条件。`WANT_READ` 保留原可读等待。观察器不可用时，仅在最坏 TCP 内存增长仍能留足录音空间的情况下回退到 SDK 等待，否则暂缓补传。

新帧的容量等待发生在 TX、TLS I/O、生命周期锁之外。发送队列暂满时，在同一文件和偏移处有界重试准入，避免反复重新开始文件事务。正常发送和低内存发送均执行容量保护。

### 网络与内存配置

| 项目 | 本轮值/规则 |
| --- | --- |
| TCP 发送缓存上限 | 131072 字节，按需分配 |
| TCP 窗口缩放 | 启用；接收缩放因子为 0 |
| TCP 接收窗口 | 保持 11520 字节 |
| TLS 输出记录 | 保持 8192 字节 |
| SD 二进制载荷上限 | 保持 8064 字节，原 64 字节头 |
| 双预读缓冲 | 两块 32KiB；正常历史帧使用每块 32256 字节有效跨度 |
| 控制发送空间 | 补传额度中留出 8192 字节 |
| 实际补传排队量 | 根据当前内部 RAM、PSRAM、已分配 TCP 字节及录音余量收缩 |

分配预读缓冲之前，计算新增 TCP 数据及元数据的峰值余量。记录缓冲关闭后，其内存信用不能继续使用。内存不足时缩小缓冲或暂缓，不能覆盖未确认录音或无限分配内存。发送队列已经清空但仍缺内存时，返回资源不足并沿用文件重试退避；前台取消仍使用原让出路径，避免资源不足被反复当成前台抢占。

128KiB 是本轮验证档位。真实 RTT、对端窗口、丢包及可用内存可能要求不同额度，不能据此保证任意网络均达到 500KiB/s。

## 保留的数据规则

- 满文件按原顺序上传，继续原场次和文件索引。
- `begin → Binary → commit → commit_ack`、最终场次确认不变。
- 文件字节、帧序号、CRC、断点偏移及持久化确认匹配保持原规则。
- 收到持久化确认之前，不因“已经写入 TCP/TLS”删除源文件。
- 保留 7.0.209 的启停控制、8 小时会议计时、监控人声保存及无卡实时路径。

## 验证与验收

定向检查入口：`tools/test-sd-flow-control.py`。执行生产发送循环、实际录音启动准入、实际 TCP 观察器与等待器；替换的边界是 socket/TLS/RTOS。包含 400 次真实 Windows 线程 ACK/等待交错、迟到输出、序号回绕、低内存及取消测试。

生产代码边界检查包含：原 WS 编码器、场次存储、文件事务、CRC、模式控制和状态同步保持不变。既有 SD/FatFs、会议、监控、唤醒、播放及模式切换回归继续执行。

主机模拟不能证明实机吞吐或长时间硬件运行稳定性。本轮不操作串口、重启或烧录设备，不中断已有采集。

实机速度按“已确认且不重复的归档字节数 / 有待上传文件期间的在线总耗时”计算，包含请求、确认、重试和退避。断网时间单独记录。约 4MiB 文件需在约 8.2 秒内完成确认，才达到 500KiB/s；短尾文件还受固定确认延迟影响。

实机回归应覆盖 8 小时会议、长时间监控、离线多场、恢复联网、传输中切换模式、低内存、卡满及各确认边界断线。除速度外，核对帧数、序号、CRC、所有文件和场次确认，以及录音队列丢帧、重启和异常停录记录。

## 新日志

- `SD formal flow revision=210`：准入等待、事件等待/唤醒/超时、发送上限及最长无进展时间。
- `SD formal TCP flow revision=210`：ACK 推进次数/字节、对端窗口与拥塞窗口范围、排队与在途峰值，以及发送到 TCP ACK 的高分辨率延迟样本。

TCP ACK 延迟包含延迟确认和网络调度，不是文件落盘确认时间。发送阶段计时包含任务抢占，不能当成纯加密 CPU 用时。日志在文件事务结束后汇总，不逐包打印。
