# SD 缓存与补传稳定性修复

## 变更

针对五分钟会议日志中的 `SD writer slow operation elapsed_ms=7767`、镜像 `rejected=8` 和补传重连，完成以下修复：

1. 镜像 PSRAM 暂存从 256 帧扩展为 768 帧。按每帧 20 ms，暂存可容纳 15.36 秒；加上 128 帧写入队列，总容量约 17.92 秒。每个镜像暂存增加约 326 KiB PSRAM，不占内部 DMA 堆。异步关闭排空上限调整为 20 秒。
2. 写入与补传读取使用显式分配在 PSRAM 的 16 KiB stdio 缓冲；写缓冲在初始化阶段一次分配，读缓冲在单个归档回放结束后释放。仍按原有周期和分段结束执行刷盘，不改变断电恢复格式。
3. 补传顺序读取不再对每个 chunk 重复 seek，只有首次续传或部分 ACK 改变偏移时定位，保留读取缓存。新增 `path_lookup`、`file_open`、`replay_validate` 慢操作日志，区分目录查找、创建文件和归档预校验耗时。
4. 独立 SD 测试网关连接的二进制整帧 I/O 上限从 250 ms 调整为 1500 ms。正式云端共用连接保持原有短预算。此前的整帧互斥、旧连接代次隔离和部分发送失败强制重连继续生效。
5. chunk ACK 超时可在同一有效连接上重试最多 3 次，保持请求 ID、偏移和字节完全一致，由网关幂等校验避免重复追加。连接失效、代次变化或录音抢占时立即停止该层重试；后续由 begin ACK 确认续传偏移。
6. begin ACK 返回越界偏移时报告协议错误，保留本地文件。避免用本地损坏错误码将正常 SD 文件误隔离为 `.bad`。
7. 会议采集日志把 `uploaded` 更名为 `enqueued`，明确它代表进入发送队列。判断交付仍需发送统计、网关提交确认和落盘校验；镜像入口的 `rejected` 与写入线程的 `dropped_frames` 应分别检查。
8. 网关文件写入处理短写，循环完成整个 chunk 并 fsync 后再 ACK。增加只读归档审计工具，校验整个会话的 CRC、重复帧、跨分段序号缺口和预期总帧数。

协议字段、归档结构、音频会话 ID 保持规则均未改变。未收到成功 commit ACK 的本地文件继续保留。本次扩大的是短期抗阻塞缓冲，8 小时音频仍持续写入 SD，不能将内存缓冲理解为对任意时长 SD 故障的保证。

## 验证

- 生产镜像暂存代码：模拟 7.767 秒和 12 秒写入不可用，恢复后逐帧检查采样内容、时间戳和序号，无拒收；同时保留超容量及关闭超时失败用例。
- 生产补传重试代码：ACK 丢失、同请求同字节重试、有界耗尽、连接代次变化、部分发送断连和录音抢占全部通过。
- 生产 WebSocket 发送代码：350 ms 写入阻塞下，原 250 ms 预算按预期失败，新独立连接预算完成整帧；原有 80 次并发帧调度与 100 次重连测试通过。
- 测试网关实际 WebSocket 集成：15,000 帧、300 秒音频、10 个归档，覆盖 10 次重连、重复 chunk、重复 commit。落盘字节与输入完全一致，CRC、跨分段连续序号和总帧数通过。短写注入通过。
- 会议、监控、离线音频、音频生命周期、对话回归及网关原有自测和实时报告测试通过。
- ESP-IDF 工程构建通过，应用分区剩余约 30%。

上述 300 秒数据是主机生成的协议测试数据，经真实本地 WebSocket 上传，不是新固件在设备上录制的五分钟音频。8 小时实机录音、真实 SD 时延和内存高水位仍需烧录后的设备测试确认。
