# 测试网关会议与监控完整音频落盘

更新时间：2026-07-21

适用工程：`Nuwax AI Partner 7.0/cloud-gateway`

## 1. 改动目的

旧测试网关只在内存中保存每个上行音频会话的前 `2 MiB` PCM，结束后再将这段内存生成 WAV。对 `16 kHz / 单声道 / PCM16` 而言，最终 WAV 只有约 65.536 秒，即使设备已经完整上传 30 分钟，文件仍会被截断。

本次将长时间音频保存与普通对话 ASR 缓冲拆分：

- 普通对话继续使用有限内存，避免改变 ASR、智能打断和现有调试逻辑。
- `meeting`、`monitoring` 和兼容名称 `monitor` 边接收边写入磁盘。
- 内存达到 `CLOUD_AUDIO_MAX_SESSION_BYTES` 后不影响长时 WAV，磁盘文件继续写入。
- 收到 END、`listen stop` 或 WebSocket 关闭时都会封装 WAV 头并完成文件。
- 长时间监控接近标准 RIFF/WAV 单文件容量上限前自动分段，不丢弃后续 PCM。

## 2. 文件位置与命名

默认目录：

`runtime-logs/audio-debug`

单段会话：

```text
<audio_session_id>.wav
<audio_session_id>.json
```

超过单段上限后：

```text
<audio_session_id>.wav
<audio_session_id>_part002.wav
<audio_session_id>_part003.wav
...
```

每一段都有同名 JSON 元数据。`latest-capture.json` 保存最近完成会话的全部分段清单。`latest.wav` 指向最近会话的第一段；当 `segment_count > 1` 时，必须按 `latest-capture.json` 的 `files` 顺序读取全部文件，不能把 `latest.wav` 单独视为完整会话。

默认单段 PCM 上限为 `1 GiB`。在 `16 kHz / 单声道 / PCM16` 下约为 9.32 小时，之后自动生成下一段。

## 3. 可配置项

```text
CLOUD_CONTINUOUS_CAPTURE_SAVE_WAV=true
CLOUD_CONTINUOUS_CAPTURE_DIR=<保存目录>
CLOUD_CONTINUOUS_CAPTURE_SEGMENT_BYTES=1073741824
```

默认开启完整落盘。测试网关状态接口 `/api/status` 的 `gateway.asr` 中会返回：

- `continuous_capture_save_wav`
- `continuous_capture_dir`
- `continuous_capture_segment_bytes`
- `continuous_capture_modes`

音频会话状态新增 `continuous_capture`，其中：

- `complete=true`：已完成封装，已写 PCM 字节数与最终文件一致。
- `bytes_written`：连续写入磁盘的 PCM 总字节数。
- `segment_count`：本会话 WAV 分段数量。
- `files`：已完成分段文件名。
- `failed=true`：磁盘、权限、空间或写入发生错误，不能宣称文件完整。
- `error`：首个落盘错误。

`memory_stored_bytes` 和 `memory_truncated` 只描述普通内存缓冲，不再代表会议或监控 WAV 是否完整。长时模式应以 `continuous_capture.complete` 和 `continuous_capture.bytes_written` 为准。

## 4. 主要代码

- `cloud-gateway/continuous-audio-capture.js`
  - 流式 PCM16 写入。
  - WAV 头最终回填。
  - 格式变化和容量上限自动分段。
  - 写入失败保留 `.wav.part` 便于诊断。
- `cloud-gateway/cloud-gateway.js`
  - 为会议/监控会话创建写入器。
  - 每个解码后的 PCM 帧先写连续文件，再进入原有有限内存缓冲。
  - 正常结束和连接关闭均执行收尾。
  - 会议/监控仍属于诊断音频模式，不进入普通 ASR。

## 5. 自动化验证

执行：

```powershell
cd cloud-gateway
npm run test:meeting
```

覆盖内容：

1. 用很小的分段上限验证三个 WAV 分段拼接后与原始 PCM 逐字节一致。
2. 将普通内存上限压到 512 字节，会议模式上传 1,024 字节，最终 WAV 仍完整。
3. 同样条件下监控模式上传 1,536 字节，最终 WAV 仍完整且不进入 ASR。
4. 不发送 END，关闭 WebSocket，网关仍保存已收到的全部 PCM，并把结束原因记录为 `peer_close`。
5. WAV 的 RIFF 长度、data 长度、采样率、通道数和 PCM 内容均进行断言。

当前自动化结果：全部通过。

## 6. 运行边界

- 完整保存依赖电脑磁盘空间。监控模式可能长期运行，部署时必须监控剩余空间并制定归档或清理策略。
- 进程被强制结束或电脑断电时，当前段可能保留为 `.wav.part`；正常 WebSocket 断开可以正确收尾。
- 本功能保存的是设备已经处理并上传到网关的 PCM，不恢复设备端在采集或网络发送阶段已经丢失的帧。
- `capture.complete=true` 证明网关收到的 PCM 已完整落盘；是否存在设备到网关的序号缺口仍应结合 `first_sequence`、`last_sequence` 和帧数检查。
