# Wi-Fi 异步恢复与启动修复

本轮针对 4bc9e65a、b1f3beae 两份串口日志暴露的启动等待、main 看门狗和重复配置问题。设备出现认证过期、连接失败及找不到 AP 时，不应把无线连接等待传递给主任务。

## 改动

- 主任务不再同步调用 `nuwax_wifi_connect()` / `nuwax_wifi_recover()`；现有 `nuwax_wifi_conn` 任务承接后台恢复，不增加任务或任务栈。
- 启动先完成本地音频、UI 和资源预检，再由主循环提交异步联网。取消原先启动路径中的 30 秒连接等待，保留模型加载与联网峰值错开的顺序。
- 主循环在网络未就绪时每轮延迟 50 ms，继续处理本地动作、离线模式交接及看门狗。50 ms 是循环延迟配置，不是实机响应时间保证。
- 一个恢复槽位合并重复请求。工作任务有明确连接请求时优先处理该请求；运行中的驱动操作仍由原 Wi-Fi 锁串行保护。
- 连续恢复失败后的退避为 3、6、12、24、30 秒，后续封顶 30 秒。连接成功后清零。此退避与云端 WebSocket 的失败计数分离。
- 配网交接使旧恢复结果失效；工作任务遵守 Wi-Fi 管理器的交接/模拟离线取消检查。配置读取失败、配置变化、保护失败仍走原有错误路径。
- 相同配置跳过 `esp_wifi_set_config()` 及其 Flash 停止保护。比较当前驱动配置；一次成功写入后同时记住请求值与驱动读回值，以兼容驱动自动归一化。外部配网改变驱动状态后重新验证，不能仅凭上次 SSID 相同跳过写入。
- 新增断线 reason/RSSI/BSSID 和关联成功 channel/authmode/BSSID 日志。未找到 AP 时 RSSI/BSSID 可能无有效值，不可据此声称信号强弱已确定。密码不输出到日志。

未改变看门狗期限，未取消 Flash 安全保护，未调整显示、音频或 Wi-Fi 驱动任务优先级。

## 验证

`tools/run-wifi-background-host-checks.ps1` 提取生产恢复协调函数，用虚拟时钟与无线驱动模拟下列场景：

- 连续六轮各 30 秒失败，检查请求合并、主任务检查点和退避。
- 主、备网络合计 60 秒等待；成功结果只消费一次；成功后链路立即消失不误报成功。
- 配网/模拟离线取消、旧结果失效、待执行请求取消、明确连接请求排队优先、锁忙退回。

`tools/run-wifi-recovery-host-checks.ps1` 提取生产 Wi-Fi 管理器函数，验证重复连接合并、20 个并发调用者、连接完成/失败/超时、时钟回绕、交接取消，以及配置复用和实际改写时的 Flash 保护。新增驱动归一化读回、外部配置改变、读取失败测试。

上述均为主机模拟测试，不代表 ESP32 已通过射频、长时间离线或交互流畅度实测。完整 ESP-IDF 工程构建、RNNT 链接检查和应用分区尺寸检查已通过。

## 固件与烧录

固定目录：`C:/tmp/nuwax-wifi-async-20260920`。

在工程目录执行（COM11 替换为设备实际串口）：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\flash-sd-replay-test.ps1 -Port COM11 -BuildDir C:/tmp/nuwax-wifi-async-20260920
```

目录内的 `build-result.json` 记录镜像与源文件校验值。分析串口回溯时必须使用该目录内的 ELF，不要使用旧 `build` 目录里的 ELF。保留现有 SD 测试网关和 UI 网络测试开关配置；未执行烧录。

## 下一轮实机检查

1. AP 不可用启动，观察本地初始化不再被 30 秒 Wi-Fi 超时拖住。启动时 `PRODUCT_READY` 的 Wi-Fi 未就绪标记是联网尚未完成的状态，不等于再次发生连接失败。
2. 保持 AP 不可用至少 5 分钟，操作菜单和配网入口；不得出现 main 看门狗重启。记录 worker 完成耗时、退避与唤醒停止次数。
3. 恢复 AP，确认关联、获取 IP、云端连接及状态显示依次恢复。
4. 在恢复中开启/退出配网、操作网络模拟开关，检查旧连接结果不覆盖新状态。
5. 保留完整启动 SHA、Wi-Fi 链路诊断及 UI perf 日志。300～376 ms 长帧和无线侧 reason=201/2/205 的最初原因仍需实机定位，本轮不声称已消除这些问题。
