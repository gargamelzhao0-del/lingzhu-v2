# 监控模式设备端开发记录

更新时间：2026-07-22  
工程：`NuwaxAIPartner`（7.0 正式设备工程，目标端口 COM8）  
状态：设备端实现、宿主机检查、ESP-IDF 构建、测试网关回归和 COM8 实机核心验收均已通过

## 1. 本轮目标

监控模式只由云端开启和关闭。模式活动期间，设备持续上传所有成功读取的麦克风帧，不做 VAD 门控、静音删除、会议增益、AEC、降噪或 30 分钟自动退出；同时禁止普通 ASR、智能体请求、TTS 生成和设备播报。

普通对话、会议和监控三种模式必须互斥。监控开启时要停止普通采集、自动追问和唤醒词采集；若设备正在播报，则约 200 ms 淡出，最多等待 500 ms 完成播放收尾后再开始监控。

## 2. 代码实现

新增独立目录：

```text
main/audio_modes/monitoring/
  monitoring_protocol.c
  monitoring_protocol.h
  monitoring_mode.c
  monitoring_mode.h
```

协议解析只接受云端 `device_command / set_audio_mode / monitoring / enabled|disabled`。状态机为：

```text
DISABLED -> STARTING -> ACTIVE -> STOPPING -> DISABLED
```

监控采集直接调用公共麦克风驱动的 `nuwax_mic_input_read_pcm16()`，再调用公共 `nuwax_audio_uplink`。监控目录不引用 `meeting_processor`、`audio_cleaner`、`live_aec` 或任何 VAD 处理器。

正式 ESP Vocat 配置下，`read_pcm16()` 读取 ES7210 四槽 TDM 的 `slot0/MIC1` 并输出单声道 PCM16；当前 `CONFIG_NUWAX_VOCAT_MIC_INPUT_GAIN_Q15=32768`，即 1.0 倍。监控层不再修改样本。

每次会话保留一个待发送真实帧，使云端关闭时最后一个真实帧可以携带 `END`。首帧设置 `START`，任何帧都不设置 `VAD_SPEECH`。

## 3. 主程序接入

- `hello.features` 新增 `monitoring_mode_v1:true`。
- 新增 `NUWAX_MIC_OWNER_MONITORING_CAPTURE`，与普通对话、唤醒词和会议采集共用同一所有权锁。
- WebSocket 文本入口先识别监控和会议控制消息，再进入普通会话解析。
- 独占模式命令一旦入队，普通采集在下一帧边界退出并释放麦克风。
- 会议与监控通过双向 `can_start` 门禁互斥；冲突命令返回 `audio_mode_busy`。
- 监控期间丢弃普通 ASR、文本回复、TTS 结果、播放事件和迟到的 TTS binary。
- 监控关闭后恢复普通睡眠/唤醒入口；WebSocket 断开时本地复位，不自动恢复旧监控会话。

### 5.2 严格完整性检查

测试网关不再只依据 WAV 文件是否成功关闭判断完整性，而是同时检查：

- 首帧 START 和末帧 END。
- 首序号为 0。
- 序号缺口、重复帧和乱序帧均为 0。
- PCM 流式落盘成功。

正常实机会话结果为 `sequence_complete:true`、`protocol_complete:true`、
`storage_complete:true` 和 `capture_complete:true`。宿主机故意跳过一帧时会得到
`sequence_gap`；断线缺 END 时会得到 `missing_end`，两种情况都不会再错误标为完整录音。

### 5.3 断线和恢复

- 监控会话 `monitoring_stream_4_78ff2275` 活动期间复位 COM8。
- 复位前已接收的 36.608 秒、2288 帧、1171456 字节 PCM 仍被封装为可读取 WAV，
  但元数据正确标记 `capture_complete:false`、`protocol_complete:false`、
  `storage_complete:true`、`incomplete_reason:"missing_end"`。
- 设备重连后 `currentUplinkAudioSession:null`，没有自动恢复旧监控会话。
- 重连后再次开启和关闭成功；新会话 202 帧，序号、END、listen stop 和 WAV 均完整，
  证明麦克风所有权和模式状态已恢复。

  该时延属于网络恢复观测，不是监控状态机超时。

## 6. 测试网关配套修正

- 保留并公开设备 hello 的 `meeting_mode_v1` 和 `monitoring_mode_v1`，开启监控前执行能力门禁。
- 支持 END 之后紧接的合法 `listen stop`，不再误记为重复停止。
- 增加逐帧序号缺口、重复和乱序统计，并将协议完整性写入 WAV 元数据。
- 开启监控前取消活动轮次，固定顺序为 `stop_playback -> set_audio_mode monitoring enabled`。
- 对重复 enabled 保持幂等，不重复取消内部 monitoring 恢复轮次。
- 网关主进程启动时恢复强制退出遗留的 `.wav.part`，保留已收 PCM，并以不完整元数据标识。

## 7. 尚未覆盖的边界

1. 一小时实机耐久首次尝试在 148.096 秒时被设备 WebSocket 重连中断；带 COM8 串口的重试
   已连续运行 3600.832 秒并通过。数小时持续录音和超大文件自动分段实机测试仍尚未执行。
2. 尚未注入磁盘写满、目录权限丢失和文件系统 I/O 故障。
3. 尚未验证操作系统断电导致底层文件系统未落盘的情况；启动恢复只能修复已经写入磁盘的
   PCM，不能恢复操作系统尚未持久化的数据。
4. 尚未由最终云端服务按 `monitoring-mode-v1.md` 完成正式联调和权限策略验收。
5. 监控模式按需求上传原始 MIC1，不做音质增强；仍需结合实际部署环境做人工听感抽检。

因此当前结论是：监控模式设备端核心功能、测试网关闭环和一小时实机耐久已经通过，达到可联调
状态；上述剩余边界属于更长时间耐久、故障注入和正式云端验收，不阻塞设备端协议与主链路交付。
