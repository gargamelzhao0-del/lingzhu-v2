# 2026-09-18 屏幕驱动像素搬运优化

本轮以修复后的 LVGL 单一路径为基础，优化 display.c 像素转换并增加低频分阶段统计。没有提高 QSPI 时钟、调整任务优先级、增加 DMA 缓冲或引入在途双缓冲。配置仍为 40 MHz、20 行、LVGL 异步双缓冲。SD 逻辑及测试网关配置保持现状。

## 实现与依据

原 copy_pixels_byte_swapped 每两个像素调用普通 memcpy。IDF 的 -fno-builtin-memcpy 使最终固件循环中实际调用 ROM memcpy，整屏该路径约 64,800 次调用。

现在先处理目标半字偏移，再区分源地址：
- 源 4 字节对齐：显式 builtin memcpy 配合已检查的对齐信息，编译为单次 32 位读取，避免违反源数据别名规则。
- 源仅 2 字节对齐：显式两次 16 位读取，避免未对齐字读取。
- 保留奇数尾像素，转换结果及源缓冲内容保持一致。

实际 Xtensa 编译检查确认：没有辅助函数调用，没有逐字节到栈的临时搬运；最终 ELF 中生产拷贝路径不再引用 ROM memcpy。减少的是 CPU 转换开销，不代表总线或整帧性能已获得某个固定比例提升。

## 新日志

启用 CONFIG_NUWAX_UI_PERF_LOG_ENABLE 时，按原 UI perf 周期增加一行 display pipeline。关闭时不进行各阶段计时。统计以临界区保护跨任务读写，不分配堆内存、不逐块输出日志。

| 字段 | 口径 |
|---|---|
| jobs / queue_us | 开始处理的 LVGL 刷新任务数 / 从其 queued_us 到驱动处理前的等待总时间；包括等待可用流水线槽位 |
| copy_us | 中转路径打包及 RGB565 转换总耗时 |
| swap_us | 直接 DMA 路径原地字节交换总耗时 |
| tx_wait_us | 像素发送调用及等待总耗时，包含调度抢占，不是纯线速时间 |
| bounce_bytes / direct_bytes | 成功像素事务的中转 / 直传字节数 |
| chunks / failures | 像素事务尝试数 / 失败数；不涵盖地址命令失败，后者仍看 display flush failed |

以上是窗口累计值，不是单帧值。各阶段可跨窗口，启动首次采样还可能包含初始化发送；不要将阶段之和当作每帧延迟，也不要直接用 tx_wait_us 算物理总线速率。copy_us 与 tx_wait_us 的比例可用于判断后续 DMA 流水线是否值得引入。
