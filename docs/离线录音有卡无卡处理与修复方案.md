# 离线录音有卡、无卡与故障恢复方案

本文件为 7.0.113 的历史设计，不代表当前有卡场次实现。当前运行逻辑见 [功能逻辑与异常处理](SD会议监控功能逻辑与异常处理.md)，当前接口见 [SD 会议监控场次上传协议](SD会议监控场次上传协议.md)。

日期：2026-10-09。基于当前 7.0.113 源码。本文件是实施设计，不是已实现功能或真机验收结论。固定 PoP、正常云端协议和现有音频格式保持；不恢复屏幕长按功能，不新增 SD 管理面板。

## 1. 产品规则

有健康保存路径才可表示“正常录音”。用户希望继续、MIC 正在工作、数据进入 RAM、数据保存成功，是四件不同的事。

默认继续当前产品范围：原来已经开启并获得授权的会议/监控，断网后续录；不在本修复中新增“开机即离线创建一场会议”。用户停止、原会话到期、换绑、关机或重启失去恢复授权后，旧意图不能自动开录。

停止录音与补传积压是两个独立动作：用户停止后不再采集，已保存的录音仍可在原归属与上传授权有效时补传，不因停止而删除。

无 SD 时可保留正常在线会议/监控，但不能承诺八小时离线保存。当前 PCM16、16 kHz、单声道、20 ms 帧，八小时原始音频为 921,600,000 字节（约 879 MiB）；加每帧 22 字节 NA 头和 4 字节记录长度，约 915 MiB，再加段元数据、文件系统和保留空间。`partitions.customwake.csv` 的 storage 分区只有 1 MiB，不能替代 SD；不应把音频写进 NVS/OTA/模型分区。

现有 mirror staging 为 768 帧，writer queue 为 128 帧，按 20 ms 算分别相当于 15.36 秒和 2.56 秒容量。这只是空缓冲的理论容量，不保证卡故障时必能保住这么长时间，也不是无卡长时间录音功能。无卡必须保存八小时，需要额外足够的持久存储，不能仅靠软件补丁实现。

## 2. 有无 SD 的统一行为表

| 情况 | 设备行为 | 用户体验与恢复 |
| --- | --- | --- |
| 在线，有健康 SD | 在线流程照常，本地镜像按当前会议/监控策略保存 | 正常使用不增加固定等待 |
| 在线，无卡或 SD 不可用 | 云端路径健康时继续在线，停用不可用的本地镜像；后台低频探测 | 不因可选备份故障中断正常在线功能，不反复弹窗 |
| 监控云端上传暂停 | 有可用 SD 时继续按人声策略本地保存；无可用 SD 时这一期间没有音频保存路径 | 即使 Wi-Fi 在线也不能宣称已保存；提示本地录音不可用，不擅自恢复云端上传来掩盖故障 |
| 原模式断网，有可写且空间足够的卡 | 原会话继续 SD；会议连续采集，监控只存符合人声策略的内容 | 可正常离线续录；恢复网络后按原流程续接 |
| 原模式断网，从一开始就无可用卡 | 不假装正在录音；释放不必要的录音资源，保留有界、可取消的恢复意图 | 一次简短提示“离线录音不可用，等待恢复”；菜单显示中断/待恢复，而不是运行中 |
| 短时 SD 慢或挂载恢复 | 内容仍完整保留在有界缓冲时维持恢复态；安全退出旧文件访问后恢复介质 | 全部补写成功不宣称丢失；不能仅凭最近没有写字节就报错 |
| 卡写坏、只读、拔出或持续失败 | 故障 owner 停止新文件准入，保留已保存文件；已知丢帧记缺口，未知持久化结果记未知；无法继续留存时暂停录音 | 说明中断，不能一直采集、丢弃又显示正常 |
| 满卡或归档配额用尽 | 保留未确认上传的旧录音；停止不可兑现的离线续录；网络恢复且授权后可继续在线 | 不自动删除旧录音腾空间；告知当前无法继续保存 |
| 插回健康卡/换入健康卡 | 后台检查可写、空间及归属；原意图仍有效才从当前时刻续录 | 保留先前缺口，不声称补回无卡时的声音；未知来源旧档不能自动补传 |
| 网络恢复但仍无卡 | 原意图、身份和时限有效时恢复在线录音 | 无卡期间无法补传；有旧档时只补传实际存在的内容 |
| 用户停止、到期或失去授权 | 取消自动续录，已有尾部按实际结果收尾 | 插卡、重连、旧 ACK 不得重新开录；后续真正的新开启请求属于新会话 |

没有可靠的物理卡检测证据时，不能把所有挂载失败都显示成“未插卡”；统一用“离线录音不可用”，内部再区分未就绪、空间不足、I/O、内存等原因。不得自动格式化来恢复录音。

## 3. 设备端最小状态改造

由模式 owner 合成一个只读快照，UI、恢复、资源准入使用同一事实来源：

- 意图：OFF / MEETING / MONITORING，带停止代际、会话、绑定范围与有效期。
- 运行：STARTING / ONLINE / OFFLINE_RECORDING / BUFFERING / WAIT_RECOVERY / STOPPING / STOPPED。
- 保存：本地准入、writer 健康、已接收/已写入/已同步水位；在线授权和发送进展单独记录。发送成功不能当作服务器持久化证明。
- 覆盖：正常、已知缺口、无法确认；当前已恢复与历史有缺口可以同时成立。

这些是内部状态，不要求向现有协议增加状态值。设备使用现有启动、错误、关闭等 UI 能力和简短提示。无需增加 SD 容量页、卡图标或补传进度面板。

当前 `main/nuwax_ai_partner_main.c:4372` 仅凭 lease 就可能把禁用控制器映射为 ACTIVE；应改为上述状态派生。`s_offline_mode_capture_failed` 只能作为一个输入，不能仅凭它或仅凭 `capture_running` 判断录音成功，因为采集可能运行但 writer 正在丢帧。

## 4. 故障恢复不重写现有正常录音链

现有 `mirror_drain` 已在部分 append 故障时请求结束旧文件 generation 并唤醒 supervisor；`recover_if_idle` 已在文件/写入/补传安全退出后恢复介质。这些保护应保留，不应描述成工程完全没有热插拔恢复。

建议在其上补齐统一的故障分类、状态发布和恢复边界：

1. **短时背压**：只要 PCM 还安全保留在有界缓冲，不当作丢失，不立即停止 MIC；保留当前延迟挂接和异步补写。
2. **文件/I/O 故障**：禁止旧文件的新访问，通知 writer 和 replay 退出其介质所有权。MIC 可以在明确容量和安全边界内继续暂存，不能为重挂载无条件立刻断开正常采集，也不能让旧 FILE/ACK 越过介质切换。
3. **持久不可用/缓冲耗尽**：停止无保存意义的录音工作，转 WAIT_RECOVERY；已知丢失与不确定尾部分别记录。保留可取消的用户意图，不让重试任务重新启动已停止的会话。
4. **恢复可用**：挂载、必要的前缀恢复、空间和写入准入成功后再恢复。恢复以新文件分片继续；原会话未终止则保留 session 和序号规则，不能重置为从未发生缺口。
5. **恢复失败**：退避重试，UI/网络 owner 不等待目录扫描或 fsync；没有卡时不循环创建大缓存、不高频刷日志。内存不足和满卡应有独立原因，不能统统重挂卡。

当前 writer 对已从队列取走但写失败的帧会统计 dropped；不能通过改状态把这些帧当成“还在缓冲”。撕裂记录不能盲目重写，沿用完整前缀恢复和不完整结果；需要保证的是不伪造成功、不重复音频、不删除唯一副本，不是承诺任何拔卡都零损失。

## 5. 八小时能力与等待时限

当前归档配额下限 1.5 GiB，不表示每次都有八小时空闲空间。开始或恢复时应根据实际空闲空间、配额余额、旧积压、待落盘内容、段开销和保留区评估剩余可保存量。会议与监控的容量保证均按持续有人声的最坏情况计算；不能假定监控必定有大量静音。

空间不足八小时但仍能录一段时，优先保存可保存的内容并给一次时间受限提示，不能宣称已具备完整八小时保障；达到安全余量时明确停录。在线录音不因这项本地容量预检而被拒绝。

保持现有离线 MIC 占用时间预算，不因插卡、写失败或重试把累计预算清零。同时增加独立的 WAIT_RECOVERY 意图截止时间，避免当前“从未启动 MIC，预算不增长”的无卡情况无限期等待后突然自动开录。建议等待意图也受八小时最大上界约束，从进入对应断网等待时固定，不被每次重试重置；这是需要实现的新异常路径策略，不是当前已有行为。

同一开机、原会话未停止/到期/换绑时，联网恢复仍使用新 `request_id`、原 `audio_session_id`。已经停止后重开是新会话。重启默认恢复文件，不自动恢复录音授权。设备可拒绝已识别的旧命令/ACK；若云端在重连后生成全新的开启命令，是否来自真实用户新操作仍需各端遵守现有控制约定，不能仅凭本地状态猜测。

## 6. 数据完整性与补传

保留现有 archive_only、begin/chunk/commit、CRC 和 ACK 语义；只有匹配的 commit ACK 成功才删除对应归档。服务器未协商正式补传能力时保留文件，不改投其他接口。录音优先于补传，补传让出资源不能被误报为录音失败。

保存少量独立会话记录：已知丢失序号、未采集时间区间、原因和当前结果。不保存原始音频到 NVS，不逐帧写 NVS；无 SD 时至多在事件边界异步保存有限摘要。摘要也无法落盘时记录未知，不能保证信息永不丢失。

不要直接扩展 `nuwax_cloud_config_t`：当前初始化检查记录长度，直接改结构体可能触发擦除旧配置。元数据独立保存且版本化。用户 APP 若需展示完整缺口时间轴，必须另接入这些信息；设备本地提示和原音频上传可先不改云端协议。

插入另一张卡或换绑时，旧档归属必须独立核验；新卡上的未知归档不默认归当前用户。用独立元数据区分设备/绑定、介质代际和会话，避免旧 ACK 操作新卡上的文件。纯设备保守隔离只能覆盖本机观察到的变化；云端静默换主需可信归属支持，不能声称完全由设备解决。

## 7. 其余问题的兼容处理

- 问候超时：按已确认的 gen=0 失败问候身份恢复，保留正常播放器 terminal 路径；异常重连不改变协议，但可能暂停补传，必须测试 ACK/取消并发。
- 固定 PoP：保持，不改 APP 配网方式。逐台身份、WSS 强制迁移和签名制程不混入此功能修复。
- 屏幕按住：不新增/恢复问候长按取消。若产品要求取消全部屏幕按住会话动作，只清理屏幕残留入口，保留头摸和正常 UI 手势。
- 低电：结合实测余量复用停录、保存、关机流程；不靠随意设定电压/温度常量。突发硬断电仍可能损失未持久化尾部。

## 8. 实施与验收

第一批：录音健康快照、UI 状态、无卡等待/恢复和已知缺口记录；修复问候超时。第二批：完善运行中拔卡/满卡/换卡的故障交接，八小时剩余容量及等待截止；保留现有安全文件生命周期。第三批：跨账号/跨卡归属、APP 缺口展示与低电实测分别交付，不能因“不改协议”承诺未实现的跨端能力。

必须以同一候选固件覆盖：在线无卡、离线无卡、正常卡八小时、短时慢卡后完整补写、持续写失败、满卡/配额满、拔插同卡、换卡、空间恢复、用户停止后插卡/联网、到期后旧 ACK、重启不自动开录、监控静音/暂停仍按人声策略、补传 commit ACK 丢失及 OTA/关机竞争。核对采集量、持久化量、云端唯一提交量、剩余文件与明确的缺口。

方案预期正常在线/健康 SD 路径保持，异常时状态真实、可操作、可恢复。以上仍需实施与真机验证；不能承诺无卡也保存八小时、任何拔卡零丢失、或所有修复零回归。
