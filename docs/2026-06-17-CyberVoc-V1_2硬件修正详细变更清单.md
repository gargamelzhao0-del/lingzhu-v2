# 2026-06-17 CyberVoc V1.2 硬件修正详细变更清单

本文档单独记录本轮根据真实可跑通参考代码 `cyberkit-main/main/boards/CyberVoc-Board-V1_2/` 对 7.0 工程做出的硬件相关修正。它用于补充 `2026-06-17-CyberVoc-V1_2硬件复检工作记录.md`,重点是逐文件列出“改了什么、为什么改、如何验证、还有什么没闭环”。

## 1. 参考代码复检依据

采用的真实硬件依据:

- 目录: `cyberkit-main/main/boards/CyberVoc-Board-V1_2/`
- 用户确认:该参考代码对应真实 PCB v1.2 且能跑通
- 排除项:参考工程顶层 `sdkconfig` 可能选择 V2.0,本轮不把顶层 V2.0 配置当作 7.0 依据

V1.2 关键事实:

| 项 | V1.2 事实 |
|---|---|
| 音频 DIN | GPIO3 |
| PA_CTRL | GPIO15 |
| CODEC_PWR | GPIO48,启动早期拉高 |
| LCD | QSPI 无 DC/TE;SCK18/CS14/D0-D3=46/13/11/12 |
| LCD reset | GPIO47,active-high |
| LCD backlight | GPIO44,active-high |
| POWER_CTRL | GPIO9,参考固件运行态输出 LOW |
| Touch | CST816S/CST816-family;INT10,RST NC,TOUCH_PAD2=GPIO6 |
| UART1 | TX5/RX4 |
| SD | CLK16/CMD38/D0 17 |

## 2. 代码变更明细

### `NuwaxAIPartner/main/Kconfig.projbuild`

改前风险:

- vocat 板名仍表达为旧 ESP-VoCat/EchoEar V1.0。
- QSPI 面板仍保留 `LCD_DC=45` 口径。
- LCD reset 没有 active-high 配置。
- 背光默认 active-low,与 V1.2 参考代码 `PwmBacklight(GPIO44,false)` 不一致。
- POWER_CTRL 口径曾偏向 OBSERVE/未冻结,与用户确认硬件正常后的参考运行态不一致。

改后:

- vocat 显示名改为 `CyberVoc V1.2`。
- `NUWAX_DISPLAY_PIN_DC` 对 vocat 默认 `-1`。
- 新增 `NUWAX_DISPLAY_RST_ACTIVE_HIGH`,vocat 默认 `y`。
- `NUWAX_DISPLAY_BL_ACTIVE_LOW` 对 vocat 默认 `n`。
- POWER_CTRL vocat 默认 `HOLD_LOW`。
- Touch 菜单命名改为 CST816S/CST816-family。

复检结论:

- 生成固件中 `CONFIG_NUWAX_DISPLAY_PIN_DC=-1`、`CONFIG_NUWAX_DISPLAY_RST_ACTIVE_HIGH=1`、`CONFIG_NUWAX_POWER_CTRL_HOLD_LOW=1` 已确认。

### `NuwaxAIPartner/main/display.c`

改前风险:

- reset 时序固定为低有效序列。V1.2 的 GPIO47 是 active-high,低有效写法可能导致屏幕复位状态错误。
- 当 `CONFIG_NUWAX_DISPLAY_BL_ACTIVE_LOW` 为 `n` 时,C 代码中直接使用该 Kconfig bool 做运行期表达式可能因宏未定义导致编译风险。

改后:

- `st77916_reset()` 根据 `CONFIG_NUWAX_DISPLAY_RST_ACTIVE_HIGH` 选择 active/inactive 电平。
- 增加 `NUWAX_DISPLAY_RST_ACTIVE_HIGH_VALUE` / `NUWAX_DISPLAY_BL_ACTIVE_LOW_VALUE` 本地 0/1 宏,日志和表达式不再依赖未定义 bool。
- QSPI 初始化日志打印 reset/backlight 极性。

复检结论:

- `git diff --check` 无问题。
- vocat 构建通过。
- 生成配置确认 reset active-high,backlight active-high。

### `NuwaxAIPartner/main/board/nuwax_board.c`

改前风险:

- QSPI banner 仍打印不存在的 DC,会误导现场调试。
- banner 不显示 reset/backlight 极性,无法从启动日志判断是否对齐 V1.2。
- bool Kconfig 在 active-high 场景下同样存在未定义宏风险。

改后:

- QSPI 分支不再打印 DC。
- SPI legacy 分支仍保留 DC。
- banner 打印 `reset_active_high` 和 `active_low`。
- 使用本地 0/1 宏规避未定义 bool 风险。

复检结论:

- QSPI banner 已只打印 SCK/D0-D3/CS/RST/BL 和极性。

### `NuwaxAIPartner/main/board/esp_vocat_v1_0_pins.h`

改前风险:

- 文件名为了兼容仍叫 `esp_vocat_v1_0`,但头部说明和部分注释会让后续开发误以为硬件仍是 V1.0。
- 旧判断可能继续传播 `LCD_DC=45`、`LCD_TE=8`、`TOUCH=7` 等错误。

改后:

- 文件头改为 CyberVoc V1.2 权威 pin map。
- 保持兼容文件名和宏名,避免扩大代码改动面。
- 宏值按 V1.2 冻结: DIN3、PA15、CODEC_PWR48、POWER_CTRL9、TOUCH_WAKE6、LCD_RST47、UART1 5/4。
- 注释明确 QSPI 无 DC/TE,GPIO45 strap 假设作废。

复检结论:

- `vocat_audio_board.c` 通过这些宏取到 DIN3/PA15/GPIO48。
- board banner 通过这些宏打印 V1.2 值。

### `NuwaxAIPartner/main/board/nuwax_power_ctrl.h`

改前风险:

- 注释仍描述为 V1.0 未冻结/需 OBSERVE 的阶段性结论。

改后:

- 说明改为 CyberVoc V1.2:参考固件将 GPIO9 配为输出并运行态写 LOW。
- OBSERVE/HOLD_HIGH 仅保留诊断用途。

复检结论:

- Kconfig 和构建脚本均已将 vocat 默认设置到 `HOLD_LOW`。

### `NuwaxAIPartner/main/touch_input.c`

改前风险:

- 用户可见日志写 `CST816D not found`,容易被理解为芯片型号已确定为 D。

改后:

- 用户可见错误和初始化日志改为 `CST816-family`。
- 内部寄存器常量名未大规模重命名,避免无必要的大范围改动。

复检结论:

- 触摸仍是未闭环项:软件侧已按 INT10/RST NC/I2C0 处理,但真机未 ACK 需硬件侧继续排查。

### `build-opus-firmware.ps1`

改前风险:

- `-Board vocat` 只覆盖 touch 配置,显示和 POWER_CTRL 可能继承旧 `sdkconfig` 中的 DC40/RST45/BL active-low 等值。
- `Set-SdkconfigInt` 只匹配正整数,`-1` 配置可能重复追加。

改后:

- `-Board vocat` 强制写入:
  - QSPI enable
  - SCK18/MOSI46/D1 13/D2 11/D3 12/DC -1/CS14/RST47/BL44
  - RST active-high
  - BL active-high
  - POWER_CTRL GPIO9 + HOLD_LOW
  - Touch INT10/RST -1/SCL1/SDA2
- `Set-SdkconfigInt` 支持 `-?\d+`。
- 构建输出显示 `[board] profile = CyberVoc V1.2`。

复检结论:

- 已用脚本完成实际构建验证。
- 生成的 `config/sdkconfig.h` 确认所有关键宏为 V1.2 值。

## 5. 是否还有遗漏

当前没有发现会影响 7.0 vocat 固件构建、硬件映射或施工卡接线的遗漏。

需要明确保留的非闭环项:

- Touch 仍未 I2C ACK,需要硬件侧验证供电/FPC/RST/INT/地址/唤醒条件。
- GPIO45/GPIO8 不能再当 LCD_DC/TE,但真实用途仍需硬件侧最终确认。
- 本轮完成的是代码/配置/文档复检和构建验证,尚未重新烧录新固件做屏幕、音频、POWER_CTRL、触摸真机回归。
