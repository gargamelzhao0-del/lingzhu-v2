## 2. 实现边界与前后效果

### 显示和业务状态分离

`main/nuwax_ui_v28/nuwax_face.c` 在最终选图处处理优先级。断网显示不会调用 `set_state` 退出睡眠事务，也不会关闭会议、监控或创建新音频会话。重连获得 Wi-Fi 后恢复原有表情选择；仅云端连接中仍沿用原有休眠/本地显示策略，鉴权失败明确显示断网。

`main/app_shell.c` 复用现有 2 秒状态轮询，用 Wi-Fi 已取得 IP 的实际状态修正仍显示“已连接”的 UI 快照。该兜底不依赖 TLS 清理完成；通常主恢复流程会更早发布。所有显示写入走现有 mailbox，不在 Wi-Fi 事件回调里操作 LVGL。

### Wi-Fi 有界恢复

`main/wifi_manager.c` 保持单一操作锁、意图版本检查和 30 秒连接总预算。一轮最多一次 STA stop/start；为 STOP/START 各预留最多 1 秒事件等待，只在总预算还余 2 秒以上时进入。纯粹找不到热点不会单独触发驱动重启。显式认证拒绝会清除瞬态累计。

STOP 后即使事件确认超时也尝试恢复 START；START 调用失败记录待恢复标志，后续初始化入口在操作锁下补启动，避免驱动停住后反复 connect。BLE 接管或模拟离线期间不会补连旧网络。下一次连接仍需通过意图版本检查。

### 配网重置及依赖持久化

修改 `managed_components/espressif__network_provisioning/src/manager.c` 的 reset 与事件处理，同时修改应用的 reset fallback。`tools/apply-network-provision-reset-fix.py` 提供受限、幂等的补丁恢复，已接入正式构建脚本；遇到不认识的上游结构直接失败，避免静默覆盖。清理或重新下载依赖后需用该脚本恢复补丁。

### 重启电源保持

`main/board/nuwax_power_ctrl.c` 在电源初始化时注册软件重启回调。在正常 `esp_restart` 过程中锁住 PG2 有效电平，bootloader 保持原有早期拉高行为，应用在输出配置成功后解除 hold。用户关机的深睡流程不调用此回调；关机准备期间不加 hold。未改变关机按键阈值和电源极性。

该措施覆盖配网、OTA 等正常软件重启，但不宣称覆盖掉电、硬件复位和所有 panic 路径。黑屏必须实机闭环。

## 4. 本轮实机验收

1. 保持手机热点在线完成一次对话，再关闭热点。默认休眠必须切断网表情；确认屏幕仍可操作。重新开启热点，确认 Wi-Fi、云端状态和唤醒恢复。
2. 关闭热点，等待至少一轮连接失败，在下拉菜单点配网。应先出现配网显示，再主动重启进入配网。分别测试电池供电和 USB 供电，至少各 5 次；这一步是黑屏问题的核心验收。
3. 配网正在认证时断开 APP 蓝牙，再重新进入配网。旧认证应及时退出，不依赖 2～4 秒自然认证超时；不得把旧 reason=36 计入下一次密码尝试。
4. 用原路由器重测，记录是否出现 `Wi-Fi STA stop/start completed with event fences`，以及之后是否 associated/GOT_IP。仍失败时提供路由器安全模式和 AP 日志，再定位射频/认证问题。
5. 会议、监控各做一次断网恢复：模式显示、离线采集和原 `audio_session_id` 应保持既有行为。再做正常关机/开机和一次 OTA 重启，确认 PG2 hold 没有阻止关机。

如再次黑屏，保留从点击前到重新启动后的完整 UART0(GPIO43/44、921600) 日志；记录 USB 是否掉线、长按电源是否还能恢复。有条件时测 PG2 与 3.3V：稳定供电而无应用日志应转查启动阻塞，电压掉落则继续电源接力定位。
