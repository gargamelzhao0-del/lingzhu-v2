# SD 40 MHz 验证与安全回退

本轮针对 SD 读取侧优化。此前本轮会话 306546 的网关端到端速度为 346.46 KiB/s；约 1 MiB 满段平均读取 1789 ms、校验 314 ms、发送 1384 ms。读取与发送已并行，不能把各阶段时间简单相加。

## 实现

- 新增 `CONFIG_NUWAX_SD_CARD_HIGHSPEED_ENABLE`，产品缺省关闭；`sdkconfig.sd-replay-test.defaults` 开启，当前测试配置也开启。
- 使用 `host.max_freq_khz=SDMMC_FREQ_HIGHSPEED` 经 SDK 正常协商，保持 1-bit 接线。启动日志报告请求、协商和实际时钟；不支持高速的卡可以协商到较低频率，不能只凭配置认为实际是 40 MHz。
- 高速尝试挂载成功后，在开放存储服务前验证独立 64 KiB 临时文件：排他创建、分块写入、fsync、关闭、重开、逐字节读回比对、删除。仅使用一块 4 KiB PSRAM，不增加常驻 DMA 缓冲，不覆盖已有文件，不格式化卡。该短测不能替代长时硬件验证。
- 高速初始化或验证失败：关闭文件、释放临时缓冲，成功卸载后以 20 MHz 重试；若卸载失败，本次返回错误，不立即继续挂载。低速挂载沿用原有存储健康与空间检查。
- 运行期间发生存储 I/O 或探测故障时标记介质不健康；高速状态同时锁定本次开机内不再尝试高速。挂载切换复用已有存储所有权保护，在采集、写入、回放和 FILE 使用者退出后由存储监督流程恢复。
- 高速下发现归档 CRC/长度错误，先保留原归档、停止回放，待 20 MHz 有序恢复后重新验证，避免在相同高速条件下立刻将瞬态读取错误判为归档损坏。20 MHz 下仍保留原有确认损坏后的隔离流程。
- 补齐窗口预读短读/读取失败对介质健康状态的标记；回放发现不健康后不继续扫描发送其他归档。

这属于保留恢复路径的测试版本，并不保证物理卡在高速写入出错时正在录制的数据无损。CRC、段确认后删除、录音抢占及内部 16 KiB 余量保护继续生效。没有降低保护预算、扩大 DMA 缓冲或增加任务优先级。

## 性能统计

每段增加一条汇总，不逐次输出读取日志：

```text
offline SD read profile calls=... sectors=... wall_ms=... errors=...
  buckets_le2_le5_le10_le20_gt20_ms=...,...,...,...,...
```

五个互斥桶分别为单次底层读取调用耗时 ≤2 ms、(2,5] ms、(5,10] ms、(10,20] ms、>20 ms。包含卡/驱动等待和调度延迟，不能直接解释为物理总线时间，也不能单凭直方图证明 ISR 到任务唤醒延迟。调用包含回放期间的相关文件元数据读取，使用段前后计数差统计。

结合既有 `sd_read_ms`、`validate_ms`、`command_ms`、`data_wait_ms` 与网关 begin→commit 耗时，可判断提高总线频率后收益是否被软件等待抵消。如需进一步定位 ISR/调度部分，应另加有针对性的驱动测量，当前未改 SDK 调度行为。

## 检查与证据

- `tools/run-sd-speed-host-checks.ps1`：编译实际驱动代码，分别检查配置关闭和开启。覆盖高速成功、低速卡协商、初始化失败、短写/短读、CRC、fsync/close/unlink、内存分配、文件名冲突、卸载失败、运行中故障只标记不卸载、恢复后保持 20 MHz。
- SD DMA 主机检查：保留原数据路径检查，新增耗时分桶边界、错误计数及不计写入的测试。
- 回放窗口检查：短读或读取错误必须标记介质故障，不发布未验证数据。
- 完整离线音频主机回归包含以上检查。主机测试不能验证实卡、走线、掉电行为或长期高速稳定性。

## 实机验证

先保留当前设备 RNNT 长测日志，再烧录独立快照 `C:\tmp\nuwax-sd40-fallback-20260916`。测试网关与 UI 断网开关保持启用。

```powershell
powershell -ExecutionPolicy Bypass -File tools/flash-sd-replay-test.ps1 -Port COM11 -BuildDir C:\tmp\nuwax-sd40-fallback-20260916
powershell -ExecutionPolicy Bypass -File tools/monitor-sd-replay-test.ps1 -Port COM11 -BuildDir C:\tmp\nuwax-sd40-fallback-20260916
```

关注启动 `SD speed qualification ... err=ESP_OK` 和 `SD clock ... actual_khz=40000 ... fallback_latched=0`。若已回退为 20 MHz，应先分析失败原因，不能将该轮作为 40 MHz 性能结果。

使用同卡、相近录音时长及相同 UI/唤醒负载进行离线会议→恢复→补传→待机唤醒测试。核对网关实际文件 CRC、帧数、序列和会话结束标记，记录补传端到端速度、采音丢帧、心跳、动画帧率及内部内存。补传后至少保留 30～60 分钟连续日志，再执行长时录音与多轮恢复测试。

既有 20 MHz RNNT 修复快照 `C:\tmp\nuwax-rnnt-growth-fix-20260916` 保留可供人工回退/对照。本轮未自动烧录或访问设备串口；没有实测提速百分比，也不能据主机测试宣称重启问题已彻底解决。
