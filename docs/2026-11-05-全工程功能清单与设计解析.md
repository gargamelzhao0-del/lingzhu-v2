## 1. 产品与系统总览

### 1.1 产品形态

灵珠是一台带 360×360 圆屏的桌面 AI 语音伙伴。全部功能可以归为七类：

1. **普通语音对话**：本地唤醒 → 设备采集并上传 → 云端 ASR、智能体、TTS → 设备播放 → 连续追问。
2. **拟人交互**：圆屏表情动画、摸头、摇一摇、云端语义表情。
3. **会议录音、监控录音**：两种独占长音频模式。插 SD 卡时先录到卡上再按顺序上传，断网继续录，联网后补传。
4. **云端主动播报**（通知播放）。
5. **BLE 安全配网与云绑定**、Wi-Fi 管理、运行时重新配网。
6. **应用 A/B OTA**，带启动健康确认与回滚。
7. **电源与电池**：电源键开关机、电量计、充电指示、低电量保护、状态灯。

### 1.4 软件架构

- **分层**：`board/`（引脚、总线、驱动、电源、SD）→ 子系统模块（`conversation/`、`audio_modes/`、`offline_audio_*`、`nuwax_provision_new/`、`nuwax_ota_new/`、`nuwax_ui_v28/`）→ 业务总控 `nuwax_ai_partner_main.c`（约 3.6 万行）。
- **三条平面**：数据平面（PCM、图像、归档字节）、控制平面（模式开关、ACK、取消）、观测平面（计数、SHA、错误快照）。设计上不让数据平面堵住控制平面。
- **owner 模型**：麦克风、扬声器、WebSocket、SD 文件、LVGL 对象各有唯一所有者。交接流程是“请求旧 owner 停止 → 等待真实退出 → 新 owner 认领 → 发布状态”，并用连接 epoch、播放 generation、会话 token 隔离迟到事件。
- **纯策略头文件 + 宿主机测试**：大量 `*_policy.h` 把判定逻辑抽成纯函数，由约 150 个 `*_host_check.c` 在 PC 上回归。

### 1.6 启动时序（`app_main`，`main/nuwax_ai_partner_main.c:33829`）

1. Bootloader 阶段提前拉起 GPIO7 电源保持并处理背光（`bootloader_components/nuwax_power_hold`），用户短按松手后不掉电。
2. 先占住 SW3，OTA 检查运行镜像期间禁止关机；初始化电源控制（PG2 锁存、按键任务）；强制关闭 4G 电源。
3. 打印固件和板卡信息。（🧪 SD 启动自检构建在此做一次卡读写删测试后卸载。）
4. 初始化离线音频与 SD 监督任务。无卡、坏卡都不算致命错误。
5. 初始化睡眠事务、延迟睡眠意图、通知事务、通知接收屏障。
6. 初始化 NVS（空间满或版本变化时擦除重建），恢复设备错误上报队列。
7. 判断是否进入“低内存配网启动档”（首次配网，或运行时重配网后重启）。
8. 初始化 OTA 控制器和固件上报，注册音频静默、启动健康、本地进度、重连等回调。
9. 初始化自动追问 preroll 缓冲、头部触摸意图、turn guard、扬声器 owner 事件队列和扬声器模块（从 NVS 读音量）。
10. 创建各队列：触摸、shell 动作（8）、会话命令（32）/ 通知命令（8）/ 关键命令（16）、唤醒事件（2）、Wi-Fi 连接/扫描/状态。
11. 初始化会议、监控控制器；安装电源键语义监听；创建 flash_ops 任务；启动 USB 配网控制。
12. 初始化头部触摸控制（GPIO8）。
13. 显示初始化（显示开机 Logo，读取亮度后点亮背光）→ 触摸初始化 → 摇一摇检测 → LVGL 移植 → V28 UI（最多重试 3 次）。
14. 启动电池服务，执行开机低电门。
15. （🧪 P1、P2 诊断构建在这里进入本地诊断循环，不联网。）
16. 创建 shell 任务、触摸任务、手势任务。触摸在联网前就可用，所以无网时也能在本地发起重新配网。
17. 初始化 Wi-Fi 和 BLE 配网模块。需要配网时：若不在低内存档，写标记后重启；否则启动 BLE 配网，运行最长 300 s 的 APP 专注窗口，失败可回滚旧 Wi-Fi。
18. 配网档结束后，把 LVGL 绘制缓冲移回内部 RAM（最多 3 次，失败则降性能继续）。
19. 刷新已保存 Wi-Fi 列表，准备 STA 配置，启动主/备 SSID 回退 watcher，从 NVS 读取 L3 打断开关。
20. 在 Wi-Fi 认证前构建唤醒模型（避开内存峰值）→ Live AEC 预检后释放 → 创建扬声器任务并预分配 → 创建唤醒监督任务 → 启动休眠唤醒检测并检查内存余量，不够就暂停到网络就绪再恢复。
21. Wi-Fi 关联交给后台 worker，不阻塞本地启动；内存充足时提前开始关联。
22. 若是 OTA 后待确认的新镜像，做一次启动麦克风健康检查。
23. 发布 product_ready（核心任务、Wi-Fi、扬声器、UI、触摸、唤醒、Live AEC、硬件参考）。非网络类阻塞会受控重启（退避 500 ms～8 s）；只缺网络则降级继续。
24. 注册 30 s 任务看门狗（超时 panic），进入云连接主循环。

### 1.7 云连接主循环（`main/nuwax_ai_partner_main.c:35043` 起）

- **每轮公共服务**（离线也执行）：喂狗、电源键事件、空闲时持久化诊断、唤醒模型恢复、独占音频的睡眠收敛、云绑定重配网、BLE 配网停放（关 WS、等音频模式让出、保存亮度）、shell 动作、断线会话宽限（30 s）、AEC 池恢复、离线唤醒保持、离线采集重试、Wi-Fi 恢复。
- **建连**：SNTP 校时一次 → 从 NVS 读云配置 → 用 URL + device_secret 建立 WebSocket。HTTP 401/403 视为鉴权被拒并触发重新绑定；其他失败按 3 s → 60 s 指数退避。
- **建连成功**：发布活动连接 → 绑定打断分派器 → 发送 hello（含 `has_sd_card`）→ 立即发一次 ping → 等云服务就绪（hello OK、pong 或合法命令）→ 重置退避 → 同步会议/监控状态 → 固件上报 → 离线补传接管 → 应用音量并上报快照 → 恢复断线前的醒着会话，否则进入“可唤醒休眠”。
- **连接内循环**：音乐占用、通知占用、离线接管、独占模式等待等分支 → `run_audio_source()`（会议、监控或普通对话）→ 对错误分类并恢复 → 排空会话命令 → 等待云端更新。
- **断线收尾**：先关应用就绪门 → 会议或监控活跃时登记离线租约（有卡场次继续本地录） → 尝试保留醒着会话（30 s 宽限）→ 复位扬声器（失败则受控重启）→ 丢弃绑定在旧连接上的队列 → 取消正式补传（6 s 内没停下则受控重启，保护归档）→ 必要时进入可唤醒休眠 → 释放 AEC → 恢复唤醒 → 退避重连。

### 3.2 云配置与鉴权

- 云端 URL、设备 ID、设备密钥全部来自配网写入的 NVS（`nuwax_cloud/active`），**没有编译期回退**（`main/nuwax_provision_new/nuwax_cloud_config.h:40-41`）。
- 设备 ID 由 eFuse 芯片唯一 ID 做 SHA-256 取前 16 字节派生，格式 `NX-AABB-CCDD-EEFF`，每次启动重新计算；NVS 副本只做校验缓存（`main/nuwax_provision_new/nuwax_device_uid.h`）。
- WebSocket 走 `wss://`，Upgrade 请求带 `X-Bridge-Token`；首个 `hello` 带 `device_id` + `device_secret`。
- 鉴权失败两条路径：HTTP 401/403 → 标记鉴权失败并触发重绑定；云端返回结构化错误码 `DEVICE_NOT_BOUND` → 关闭该连接、保留 Wi-Fi、请求一次 BLE 重绑定。

### 3.3 WebSocket 传输（`main/ws_transport.c`）

- 只收 FIN=1 的完整帧，不支持压缩扩展，单帧上限 16 KiB。
- 活性检测：应用层 `ping` 就绪后每 15 s 一次（准备阶段 5 s）；应用活动超时 45 s；WS 活动超时 120 s；传输层心跳健康窗口 60 s。
- 关闭原因分类：业务恢复、业务停滞、心跳过期、传输完整性、鉴权拒绝、OTA 状态刷新、所有权转移。心跳健康时，普通业务恢复请求会被拒绝，连接保留。
- 每条连接有递增 epoch。旧连接的回调、ACK、命令不能作用到新连接。
- 部分发送失败时整条连接标记断开，不重复发送可能已送达的帧。
- 发送侧优化：掩码生成优化、TLS 记录指标、网络发送探针（诊断）。
- 重连退避：3 s 起，最大 60 s。
- 无效 JSON：丢弃并且不刷新活性，连接保留。

### 3.4 hello 内容（`main/session_protocol.c:861-987`）

- 顶层：`type`、`version=1`、`device_id`、`device_secret`、`transport=websocket`、`has_sd_card`。
- `features`：`audio_upload`、`meeting_mode_v1`、`monitoring_mode_v1`、`monitoring_pause_resume_v1`、`remote_ble_reprovision`、`volume_changed_v1`、`remote_wake_word_config`、`ota_v1`、`audio_playback`、`notify_playback_v1`、`music_playback_mp3`（产品为 false）、`mcp`。
- `firmware`：project_name、version、release_sequence、target_board、target_chip、partition_schema、build_flavor、running_partition、ota_state（`pending_verify` 或 `valid`）、image_sha256。
- `audio_params`：PCM16、16 kHz、单声道、20 ms、有扬声器、有唤醒、有 VAD、full_duplex、shared_i2s、硬件档案、`aec`（Live AEC 关时为 false）、`aec_reference=software`、硬件参考健康状态、`ref_slot=-1`、AFE 输入格式。
- 每条连接只发一次 hello，会议/监控的开启和结束不再补发（`main/session_protocol.h:108-109`）。

### 3.5 命令处理基础设施

- 三条命令队列：普通 32、关键 16、通知 8。队列满时关闭当前连接，让事务可以在新连接上重试。
- `device_command` 必须带 `request_id`（唯一例外是旧版不带包络的 `set_wake_word`）。
- 命令台账：每个连接 epoch 保留 8 条。相同 `request_id` 且内容指纹相同 → 重放原 ACK；指纹不同 → 拒绝为冲突；仍在执行中 → 回复“request still in progress”（睡眠命令例外，会并入同一事务）（`main/conversation/session_dispatch.c:18-161`）。
- 所有入站 JSON 有总资源预算，嵌套深度上限 32（构建时强制检查）。
- 安全敏感协议（监控 ACK、模式协议、OTA）拒绝重复字段、尾随数据和超长字段。

### 3.6 时间

- 每次建连前做一次 SNTP（`ntp.aliyun.com`，超时 12 s）。
- 另外以应用层 `pong.server_ms` 建立“UTC ↔ 本次开机单调时钟”的映射，供 SD 场次和文件时间戳使用。离线时继续推算，时间基准最多每分钟持久化一次。

### 3.7 MCP（`main/mcp_server.c`）

- 方法：`initialize`（协议版本 2024-11-05）、`tools/list`、`tools/call`。
- 工具：`self.get_device_status`（状态、SSID、IP、堆内存）、`self.ui.set_emotion`。`self.servo.head_shake` 只在有真实舵机回调和能力位时才发布，当前产品没有接舵机，所以不出现。
- MCP 不提供音量、会议、监控、配网、OTA 工具，这些都走 `device_command`。

### 3.8 设备错误上报（`main/device_error_report.h`）

- 上行 `device_error_report`，下行 `device_error_report_ack`。
- 字段：内嵌开机随机数的 event_id、严重级别（error/warning）、组件、错误码、结果字符串（≤160 B），可选状态、generation、turn_id。
- 有界队列，一次只有一个在途事件；空闲时把队列快照持久化到 NVS `nuwax_err/queue`；NVS 空间不足时优先释放这部分，保证凭据和设置能写入。
- 启动期各模块初始化失败都会入队（扬声器、会议、监控、Wi-Fi、配网、唤醒模型、AEC、SD 归档等）。

### 3.9 PC 状态转发

- 协议支持 `pc_status_request` 和 `status_app_request`（app 为 `work`、`issues`），结果由云端转成 `show_status` 显示。
- 产品界面没有触发入口（对应 shell 动作只剩处理代码），属于 🗄️ 遗留能力；云端仍可直接下发 `show_status`。

## 4. 普通语音对话

### 4.1 设备状态

`BOOTING`、`WIFI_CONNECTING`、`WS_CONNECTING`、`IDLE`、`SLEEPING`（可唤醒的待机）、`LISTENING`、`THINKING`、`SPEAKING`、`ERROR`。

这些状态由设备本地生命周期独占。云端 `set_state` 只能请求 `sleeping`/`wake_only`，其余值被拒绝（`main/conversation/session_dispatch.c:328-346`）。

### 4.2 一次完整对话

1. **唤醒**：休眠时 MultiNet 命中唤醒词。只有在云服务已就绪时才放行；离线命中会被忽略并重新武装检测器。唤醒事件超过 2 s 视为过期。
2. **问候**：建立醒着会话（awake session），停止休眠唤醒检测，发送 `text_request`，文本为“你好”（`main/nuwax_ai_partner_main.c:698`），等待云端回复（15 s）。
3. **音画同步**：表情在本轮第一帧 PCM 到达时才切换，不在请求发出时提前变化。
4. **播放问候**：`playback_begin` → NA 二进制音频 → `playback_end`。
5. **进入聆听**：播放结束后等 350 ms 防抖（期间若有下一段 TTS 就取消），进入 prelisten，聆听窗口 60 s。
6. **采集上传**：检测到人声后发 `listen start`（mode 为 wake_word、awake_session、auto_followup 等），随后发送带 START 的 NA 帧、普通帧、END 帧，最后 `listen stop`。preroll 保证首字不丢。
7. **端点判定**：本地 VAD + 自适应端点决定何时结束本句（4.4 节）。
8. **等待回复**：`asr_partial/asr_final/asr_result` → `text_response`（含情绪）→ TTS 播放。
9. **连续对话**：播放完再次进入聆听，如此循环。
10. **回到休眠**：醒着会话里连续 60 s 没有有效人声（滚动计时，只在聆听等待时计时）→ 进入可唤醒休眠。播放、思考、等 ASR、采集中都不计时。

### 4.7 下行播放（`main/conversation/speaker_playback.c`）

- 只接受 PCM16 单声道。必须先有匹配的 `playback_begin` 和 NA START；过时的 turn_id、playback_id 或立体声一律拒绝。
- 抖动缓冲总容量 393,216 B（约 12 s 音频）。启动门槛按已到数据量、是否已收到 END、短回复和历史抖动动态决定，短回复不会卡在大门槛上。
- 卡顿：12 s 告警，60 s 超时；重缓冲 15 s 超时；背压轮询 20 ms。
- 播放 generation 隔离：迟到的旧 stop、旧完成回调不能影响新一轮播放。
- 接收屏障：被拒绝的旧流一直隔离到明确的 END 或连接 epoch 变化，不按“最后一个 BEGIN”猜测二进制数据的归属。
- 结束条件：网络 END、缓冲与 DMA 排空、终止回调三者都满足才交还资源。
- 故障恢复：播放故障时发取消（ACK 等待 3 s），本地恢复看门狗 3 s。
- `tts_result` 只是统计信息，不驱动播放状态。

### 4.8 音量

- 默认 80%，范围 0～100，存在 NVS `nuwax/spk_vol`。
- 来源：控制中心音量滑条（拖动时 90 ms 实时预览，松手提交）、云端 `set_volume`（`persist` 默认 false）。
- 设备 UI 改音量后上报 `volume_changed`（source=`device_ui`，快速连续调节只保留最后值）；每次重连就绪后上报一次快照（source=`device_sync`）。云端 `set_volume` 不产生回显，避免环路。

### 4.9 `tts_skip` 与取消

- `tts_skip`：云端关闭语音播报时，在 `text_response` 之后、`playback_begin` 之前发送。设备结束本轮 TTS 等待并恢复聆听；表情保留窗口 8 s。已经开始物理播放的轮次不会被它打断。
- `cancel_turn`：思考或说话时按住屏幕 ≥180 ms，设备发 `cancel_turn`（reason=`touch_cancel`）并停止播放，触摸取消恢复 3 s。
- `stop_playback`（云端）：必须同时带 turn_id 和 playback_id，只停严格匹配的播放；过时命令回复“已隔离”。

### 4.10 断线保护

- 对话进行中断网：保留醒着会话 30 s。宽限内重连就恢复聆听；超时进入可唤醒休眠。
- 旧连接上的 request_id、audio_session_id、命令都不跨连接复用。

## 5. 唤醒词与休眠

### 5.1 唤醒引擎（`main/wake_word_detector.c`）

| 项目 | 产品值 |
| --- | --- |
| 后端 | ESP-SR MultiNet7 量化中文模型（`model` 分区）；WakeNet 后端 ⚙️ 不用 |
| 出厂唤醒词 | 10 组拼音：xiao zhu xiao zhu、xiao zu xiao zu、xiao zhu xiao zu、xiao zu xiao zhu、ni hao ling zhu、ni hao lin zhu、ni hao ling zu、ni hao lin zu、ni hao xiao zu、ni hao xiao zhu（`main/conversation/wake_word_alias_policy.h:15-26`）；界面显示“小珠小珠” |
| 模型阈值 | 9%（0.09） |
| 设备声学证据门 | 分数 Q1000 ≥ 90（`main/conversation/wake_word_detection_policy.h:7-8`）；人声证据 ≥160 ms；160～249 ms 要求幅度比 ≥2.5 倍背景，≥250 ms 要求 ≥2 倍；削波 ≤1%；证据跨度 ≤3.5 s |
| 背景噪声估计 | 8 个 128 ms 最小值桶取低分位；下降快、上升慢，人声期间最多冻结约 3.5 s |
| 运行时机 | 休眠时持续运行；对话中停止；会议/监控期间不运行；通知播放期间有专门的检测器（用于取消通知） |
| 生命周期 | 采集与推理解耦；监督任务负责恢复；模型加载串行化；Flash 写入期间暂停；内存不足时先停放、网络就绪后恢复 |
| 离线命中 | 云服务未就绪时忽略命中并重新武装，所以**断云时叫不醒是设计如此** |

### 5.2 运行时修改唤醒词

- `set_wake_word`：数组形式，非空，保留前 10 项，每项 2～63 个 ASCII 拼音字符；自动转小写、合并空白、去重；整体替换旧命令组；`persist` 默认 true。旧版单字符串仍兼容：任一出厂词字符串会展开成全部 10 组。
- `reset_wake_word`：恢复出厂 10 组，只删除 NVS `wake_word/config_v2` 和 `wake_word/command`；任何一步失败都回滚到复位前的运行配置和 NVS 快照。
- 只有 `hello.features.remote_wake_word_config=true` 时云端才应下发。

### 5.3 休眠事务（`main/conversation/sleep_transaction.c`）

- 这里的 SLEEPING 是**产品交互状态**，不是 ESP32 深度睡眠；Wi-Fi、WebSocket、屏幕都保持工作。
- 阶段：REQUESTED → QUIESCING → COMMITTING → SLEEPING；超时后满足条件可走 RECOVERING → COMMITTING。
- 提交条件：同一事务（token、ws_epoch、speaker_generation）下，采集已释放、扬声器已停止、协议流已关闭三项都成立。
- 超时：事务 2 s，恢复 3 s；播放已开始时等 3 s；播放卡住时最长 120 s。
- 进入休眠的途径：醒着会话 60 s 无人声、云端 `sleep_conversation` 或 `set_state=sleeping|wake_only`、电源键短按、断网且会话未被保留、本地音频错误重试耗尽、开机就绪。
- 会议、监控、离线录制持有麦克风时禁止进入休眠。

## 10. SD 卡录音存储与补传

### 10.1 存储与文件格式

- 目录：新音频在 `/sdcard/offline2/<分桶>/`，旧归档在 `/sdcard/offline_audio/`，场次和文件目录在 `/sdcard/audio_sessions/`（场次记录使用两个 CRC 槽，防撕裂写）。
- 文件后缀：`.part`（录制中）、`.ready`（已封存）、`.ready.meta`（本地旁路元数据副本）、`.blocked`（冲突隔离）、`.paged` 与 `.index.<页号>`（监控分页索引，每页 128 个文件）。
- 归档格式：96 B `NWXOFF1` 文件头 → 重复的“4 B 长度 + 662 B NA 帧” → 32 B `NWXEND1` 文件尾。
- 文件头字段：模式、声道、编码、采样率、帧长、segment_index、首帧开机毫秒、场次 ID、首帧 UTC 毫秒、文件时间跨度。
- CRC：CRC-32/ISO-HDLC，只算按顺序拼接的完整 NA 帧。
- 满文件：6,297 帧，4,193,930 B，125.94 s 音频，不补零、不拆帧。

### 10.2 上传协议（复用正式云端 WebSocket）

| 操作 | 会议 | 监控 |
| --- | --- | --- |
| 建立/恢复场次 | `meeting_audio_begin` | `monitoring_audio_begin` |
| 提交文件 | `meeting_audio_commit` | `monitoring_audio_realtime_commit` / `monitoring_audio_history_commit` |
| 结束场次 | `meeting_audio_session_end` | `monitoring_audio_session_end` |

- ACK 名称为请求名加 `_ack`。
- 二进制分片：64 B `NWXCH1` 传输头（version 3、offset、长度、场次 ID、segment_index、末片标志）+ 1～8,064 B 归档原始字节。
- 每场正常只发一次 begin，每个文件一次 commit，最后一次 session_end；begin/session_end 带 `session_time`（开始 UTC 与时长）。
- 断点续传：begin 中带 `resume`（每次最多 16 个文件），云端回 `next_offset`：0 表示从头发；中间值表示从该偏移续传；等于文件长度表示直接 commit。
- ACK 超时：begin/commit 6 s，session_end 60 s。临时失败按 1、2、4、8、16、30 s 退避，之后每 30 s 一次，**永不因重试次数删除未确认音频**。
- 冲突（invalid_argument / conflict）：持久化为 `.blocked` 并保留数据，同模式后续场次不越过这个队头。
- 顺序：会议、监控各一条 FIFO 队列；同场按 segment_index 递增；旧场 session_end 确认后才传新场；未封口的文件不能被越过。
- 删除：收到 commit_ack，并在 SD 上持久化确认状态之后才删除本地音频。

### 10.3 可靠性机制（✅ 均默认开启）

- **写校验**：经私有内部 DMA 缓冲回读，不一致重写一次。
- **批次修复**：延迟损坏时，用 CRC 匹配的 RAM 副本重写当前未封存范围，每批至多一次。
- **目录守卫**、**SD 命令历史**（首个故障时导出）、**分层完整性证据**（空闲时最多导出 4 个本地文件）。
- **元数据准入自检**：每个挂载周期首次使用时，用临时文件做双槽初始化、交替更新、改名回读和跨扇区稀疏索引校验。
- **I/O 恢复窗口**：10 s，退避 250/500/1000/2000 ms；换卡、关机、低电时停止。
- **掉电恢复**：重启扫描完整记录，恢复索引；中断的场次标记不完整，新录制用新场次 ID。
- **已封存文件损坏**：不再导致停录，场次标记为不完整（`main/sd_audio_active_recovery.inc:298-364`）。
- **正在写入的文件或前缀丢失**：仍然停止采集。
- **不可恢复文件终止丢弃（RETIRED，7.0.222）**：持久化缺失记录后从上传队列移除，后续文件照常上传，最终 `segment_count` 含缺号、`recording_complete=false`。断网、超时、内存不足、正在写的尾文件不会触发丢弃。
- **SD 40 MHz 高速模式**：⚙️ 默认关闭（测试档用，失败回退 20 MHz）。

### 10.4 补传性能相关

两块最多 64 KiB 的预读缓冲；读取准入事件化；TLS 记录与 GCM 上下文跨文件复用；GHASH 8 位查表（需先通过校准）；SD 上传专用的 scoped 硬件 AES-GCM（失败回退软件，不改动明文）；TCP 提前可写通知（2 MSS）；lwIP 核心锁路径；上传 worker 按是否在采集选择核心；在完整帧之间让出给表情解码。

实测吞吐约 220 KB/s，瓶颈在读取侧；500 KiB/s 目标未经实机验收。

### 10.5 测试专用路由

- 🧪 局域网 PC 测试网关补传（独立低优先级 WS）、配对网关 UDP 发现。产品构建关闭。
- 🗄️ 旧补传协议 `offline_audio_begin/chunk/commit`：用于没有开启 SD 场次的构建。

## 13. UI 与显示

### 13.1 显示与 LVGL

- ST77916 QSPI 40 MHz，TE 同步，背光 PWM。
- 绘制缓冲：两块 20 行内部 RAM 缓冲（共 28.8 KiB），内存紧张时降为单缓冲，之后自动恢复；配网低内存档使用 PSRAM 缓冲，结束后移回内部 RAM。
- LVGL 9.5 本地副本，带工程补丁（`lib/lvgl` 多个文件有修改）；自定义内存分配；刷新周期 5 ms；异步刷屏任务；LVGL 任务栈 12 KiB（内部 RAM）带守护区和栈尾硬件 watchpoint。
- 开机 Logo：显示初始化时先画“灵珠”Logo，再开背光，一直保留到第一帧正式 UI。
- 动画目标 40 FPS。

### 13.2 主屏表情

- 逻辑表情 36 种（`main/nuwax_ui_v28/nuwax_device_state.h:6-45`）。
- 表情包中有 16 个动画资源：dizziness、happy、excited、sleeping、provisioning、disconnected、thinking、thought_complete、meeting、monitoring、touch、playful、like、angry、listening、question（`main/nuwax_ui_v28/face/emotion_asset_pack.h:27-44`）。
- 资源包格式 ABI v1～v4。v4 为逐帧区域差量（最多 5 个区域）+ RLE，带绝对关键帧和交接帧；64 色调色板；分 intro / loop / completion 段；标志分持久、临时、完成。
- 完整性：SHA-256 必须在兼容列表中，另有 payload CRC 和逐段 CRC；资源异常时切换到静态 failsafe 表情。
- 后台解码 worker；最低 40 FPS；可冻结一帧供控制中心做背景。
- 轻量活泼模式：表情过渡和小面积眨眼。

### 13.3 状态到表情的映射

- 连接中 → 断联表情；思考 → thinking；配网中 → provisioning；会议、监控 → 各自表情；摸头 → touch；摇一摇 → dizziness；聆听、说话有对话视觉叠加。
- 说话时由 PCM 驱动画面，第一帧 PCM 到达才切换。

### 13.4 语义表情

- 来源：`text_response.emotion`、`device_command/set_emotion`（可带 duration_ms 500～30000）、MCP `self.ui.set_emotion`。
- 有租期，结束后恢复；旧回复不能覆盖新回复的表情；休眠中也接受并 ACK；只改表情，不改任何业务状态。
- 配网、会议、监控等真实业务状态的表情优先级更高。

### 13.5 控制中心（从屏幕顶部下滑打开）

## 17. 工程基础设施

### 17.1 构建与身份保证

- ESP-IDF 6.0；`PROJECT_VER` 必须是 `7.0.N`，发布序号必须等于 7000000+N，否则 CMake 直接失败（`CMakeLists.txt:5-24`）。
- 表情包 SHA-256 固定在构建脚本中，并维护兼容旧版本的摘要列表；摘要不符则构建失败；表情包随完整烧录写入 `emotion_0`（`CMakeLists.txt:38-112`）。
- cJSON 嵌套上限必须 ≤32。
- 产品 OTA 构建不能与隔离诊断模式同时开启（`main/CMakeLists.txt:119-130`）。
- 生产安全门：打开 `NUWAX_PRODUCTION_SECURITY_REQUIRED` 时，必须开 Secure Boot V2 和 Flash Encryption（当前未打开）。
- 链接器包装：
  - `network_prov_mgr_done`：配网生命周期。
  - `sdmmc_read_sectors` / `sdmmc_write_sectors`：SD 写校验、命令历史、完整性证据。
  - `psa_aead_encrypt` / `mbedtls_psa_aead_encrypt`：SD 上传专用硬件 AES。
  - `mbedtls_net_send`：TLS 记录指标与 SD 套接字等待。
- 兼容修复：esp-sr `_ctype_`、esp_audio_codec 在含空格的 Windows 路径下的链接问题、esp-dsp 的 C++26 头文件。
- `tools/cmake/` 补丁：protocomm 生命周期、MultiNet RNNT 内存增长、SD 事件配置、SD 状态、SD TCP 可写阈值。

### 19.2 风险与待办

1. **量产安全未完成**：开发 PoP 模式、允许 `ws://`、USB 配网控制开启、生产安全门（Secure Boot V2 + Flash Encryption）未启用。当前产品配置和 7.0.222 构建配置都是如此。另外，开发模式下配网二维码中的 PoP 是固定开发值。
2. **SD 坏区**：已封存文件损坏不再停录，坏文件可丢弃并继续上传；但**正在写入的文件或前缀损坏仍然停止采集**，簇隔离（quarantine）尚未实现。如果卡上坏区命中正在写入的文件，长会议仍可能中途停止（此前约 2 h 37 min 停录问题的根因就是卡的坏区）。
3. **补传速度**：约 220 KB/s，500 KiB/s 目标未经实机验收。
4. **通知播报**：设备端完整，云端网关编排需补齐后端到端联调。
5. **智能打断**：分支名为 smart-barge-in，但语音打断、唤醒词打断、Live AEC 在产品中都关闭。
6. **遗留入口**：Wi-Fi 列表和 PC/工作/问题状态等 shell 动作只剩处理代码，没有界面入口，可以清理或补回入口。
7. **版本来源**：7.0.221、7.0.222 从 `C:\tmp` 副本构建，工作区 CMake 默认版本仍是 7.0.220；正式发版前需要确认源码与发布包一致。
8. **主控文件过大**：`nuwax_ai_partner_main.c` 约 3.6 万行，其中 `stream_microphone_audio` 一个函数约 7,300 行，维护和评审成本高。
