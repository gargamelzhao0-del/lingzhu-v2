### 1.3 最重大判断:P3-0H 硬件 reference 入口放行，slot2/MIC3 固定为 R

> **2026-06-25 P3-0 真机复盘裁决**:本节下方旧分析保留为历史过程。`cyberkit-main` reference AECVERIFY 全槽探测的原始数据已经证明 slot2/MIC3 是硬件 playback reference:`base_1k=0.1/tone_1k=425.3/score=433.3`。诊断最终候选为 `slot0` 是 score-based 算法被空气声学耦合误导，不得覆盖物理固定的 R slot2。结论:P3-0H 硬件 reference 入口通过，允许进入 AFE MR 接入。

原理图 `ES8311 OUTP/N → RC → ES7210 MIC3` 已由 COM8 cyberkit AECVERIFY 原始数据交叉确认。实际施工仍必须区分“硬件 reference 存在”和“7.0 AEC 算法产品可用”:前者已通过，后者还需要 AFE MR 常驻、A/B ERLE、误触发、资源与 soak 验收。

→ 7.0 工程前沿 = **P3 AFE MR 接入与 A/B 验收**:固定 M=slot0、R=slot2，先把 AFE MR 接入 7.0 主链路，再用 AEC on/off 对照证明 ERLE >= 6dB、播放中不误触发、近端语音不过度损伤、资源水位可接受；通过前 `aec=false` 与默认自动打断关闭。

## 17. 一句话结论
7.0 的最优路线 = **以 MIT 许可的 EchoEar V1.0 官方固件为逐文件嫁接源,先白拿半双工 codec 基座 + 低风险保底打断(L0/L1),再把那条连上游都默认关闭的"硬件 AEC + realtime 全双工"休眠路径逐项点亮、用两档量化门禁验证(L3/L4),并在自研云端协议上补真 abort、上下行并发与真流式 TTS**;而所有高风险判断在开工前先经五道硬门禁(证据/codec×IDF6/I2S mixed-mode/协议兼容/资源预算)变成可审计证据——这样 7.0 才是可交付、可证明、可量产演进的产品级版本,而非演示效果。
