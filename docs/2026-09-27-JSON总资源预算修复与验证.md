# JSON 总资源预算修复与验证

日期：2026-09-27。承接全工程复核 W03。本轮只修改输入 JSON 资源准入，不修改对话状态机、Wi-Fi恢复、音频/SD发送策略、表情或电源逻辑。AU05固件保留在 `C:/tmp/nuwax-au05-v1-20260927` 用于回退。

## 问题与修复效果

原有16KiB WebSocket载荷和32层cJSON深度限制，不能限制浅层宽数组的节点分配。生产会话校验原先接受16,025字节、8,000个元素的额外字段，主机cJSON解析峰值512,213字节。

新增 `main/json_resource_budget.h`：使用定长栈空间，单次线性扫描，不递归、不申请堆内存、不修改全局cJSON分配器。超出预算时不调用cJSON。原有解析器继续负责语法、协议语义、鉴权和业务验证。

同一宽数组报文现在在进入解析器之前被拒绝，解析分配为0。这里比较的是主机实验；512,213字节不是ESP32实测峰值，也不表示修复后系统所有JSON相关内存都为0。

## 预算及兼容性

| 项目 | 上限 | 含义 |
| --- | ---: | --- |
| 有效原始报文字节 | 16,384 | 与现有WS帧预算一致；允许旧调用把末尾一个NUL计入长度 |
| 容器嵌套深度 | 32 | 与现有真实cJSON编译限制一致 |
| 词法项 | 512 | 容器、键字符串、值字符串和原始值均计数；包含键，因此比实际cJSON节点数保守 |
| 单个容器成员/元素 | 256 | 按容器内逗号计数；对象仍同时受总词法项限制 |
| 字符串分配估算合计 | 16,384字节 | 按原始转义前长度+2保守计算，不按解码后显示字数计算 |
| 原始值长度 | 128字节 | 控制数字临时缓冲和异常长字面量；当前协议数值字段远小于此值 |
| 单次解析分配估算 | 32,768字节 | `(词法项+1)*sizeof(cJSON)+字符串估算+最长原始值+1` |

分配估算包括当前cJSON节点、保守字符串分配及数字临时缓冲；不包含malloc元数据、原始RX缓冲、业务对象、序列化输出或并发解析总和。不同ABI的 `sizeof(cJSON)` 不同，实际准入会更早或更晚触及估算上限；独立词法项/容器/长度上限不变。这不是物理堆绝不耗尽的承诺，分配失败仍由现有失败路径处理。

保持旧解析器对符合预算报文的语义验证，不修改request_id、audio_session_id、OTA包络或配网密钥格式。测试覆盖原有合法协议、字段长度包络、BOM、转义、中文、最大长度字符串和数值。超过新预算的报文即使语法合法也会拒绝，不能宣称所有以前可解析的任意JSON仍被接受；未来若云端新增大型列表，需按协议样本评估预算。

字段包络依据：云端配置device_id/cloud_url/device_secret分别40/192/96字节数组，唤醒词最多10个、每个63字节，普通命令text为512字节数组，OTA URL/版本/更新ID数组为256/32/64字节。字段包络实验只验证预算兼容，签名/URL/OTA业务语义仍由原有主机套件和实机联调验证。

## 接入范围

1. `nuwax_ai_partner_main.c::on_ws_text` 在OTA专用处理之前执行预算检查。拒绝时直接返回，不刷新业务活跃时间，不关闭WebSocket，不增加RX活跃回调计数。
2. 工程14处cJSON输入解析改为同一个受保护包装接口，涉及11个解析模块：普通会话、云端兼容分类、MCP、诊断ACK、会议、监控、离线补传、OTA命令、OTA清单、固件上报ACK和BLE配网。加上主分发入口共12个编译单元。
3. 独立入口仍检查预算，因此即使绕过主WS回调直接调用，也不能跳过资源准入。没有修改托管cJSON库文件或输出JSON构造逻辑。
4. 包装层预算失败返回NULL，并设置显式parse_end；调用方沿用原有无效报文处理。BLE配置失败继续使用原有错误响应，不先改配置或密钥。

WS主入口与独立解析器存在重复线性扫描，目的是保持不同入口独立安全；正常小报文开销有界。本轮不混入解析树复用或全局分配器改造，避免改变所有权与线程安全。实际设备解析耗时和栈余量仍需实测。

## 主机验证

`tools/test-json-resource-budget.py` 使用真实cJSON和生产会话验证代码：

- 复现修复前宽数组分配峰值，再确认受保护入口拒绝且零解析分配。
- 1000份确定随机种子的合法JSON，另加6类当前协议字段长度包络。
- 最大16KiB字符串、32层深度、256个容器元素边界及超限、总词法项、过长原始值、转义/BOM、嵌入NUL、畸形输入和长度溢出。
- 解析器不同分配点失败时释放部分树；连续拒绝后仍能处理正常pong。
- 提取真实 `on_ws_text`，对下游协议处理器做受控桩，执行1000轮“超限报文→pong→OTA确认”。确认拒绝发生在OTA及普通解析回调前，且回调计数平衡、后续分发继续。此项不是实际TCP/云端联调。
- 关闭包装层预算的错误变体必须失败；扫描main业务源码，禁止新增未保护的直接cJSON输入解析。

既有 `test-json-budget.py` 继续验证深度、严格语法、合法协议和错误配置负例。产品综合、完整对话、配网、会议、监控、离线音频及音频生命周期套件执行结果归档于 `docs/audits/2026-09-27-json-resources/`。完成状态以该目录 `result.json` 为准，不将主机检查等同于实机完成。

历史审计 `audit-remaining-boundaries.py` 继续使用AU05修复前快照复现历史回收问题；当前宽JSON部分更新为验证拒绝且零分配，不覆盖旧审计证据。
