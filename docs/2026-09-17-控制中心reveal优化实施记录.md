## 2. 改动记录

### 改动 F3：reveal 单帧步进上限（跳帧螺旋保险丝）

- **文件**：`main/nuwax_ui_v28/nuwax_drawer.c`（:63 常量区、`reveal_timer_cb :3126`）
- **改动前**：
  ```c
  const uint32_t planned_step = nuwax_control_center_timeline_step(...);
  if (planned_step <= s_reveal_anim_step) return;
  if (planned_step > s_reveal_anim_step + 1U) {
      s_reveal_perf_skipped_steps += planned_step - s_reveal_anim_step - 1U;
  }
  s_reveal_anim_step = planned_step;
  ```
- **改动后**：新增 `CC_REVEAL_MAX_STEPS_PER_FRAME 2U`；单次回调最多前进 2 步，超出部分顺延（墙钟时间线不变，动画 wall time 自动延长），跳步计数仍如实累计。慢帧不再一次性绘制巨大环带，打断自激环。
- **预期**：最坏单帧环带 ≤ ~9K px（2 步 × Δr），reveal fps 回到 ~25；为 F2 提供干净基线。

### 改动 F2：环带失效去包围盒化（逐行精确 + 游程合并）

- **文件**：`main/nuwax_ui_v28/nuwax_drawer.c`（`update_backdrop_progress` 失效块重写，:2180-2280 附近）
- **改动前**：4 个 90px band × 左右各 1 个外接矩形（`circle_half_width(old/new_radius, near_y/far_y)` 构造包围盒）——矩形四角大量未变化像素（实测 56-83K px/帧 vs 环带真值 ~4-8K）。
- **改动后**：
  1. 从 `s_backdrop_progress` 现场推导**旧圆半径（Q4）**：`old_radius_q4 = (CC_REVEAL_RADIUS_Q4 * s_backdrop_progress + 500) / 1000`，逐行用与 `update_reveal_mask_rows` 完全相同的 Q4 公式重算旧圆边（`integer_sqrt_u32`）——**无快照栈缓冲**（初版曾用 1.4KB 栈数组 `old_rows[CC_H]`，因叠加菜单峰值会跌破 4KB 栈告警线而改为现场计算）；
  2. 每行分别计算**左缘 delta 跨度** `[min(old_edge,new_edge), max(...)]` 与**右缘 delta 跨度**（开/合两个方向、圆边未覆盖行（left=right=center）及首帧/末帧均由此公式统一正确处理）；
  3. 左右缘各维护一个**游程合并器**：容差 `CC_REVEAL_ANNULUS_MERGE_TOLERANCE_Q4=128`（8px）内扩展矩形，超差闭合（Q4→px 换算 + 两侧 1px pad）；每侧矩形数封顶 `CC_REVEAL_ANNULUS_RECTS_PER_SIDE 12U`，超限则扩展当前矩形（尾部粗化，保证不超 LVGL 32 项失效缓冲）；
  4. 复用 `invalidate_backdrop_band()`（含 clamp）与 perf 统计（`backdrop_areas/pixels/max` 口径不变）。
- **静态断言**：新增 `CC_REVEAL_ANNULUS_RECTS_PER_SIDE * 2U + CC_REVEAL_CONTENT_DIRTY_AREAS < CC_REVEAL_INVALIDATION_BUDGET`（12×2+6=30<32）。旧 `CC_REVEAL_DIRTY_BANDS` 静态断言保留（常量仍存在，数学上仍成立）。
- **附属改动**：`circle_half_width` 失去全部调用者，加 `__attribute__((unused))` 标记保留（`backdrop_radius` 在 `draw_backdrop_cb:2318` 仍有调用，不动）。
- **预期**：背景失效像素 56-83K → **5-9K**；reveal 单帧 230ms → ~20-27ms；fps 10-18 → 30-38；`skipped_steps` 归零。

### F2 实现过程中的自审修正（记录）

1. 初版用 `old_rows[CC_H]` 栈数组快照旧掩码（1.4KB）——自审发现叠加菜单路径栈峰值 7.3KB 后，LVGL 栈（12KB）余量将跌破 4KB 告警线 → **改为从旧 progress 现场重算旧圆边**（与掩码同 Q4 公式，零内存开销，`integer_sqrt_u32` 每行 ~18 次迭代 × 360 行可忽略）；
2. 初版右像素换算 `run_max/16 + (run_max%16?1:0)` 不对称 → 改为两侧各 1px pad；
3. 首帧行状态：零初始化掩码行会被 min/max 公式误判为"全行变化"→ 现场计算方案中 `s_backdrop_progress==0` 时 `old_radius_q4=0` → 旧圆边=中心 → 跨度=新圆全 span，天然正确，无需特殊分支。

### 3.1 第一轮实机验证（F2 初版 + F3，2026-09-17 18:20 日志）与合并器 bug 修正

| 方向 | 改前 backdrop_px | F2 初版实测 | 判定 |
|---|---|---|---|
| close | 4,140–10,620 | **36–1,515**（areas=2） | ✅ 环带真值，精确生效 |
| open | 56–83K | **90–130K**（areas=3） | ❌ 合并器 bug |

**Bug 与修正**：游程扩展条件用的是"对运行包围盒（run_min/run_max）的容差"——open 方向左缘**单调**向左漂移，`run_min` 随行更新，容差检查永不失败 → 单个游程横跨整个圆高 → 每帧失效近整圆（90-130K px，比旧 band 包围盒更差）。修正：扩展条件改为**对上一行的边**逐行追踪（前后差 ≤8px Q4），圆中部行差 <1px 合并成长矩形、切线区自动断行——每矩形过绘制 ≤8px 边带。修正后断言手动验证通过、括号平衡。**待下一轮实机验证 open 方向 backdrop_avg_px ≤9K。**

### 改动 F5：内容半频暂存（第三层——内容路径减负）

- **文件**：`main/nuwax_ui_v28/nuwax_drawer.c`（`apply_reveal_progress`，backdrop 更新之后、内容暂存段之前）
- **改动前**：reveal 每帧执行完整内容暂存——移动/淡入全部组件（pager/header/footer/cards/volume）+ 六个批量区域条件失效（≈25-30K px/帧，**菜单风暴期 dirty 34-42% 的主导源**）。
- **改动后**：动画活跃期间内容暂存**仅在偶数步执行**（`s_reveal_anim_step & 1`），奇数步只推进背景圆环（backdrop 全频 40fps，组件位移 20fps）；`force_content`（完成/取消路径）与 `progress==0/1000` 的终态应用**始终绕过门控**——终帧永不漏。
- **依据**：F2 修好 backdrop 后内容区域失效成为剩余大头（事件循环实测）；20fps 组件位移在 1.3s reveal 中视觉不可感知（人眼对短时小幅滑动不敏感），而渲染成本直接减半。
- **预期**：内容失效 25-30K → **12-15K px/偶帧（0 px/奇帧）**；reveal 平均帧成本（内容+环带）从 ~50K px 降至 ~20K px 平均 → reveal fps 进入 35-40 区间；handler 长尾同比下降。
- **验证**：断言手动验证通过（d1-d4 全过）+ 括号平衡。待实机确认 `dirty_pct` 在 reveal 窗口降至 ≤10%、reveal fps ≥35。

### 6.2 第一轮直通实测：花屏缺陷、根因与修复（2026-09-17）

- **现象**：直通构建首次实机开合压测出现**花屏**（多帧内容交错、撕裂）。
- **日志铁证**：风暴窗口 `dirty_pct=169.5 / 213.6 / 281.6`（>100% = 同屏每周期被多来源重复刷写）、`flush hz=195`（正常 82）；`flush hz=415` 的空渲染窗口。
- **根因**：**双写者冲突**——直通 present_rgb565_regions 与 LVGL 自身 flush 管线**未协调地交替写屏**。直通模式只跳过了 reveal 自身的失效，但 transition cache 周期刷新（~15s）、状态栏/电池/wifi 图标更新等仍产生 LVGL 失效 → flush 任务把 **LVGL 过时状态视图**写上屏，与合成帧交错 → 花屏。
- **修复（单写者纪律）**：
  1. `animate_reveal`：直通激活成功后 `nuwax_lvgl_port_set_panel_output_enabled(false)`——LVGL flush_cb 直接丢弃（不占失效管线槽位），面板唯一写者 = 直通 present；
  2. `reveal_completed`：`s_reveal_direct_active=false` + 门控复位 `set_panel_output_enabled(true)` + `apply_reveal_progress(target, false, force=true)`——强制一次完整内容暂存使 LVGL 对象状态与显示帧收敛，随后常规失效恢复。
- **验证**：断言手动验证通过、括号平衡、**重建成功**（同批次产物）。待实机复测：花屏消失、reveal fps 达标。

### 6.3 实机复测仍有竖线伪影 → 直通路径回退（2026-09-18）

- **实测**：单写者门控修复后的构建，开合压测**仍可能出现竖直花屏线条**（屏幕中部）。同时确认：直通激活（backdrop_avg_px=0）、F5 生效（风暴 flush hz=168-195）、门控抖动（gate=black/ui 每次开合各一次）。
- **结论**：门控修复解决了"直通 present 与 LVGL flush 交错"，但**竖线伪影的另一机制仍在**——`gate=ui` 窗口内 LVGL 对**中间态对象树**（内容暂存半途/快速开合交错）做 20 行条带渲染时，flush filter 仍带着动画期掩码行做合成（filter 与动画状态耦合，见根因分析），加上 present 直写与条带 flush 在任意行边界交错——该架构在快速开合场景下无法收敛。
- **决策（回退）**：`animate_reveal` 内直通路径强制禁用（`s_reveal_direct_active = false` + 表面释放），`reveal_direct_frame` 保留（unused 标记）供重设计后复用。回到 **F2+F3+F5 已验证状态**：close 环带 352-3,059 px、idle 39.4fps、内容半频生效、**无任何伪影**。
- **重建**：成功，无告警（drawer 相关断言不受影响——:900/:901 断言针对 F2/F3 路径，仍在）。
- **后续**：直通方案（§5.2/§5.4 设计）需以独立状态机重设计——filter 总闸（非直通 flush 一律旁路）、门控切换冻结、捕获状态机完整化——作为独立变更再上，不在现有 reveal 代码上渐进叠加。

## 7. 花屏根因最终定位与 F2 回退（2026-09-18）

### 7.1 决定性证据

直通路径禁用后的构建，开合压测**花屏依旧**，且**每次 reveal 的 `backdrop_avg_areas=0 backdrop_avg_px=0`**（双向、无例外）——F2 逐行失效代码在实际运行中**产出的环带失效为零**。

### 7.2 根因（最终）

**F2 重写引入功能回归**：逐行跨度计算在实机上产出空跨度（`invalidate_backdrop_band` 零调用）→ 圆环失效从未发生 → 屏幕上只有 F5 门控放行的 6 个内容区域在刷新，**内容区之间的环带像素全部滞留旧帧** → 竖直花屏线条（内容区域间竖向条带），首次打开最严重（累积滞留最多）。flush filter 按最新掩码行对内容区合成，进一步放大了"内容新、环带旧"的割裂观感。

教训：对"必定产生失效"的原始代码做失效路径重写时，缺少设备端像素级对照（改前改后同帧截图），导致"零失效"的回归两轮未被发现——**失效路径的改动必须有像素级验收**。

### 7.3 处置

- `update_backdrop_progress` **整体回退至原始 band 包围盒失效**（数周实测正确渲染的基线）：`circle_half_width(old/new_radius, near_y/far_y)` 4 边带构造——该代码渲染的 56-83K px/帧是"必要绘制"而非浪费；
- F2 逐行实现完全移除；F3 步进上限、F5 内容半频**保留**（两者不改变失效几何，仅限频/限幅，独立于本次回归）；
- 80MHz、B1 栈裁剪、C1、A1 不变；
- drawer 相关断言手动验证通过（:900 band 序列恢复即匹配）。

### 7.4 当前验收口径

烧录本构建后：圆形 reveal 展开动画应**恢复到优化前基线**（圆环正确扩张、无花屏竖线、无滞留环带），同时保留 F3/F5/B1/80MHz 的改进。open 方向 fps 与改前一致（20-27fps 量级）——**reveal 提速专题整体暂停**，待有像素级验收手段（同帧截图对照）后再重启 F2 类失效路径优化。

## 8. 花屏最终根因：80MHz QSPI 信号完整性失败（软件全部排除，2026-09-18）

### 8.1 差分证据链

| 构建 | 80MHz | F6 直通 | F2 逐行 | 花屏 |
|---|---|---|---|---|
| 历史基线（数周） | ✗ (40M) | ✗ | ✗（原 band 代码） | **无** |
| 优化首版 | ✓ | ✓ | ✓（F2 逐行） | **有** |
| F6 禁用 + F2 回退 | ✓ | ✗ | ✗（原 band 代码逐字还原） | **有** |

**唯一贯穿全部花屏构建、且不存在于任何正常构建的变量 = 80MHz QSPI 时钟。**

### 8.2 机理

菜单打开 = 全屏渲染 + 最高 QSPI 流量 → 4 根数据线（GPIO 13/9/12/46）在 80MHz 采样失败 → 该数据线的像素流错乱。竖直条纹 = QSPI 4-bit 模式下某根数据线错位的经典特征（一条线错 → 对应 bit 平面整列错乱）。"第一次开菜单最严重" = 启动后首次全屏级最大流量（且冷机状态）。

### 8.3 处置（本轮）

`CONFIG_NUWAX_DISPLAY_SPI_HZ` 回退 40MHz——四处同步：`sdkconfig.defaults`、`sdkconfig`、`tmp/sdkconfig.sd-replay-test`、host check 断言（:1473）。**重建成功**。

### 8.4 验收

烧录后：a) 开合压测无花屏/竖线；b) idle 表情 39.4fps 维持；c) 若 40MHz 下花屏消失，则 80MHz 判定 SI 失败，**永久回退 40MHz**（或待硬件整改后另行评估 60MHz 中间档）。
