## 本轮实现

### 二级页缓存绘制

二维码与设备信息按控件区域建立 RGB565 缓存；每个空闲定时周期最多生成一个区域，动画、按压、拖动时暂停预热。缓存时按该区域裁剪绘制完整所属页面，保留相邻文字的扩展笔画，避免独立控件黑底缓存互相覆盖。

切换过程中隐藏真实详情树，合成缓存平移；只刷新移动区域，跳过已被详情页完全遮挡的底层菜单。结束后恢复真实控件，继续显示最新状态。菜单状态、二维码载荷、设备 ID、版本、SSID、IP 的缓存有效性分别检查，变化后不使用旧内容启动动画。

两页像素缓存共 289,636 字节（约 282.85 KiB），描述信息也动态分配在 PSRAM。每次缓存分配保留至少 1 MiB PSRAM 空闲量。未预热、内容变化、空间不足或分配失败时直接完成详情切换，保留按钮反馈和页面功能。诊断测试页仍沿用原有切换路径。

### 同级切页与合成

- 按移动组件的旧、新边界提交刷新区域，替代固定 360×270 全内容区刷新。
- 每次更新动画位置后统一计算组件位置及透明度，刷新分块复用结果。
- 分页按钮颜色未改变时不重复设置样式。
- RGB565 复制使用对齐的 32 位读写；半字错位时使用 16 位读取，处理奇数长度。明确使用编译器内建小块复制，避免 IDF 禁用普通 memcpy 内建优化后生成逐次外部调用。

### 实机耗时拆分

新增 `ui stages` 日志，与原来的 `ui perf`、`display pipeline` 同窗口输出：

| 字段 | 含义 |
| --- | --- |
| `compose_us` / `compose_max_us` | 本窗口 flush filter 合成总耗时 / 单次分块合成最大耗时 |
| `owner_wait_us` / `owner_wait_max_us` | LVGL 所属任务等待异步显示资源的累计耗时 / 单次最大耗时 |
| `draw_other_us` / `draw_other_max_us` | render 区间扣除上述区间后的剩余时间 / 单次 render 剩余时间最大值；包括绘制、其他处理与调度等待，并非纯 CPU 用时 |

总量与最大值的统计单位不同，不能直接把 `compose_max_us` 当作完整一帧合成耗时，也不能把不同任务的 pipeline 累计值简单相加。
