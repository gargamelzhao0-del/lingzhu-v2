# 显示链路与下拉菜单花屏分析

## 结论与证据范围

本次只分析显示代码、日志并进行主机复现，未修改固件业务代码，未烧录、重启或调整 SD 网关。

日志为 `d25766cc-c005-47c4-ab48-4a7cd9183f21/已粘贴的文本.txt`，从约 45 秒至 98 秒，缺少启动 SHA。日志中的直出开关、零 backdrop 脏区统计和当前代码路径一致，但不能据此确认完整镜像身份。

严重花屏的首要代码缺陷在下拉菜单的 **整屏直出合成**：新缓冲没有完整底图，每帧也没有重新建立底图；圆形边界存在漏写；动画直出绕过了组件状态更新。这些缺陷不依赖 SD 上传，可以独立复现。日志中的性能下降会放大可见时间，但卡顿不是随机像素的充分解释。

## 显示链路

| 层级 | 主要文件 | 职责与边界 |
|---|---|---|
| 表情资源 | `face/emotion_asset_pack.c` | 读取 emotion_0 分区，管理目录、帧资源及 CRC 校验 |
| 解码和前台帧 | `face/emotion_animation_player.c` | CPU0 后台解码，发布补丁；UI 所有者维护 360×360 RGB565 可见帧与脏区 |
| 表情界面 | `nuwax_face.c` | 状态桥接、冻结交互、提供冻结 RGB565 帧 |
| 菜单 | `nuwax_drawer.c` | 页面、组件快照、圆形遮罩、拖动和动画状态；包含普通 LVGL 与整屏直出两条路径 |
| LVGL 端口 | `nuwax_lvgl_port.c` | UI 互斥锁、部分刷新缓冲、异步刷新队列、完成令牌、直出所有权隔离和性能统计 |
| 屏幕驱动 | `display.c` | ST77916 地址窗口、RGB565 字节序转换、分块 QSPI 同步传输、内部 TX 缓冲 |

当前源码的 UI 任务在 CPU0、优先级 7；刷新任务优先级 6；表情解码优先级 4。声音实时任务主要位于 CPU1。不能简单把所有显示任务提到最高优先级。

普通 LVGL 路径先绘制黑色菜单底图，再将组件缓存叠加到已存在的像素上，最后恢复圆外冻结表情并处理边界。直出路径调用的是同一个“叠加组件”函数，却没有先完成底图步骤，这是关键契约差异。

## 确定性缺陷

### P1：整屏缓冲未建立完整底图

位置：`nuwax_drawer.c:1541`、`:2080`、`:3251`。

`s_reveal_direct_surface` 使用 aligned_alloc 分配 360×360×2 = 259,200 字节，没有清零。`reveal_direct_frame()` 首先调用 `transition_cache_compose()`，后者只绘制有效组件所覆盖的区域，不填充其余像素；其余处理只复制圆外部分冻结表情。最后却将整屏像素全部提交。

因此圆内组件之间的空白、组件隐藏部分和边缘漏洞可显示分配前的内存内容或前帧残留。即使第一次分配改为 calloc，也不能解决后续展开时把前帧圆外表情带入新圆内、以及半透明混色依赖前帧内容的问题。必须每帧建立确定性底图，再叠加组件。

`transition_cache_compose_component()` 在透明度非 255 时读取 destination 进行混色，因此未定义底图还会污染组件自身的颜色。

### P1：圆形遮罩边缘漏写，空圆没有整行恢复

位置：`nuwax_drawer.c:1554–1568`、`:1706`，可与普通 `control_center_flush_filter()` 对照。

直出左侧循环以 `x < left_pixel - 1` 结束，右侧从 `right_pixel + 2` 开始，跳过了本应恢复的边界像素；也没有处理 `right_q4 <= left_q4` 的空圆行。普通刷新过滤器有空圆整行恢复和 Q4 边缘混色，直出没有沿用。

主机提取原样的整数平方根、遮罩函数和直出函数，在 progress=0 时验证：左侧只恢复 x=0..178，右侧只恢复 x=181..359，x=179、180 两列残留，共 **720 像素**。这是生产像素循环的确定性结果。

### P1：直出提前返回，组件状态停留在旧进度

位置：`nuwax_drawer.c:2904`，对比后续 `apply_content_reveal()` 和 `set_opa_if_changed()`。

当进度变化且直出开启时，函数绘制直出帧后立即返回。分页点、标题、卡片、页脚、音量条的位置与透明度更新全部在该分支之后，因而被跳过。而合成组件时又读取这些对象当前的坐标和透明度。

结果随入口状态不同而变化：从关闭状态打开可沿用透明状态，拖动释放后可停留在释放时样式，关闭时可保持打开状态样式直至结束；在恢复普通 LVGL 刷新后发生突变。合成正确性需要先计算统一状态，再选择呈现方式，不能将“减少无效区域”变成“跳过状态更新”。

## 其他需要修复或验证的问题

| 优先级 | 问题 | 判断 |
|---|---|---|
| P1 | `reveal_direct_frame()` 丢弃 present 返回值，动画状态和成功显示没有绑定 | 代码确定。超时或传输失败时仍推进动画，日志难以区分丢帧；本日志没有证据证明本轮由传输错误触发 |
| P2 | 取消、销毁和回退缺少统一的直出所有权退出 | `cancel_reveal_animation()` 只删定时器；deinit 清除 direct_active 但不恢复 output gate。正常完成会恢复，但异常退出存在显示一直受抑制的风险。本日志每次正常动画都有 gate=ui，不能说本轮已发生永久黑屏 |
| P2 | `gate=black` 日志语义不准确 | 实际只禁止普通 LVGL flush，不清屏、不关背光，也不禁止 direct present。不能用该日志推断屏幕输出已经安全 |
| P2 | 直出整屏同步提交阻塞 UI 动画回调 | 一帧 259,200 字节，当前驱动以内部缓冲分块复制和传输。等待在 UI 所有者上下文发生，会拉长触摸、动画和其它 UI 的处理时间 |
| P2 | 性能统计混合两条呈现路径 | direct present 加入 flush 像素数，却不增加 LVGL refr 次数；故 dirty_pct 可超过 100%，不直接表示越界或内存破坏 |

直接呈现接口要求持有 LVGL mutex，并先取得全部 pipeline slots，待异步刷新排空后再写屏，完成后归还。现有序列化机制应该保留，不能为了速度去掉；目前没有证据证明首要原因是两路 SPI 同时写屏。

冻结表情仅停止后台解码发布，前台帧仍由 UI 所有者管理；消费补丁路径在 interaction_active 时停止应用补丁。当前检查没有发现必须先将整张表情复制一份才能保证冻结安全的依据。

## 日志对应关系

- 普通表情显示约 39–40 fps，刷新脏区约 2–3%，说明持续性的全局颜色格式错误或完全损坏的资源包不是优先解释。
- 54.729 秒启用菜单缓存；54.839 秒 gate=black；55.619 秒 gate=ui。该次打开 24.4 fps，最长 handler 211.514 ms。
- 随后关闭 22.7 fps、打开 27.1 fps，多个窗口出现大面积刷新；与直出期间的整屏传输一致。
- `backdrop_avg_areas=0` 与直出绕开 LVGL 脏区路径一致，并非本身证明没有背景。
- `dirty_pct=496.5` 是统计口径混合，不能直接当作 496% 显存越界证据。
- `internal_min=931` 是历史低水位；当时 internal 约 35.8 KiB、PSRAM 约 1.7 MiB，UI 栈余量约 5.5 KiB。不能仅凭历史最低值认定当时内存耗尽或栈溢出。
- 缓存 166,560 字节，加直出表面 259,200 字节，共约 415.8 KiB PSRAM，尚未计算表情帧、LVGL 缓冲和解码状态。它解释了开启时约 259 KiB 的常驻下降，不等于已经证明泄漏。
- 日志包含语音播放与睡眠切换，并非所有长 handler 都可归于菜单。当前截取未显示 display flush failed、flush completion timeout 或崩溃重启。

## 建议实施顺序

1. 先将当前不完整的直出路径退出默认路径，恢复普通 LVGL 呈现作为止血基线；这可能牺牲动画帧率，不能当作最终性能优化。
2. 抽出无 LVGL 副作用的帧合成核心：每帧建立完整底图，圆内黑底加组件，圆外冻结帧，空行完整复制，边缘使用一致的 Q4 覆盖率。任何像素不得依赖上次分配/上一帧的内容。
3. 将组件状态计算与 invalidation 分离，普通路径和直出使用同一进度/坐标/透明度模型。缓存快照须携带一致的布局尺寸和步长契约。
4. 为直出增加统一的进入、成功完成、反向、取消、销毁、分配失败、present 失败退出流程；保留刷新队列排空与缓冲所有权机制。
5. 完成像素级回归后再优化传输：优先减少变化区域，或缓存静态完整页面后做确定性合成；避免先增加整屏缓冲、改 SPI 频率或提高任务优先级。
6. 实机验证打开/关闭/反向/拖动中断/切页/详情页、低内存回退及对话并发。检查随机初值不同但输出完全一致、重复合成不累计变色、进度 0 与冻结帧完全一致。分别统计 direct compose、present、LVGL render 和触摸响应，再评价 40 fps。
