# 设备端稳定性修复交付：7.0.114

本轮落实无需改动现有 APP 和云端的设备端核心修复。构建为正式云端配置，测试网关和模拟断网面板关闭。代码与主机故障注入已验证；未烧录、未发布到云端，真机验收未完成。

## 已实现的变化

| 问题 | 本版处理 | 正常流程的约束 |
| --- | --- | --- |
| 问候等不到文本/TTS、尚未开始物理播放时，超时后可能不再听 | 匹配当前连接、唤醒代际、问候请求与未播放状态，退休异常连接，沿用原重连收音恢复 | 正常问候不增加延迟；普通播放和非零播放代际仍走原终止流程；睡眠、关机、模式接管优先，OTA 期间暂缓 |
| 仅保留离线恢复意图，界面却显示运行中 | 分开采集任务存在、MIC 启动、有效保存路径、完整缓冲等待与不可用状态；离线保存不可用映射现有失败状态 | 在线控制器状态优先，在线无 SD 不被本地保存故障停掉；监控静音不要求文件持续写入 |
| 无卡/满卡/尾部收尾时反复启动录音任务 | 在创建任务和分配采集内存前，检查介质、空间、关闭任务、关机与恢复准入 | 不增加帧路径文件系统操作；挂载和扫描归后台存储任务 |
| 持续写失败仍长期采集丢弃 | 有现存缓冲时保留最多 15 秒恢复窗口，容量先到则提前停止；失去留存能力后停止读者并异步收尾，保留已有归档 | 保留此前 12 秒卡顿容忍范围；不能把已丢帧改称已保存，也不保证任意拔卡零损失 |
| 用户停止恰好与采集任务创建重叠 | 读者携带停止代际；任务启动时清布尔标记不能擦除之前的停止；恢复 owner 再次检查意图 | 停止优先，恢复沿用原 session 与序号；不改云端授权规则 |
| 无卡从未开始 MIC，八小时计时不增长，可能一直等待 | 原有实际离线 MIC 八小时预算保留；不可录等待另受本次离线意图八小时上界约束 | 不因重试、插卡清零等待截止；到期取消旧意图，不自动恢复录音 |
| 长时间无卡持续生成诊断写入 | 每次连续失败最多前两个尝试进入原诊断队列，其余保留串口日志 | 不扩展诊断协议，不逐帧写 NVS |
| 重挂载清除了读者之前的不完整结果 | 移除介质恢复对 capture_complete 的成功重置 | 只有新采集启动建立新的完成状态；旧损失不会被卡恢复擦除 |
| 静音监控期间例行探测短暂清除介质状态，可能触发误停 | 健康离线采集期间推迟例行探测；准入后再次检查；真实故障/满卡仍允许恢复 | 不把“没有正在打开的文件”当成“没有采集任务” |
| 会议失败状态下点击按钮再次尝试开启，无法取消离线意图 | 失败状态的第一次点击发送原有关闭动作 | 不新增 SD 页面、屏幕长按或 APP 操作 |

诊断中的 `offline_storage_paused` 记录当前序号、保留帧和拒绝帧，用于分析。它不是新的云端音频字段，也不是完整、永久的缺口时间轴。静音监控正常无文件时不被标为失败；在线监控暂停期间无 SD 的声音不能由设备补回，原有云端 pause/resume 策略保持。

## 兼容性

- 固定 PoP、配网方式、云端地址选择和现有凭据结构不变。
- 消息、音频帧、归档头尾、补传 begin/chunk/commit 和 CRC 格式不变。
- 恢复申请用新 request_id；同一未终止会议/监控继续原 audio_session_id。用户停止后的全新开启仍是新会话。
- 仍只在匹配的 commit ACK 成功后删除归档；不自动格式化、不删除未确认数据腾空间。
- 正式云端未声明现有补传能力时保留文件，不向不支持的服务器强行发送新类型数据。
- 本轮只修改设备本地状态投影，不要求 APP 识别新状态。因此 APP 的缺口显示、云端静默换主等跨端行为不在此版本中新增。
- 唤醒模型阈值、充电参数、分区表和表情资源未修改。当前 OTA 仅包含应用。

## 验证

最终产物与日志位于 `artifacts/release-7.0.114`。`release-manifest.json` 给出应用与 ELF 摘要，`verification` 保存验证记录；`hardware_validated` 为 false。

通过以下主机回归：产品、会话、会议、监控、离线音频、WebSocket 和配网七组；最终受影响的音频生命周期、SD 介质故障及存储关机边界另行复测。正式固件构建和 20 项集成产物检查通过。

新增 `tools/run-device-stability-host-checks.py` 提取当前生产函数执行，覆盖：

- 等文本、等 TTS 两条真实等待循环到超时，当前连接仅退休一次，新连接恢复收音。
- 正常发送失败路径、旧连接关闭、菜单、OTA、请求身份、物理播放、模式接管和休眠边界。
- 两种模式各模拟十分钟无卡：零采集启动、失败状态、124 次有退避的轻量准入尝试、最多 2 次诊断入队。
- 卡恢复、用户停止、创建任务中停止、无 MIC 的八小时等待到期、原有采集时间到期。
- 空间保留区、归档配额、空间查询失败及恢复；无卡、满卡、尾部收尾、关机状态拒绝采集且不分配内存。
- 健康静音监控不执行例行介质探测；真实故障仍允许恢复。
- 短时背压、12 秒卡顿保留、持续故障、已知丢失、时间戳回绕。

这些测试使用模拟时钟、介质结果和任务/传输替身；未证明实际 SD、Wi-Fi、RTOS 调度或八小时连续运行的稳定性。七组原回归之后的收尾修改仅涉及诊断限流与介质探测互斥，已重跑对应故障注入及受影响模块，并重新构建。

## 真机验收与后续边界

用同一 7.0.114 固件依次验证：正常唤醒/问候、在线无卡会议/监控、无卡断网与停止、健康卡八小时、静音监控、录音中拔卡、满卡、插卡恢复、重连保留 session、补传完成对账及 OTA/关机交接。核对云端唯一提交量与本地归档，不能仅看发送成功日志。

本版本不宣称全部上架问题已经关闭：跨绑定/跨卡的可信归属、完整持久化缺口索引、APP 缺口展示、板级低电自动停录以及生产信任链仍需独立处理。无法从当前设备可见信息确认的云端新命令，不能武断当作旧命令拦截；本版保留原协议控制语义。无 SD 八小时保存需要额外持久存储，不能通过本次软件修复实现。
