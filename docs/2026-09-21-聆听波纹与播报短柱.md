# 聆听波纹与播报短柱（原表情叠加版）

此版修正上一轮对需求的误解：**原有表情本身及动画完全保留，只在最下方叠加两个互斥状态小标**。不使用上一版重新绘制的双眼、微笑或眨眼动画。上一份 `C:/tmp/nuwax-conversation-visual-20260921` 固件已被本版取代，勿继续用它验证此需求。

圆润微调版（v3）：仅将聆听弧线从 2.6px 加厚至 3.6px，使用平滑连接和圆端点，略减扩散半径以保持小标占位不变。说话短柱遮罩、原表情、状态判定、刷新频率和位置均不变。对应固件目录为 `C:/tmp/nuwax-conversation-rounded-20260921`。

播报平滑版（v4）：说话短柱由 24 帧/1.2 秒改为 60 帧/3 秒，高度范围由 6～16px 收敛为 7～15px。依然每 50ms 更新一次，每帧最大理论高度变化小于 0.42px。首尾取自同一连续周期曲线，不重复末端帧、不插入停顿帧。聆听波纹逐字节保持 v3，不改变原表情、图标尺寸和状态权限。只增加固件常量帧数，运行时 RAM 和刷新区域不变。固件目录为 `C:/tmp/nuwax-conversation-smooth-20260921`。

## 本轮行为

- 聆听：原有聆听表情和原动画照常运行，仅在最下方叠加中心圆点和向外扩散、渐隐的圆头弧线。
- 设备播报：保留现有表情及云端表情选择，只在底部叠加三根白色圆头短柱。
- 不显示“我在听”等小字。
- 两个小标互斥。用户说话不会触发播报短柱，短柱只在 `dialog=SPEAKING` 且 `speaking_pcm_active=true` 时出现。
- 本轮短柱是实际播报期间的平滑循环动画，不宣称代表实时音量。等待 TTS 首包、播报结束后不显示。
- 待机、思考、识别、会议、监控、配网、OTA、低功耗、触摸插入表情及云端未连接时不显示对话小标。

## 代码路径

- `main/nuwax_ui_v28/nuwax_face.c`：根据真实状态选择小标；仅在菜单交互时冻结原动画和小标。
- `main/nuwax_ui_v28/face/conversation_visual.h`：状态判定。
- `main/nuwax_ui_v28/face/conversation_visual.c`：透明小标、局部刷新和冻结画面，不绘制表情。
- `conversation_visual_assets.h`：固件内置的抗锯齿灰度遮罩。
- `tools/generate-conversation-visual.py`：可重复生成上述遮罩。

不修改云端协议、播放音频、麦克风采集、SD 补传和原有表情资源分区。

## 性能与生命周期

- 小标区域为 44×24，位置 `(158,320)`，靠近圆屏底部；空白部分透明，不用黑色矩形覆盖底图。
- 最多 20 FPS；错过时间点直接跳帧，不补算积压帧。每帧切换固件内置 A8 遮罩，由 LVGL 做透明混合，不运行三角函数，不分配内存。
- 小标出现、消失和动画只使小标边界失效。原有表情动画仍按原刷新节奏运行，新增模块不更改其帧率和播放内容。
- 预留一块 **259,200 字节，约 253.1 KiB PSRAM** 的 RGB565 缓冲，仅供菜单冻结背景使用；小标遮罩直接读固件常量。没有新增后台任务，不把像素缓冲回退到内部 RAM，只有一个小标图像对象。
- 菜单打开时冻结小标与原表情，也暂存新的状态请求；菜单关闭后显示最新状态。两种模式都复制原表情并按 LVGL 相同的透明混合规则叠加小标，每次冻结最多合成一次，绝不改写原表情像素缓冲。
- PSRAM 申请失败时记录告警并省略小标，原表情和动画正常运行，不阻止音频、网络和菜单启动。退出 UI 时删除对象并释放缓冲。

## 验证

运行 `tools/run-conversation-visual-checks.ps1`，使用工程实际 LVGL、实际 `nuwax_face.c` 和新绘制模块。

已覆盖：

- 聆听/播报/等待首包的状态权限，以及特殊模式互斥。
- 使用静态测试底图测量小标新增开销：550ms 的 11 次更新仅刷新 **11,616 像素**；原播放器持续运行，没有因聆听而暂停。
- 逐像素验证小标边界以外与原底图完全相同，小标内部透明角落也不覆盖原像素；底图发生更新后仍正确透出。
- 使用非零测试底图，校验冻结 RGB 与当前实际显示逐像素相同，覆盖聆听和播报两种路径。
- 菜单期间状态改变不会污染冻结背景，退出菜单后正确恢复。
- 播报停止后短柱消失，完整恢复原底图，无残影；没有文字对象。
- 周期波纹、内存不足降级、销毁和再次创建。
- 播报小标 3 秒后像素准确回到相同相位；周期内反复提交相同设备状态也不会重启动画。
- 原表情状态策略测试通过。

正式云端配置下完整构建、RNNT 增长检查、分区容量检查、正式补传配置与 BIN/ELF 身份检查通过。

扩展的 `run-v2-product-host-checks.ps1` 在既有 BLE 重配网源码正则检查处失败；本轮未改变其检查涉及的业务代码，主程序和 Wi-Fi 文件 SHA256 与上一份正式补传固件源快照一致。因此不能把该完整脚本标记为全部通过，也不将此项失败归因于本轮 UI 修改。

上述为主机验证和构建验证，尚未烧录实机；原生绘制测试不能代替设备实际帧率和音频并发测试。

## 烧录后验证

启动应看到：

```text
conversation visual active overlay_only=1 ripple=listening bars=playback text=0 fps=20 snapshot_psram_bytes=259200
offline replay route=formal_cloud test_panel=0 simulated_network=0
```

进入聆听、开始实际播报、结束播报分别应出现 `conversation_visual: mode=listening`、`mode=playback`、`mode=hidden`。检查：

1. 唤醒后仍为原来的聆听表情及动画，仅底部新增波纹，无小字；用户讲话期间仍为波纹。
2. 等待回复时没有播报短柱，设备真正开始播报才出现三根短柱。
3. 中断播报、断云、进入会议或配网后没有遗留小标。
4. 聆听和播报中分别下拉、左右翻页、收起，检查冻结背景无闪回、丢失或卡顿。
5. 观察新增 PSRAM 占用下的音频、Wi-Fi 与正式云端补传并发稳定性。
