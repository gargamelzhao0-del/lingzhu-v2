# NuwaxAIPartner-v2 全工程性能与产品化审计

审计日期：2026-09-08  
范围：当前工作树、`main/`、CMake/Kconfig/sdkconfig、现有 host 回归脚本与既有审计记录。  
证据边界：本轮完成源码和配置静态审计，并运行六组 host 检查；未连接 COM5，未执行 ESP-IDF 目标机构建、功耗测量、8 小时 soak 或声学验收。

## 1. 总体判断

功能链路已经接近完整产品，但性能和量产成熟度还没有达到“优秀产品”标准。当前主要矛盾是资源常驻和实时链路缺少目标机证据：离线 SD、UI、唤醒词、Wi-Fi/BLE、错误持久化、播放和音频上传都在同一固件中长期占用资源，许多缓冲按最坏情况预留，导致内部 RAM 碎片、PSRAM 峰值和调度抖动被隐藏在“功能可用”之后。

当前应把发布状态定义为：**功能候选版，性能与量产安全仍需门禁**。Live AEC 和自动真人打断默认关闭是合理的降级策略，但不能作为最终产品能力完成的证明。

## 3. 分模块结论

### 启动、电源和持久化

电源保持、SW3、OTA 启动互锁设计完整，但启动顺序承担过多工作：电源、SD、NVS、UI、唤醒、Wi-Fi、错误队列、音频 owner 需要明确关键路径和延后初始化。NVS 不应把“版本不兼容/空间不足”直接等同于整分区擦除。应建立 schema version、备份 namespace、恢复出厂命令和 recovery UI。

### 音频采集、AEC、播放

20 ms/16 kHz/mono 协议约束清晰，音频指标模块也已具备。实际瓶颈是 owner 切换、播放参考连续性、队列 age 和核心调度。建议把每帧处理拆成固定预算：采集 <= 4 ms，DSP <= 8 ms，编码 <= 4 ms，入队/发送不得阻塞采集；超预算自动切换 raw/candidate-only，并报告原因位。

### WebSocket、TLS 和上行

当前发送路径有 epoch、超时、in-flight drain 和失败策略，工程质量较高；代价是锁和超时状态复杂。实时二进制帧必须采用丢旧保新，控制帧和终止帧必须保序可靠。应把 TLS 握手、JSON 分配、发送锁等待分别计时，避免只看总发送耗时。

### UI、表情和显示

表情资源已经迁移到分区、mmap 和后台解码，方向正确。LVGL 仍然是系统级竞争者：2 ms tick、5 ms refresh 和 20 KiB stack 不能凭配置宣称高效。需用真实 dirty area、flush pixels、render p95 和屏幕关闭时电流决定刷新策略。

### 离线录音、SD 与错误诊断

离线 spool 的分段、footer、恢复和 fsync 设计偏可靠，但不适合默认常驻在线产品。SD 写入应按会话开启，fsync 周期必须由掉电风险和卡寿命共同决定；错误上报要避免异常期间反复 NVS commit。

### Wi-Fi、BLE 配网和 OTA

功能覆盖较全，但 BLE Security 2、TLS、LVGL、音频同时启动是内部 RAM 峰值场景，必须有启动阶段资源预算。量产 OTA 还需要签名、加密、anti-rollback、坏包、掉电、旧 NVS 和跨版本 schema 的组合测试矩阵。

## 4. 建议的优化顺序

1. **建立基线**：在目标机采集启动各阶段 internal free/largest/min、PSRAM、每任务 stack HWM、CPU idle、队列高水位、DSP/flush/TLS p50/p95/p99、电流。
2. **先减常驻资源**：离线 SD 改懒加载；确认错误报告、battery、shake、BLE、wake 的按需启停；把实时上行队列降为 age-bounded 小队列。
3. **再做实时调度**：固定音频预算和丢旧策略，关键 task/stack/queue 逐项迁移到合适内存，禁止实时路径无限等待和动态分配。
4. **再做 UI 功耗**：空闲降刷新，动画和 flush 只在 dirty 窗口运行；实测双缓冲是否值得长期保留。
5. **最后启用高风险能力**：硬件 AEC、自动真人打断、离线回放、音乐播放分别灰度，不在同一版本同时打开。
6. **量产收口**：安全 profile 强制门禁，干净构建、SBOM/CVE/license、OTA 100 次循环、掉电恢复、8 小时 soak 和出厂自检全部留证。

## 5. 可接受的发布门禁

- 音频：20 ms 帧无 sequence gap；capture age p99 <= 60 ms；播放期 DSP p99 <= 20 ms；speaker underrun=0；实时队列只丢旧帧。
- 内存：Wi-Fi/TLS/BLE/音频/UI 并发时 internal minimum 和 largest block 均高于冻结阈值；8 小时下降斜率接近 0；所有 task stack HWM 留出 20% 余量。
- 功耗：待机、聆听、播放、会议、监控、SD 写入分别测平均/峰值电流；屏幕无变化时刷新不会维持满速。
- 稳定性：网络断开、云端半包、播放中触摸/唤醒、SD 拔出、NVS 损坏、OTA 掉电、重复 init/deinit 均能在有限时间内恢复。
- 安全：量产镜像必须 Secure Boot + Flash Encryption；设备 secret 不进入日志、构建默认值或明文持久化；OTA manifest、镜像、模型和配置 hash 可追溯。
- 测试：六组 host 检查当前均通过；仍需目标机 build、COM5 实机、声学样本、功耗和 soak 证据后才能升级为发布结论。
