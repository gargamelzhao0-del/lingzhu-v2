# 摇晃回复被隔离后的回合收尾修复

## 真实性复核

日志 a8485ea2：475.015 秒旧普通回复 BEGIN 被交互替换逻辑拒绝，屏障转为 REJECTED；475.045 秒 shake_4 提交并固定摇晃表情；475.085 秒新 BEGIN 被接收屏障拒绝，RX 直接 return，主线程不知道新回复已经不可播放；477.665 秒音频 END 排空，477.725 秒逻辑 END 因未绑定 turn/playback 被忽略；505.125 秒 WAIT_TEXT 满 30098ms 才解除回合。动画仍约 40fps，心跳正常。

已用实际 notification_rx_barrier、turn_guard 及主线程新增处理分支重放相同顺序。旧行为缺少拒绝结果交付，界面只剩通用超时收尾。日志文案 notification stream 不准确，因为该屏障也管理普通回复，现改为 audio stream。

## 本轮设计

二进制流归属存在歧义时继续隔离，不把新 BEGIN 当作旧流已经停止的充分证据，不直接清空屏障，不自动重发摇晃请求。这样避免旧音频误播和重复云端交互。

新增仅设备内部使用的 rx_playback_rejected 标志。解析器仍先清零命令，云端 JSON 不能设置该字段。RX 把拒绝的 BEGIN 带原身份放入现有关键队列。主线程只在当前连接、当前 awake generation、已知 request 或 turn 锚点匹配、没有 speaker generation、且处于 WAIT_TEXT/WAIT_TTS/WAIT_TTS_RETRY 时清理回合并恢复聆听。

不创建新回合，不接纳二进制，不清空音频屏障；PLAYING/DRAINING、旧连接、旧请求、冲突 turn/playback、无身份锚点均不能触发收尾。已有通知/休眠隔离优先级保持；队列满仍按原 epoch 关闭恢复。排空 END 和隔离超时恢复机制保持原行为。

## 前后效果

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 本轮 shake_4 回复被隔离，身份可确认 | 无声等待约30秒，摇晃表情固定 | 主线程收到拒绝后结束等待、释放表情并恢复聆听 |
| 正常摇晃回复 | 正常播放后释放表情 | 相同 |
| 旧连接/旧请求迟到 | 隔离或忽略 | 不能终止新回合 |
| 正在播放的回合 | 原播放/结束流程 | 新拒绝路径不能取消它 |
| 模糊二进制 | 丢弃到END或连接恢复 | 相同，不为恢复回复而放宽隔离 |

此修复解决已知“失败后仍等待”的状态机缺口，并不保证这次被隔离的语音能播放。该边缘场景仍会丢弃这次回复，但不再靠30秒超时解除已确认失败的等待。身份不足时宁可保留原超时保护，也不猜测归属去取消其他回合。
