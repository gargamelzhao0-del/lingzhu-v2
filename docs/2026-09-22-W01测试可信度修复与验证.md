## 1. 长稳检查

原 `check-device-longrun-gate.ps1` 对以下输入实际返回 PASS：

```text
internal_min=20000 dma_largest=10000
partial_reads=0 timeouts=0 input_gaps=0
dropped_frames=99
queue_drops=12 partial_reads=5 timeouts=5 input_gaps=3
```

新版保留 PowerShell 入口，使用标准库 Python 流式解析 ESP 日志。结果定义：

| 结果 | 退出码 | 含义 |
| --- | ---: | --- |
| PASS | 0 | 本次指定时长、日志覆盖和已实现诊断规则满足要求 |
| FAIL | 2 | 已观察到崩溃、重启/明显时钟回退、已识别音频丢帧或内存预算违规等 |
| INCOMPLETE | 3 | 时长不足、必要指标缺失、日志间断、异常计数重置、读超时缺少解释或无法读取输入 |

PASS 只表示日志指标门禁通过，不证明所有业务场景覆盖或硬件可靠性。无硬件测试时不能写成“设备已通过 72 小时长稳”。

实现要点：

- 默认要求单个启动周期连续覆盖 72 小时；不能相加多个启动周期凑够时长。
- 默认日志最大间隔 120 秒；内存使用 `heap checkpoint=` 的 `internal_min` 和 `dma_largest`，要求持续覆盖。其它文本里的同名字段不用于伪造证据。
- 原内存门限 16384 B / 8192 B 保留并允许显式设置，报告记录实际门限。历史内部堆低水位含启动谷值；门限违规不等同于已经崩溃，后续必须按分配预算评估，不能为了通过测试任意降低。
- 按模块、诊断流、可用会话标识、唤醒任务代次隔离计数；重复上报不重复累加，出现未解释的倒退则标为证据不足。
- 首次看到非零计数不能直接忽略。读超时和部分读取可能来自正常切换，缺少上下文时需要人工核查，不当成已证实的音频丢失，也不自动放行。
- 识别已知丢帧字段、panic/watchdog/brownout、启动横幅和大幅设备时间回退。允许小幅多核日志时间交错；大幅回退以“重启或时间重置”报告，不武断归因。
- `no_speech` 不构成故障。会话正文预览不当作系统计数或 panic 证据。
- 报告含输入 SHA256、时长、启动周期、规则预算、行号、时间和计数增量；不复制对话正文。记录最多 500 个问题详情，保留总数及截断标识。
- 支持 UTF-8 BOM、UTF-16 日志。输入缺失不能留下旧 PASS 报告；禁止报告路径覆盖原日志。

日常短测可明确设置检查时长：

```powershell
.\tools\check-device-longrun-gate.ps1 -LogPath C:\logs\device.log -MinimumDurationSeconds 600 -ReportPath C:\logs\device-gate.json
```

72 小时门禁省略 `-MinimumDurationSeconds`。采集前应确认当前测试流程有相应周期性内存/唤醒健康记录；证据缺失应补采，不应把 INCOMPLETE 改成 PASS。

本轮使用上一份 `a29589a3-f41a-49d5-a426-82597fad8767` 日志验证：94.24 秒、没有门禁识别的硬故障；因时长、内存覆盖及部分读超时的上下文不足，结果为 INCOMPLETE。它不能替代原来的人工日志分析，也没有据此认定设备发生新故障。

## 2. 配网回归规则

原脚本先在包含 26 条规则的笼统检查处失败，无法直接知道是哪项。修正后继续发现 QR/取消检查中的两条旧规则也失效。

| 旧要求 | 现行正确行为 | 修改 |
| --- | --- | --- |
| 迁移后 `heap_caps_free(previous1)` | 统一 `release_draw_buffer` 区分自有和驱动借用内存 | 检查归还函数，不要求直接 free |
| 跟手下拉切到菜单页 | 进入灵珠状态页，避免纵向/横向动画串页 | 保留状态页规则 |
| 快速下滑打开菜单页 | 调用普通控制中心入口，进入状态页 | 与现有串页修复一致 |

运行期 26 项、QR/取消 27 项现在有独立编号和 JSON 结果，分别写入 `build-host-checks/provisioning/runtime-contracts.json`、`qr-contracts.json`。其余原有配网检查仍保留。自动配网二维码入口继续进入对应菜单详情，没有为通过旧测试改动产品行为。

新增验证执行实际 `nuwax_lvgl_port_set_runtime_provisioning_memory()`、缓冲借用/归还函数，外部 RTOS/LVGL/分配接口由可控桩代替：

- 第一/第二块分配失败、LVGL 锁失败、DMA 屏障忙；失败时旧缓冲仍有效，临时分配释放。
- 正常切换归还驱动借用缓冲，自有缓冲仅释放一次。
- 重复请求幂等、第二块失败降级单缓冲、内部内存不足保留恢复目标、随后恢复。
- 四个故意破坏的生产函数变体：遗漏释放、重复释放、直接 free 借用缓冲、跳过 DMA 屏障，都必须被拒绝。

另在隔离源码副本上运行完整配网脚本：正确副本通过；删除凭据回滚、删除音频恢复、移除失败隔离、遗漏缓冲归还的四个变体，均在预期检查项失败。未修改工程产品源码进行这些注入。源码约束仍只是补充，不代替完整配网事务的硬件故障测试。
