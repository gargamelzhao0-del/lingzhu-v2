## 1. 背景与目标

代码级分析确认的两个瓶颈（均有量化依据）：

1. **时钟临时降频**：`CONFIG_NUWAX_DISPLAY_SPI_HZ=40000000` 是点亮期临时值，Kconfig 默认值为 80MHz 且 help 注明"raise after real panel testing"。线带宽因此少一半（20 vs 40 MB/s）。
2. **flush 链 CPU 拷贝税**：每条带（360×20=7200 像素）实测 1.6ms，其中线时间仅 0.72ms，差值 ~0.9ms 花在 `copy_pixels_byte_swapped` 把 LVGL 缓冲交换+搬运进 `s_tx_buffer` 再 DMA——而 LVGL draw buffer 本身就是内部 RAM 16B 对齐分配，天然 DMA 可用，中间拷贝在常规路径上冗余。

目标：条带 flush 1.6ms → **~0.7ms**；整帧连续刷新上界 34fps → **~75fps**；CPU0 每帧 flush 负担 ~16ms → ~6ms。

### 改动 1：display.c 新增原地交换 + DMA 直传快路径

**位置 A：include（:14）**

改动后：
```c
#include "esp_heap_caps.h"
```

**位置 B：新增 `swap_pixels_inplace()`（:588，插在 `spi_write_pixels` 之后）**

改动前：无此函数。
改动后（完整）：
```c
static void swap_pixels_inplace(uint16_t *pixels, size_t count) {
    if ((((uintptr_t)pixels) & (sizeof(uint32_t) - 1U)) != 0U) {
        for (size_t i = 0; i < count; ++i) {
            pixels[i] = __builtin_bswap16(pixels[i]);
        }
        return;
    }
    uint32_t *pairs = (uint32_t *)pixels;
    const size_t pair_count = count / 2U;
    for (size_t pair = 0; pair < pair_count; ++pair) {
        const uint32_t value = pairs[pair];
        pairs[pair] = ((value & 0x00FF00FFU) << 8) |
                      ((value & 0xFF00FF00U) >> 8);
    }
    if ((count & 1U) != 0U) {
        pixels[count - 1U] = __builtin_bswap16(pixels[count - 1U]);
    }
}
```
依据：与既有 `copy_pixels_byte_swapped`（:475）相同的成对 32-bit 交换算法，改为就地写回；调用点已保证 32-bit 对齐，防御分支兜底奇对齐。

**位置 C：新增 `st77916_transmit_pixels_direct()`（:611）**

改动前：无此函数。
改动后（完整）：CS 拉低 → 分块（上限 `ST77916_SPI_SAFE_TRANSFER_PIXELS`=15360 像素，不再受 tx buffer 7200 像素限制）→ 首块带 QIO `0x32` 命令+地址、后续 `SPI_TRANS_VARIABLE_CMD/ADDR/DUMMY` 零位宽续传 → ≥2048B 走 `spi_device_transmit`、否则 polling → 每 8 块 `taskYIELD()` → CS 拉高。与 `spi_write_pixels_strided` 的传输循环一致，**唯一区别是不经过 `s_tx_buffer` 拷贝，直接从调用方缓冲发送**。
依据：LVGL flush 场景每条带 7200 像素单次事务即可完成；chunk 起始地址始终 4 字节对齐（首地址已校验对齐 + 前续块均为偶数像素数）。

**位置 D：新增公共 API `display_write_region_pixels_swapped_inplace()`（:1379，`#else` 之前）**

改动前：无此函数；flush 未裁剪路径调用 `display_write_region_pixels()`（纯拷贝路径）。
改动后（核心逻辑）：
```c
esp_err_t display_write_region_pixels_swapped_inplace(
    int16_t x, int16_t y, int16_t w, int16_t h,
    uint16_t *pixels, size_t pixel_count) {
    /* 与 display_write_region_pixels 相同的边界/状态校验 ... */
    ESP_RETURN_ON_ERROR(st77916_set_addr_window(...), TAG, "set inplace window failed");
    if (esp_ptr_dma_capable(pixels) &&
        (((uintptr_t)pixels) & (sizeof(uint32_t) - 1U)) == 0U) {
        swap_pixels_inplace(pixels, pixel_count);
        return st77916_transmit_pixels_direct(pixels, pixel_count);
    }
    return spi_write_pixels(pixels, pixel_count);   /* PSRAM/奇对齐回退拷贝路径 */
}
```
依据与安全性：
- **原地改写 px_map 不与 LVGL 渲染竞争**：异步 flush 流水线的槽位令牌保证 draw buffer 在传输完成前归 flush 任务独有（LVGL 在 `flush_wait_cb` 阻塞等 token，`nuwax_lvgl_port.c:710-729`）；双缓冲时 LVGL 渲染的是另一块。
- **快路径条件**：`esp_ptr_dma_capable`（内部 RAM；S3 内部 DRAM 无缓存一致性问题）+ 4 字节对齐。PSRAM draw buffer（低内存降级）与奇数 x 起始的脏区自动回退原拷贝路径——回退分支与改动前行为逐字节一致。
- flush_filter（控制中心合成冻结表情）在交换之前于 flush worker 内写入 px_map，顺序不变。

**位置 E：stub（:1512，`#else` 禁用构建分支）**：新增同名 stub 返回 `ESP_ERR_NOT_SUPPORTED`，与其他 stub 一致。

### 改动 2：display.h 新增声明（:45-54）

改动前：仅声明 `display_write_region_pixels` 与 `display_write_region_pixels_strided`。
改动后：追加：

```c
esp_err_t display_write_region_pixels_swapped_inplace(
```

### 改动 3：nuwax_lvgl_port.c flush 快路径接入（:490-520）

改动前（`lvgl_flush_write_job` 未裁剪分支）：
```c
return display_write_region_pixels((int16_t)job->clip_x1, ... ,
                                   src,
                                   (size_t)job->clip_w * (size_t)job->clip_h);
```
改动后：
```c
return display_write_region_pixels_swapped_inplace(
    (int16_t)job->clip_x1, (int16_t)job->clip_y1,
    (int16_t)job->clip_w, (int16_t)job->clip_h,
    (uint16_t *)src, (size_t)job->clip_w * (size_t)job->clip_h);
```
依据：该分支即"区域未裁剪、px_map 即整块连续区域"的快路径场景（等价性检查 `clip == src` 原样保留）；`(uint16_t *)src` 去常量化与既有 flush_filter 调用（:928 已将 px_map 传为可变指针）先例一致。**裁剪分支的 `display_write_region_pixels_strided` 调用原样保留**（host check 断言依赖其存在与顺序）。

### 4.4 实测结果（2026-09-17，perf 遥测，72 窗口 × 2s，休眠表情 idle 场景）

| 指标 | 改前基线 | 预期 | 实测 | 判定 |
|---|---|---|---|---|
| flush avg_us | ~1600µs | ~700µs | **676–832µs（均值 ≈750µs）** | ✅ 2.1 倍，命中预测带（0.36ms 线时间 + ~0.35ms CPU） |

遗留观察项：
1. **flush 尖刺 7.2–10.2ms**（约每 30–60s 一次）：帧预算（25ms）内，暂不阻塞；疑似与逐秒时钟刷新较大脏区或 flash 写（cache 禁用）交织有关；
2. **单次 96ms handler 长尾**（24 分钟 1 次，over33=3）：最可疑为 NVS/flash 写期间 cache 禁用的全局停摆，需加桩定位；
3. **internal_min=51 B**：内部堆历史最低水位持续创新低（571→115→51），PSRAM 侧稳定；内部 RAM 峰值治理在性能审计中的优先级应上调；
4. 表情**过渡期** 25–31fps 的瓶颈在 v4 解码耗时（24–36ms，超 60% 帧预算），与显示驱动无关——列为下一优化专题。
