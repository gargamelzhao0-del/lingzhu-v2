# 充电停留在 93% 的诊断

本次只增加设备串口诊断，不修改充电判定、满电映射、电量计配置、UI 或实体 LED。

## 采集方式

烧录包含本次修改的固件后，保留开机日志，并在 USB 插着、电量停滞时连续记录至少 10 分钟。记录当时是待机、会议/监控还是播放状态，以及界面显示“充电93%”还是“电量93%”。不必为了取得首次采样而反复重启设备。

筛选 `battery_service: charge diag`。首次采样、充电/满电/有效性等状态变化会打印；状态稳定时每 30 秒到期，在下一个采样点打印（当前 8 秒采样周期下约每 32 秒一条）。I2C 总线统计仍保留。

## 字段

| 字段 | 含义 |
| --- | --- |
| `reason` | `first` 首次，`state_change` 状态变化，`periodic` 定期 |
| `valid / stale / telemetry_valid` | 产品采样有效性、数据是否过期、本次电量遥测是否完整 |
| `age_ms` | 电量采样时间距今；`-1` 表示没有可用时间戳 |
| `soc / display` | 原始 SOC 和设备服务输出的显示百分比 |
| `voltage / current` | 电量计电压和有符号瞬时电流；电流正值表示充电方向 |
| `avg_current / avg_valid` | 电池服务的软件平滑电流及其有效性，不是芯片 AverageCurrent 寄存器 |
| `remaining / fcc / design` | 剩余容量、满充容量、设计容量，单位 mAh |
| `temp` | 电量计温度读数，不能未经配置核验就视为电芯表面温度 |
| `charging / full` | 设备服务的充电和满电状态 |
| `trusted` | 现有容量/CEDV 校验通过，不代表充电结束参数已完成实物校准 |
| `flags_valid / flags` | 本次 BatteryStatus 寄存器是否成功取得及其原始值 |
| `FC / CHGINH / DSG` | 满电、充电禁止、放电状态位；读取无效时输出 `-1`，不能当作未置位 |
| `operation` | 本次 OperationStatus 原始值，与 `flags_valid` 一起看 |
| `power_valid / power_stale / err` | 物理电源采样有效性、时效和本次采样错误 |

当 `telemetry_valid=0`、`valid=0` 或 `stale=1` 时，不应把容量、电流等字段作为完整的新采样；错误路径可能保留旧数据或只取得电压/状态组。

## 判读顺序

1. 先确认采样有效且持续更新，再观察数分钟的电压、电流、剩余容量变化。
2. 正电流且剩余容量增长：仍在充电，结合末段电流判断速度。
3. 电流接近零、接近实际电芯的满充电压而 `FC=0`：进一步读取充电结束参数和检查电量计校准，不能直接把百分比改成 100%。
4. 插着 USB 但电流持续为负：检查电池是否净放电、供电能力及设备负载。
5. 有效采样 `FC=1` 时，现有逻辑应输出 `display=100%`；如果界面不同，再检查运行固件和 UI 同步。

新增日志只使用现有采样，不新增 I2C 访问、不写电量计、不申请动态内存，并在服务锁之外打印。
