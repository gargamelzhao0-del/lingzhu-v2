# 无卡启动与联网状态收敛修复

修订：`20260923-link-convergence-v1`。日期：2026-09-23。

## 依据与根因

输入日志为 `06ca82d5-b7df-4c13-bb1f-c801df2af13b/已粘贴的文本.txt` 和 `5cd03aaf-cb68-4f5c-bac4-bbdf656b05d3/已粘贴的文本.txt`。测试为拔出 SD 卡后启动，上轮 ELF 前缀 `6daa6e046`。

12.416 秒取得 IP，17.746 秒云端应用就绪，17.766 秒进入 SLEEPING，但 UI 保留 `wifi=1`（CONNECTING）和 `cloud=0`（CONNECTED）。154.246 秒仍收到应用 pong，154.486 秒播放器仍播放 asset=6（断联）。这不是网络失败或表情资源丢失：表情包从 Flash 的 emotion_0 分区 mmap 读取。

生产函数主机复现确认：GOT_IP 先于后台 Wi-Fi 任务提交 DONE；主线程看到 connected 提前退出联网恢复循环，未消费 DONE 就进入云端在线循环。只有消费 DONE 才会发布已连接状态，在线循环原本不负责收尾，UI 定期检查又只处理“连接变断开”。因此错误的连接中状态持续压过正常表情。日志也向云端发出了过时的 `connecting/RECOVER` 状态。

无卡启动改变了运行时序，暴露此竞态；代码没有要求插卡才能连接云端或显示正常表情。

## 修改

1. 后台联网仍为 RUNNING 或 DONE 未消费时，主线程保持非阻塞轮询，不凭 GOT_IP 提前跳过完成处理。包括 PENDING 被 worker 抢走的 CAS 竞争窗口。
2. 已在线的控制处理循环也会消费迟到的 DONE，再发送 Wi-Fi 状态报告。取消代次、配网接管及模拟断网栅栏保留，旧结果不能作为新配网结果发布。
3. 尚未执行的 PENDING 任务遇到真实连接已恢复时，取消多余工作并发布一次已连接状态。
4. UI 每两秒核对实际链路，可从“连接中/断开”收敛到“已连接”，也保留真正掉线时的反向收敛。配网期间不抢占显示；不会凭 Wi-Fi 成功改写云端认证状态、会议/监控或对话生命周期。同步修正 RSSI 调用参数求值顺序，先读取再提交。
5. 开机尚未成功准备 SD 介质时，以 5、10、20、40、80、120 秒退避探测；初始化失败已探测过一次，不再立即重复探测。同错误达到上限后不重复输出 spool 层退避告警。介质准备成功后重置退避；之后的介质故障保留 1～30 秒恢复节奏。
6. 诊断 NVS 写入发现空间不足时，不再在 housekeeping 中执行“擦除命名空间、commit、重新写入”的压缩重试。保留现有一次失败后阻止重复持久化的机制，RAM 队列和云端错误上报继续运行。Flash 安全保护及关键配网/NVS 操作主动释放诊断空间的能力保留。

## 实际边界

- 无 SD 卡不能保存离线录音；在线对话和在线会议/监控仍可用。不新增用户可见 SD 状态。
- 未把 SD 超时直接认定为“确定缺卡”，因为缺卡、介质异常和线路异常可能返回同一错误。底层驱动探测失败日志仍可能出现，只是启动重复探测和长期频率降低。
- 首次无卡启动后再插卡，探测可能需要等待当前退避窗口，最长约 120 秒再加调度/挂载时间；不是即时热插拔承诺。正在写卡时拔卡仍可能丢失未落盘数据。
- NVS 满时，尚未持久化的诊断事件在断电后可能丢失；在线 RAM 上报不受此策略阻断。未主动删除 Wi-Fi 凭据、设备密钥或 OTA 元数据。
- 移除的是显式压缩重试链，不能承诺所有 NVS 操作都没有 GC 或 Flash 暂停。
- 本轮保留上轮云端恢复优化、真实断网表情优先级、SD 正式云端路由、音频所有权和 OTA 保护。

## 回归覆盖

`wifi_background_recovery_host_check.c` 执行提取的实际后台联网生产函数，新增 GOT_IP 先于 DONE、已有链路抢先恢复两个用例，保留无 AP 多轮超时、取消代次、配网/模拟断网、显式连接优先级检查。

`tools/test-link-convergence.py` 执行实际 UI 更新函数，验证双向收敛、相同状态不重复发布、IP 变化、配网保护、状态读取失败及读取期间掉线；执行实际 SD 退避函数，验证缺卡、恢复后再次故障和计时回绕；执行实际 NVS 写入代码，验证空间不足不压缩/重试、成功写入、空队列清理、打开/提交失败及句柄关闭。四个破坏性负例（UI 不修复、缺卡高频重试、NVS 重写和联网提前放行）必须被拒绝。测试已接入产品回归入口。

`tools/verify-link-convergence-build.py` 验证固件修订标识、新 NVS 策略标识、旧压缩日志缺失、四个修改源码对应的新编译对象以及 BIN/ELF 身份。它不代替实机验证。

## 烧录后验收

1. 无卡冷启动：启动日志有本修订标识，获取 IP 后出现 `Wi-Fi recovered`，随后状态中 `wifi=0 cloud=0`，休眠时播放器应切换到休眠资源。
2. 无卡下完成唤醒、聆听、播放、摇晃及恢复休眠，不能因错误的网络状态始终显示断联表情。
3. 关闭热点：真正断网时仍显示断联；恢复热点后正常恢复 Wi-Fi 状态、云端状态和表情。重复至少五次。
4. 连网过程中点击配网、改用另一热点、取消配网，确认旧任务结果不覆盖新状态。
5. 正常插卡启动、会议/监控离线恢复及 SD 补传回归；无卡启动再插卡需考虑上述探测延迟。
6. 若诊断 NVS 已满，应出现 `retaining RAM reports without online compaction`，而非旧的 `compacted after no-space; retrying snapshot`。仍需观察长时间运行和电池/USB 配网切换。

本轮只在主机执行测试和构建，不自动烧录。实机稳定性须通过上述回归确认。
