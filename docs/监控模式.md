云端开启监控：
{
  "type": "device_command",
  "command": "set_audio_mode",
  "request_id": "cloud_monitor_open_001",
  "mode": "monitoring",
  "state": "enabled"
}
开启监控本身就代表取消普通对话和停止播报，不再增加 interrupt_current_turn。
设备建立音频会话：
{
  "type": "listen",
  "state": "start",
  "mode": "monitoring",
  "audio_session_id": "monitor_stream_001",
  "request_id": "cloud_monitor_open_001"
}
麦克风、上行队列和会话真正启动后，设备回复：
{
  "type": "device_command_ack",
  "request_id": "cloud_monitor_open_001",
  "command": "set_audio_mode",
  "ok": true,
  "mode": "monitoring",
  "state": "enabled",
  "audio_session_id": "monitor_stream_001"
}
云端关闭监控：
{
  "type": "device_command",
  "command": "set_audio_mode",
  "request_id": "cloud_monitor_close_001",
  "mode": "monitoring",
  "state": "disabled"
}
设备发送带 END 的最后一帧、排空队列，然后发送：
{
  "type": "listen",
  "state": "stop",
  "mode": "monitoring",
  "audio_session_id": "monitor_stream_001"
}
全部资源释放后回复：
{
  "type": "device_command_ack",
  "request_id": "cloud_monitor_close_001",
  "command": "set_audio_mode",
  "ok": true,
  "mode": "monitoring",
  "state": "disabled",
  "audio_session_id": "monitor_stream_001"
}
不使用 revision 和 base_revision。request_id 由云端自行生成，限制为 1 至 47 个字母、数字、点、下划线或短横线，设备原样返回。
失败时统一使用：
{
  "type": "device_command_ack",
  "request_id": "cloud_monitor_open_001",
  "command": "set_audio_mode",
  "ok": false,
  "mode": "monitoring",
  "state": "enabled",
  "error_code": "audio_mode_busy",
  "active_mode": "meeting"
}

最终效果是：云端开启后，设备停止所有播报和普通对话，持续上传 MIC1 的全部 PCM，包括人声、静音、环境声和杂音；不触发 ASR、智能体或 TTS。云端关闭后完整发送尾部音频并恢复普通对话模式。
