# SD 补传直接读取优化（2026-09-15）

## 基线

会话 `meeting_20260915_76f279a7_293895`：9 段、11055 帧、221.10 秒音频全部通过网关 CRC 和序号校验。7,363,782 字节补传耗时 23.175 秒，平均 310.30 KiB/s。六个完整大分段的 SD 读取平均约 2224 ms，校验约 339 ms；唤醒队列未丢块。此次优化不调整采音保护阈值、任务优先级、SD 时钟或协议。

## 修改内容

原批量读取路径经过内部 DMA 缓冲、PSRAM stdio 缓冲、PSRAM 预读窗口，再在窗口上校验。新路径在读取元数据后同步 stdio 状态，将文件描述符定位到开头，使用 POSIX `read` 直接读取顺序数据；元数据读取和正式 v1 补传继续使用原来的 stdio 路径。

每次最多读取 8 KiB。内部内存足够时临时申请 DMA 缓冲，读取及 CRC/帧校验在此缓冲执行，成功后复制到 ACK 保留窗口，再发布可发送的长度。分配前后均检查至少 16 KiB 内部剩余内存；内存不足或申请失败时直接读取到 PSRAM 窗口，由已有 SD DMA 适配器处理。缓冲在本次读取/校验/复制后立即释放，不跨采音压力等待、网络发送或 ACK 等待持有。

任意偏移续传可能处于扇区中间，因此首个不对齐切片使用 PSRAM 适配路径，并将后续读取对齐到扇区边界，避免 FatFS 调整内部目标指针后让 SDK 退化为逐扇区 DMA。

文件仍只有一个读取所有者；发送任务继续通过 release/acquire 获取已验证前缀，两个窗口仍在持久化 ACK 后才能复用。取消后必须等待读取任务退出，才能关闭文件和释放窗口。短读、读取错误、CRC 错误均不提交归档，不删除未确认文件。

## 观察指标

新增日志：

```text
offline replay read path=descriptor internal_bytes=... fallback_bytes=... copy_ms=... allocation_ms=...
offline SD bulk commands=... sectors=... fallback_sectors=... native_calls=... native_sectors=...
```

- `internal_bytes`：在临时内部缓冲执行校验的字节数。
- `fallback_bytes`：在 PSRAM 窗口执行校验的字节数，低内存或不对齐切片会出现，不能当作上传失败。
- `copy_ms`：内部缓冲校验后复制到窗口的耗时；已计入工作让步预算。
- `native_calls/native_sectors`：直接交给 SDK 的内部缓冲扇区调用/扇区计数，不等于 SD 总线实际命令数量。走新路径后原 `bulk commands` 减少不代表少读了音频。

比较时同时查看整轮网关速度、`sd_read_ms`、`validate_ms`、复制耗时、采音压力等待以及 `queue_drops/input_gaps/partial_samples_dropped`。不能把少做的 memcpy 次数直接换算成实测提速比例。
