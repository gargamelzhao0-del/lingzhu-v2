# Nuwax AI Partner 7.0.113 产品上架评估

评估日期：2026-10-09。发布结论：**NO-GO，暂缓上架。**

主要正向功能已经具备，现有自动化回归也能通过。但当前版本存在可复现的唤醒超时恢复缺陷、录音状态失真，以及换绑录音隔离和量产配网安全问题。稳定性尚不能判定为面向消费者可接受。应先修复阻断项，再冻结候选版本完成设备、APP、正式云端联合验收。

此结论来自重新读取当前代码、正式构建配置、发布文件和本轮测试，不以历史聊天结论代替证据。未修改产品源码、配置、协议或设备，未发布 OTA。销售地区、目标年龄和首发承诺尚未确认，因此本评估不构成特定市场的认证或合规放行。

## 必须修复的阻断项

### R1 唤醒问候超时后可能失去自动收音和唤醒能力

**严重度 P1，当前生产函数主机复现成立。**

触发条件：设备从休眠被唤醒，问候请求发送成功，WebSocket 和心跳仍然正常，但云端没有返回问候文本或后续 TTS。并不需要断网或崩溃。

当前流程在首 PCM 前保留 `SLEEPING` 逻辑状态，同时已建立 active/paused 的 awake session 并停止唤醒检测。WAIT_TEXT 15 秒或 WAIT_TTS 30 秒到期后，超时处理清除回合，再调用恢复函数；恢复函数看到 `SLEEPING` 直接返回。空闲补救只从 `IDLE` 恢复收音，而唤醒监督又因 awake session 仍 active 拒绝重启检测。

依据：`main/nuwax_ai_partner_main.c:19136`、`:18933`、`:11880`、`:9112`、`:9541`、`:5496`。本轮抽取真实超时、恢复、空闲和唤醒监督函数，结合真实 awake/turn/terminal 状态模块执行：模拟推进 100 分钟仍 `capture=0`、`wake_rearm=0`；相同超时从 IDLE 开始的对照能恢复收音。**这是主机模拟，不是真机运行了 100 分钟，也不表示设备永久损坏；外部状态变化可能解除它。**

用户影响：偶发一次云端缺失回复后，设备可能一直不听也无法再次用唤醒词唤起。此项单独就足以阻止发布。

关闭条件：明确“等待问候”和“真正休眠”的状态区别，任何问候超时都必须在有界时间内回到可收音或可唤醒状态；覆盖无文本、文本无 TTS、迟到回复、网络仍在线、重复唤醒、菜单和 OTA 并发。保持用户要求的音画时序，不需要提前切换表情。

复现输出：[audio-ux/reproduction-output.txt](audits/2026-10-09-product-release/audio-ux/reproduction-output.txt)。

### R2 录音无法保存却仍显示进行中

**严重度 P1，存储失败路径静态确认，状态发布函数已执行复现。**

无卡或介质未就绪时，归档准入失败，后续帧可能被跳过；满卡或配额耗尽时，writer 丢帧并退避。离线采集可以仅标记不完整后继续运行。另一方面，UI 只要看到保留的离线模式 lease，就把已 disabled 的控制器发布为 ACTIVE，即使此时 `capture=false`。`s_offline_mode_capture_failed` 在当前主文件中只有写入，没有读取来影响该状态。

依据：`main/offline_audio_spool.c:1775`、`:1812`、`:1397`、`:2595`；`main/nuwax_ai_partner_main.c:4372`。已用真实状态同步函数复现“无 capture、有 lease”时会议和监控分别显示 ACTIVE，清除 lease 的对照显示 disabled。

用户影响：用户相信会议仍在录音，事后才发现缺失；设备后台日志和云端错误上报不能替代离线当时的告知。

关闭条件：把“保留恢复意图”与“有效录音”分开；不能保存、持续写失败或缓冲耗尽时，通过现有错误状态或提示告知录音中断，并定义暂停/停止与恢复规则。**不要求开发此前明确暂不开发的 SD 状态面板。**

复现输出：[data-network/false-recording-state.log](audits/2026-10-09-product-release/data-network/false-recording-state.log)。

### R3 换绑后的旧录音没有本地归属隔离

**严重度 P1，当前代码可达路径，未执行跨账号线上攻击或读取。**

条件：账号 A 留有未补传归档，设备解绑并被账号 B 重新绑定。新配置提交会更新 active 云端凭据，正式补传使用新连接遍历同一个 SD 目录。归档头及 begin 请求没有原绑定代际标识。

依据：`main/nuwax_provision_new/nuwax_provision_main.c:1254`、`:2215`；`main/nuwax_provision_new/nuwax_cloud_config.c:246`；`main/offline_audio_spool.c:191`、`:3659`、`:4278`。设备会向新连接提出旧归档，**只有云端接受 begin 后才发送数据**（`:3684`、`:3718`），B 能否看到录音取决于云端额外授权，不能断言已经发生泄露。

关闭条件：定义解绑、换绑、转赠、恢复出厂的数据处理规则；在本地持久记录归档绑定代际并隔离旧数据，补传时校验归属。由设备、APP、服务端共同验证 A→解绑→B 及同账号重新配网，避免把正常换 Wi-Fi 错当换账号或直接误删旧数据。

### R4 正式包仍包含共享开发配网凭据

**严重度 P1，配置、代码及实际 BIN 均已确认。**

正式编译头 `config/sdkconfig.h:427` 开启 `CONFIG_NUWAX_PROVISION_SEC2_DEV_MODE`；`prepare_security2`（`main/nuwax_provision_new/nuwax_provision_main.c:1466`）使用共享开发 PoP。只读检查确认该值实际存在于候选 BIN，报告不披露凭据内容。

Security 2 提供安全会话，不会自动把跨设备共享的持有证明变为逐台身份。攻击前提是设备进入首次或重新配网窗口且对方取得共享值，不能描述为任意时刻远程接管。当前 USB 控制入口也开启，可通过物理串口请求进入配网；它是物理接入面，不能单独当作无条件远程漏洞。

关闭条件：消费者生产配置禁用开发凭据；建立逐台凭据注入、标签/APP 获取和校验流程；明确 USB 工厂入口的产品策略。对正式配置增加构建失败门槛，避免测试配置误入量产包。

### R5 正式配置允许明文云连接且缺少独立固件发布者信任链

**严重度 P1，带明确配置前提的安全路径。**

正式编译头 `config/sdkconfig.h:439` 允许 `ws://`；`main/nuwax_provision_new/nuwax_cloud_config.c:43` 的 URL 校验接受该地址。`main/ws_transport.c:1250` 在握手中携带设备密钥。若实际绑定为明文地址，网络中间人可接触凭据并伪造控制流。此处没有读取设备 NVS，因此**没有断言当前设备实际使用明文地址**。

OTA 有 epoch 准入、HTTPS 下载和 SHA256 校验，并非完全没有鉴权。但控制来源若已被冒充，同一消息提供的 URL 和摘要不能单独证明发布者身份；当前候选关闭签名应用验证、Secure Boot 和 Flash Encryption。依据：`main/nuwax_ai_partner_main.c:12171`；`main/nuwax_ota_new/nuwax_ota_transport.c:664`；正式配置 `tmp/sdkconfig.sd-replay-formal:801` 起。

关闭条件：正式设备与 APP 强制 WSS，验证现存绑定迁移；落实签名、密钥托管和设备信任链，并按威胁模型处理 NVS、Flash 和调试口。不可把开启 eFuse 当普通 OTA 参数直接试烧。

Espressif 的 [ESP-IDF 6.0 安全指南](https://docs.espressif.com/projects/esp-idf/en/v6.0/esp32s3/security/security.html)建议生产设备启用 Secure Boot、保护机密存储，并对外部通信使用 TLS。这里用作工程发布基线，不是特定地区法律结论。

### R6 量产身份与可整体擦除的用户 NVS 混放

**严重度 P2，切换量产配网前必须关闭的组合缺陷。**

关闭 DEV 后，Security 2 从默认 NVS 的 `nuwax_factory` namespace 读取工厂盐和 verifier（`main/nuwax_provision_new/nuwax_provision_main.c:1496`）。但启动在 `NO_FREE_PAGES` 或 `NEW_VERSION_FOUND` 时执行整区 `nvs_flash_erase()`（`main/nuwax_ai_partner_main.c:33168`）。当前分区表只有一块普通 NVS。

结果：一旦走该恢复分支，不可重建的逐台工厂身份会随用户数据一起消失，后续配网失败。当前开发模式不依赖这份工厂数据，不能把它误报成现有每台设备都会失败。

关闭条件：隔离工厂身份与可恢复用户状态，明确 NVS 迁移/故障策略，并验证配网身份在升级回滚、用户重置、故障恢复后仍可用。

## 其他明确问题与硬件边界

问候播放期间屏幕长按取消不一致，列为 P2：首 PCM 后逻辑状态为 LISTENING，`main/app_shell.c:1656` 的取消只接受 THINKING/SPEAKING；正式配置关闭 touch wake，因此该状态返回 NONE。真实函数主机执行已确认 SPEAKING→CANCEL、LISTENING→NONE。应按实际播放所有者决定是否允许取消，不必修改已约定的问候表情设计。没有把半双工本身判成缺陷。

低电量、温度与充电要区分“显示”和“保护”：`main/board/bq27220_driver.c:825` 按净电流和 full 标记判断充电；`main/board/battery_service.c:296` 发布电量和低压状态；`main/nuwax_ai_partner_main.c:1305` 的 listener 更新灯和 UI。没有发现此链路在电池耗尽前触发优雅停录/保存/关机。`nuwax_battery_compute_insights` 中虽有温度告警计算，当前生产代码未发现调用者。**不能据此认定硬件没有保护或充电不安全**，但必须用充电芯片、电芯、保护板和样机测试证明实际边界。

SD 重启恢复有实质保护：writer 定期同步，`.part` 会保留完整记录前缀、截断半记录并标为 incomplete，不可恢复文件保留隔离。尚未写入 SD 的 RAM 数据仍会在断电时丢失。因此不能说“整场一定丢”，也不能承诺“掉电零损失”或“最多只丢两秒”。应验证低电停录策略和突发断电各自的尾部损失。

共享 I2C 当前已经有串行化总线 reset 和恢复统计；旧文档中“完全没有总线恢复”的结论不能沿用。实际 SDA/SCL 拉低恢复、温升、低压、大音量和充电负载仍属于硬件验收。

## 稳定性证据达到什么程度

本轮 7 组回归均退出 0：产品、对话、会议、监控、离线录音、配网、Wi-Fi 恢复。另跑充电灯、电池历史、充电诊断、菜单合成、显示缓冲所有权 5 组检查，也全部通过；20 项构建产物检查全部通过。

这些结果确认了已覆盖条件下的逻辑、边界和构建一致性。新故障复现同时证明：**现有 PASS 没有覆盖整个产品状态组合。** 本轮没有把测试数量换算成稳定性百分比，也没有用代码审查代替真机长期运行。

有旧版八小时测试证据，不应抹去：`tmp/eight-hour-final-analysis.json` 记录 2026-09-16 局域网测试网关接收了约 28,800.02 秒离线音频，已收到的帧序号连续；对应会话约 250.37 KiB/s。该材料同时记录 `expectedFrames:null`、`verifiedComplete:false`，没有独立设备采集总量和设备 SD 剩余量闭环，首个在线段标为不完整。它不能证明 7.0.113 在正式云端上完整补传，更不能背书当前 500 KiB/s 目标。

正式补传还要求服务器协商归档能力；不支持时设备保留本地文件，并非自动证明正式后台已实现。需要当前版本服务器提交记录、APP 可见结果和设备采集/删除记录对账。

仓库长稳门禁默认要求 72 小时、内部内存最低 16 KiB、最大 DMA 连续块至少 8 KiB，并区分硬丢帧与需解释的超时/partial read。没有找到候选 SHA 对应的完整通过材料；高 uptime 日志片段只能说明设备在某一时刻仍运行，不能证明其间没有功能卡死或静默丢数据。

## 建议采用的产品验收矩阵

下面是建议建立的验收方案，不是声称已经达标，也不是法规指定数值。最终数值应与产品承诺、网络条件和硬件规格绑定。

| 领域 | 建议样本与场景 | 放行标准 |
| --- | --- | --- |
| 多机长稳 | 5–10 台量产候选板，至少 72 小时混合运行；包含电池/外电、录音、播报、菜单、Wi-Fi、BLE、OTA 交接 | 零非预期重启、无法自恢复卡死、静默录音丢失；内存无持续下降；日志连续。无故障的小样本仍不能推导全量寿命 |
| 唤醒准确性 | 多人、多距离、轻声/正常音量；安静与电视/多人讨论分别记录真实口令和背景总时长 | 分别统计唤醒成功率、每设备小时误触发率、P95 响应延迟；不能用单个模型分数或“感觉不错”验收 |
| 可讨论的唤醒目标 | 固定测试距离/声压后，1 米正常说话成功率≥95%；背景误触发目标≤1次/24设备小时 | 这些是拟议目标，需样本统计支持；问候首音频延迟与本地检测耗时分开计算 |
| 云端失败恢复 | 保持心跳，丢弃问候文本/TTS；迟到、重复、乱序、断流、取消丢失各测试 | 所有路径在定义的超时后可继续使用，无需重启；既不误播旧回合，也不永久停止唤醒 |
| 配网与换绑 | Android/iOS 真 APP，错密码、弱网、断电、取消、重复绑定、A→B、原账号换 Wi-Fi | 无半提交状态；可恢复；身份正确；旧数据不会跨账号暴露 |
| 会议与监控 | 正式云端开启、停止、暂停、反复断网恢复；校验 request_id 与 audio_session_id、APP/设备开关 | 设备/APP/后台一致；用户停止后不被旧命令重新打开；完整音频可按会话重建 |
| 八小时离线 | 当前候选连续采集约 8 小时，含已有积压、接近满卡、慢卡 | 设备采集总量、序号、持久化总量、服务端唯一帧、commit/ACK 和剩余 SD 文件逐项对账；任何缺失均明确标记 |
| 补传速度 | 固定 AP、RSSI、卡型、服务器、模式并区分空闲与交互并发 | 若承诺 500 KiB/s，按约定有效字节口径测整场到持久化完成的平均速率，同时满足无丢失和交互指标；不能拿瞬时峰值代替 |
| 断电与 OTA | 下载、写入、切槽、首次启动、确认前后分别断电；配网/NVS 提交中断 | 能进入有效新旧镜像；身份与用户配置保留；录音恢复前缀可说明；无永久失联 |
| 电源与充电 | 标定电芯与保护方案，测充放电、温升、低电大音量、充电加补传、拔插 USB | 指标符合硬件规格；验证软硬件保护分工，关机/录音/OTA 的电量策略不靠百分比猜测 |
| 出厂及售后 | 每台身份、分区、模型/表情资源、全量镜像、测试记录和返修方案 | 不能仅交付应用 OTA；现场可追溯、可恢复，私密数据处理明确 |
