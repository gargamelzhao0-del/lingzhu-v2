# 灵珠工程全面复核与剩余风险

日期：2026-09-26。用户暂不能烧录，本轮不修改生产业务代码、不烧录；新增边界实验工具、证据归档并更新计划。

## 1. 结论与证据边界

现有主机回归未发现新的正常路径回退，但仍有两个可重复验证的边界缺口：上传任务清理可以被健康心跳无限延后；浅层宽 JSON 缺少节点/内存总预算。这不等于设备已经发生相应故障，也不等于本轮确认工程没有其他问题。

审查围绕启动、联网配网、对话、音频所有权、会议/监控、SD、OTA、显示、传感器、电源和维护路径展开。当前 main 下 449 个 C/H 文件建立了哈希清单（包含主机检查和归档文件），并非逐行审计全部文件。主协调文件约 35,099 行，重点复核状态切换、资源释放和异常入口。

主机实验可验证代码条件和模拟时序，不能替代真实 FreeRTOS 调度、内存布局、射频、SD、供电及云端联调。实机尚未验证的新修复继续保留待验收状态。

## 2. 优先问题

### R1 / W05 / AU05：心跳正常不等于上传任务有进展

依据：`main/conversation/audio_uplink.c` 中 reaper 等待循环。取消宽限约 250ms，最终兜底约 90s，但关闭连接和最终兜底均受 `!heartbeat_healthy` 条件控制。发送阶段信息已用于诊断，却没有作为停止进展的恢复判据。

本轮直接提取生产等待循环，以模拟 RTOS 时间和连接状态运行，固定发送任务始终未完成：

| 注入条件 | 模拟时间 | 关闭连接次数 | 最终重启兜底次数 |
| --- | ---: | ---: | ---: |
| 心跳不健康 | 90,100ms | 1 | 1 |
| 心跳健康 | 100,000ms | 0 | 0 |

因此，条件性缺口真实存在：如果发送任务未退出而心跳仍正常，清理会反复通知并持续占用上传 owner，可能阻碍后续上传。实验主动注入了发送任务停滞，不代表已证明实际设备会进入该状态；也不是设备发生了 100 秒卡顿的测量。

建议：以实际发送/退出进展及阶段预算决定升级恢复，保留旧连接 epoch 校验；禁止释放活任务仍引用的缓冲，禁止用强制删任务掩盖所有权问题。先补健康心跳下停滞、慢但有进展、新旧 epoch 交叉、退出临界竞争四类回归，再实施修复。预计改善异常回收上界，正常对话不应受到影响。主要新增风险是误判慢链路，必须通过进展判据和分阶段预算控制。

### R2 / W03：JSON 深度已受控，总节点预算仍缺失

依据：`main/ws_transport.c` 文本载荷上限 16KiB；`main/session_protocol.c` 校验及后续处理会解析 JSON；配置已限制 cJSON 嵌套深度为 32。主接收入口还会先交给 OTA 处理器，不能仅在后面的会话校验器增加预算。

使用真实 cJSON 和生产会话校验代码，构造 pong 中未知字段携带 8,000 个元素的平数组：

- 文本 16,025 字节，当前校验接受。
- 主机 cJSON 节点大小 64 字节，解析峰值分配 512,213 字节（约 500.2KiB）。
- 统计分配次数 16,006，删除后存活分配为 0；未发现该实验存在内存泄漏。

这说明宽数组能绕过深度约束，产生较高瞬时堆和分配开销。ESP32 的结构大小和分配器不同，不能把主机峰值直接当作设备测量值。多处重复解析增加累计工作，也不能直接相乘为同时占用峰值。本轮未证明未经授权的外部攻击路径。

建议：在所有业务解析器之前统一实施有界扫描，限制节点、容器元素和必要字符串预算，并验证实际最大合法 hello、OTA、设备命令及未来扩展字段。不能简单降低整帧长度或禁止所有未知字段。预计降低异常报文瞬时资源压力；新增风险是误拒合法大报文，需要协议样本回归和明确拒绝原因。

### R3 / W04：同步持久化仍可能拉长主循环延迟

依据：主程序 `service_idle_error_report_persistence` 在空闲准入检查后同步调用持久化；`main/device_error_report.c` 的首次 `nvs_set_blob`、`nvs_commit` 仍是同步调用。

现有代码已在存储阻塞后保留 RAM 状态并阻止重复写入，也已避免在线满空间压缩，因此不是持续紧循环写 NVS。此前日志有一次约 656ms 持久化耗时，属于已有实机证据；停止事件约 373ms 排队不能仅凭相邻日志归咎于 NVS。

建议先补主循环任务排队与持久化时序关联，再考虑独立维护任务，以不可变快照、版本号、Flash 操作隔离和电源/OTA 优先级维护一致性。不可简单把现有函数搬到线程，也不应清空诊断 NVS 作为常规修复。预期改善异常维护时尾延迟，不承诺提高持续渲染帧率。

### R4 / W02：兼容配置仍需发布前决策

有效配置仍保留开发配网、允许不加密 WS、USB 配网控制等兼容入口，未启用完整的安全启动/Flash 加密方案。允许 WS 不表示所有当前连接都使用明文；正式构建文件名也不代表量产安全验收。

用户明确要求先保留兼容性，本轮不关闭这些开关。后续应先确认 APP/云端 WSS、每台独立凭据、工厂烧录和回退能力，再设计迁移。该项不同于可直接无影响修复的普通逻辑 bug。
