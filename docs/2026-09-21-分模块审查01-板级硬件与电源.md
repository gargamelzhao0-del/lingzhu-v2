## 2. 板级资源与执行链

有效配置核对自 `C:/tmp/nuwax-shake-fix-20260921/config/sdkconfig.h`；该目录是已有冻结固件，本轮未修改。当前选择 `NUWAX_BOARD_ESP_VOCAT_V1_0`，板名代码为 Miaopan 2.0，部分符号仍沿用 ESP-VoCat 名称。

| 资源 | 当前代码分配 | 主要所有者 |

| PG2 保电 / SW3 按键 | GPIO7 高有效 / GPIO16 低有效 | bootloader、power_ctrl |
| 共享 I²C | SCL1、SDA2 | i2c_bus_manager |

| 功放 / 背光 | GPIO4 / GPIO3 | 音频板 / display；关机直接置灭 |
| SD | CLK48、CMD45、D0 47 | sd_card_driver / offline_audio |
| 可选 4G 电源 | GPIO15 | 启动时主动关闭 |

引脚依据：`main/board/esp_vocat_v1_0_pins.h`。本轮未对实物 PCB、上下拉电阻、波形和电芯型号作独立验证；不得由启用内部 I²C 上拉推断板上没有外部上拉。

启动链：bootloader 关闭背光并提前拉高 PG2 → `app_main:32929` 申请 OTA 启动关机保护 → `nuwax_power_ctrl_init:572` 处理关机标记并启动按键任务 → 业务状态初始化完成后 `app_main:33288` 注册按键语义回调。

普通关机链：按键消抖后持续 3 秒 → 原子事件邮箱 → 主 owner 停止模式/录音、收敛 sleep 事务、停止唤醒 MIC、等待扬声器 → 再检查保护 owner → `commit_shutdown(false)` → PA/背光关闭 → 20ms 静音间隔 → 释放 PG2 / 深睡眠。

紧急关机：持续至少 5 秒后**松手**，按键任务调用强制关机，不等待应用退出。这是 `Kconfig.projbuild:1767` 明示的应急设计，不能误报为 OTA 关机保护失效；它也不能承诺录音尾部或正在进行的持久化安全。

## 3. 已确认有效的保护

1. `nuwax_power_ctrl.c:323` 将关机 claim 和 inhibit owner 放在同一个原子字中，普通关机与新保护 owner 的争用有原子裁决；不是先检查后无条件掉电。
2. `nuwax_power_ctrl.c:372` 区分关机时按键仍按住和已释放。USB 维持供电时先等松手，再等下一次按下，避免同一次长按立即唤醒。
3. `i2c_bus_manager.c:239` 在 reset 前取得交易屏障；电量计、IMU、触摸及 codec 包装均使用共享保护。`vocat_audio_board.c:138/159/205/217` 包住读、写、创建、删除控制对象。本轮没有确认 codec 绕过该屏障。
4. 本地 IDF 的 `esp_driver_i2c/i2c_master.c:1240` 显式 reset 不取得普通交易的 `bus_lock_mux`；因此不能因驱动普通传输有锁而删掉应用侧 reset 屏障。
5. 电量样本区分有效、过期和 SOC 可信；采样失败保留旧读数，OTA 会拒绝过期样本。电池不存在也没有被误当作 USB 稳定供电的证明（`battery_service.c:169`）。
6. BQ27220 配置验证失败时尝试恢复正常封印状态；无法确认恢复则拒绝启动。FCC 允许合理学习范围，当前代码并不是每次开机都无条件把 FCC 重置成 1200mAh（`bq27220_driver.c:483`）。

## 4. 问题、触发条件和建议

### BP01：OTA 未区分可读电量与可信电量

依据：

- `battery_service.c:203` 的 `sample_valid` 不要求配置匹配或 profile_verified；`soc_trusted` 在 205 行另行计算。
- `bq27220_driver.c:666` 允许配置验证未通过但安全状态已恢复时继续标准遥测。
- `nuwax_ota_device.c:757` 的升级前检查，以及 `nuwax_ai_partner_main.c:15489` 的启动健康检查，均只传入 valid、low、percent 等字段，没有传入 soc_trusted。
- `nuwax_ota_power_policy.h:12` 没有可信度参数。

探针使用实际生产策略头文件：SOC 不可信、显示百分比 60%、电压 3650mV、样本有效且未过期时，低电策略返回 false，OTA 策略返回 ALLOWED。见 `audits/2026-09-21/board-ota-untrusted-probe.log`。

这是准入缺口的复现，**不是“3650mV 一定无法升级”的证明**，也没有测得真实剩余容量。相反方向亦可能发生：不可信百分比过低导致不必要地拒绝升级。

建议：共享一个电源判定对象，包含样本新鲜度、SOC 可信度、独立有效电压及可验证的外部供电证据。未知电量采用明确的等待/拒绝策略；不要仅因 charging=true 就认定供电足够。修改时同步核对“新升级准入”和“首次启动确认”，避免引入无休止等待或回滚循环。

验收：可信/不可信 SOC × 低/正常电压 × 新鲜/过期 × 有/无可验证外部供电的矩阵；断网首次启动和 rollback 单独回归。

### BP02：普通关机未等待补传退出

依据：`nuwax_ai_partner_main.c:7034–7117` 检查录音、模式、唤醒、扬声器和电源保护，但未检查或取消正式补传。`nuwax_offline_audio_is_active()`（`offline_audio_spool.c:2766`）只读取归档 active，不代表 replay worker 已退出。

正式补传有独立的 running 状态和取消 API（`offline_audio_spool.c:4249/4255`）。主程序目前在 WebSocket 断开清理处调用取消（34910 行），普通关机不必先经历该路径。补传收到 commit ACK 后仍会 `remove(path)` 更新文件系统（3772 行）。

触发：设备休眠但后台仍在补传，用户正常长按关机；或停止会议后后台补传仍在收尾。关机可在补传持有文件、发送数据或删文件期间释放 PG2。

代码确认的是缺少退出屏障。已有 commit ACK 才删除的规则仍有效，不能把它说成“未上传就删除”；具体 FAT 损坏、重复补传或数据丢失必须掉电测试确认。

建议：关机请求先建立禁止新补传的门禁，按连接 epoch 请求取消；由 owner 分步等待 worker 退出及存储写操作完成，再进入硬件关机。不要在高优先级按键任务中等网络或文件系统。对已有录音停止、文件尾部封存、诊断/NVS 写入统一列出 barrier 清单。紧急关机继续是有明确数据风险的独立兜底。

验收：分别在读取、等待 chunk ACK、等待 commit ACK、ACK 后删除、录音封存时长按关机；重启对账，允许幂等重试，禁止误删和目录不可恢复。

### BP03：低电处置缺少业务闭环

依据：`battery_service.c:283–284` 发布 low/hard_low_voltage；`nuwax_ai_partner_main.c:1355` 的监听回调更新 UI；OTA 消费 low。项目搜索未找到 hard_low_voltage 驱动录音停止或关机的调用链。

因此现状是低电提示和升级门禁，不是完整的电量耗尽保护。长时会议或补传期间持续耗电，软件没有在电源不足前统一封存录音并有序退出的路径。电池保护板可能有硬件保护，但它不等于文件落盘保护，本轮没有测其阈值。

建议：先定义低电提醒、限制高负载、临界收尾三个阶段；临界状态进入 owner 事务，停止接纳新业务，封存 SD 并有序关机。阈值、连续样本数、充电恢复条件需结合负载压降和实测供电余量决定，不能直接把现有 3400mV 告警阈值当成关机阈值。

验收：纯电池录音、Wi-Fi 发射和大音量组合；短暂电压跌落与持续低电；临界时插拔 USB；卡写入慢和 OTA 活动期间的优先级。

### BP04：硬低压判断被电量模型有效性阻断

依据：`battery_service.c:194–204` 将电压、温度、FCC、剩余容量、初始化状态一起决定 sample_valid；只有 sample_valid 时才调用低电策略（228 行）。

例如电池存在、电压读到 3300mV，但 FCC 读数超出允许区间，整份样本无效，新硬低压判定不会执行，而是保留之前的 low 状态。已有 pure policy 的“硬电压覆盖乐观 SOC”测试不能覆盖这层 service gating。

建议：拆分电压有效性、模型有效性、SOC 可信度和整体业务准入，独立评估经过范围与连续性验证的低压读数。不能简单删除 plausibility 校验，否则 I²C 异常零值会被误当成真实低电。与 BP03 一起设计故障退化行为。

验收：使用生产 service 判定路径注入“电压正常/FCC 异常”“电压低/FCC 异常”“0mV/总线错误”，分别证明不会漏掉有效电压风险或误触发关机。

### BP05：容量配置与固定 CEDV 表不一致

依据：`Kconfig.projbuild:89` 允许容量 100–20000mAh；驱动记录调用者 design_capacity（`bq27220_driver.c:652`），但实际校验、必要时写入的 `s_vendor_profile:77` 是固定 1200mAh 的整套参数。服务再用配置容量判定可信（`battery_service.c:190`）。

默认 1200mAh 没有这个配置冲突。风险在未来换电芯/换板，或仅修改 menuconfig 容量时出现：实际写表仍为 1200，服务却期待另一个容量，SOC 长期不可信，且错误型号的表可能被写入。

建议：当前型号明确限制为经过验证的 1200mAh profile；后续引入 board/cell/profile ID 与版本。不能仅将表内几个 1200 替换成变量来支持任意电芯。新增电芯须提交整套测定参数及兼容验证。

验收：非支持容量必须在构建/初始化时清晰拒绝，并证明拒绝前没有写入电量计配置。

### BP06：摸头间隙配置不生效

依据：`Kconfig.projbuild:3606` 承诺短暂失活保留同一次摸头；`board_gpio_inputs.c:323` 保存 gap_tolerance_ms；轮询任务没有读取它，在已消抖的释放处立即清零会话（156–168 行）。`head_touch_control.c:285` 仍打印该容忍参数。

因此同样的摸头中间出现超过释放消抖窗口的短暂失活，会被拆成两次，需要重新计时；调整该参数不会改变行为。是否应容忍间隙是产品决策，当前 Kconfig 又要求“连续有效”，两处契约也应统一。

建议：若保留严格连续触摸，删除/弃用失效配置与日志；若要容忍脉冲，明确累计有效时间还是会话总时间，且释放期间不能迟发触发、长时间粘连必须过期。不要把 750ms 配置直接恢复而改变误触防护。

### BP07：生命周期接口尚未支持并发调用

`battery_service_stop:509` 在等待停止、删除任务阶段释放服务锁；两个停止调用者可能竞争单个 stopped 信号并产生超时，任务句柄读取/通知也缺少生命周期互斥。`board_gpio_inputs_init:224` 只有 initialized load 而无初始化 claim；并发首次调用可能创建重复任务。电量计 init 用 s_init_lock，读取/deinit 用 s_bq.lock，二者不是统一的生命周期锁。

这是接口能力边界，当前产品主路径主要由唯一电池任务调用电量计，GPIO 在启动时初始化，未发现产品路径必然并发调用，也未在设备复现 use-after-free。优先明确唯一 owner 和接口前置条件；确需运行时启停，再增加 STOPPING 状态、世代号与单一回收者，避免先增加一组可能死锁的锁。

### BP08：优化应先测量 I²C 尾延迟

当前电池采样周期 8 秒，错误退避 5→10→20→40→60 秒；过期边界是 3 个周期，即超过 24 秒。GPIO 输入约每 10ms 轮询，电源键 20ms 轮询。配置 tick=100Hz；不应通过把延时常量减成 1–4ms 来假设会获得更细调度。

电量计逐次传输取得共享锁，未把整个 profile 验证期间的全部等待包在总线锁内，这一点应保留。触摸故障则会重试并显式恢复共享总线；仅凭读写超时配置不能判断一次 UI 卡顿究竟来自锁等待、总线传输还是日志输出。

建议增加低开销累计指标：设备类型、lock_wait、transfer、reset 时间、错误阶段、最长连续失败与恢复次数；按窗口输出而非每次交易打印。确认正常路径低成本之后，再评估缩减重复配置读取、分步初始化或改变采样策略。不得仅提频、提任务优先级或移除交易屏障。

## 6. 后续实施顺序与验收

1. **先补针对缺口的可执行测试。** 覆盖服务级电压有效性、SOC 可信度准入、补传中关机；现有源码正则检查不能代替事件时序测试。

4. **实现临界电量处理。** 在实机测得电压/负载关系后定阈值；共用正常关机协调器，不另写一条直接掉电路径。

## 7. 二次复核：具体修复设计与前后效果

本节是再次核对调用链后的实施设计，尚未修改固件。尤其不能把以下方案理解成已经完成的修复或实测结果。

### 7.1 电池数据与 OTA：不能只增加一个布尔条件

二次复核补充三个关键事实：

1. `bq27220_get_status:707–718` 先读电压，再读其他寄存器，任何后续读取失败都会整次返回错误。即使拆开 service 的 FCC 校验，也不能解决“已经读到电压，却被后续寄存器超时丢弃”的问题。
2. `bq27220_init:666–671` 在 profile 校验失败但安全状态已恢复时，把 initialized 置为 true、profile_verified 置为 false。之后正常遥测成功就不会重新初始化（`battery_service.c:380/400`）。因此简单增加“不可信就拒绝升级”可能把一次临时验证失败变成长期升级不可用。
3. 新升级命令在入队时（`nuwax_ota_device.c:1419`）和实际启动时（861 行）都检查电源；新固件启动健康检查还调用同一电源策略（`nuwax_ai_partner_main.c:15489`）。`process_cloud_ready_event:1588–1624` 遇到非等待错误会回滚，等待超过有效配置的 120000ms 也会回滚。不能无区别地收紧这三种场景。

建议分三层修复：

- **驱动层：分组采样结果。** 在现有 API 之外提供带字段有效位和时间戳的扩展结果，区分电压/电流、状态标志、SOC/容量模型。复用本次已成功读取的数据，不因普通字段失败重读整份，也不把旧状态拼接成新鲜的安全证据。原完整快照接口保留严格错误语义，避免现有调用者误用。
- **服务层：独立形成测量有效、SOC 可信、数据新鲜三个维度。** 电压保护使用新鲜且合理的电压及足够的电池状态证据，模型异常仅降低 SOC 可信度。未知状态不解释成电压正常，也不把 0mV/传输失败解释成真实临界电量。profile 未验证时提供有上限、退避且由单一电池 owner 执行的再验证；OTA/关机期间不进行配置写入。再验证仍失败则保持明确降级，不能伪造可信状态。
- **策略层：分开评估“升级准入”和“运行镜像健康”。** 新升级准入要求可信百分比达到门槛、没有有效低压风险；若没有可验证外部电源，未知电量使用现有 `power_unknown` 拒绝。入队和真正启动都检查。启动健康验证继续要求镜像、音频、云端与必要电源测量通过，但不机械复用“至少 30% 才能启动新升级”；单纯降级的 SOC 不等同于新固件损坏。对电池服务失效、持续没有必要测量的情况保留有界等待和既有失败判定，不能一律放行。

上面的启动确认调整必须覆盖旧固件升级迁移：旧固件可能已经在不可信 SOC 条件下接受了新镜像。不能让新版本仅因新增的百分比可信度门槛而自动回滚。真实临界电压也不能因此被忽略；应交给独立电源处置流程。

预期：正常可信电池下升级行为基本不变；异常 SOC 不再错误放行；临时 profile 验证故障有恢复机会；正常新固件不会仅因升级前后百分比跨过 30% 或 SOC 降级被当作坏固件。最后一项属于拟调整的产品策略，需对应测试验证，并非当前代码已具备。

### 7.2 正常关机：增加持续的准入门禁与分步退出

只调用一次现有 `replay_formal_cancel` 不足够：worker 退出时会清除取消标记（`offline_audio_spool.c:4163`），下一次 start 又会清除它（4227 行）。同时 `storage_busy:2885` 是录音/写入占用的快照，不是禁止新工作的锁，也不能代表补传停止。

建议引入一个小型关机事务，而非改写整个主程序：

`RUNNING → PREPARING → DRAINING → READY_TO_CUT → OFF`

- **PREPARING：** 在电源原子 gate 内新增“准备关机”的状态，与 OTA/配网申请保护原子互斥。不是简单添加一个各任务自行读取的普通 bool，也不是提前复用最终 CLAIMED 位。返回事务代号，用于匹配取消/回退。先占到保护的 OTA 拒绝普通关机；先进入关机的设备拒绝新 OTA/配网/模式启动。
- **DRAINING：** owner 发停止请求，各资源 owner 自行结束。补传建立独立的关机准入门禁，start 与门禁关闭在同一同步协议下裁决；已经启动的 worker 被纳入等待。按 epoch 请求取消并持续检查 running；不在主循环调用长时间同步等待，不用 `vTaskDelete` 强杀网络或文件任务。
- **收尾屏障：** 采集结束、镜像尾部关闭、SD writer 队列与 writer_busy 清零、归档 closing/mirror closers 归零、补传文件已关闭、必要的 Flash 写入退出。检查与禁止新工作必须配套，否则“检查为空后又开始写入”仍有竞争。
- **READY_TO_CUT：** 在资源确认后才调用硬件关机。可以由存储 owner 同步必要元数据/卸载媒体，不能由电源线程与文件写线程同时操作挂载实例。
- **超时：** 普通关机超时不得假装收尾成功后直接断电；记录阻塞资源，按明确策略继续等待或回退，并恢复准入状态。临界电压与紧急长按使用独立优先级，不能为了形式上的“零丢失”无限等待电源耗尽。

普通长按仍为 3 秒触发；之后的实际掉电时间取决于在途写入和发送收尾。关机应等待正在进行的操作退出，**不等待整个历史补传积压上传完**。目前没有实机数据支持承诺固定额外 100ms 或 500ms。

预期：后台上传期间可有序关机，下次开机继续处理未提交归档；commit 已被云端接受但本地保留的归档可幂等重试。正常关机风险下降，紧急长按/拔电的持久化风险仍必须独立测试。

### 7.3 临界电量：先具备可靠采样和收尾能力，再启用自动关机

当前 hard_low_voltage 表示告警判定，不是已验证的关机阈值。建议先完成 7.1/7.2，再引入 `NORMAL / LOW / CRITICAL_PENDING / QUIESCING`，用连续有效样本与恢复滞回确认临界状态。持续时间不能单纯按“取两个样本”决定，因为默认两次采样相隔约 8 秒，而且错误退避会延长检测时间。

接近临界区时可增加独立、有限频率的电压采样，正常区仍保持当前低开销周期；具体频率与阈值用真实电芯在 Wi-Fi、音量、SD 写入组合负载下测得的电源余量确定。检测到不可信样本只进入未知/退化状态，不能以旧高电量继续放行高风险业务。

OTA 活动时由 OTA controller 协作处理：`nuwax_ota_main.h:42` 明示下载/写入可取消，但短暂 VERIFYING 提交阶段不可取消，且必须等 worker-idle 才能确认 abort/传输清理结束。不能在电池回调内直接释放 PG2 或删除 OTA 任务。新的低电协调也需要在运行中订阅电源状态，当前两次升级前检查并不能覆盖整个升级过程。

预期：持续低电时先保存录音并结束业务，减少电源耗尽造成的尾部中断；正常瞬时负载压降不会立即关机。软件无法承诺在已经没有足够储能时完成写卡，阈值验证是启用该能力的前提。

### 7.5 推荐提交顺序及验收门槛

1. **采样有效性 + profile 恢复 + OTA 策略分场景。** 补 service/driver 故障注入，不仅调用 pure policy；模拟后续寄存器失败、错误 FCC、profile 一次失败后恢复，以及新镜像 pending-verify。
2. **正常关机准入 + 后台任务退出。** 交错执行“start 与关机门禁”“commit ACK 与断电”“worker 结束与再次调度”“OTA 申请保护与长按”，证明一个请求不能越过已关闭的准入，也不会强杀资源 owner。
3. **固定电芯配置与输入配置整理。** 非支持电芯在写表前失败；摸头原有短触、连续触摸、超时和冷却行为回归。
4. **临界电量策略与实机标定。** 在可调电源/真实电芯测试得到阈值和收尾余量后启用；覆盖 SD 慢写和 OTA 各阶段。
5. **生命周期加固及指标。** 依据实际调用者需求实施，避免为不存在的并发入口引入大规模锁改动。

验收应分别报告正常业务、异常保护和性能：正常 UI/录音/联网无回退；异常条件有确定结果；关机耗时报告 P50/P95/最大值及阻塞阶段。修复后不再出现某种竞争，要通过对应交错测试和实机日志证明，不能仅以“整机能开机”判定完成。
