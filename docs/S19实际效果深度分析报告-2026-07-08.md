## 三、S19 实际数据流（逐级分析）

```
原始人声 + 设备回声
  │
  ▼
┌─────────────────────────────────────────────┐
│ 第1级：live_aec 核心处理                     │
│ (AFE_TYPE_VC + AFE_MODE_LOW_COST)           │
│ 作用：消除回声，同时衰减人声 50-90%         │
│ 结果：人声衰减，回声大部分消除              │
└─────────────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────────────┐
│ 第2级：residual_cancel（残余消除）           │
│ 作用：AEC 输出中与参考相关的部分再次相减    │
│ 阈值：corr_q15 >= 8192(0.25) 时执行         │
│ 近端保护：corr_q15 < 16384(0.5) 时跳过      │
│ 结果：人声进一步衰减                        │
└─────────────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────────────┐
│ 第3级：nearend_blend（近端混合）             │
│ raw_mix = 0（用户说话时）                   │
│ raw_mix = 0（用户大声说话时）               │
│ 结果：‼️ 人声恢复为 0，被 AEC 衰减的人声    │
│        永久丢失，完全不混回                 │
└─────────────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────────────┐
│ 第4级：dual_restore（双麦近端恢复）         │
│ guard 条件极其严格：                        │
│  - diff avg >= 260 && diff peak >= 900      │
│  - spatial balance <= 22000 + diff >= 320   │
│  - score >= 14000                           │
│  - corr_q15 < 24576(0.75)                   │
│ 结果：实际极少触发，人声恢复几乎为 0        │
└─────────────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────────────┐
│ 第5级：post_blend_residual_cancel（再消除）  │
│ 当 dual_restore 和 floor_restore 都失败时   │
│ 作用：输出与参考相关部分再次相减            │
│ 阈值：corr_q15 >= 12000(0.366) 时执行       │
│ 结果：人声继续衰减                          │
└─────────────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────────────┐
│ 第6级：audio_cleaner softref（第二次消除）   │
│ ⚠️ 在 live_aec 输出上再次做回声消除         │
│ 延迟 360 样本(22.5ms)                       │
│ 线性抵消 + echo gate 衰减                   │
│ 结果：‼️ 人声被彻底消除                      │
└─────────────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────────────┐
│ 第7级：quiet_gate（噪声门）                  │
│ 播放时使用 base 值(avg=90, peak=420)        │
│ AEC 残留回声 (avg≈100-300) 穿透门限        │
│ 结果：残留回声通过，人声已不存在            │
└─────────────────────────────────────────────┘
  │
  ▼
┌─────────────────────────────────────────────┐
│ VAD 播放门控                                 │
│ 门槛：avg >= 650, peak >= 1800              │
│ 评分系统每帧衰减 1 分                       │
│ 结果：衰减后的人声能量可能低于门槛，被丢弃  │
└─────────────────────────────────────────────┘
  │
  ▼
上传至云端
```

## 四、三个现象的根本原因

### 现象1：人声完全被压没 ← 4 个原因叠加

```
人声衰减链（累计效果）:

原始人声能量 (100%)
  → live_aec 核心     ：剩余 10-50%
  → residual_cancel   ：剩余 5-40%
  → nearend_blend(0%) ：剩余 5-40% (无人声恢复)
  → dual_restore(极少) ：剩余 5-40%
  → post_blend_cancel ：剩余 3-30%
  → audio_cleaner softref ：剩余 0-15%
```

| 原因 | 位置 | 说明 |
|------|------|------|
| **🔴 主因** | `NEAREND_RAW_MIX_Q15=0` | AEC 消除回声后，完全不把原始人声混回来。被 AEC 衰减的人声永久丢失 |
| **🔴 主因** | audio_cleaner softref 在 AEC 后二次运行 | 两套独立的回声消除系统在播放时**串行执行**。live_aec 已经消除了回声并衰减了人声，softref 再在残余上做线性抵消，人声被二次消除 |
| **🟡 次因** | 三次残余消除循环 | `residual_cancel` → `post_blend_residual_cancel` → `dual_restore_residual_guard`，无论走哪个分支都有残余消除 |
| **🟡 次因** | `REF_MISSING_ATTENUATE_Q15=2048(6.25%)` | 参考丢失时信号被压到 6.25%，即使双麦恢复最高提升50%，输出仅 3.125% |

**结论：这不是单一参数的问题，而是管线中每一级都在衰减人声，且没有任何一级做了有效恢复。**

### 现象2：设备声存在但较为小声 ← 2 个原因

| 原因 | 说明 |
|------|------|
| AEC 有效 (VC+LOW_COST, ~15-20dB ERLE) | 大部分回声被消除 |
| `quiet_gate` 门限过低 (90/420) | AEC 残留回声 (avg≈100-300) 穿透门限，不被衰减，作为有效信号上传 |

### 现象3：设备声时不时出现尖刺 ← 2 个原因

| 原因 | 说明 |
|------|------|
| **自适应参考搜索阈值过低** (`MIN_CORR_Q15=1500=0.046`) | 几乎任何弱相关都会被当作"最佳偏移"，导致 AEC 使用错误的参考信号。错误参考 → AEC 滤波器发散 → 输出出现未被消除的回声尖刺 |
| **audio_cleaner softref 与 live_aec residual_cancel 双重消除冲突** | 两套独立的系统都在检测 AEC 输出与参考信号的相关性并做线性抵消。当二者检测到同一个残余回声时，双重决策冲突产生瞬态不稳定 |

## 五、当前 vs 预期效果对比

| 场景 | S19 实际效果 | 应达成的目标 |
|------|-------------|------------|
| 播放 + 大音量说话 | 人声被完全压没，几乎听不到 | 人声保留 60-80%，回声消除 |
| 播放 + 正常音量说话 | 人声被压没，VAD 不触发 | 人声保留 50-70%，正常触发 |
| 播放 + 安静说话 | 人声消失 | 人声经衰减后仍可辨识 |
| 设备播报声 | 存在但小声，伴有尖刺 | 被消除或极弱，无尖刺 |

## 六、修正后的优化方案（基于 S19 实际现象）

### P0 — 必须立即做（6项，按优先级排列）

**P0-1：禁止 audio_cleaner softref 在 live_aec 之后二次运行**

| 项 | 内容 |
|----|------|
| 文件 | `main/conversation/audio_cleaner.c` |
| 位置 | `process_softref_echo()` 函数第240行附近 |
| 改动 | 增加 `CONFIG_NUWAX_LIVE_AEC_ENABLE` 守卫：当 live_aec 启用时，`process_softref_echo` 直接 return |
| 原因 | **这是当前最严重的问题。** audio_cleaner 的输入是 live_aec 的输出，在已处理过的信号上再次做线性抵消，导致人声被二次消除。两套 AEC 不应该串行运行 |

**P0-2：开启 nearend_blend 恢复人声**

| 配置项 | 当前值 | 改为 | 含义 |
|--------|-------|------|------|
| `NEAREND_RAW_MIX_Q15` | 0 | **2048** | AEC 输出中混入 6.25% 原始麦克风信号 |
| `STRONG_NEAREND_RAW_MIX_Q15` | 0 | **4096** | 强近端时混入 12.5% 原始麦克风信号 |

| 项 | 内容 |
|----|------|
| 文件 | `sdkconfig` 第1033行、第1036行 |
| 原因 | raw_mix=0 时 `apply_nearend_blend` 第780行直接 return，完全不执行混合。这是被 AEC 衰减的人声**唯一被部分恢复的机会** |

**P0-3：降低残余取消的近端保护阈值**

| 配置项 | 当前值 | 改为 |
|--------|-------|------|
| `RESIDUAL_NEAREND_MIN_CORR_Q15` | 16384(0.5) | **12000(0.366)** |

| 项 | 内容 |
|----|------|
| 文件 | `sdkconfig` 第1045行（或 `live_aec.c` 第94行默认值） |
| 原因 | 当前 16384(0.5) 的门槛意味着 AEC 输出与参考相关性超过 0.5 时才跳过残余取消。调低到 0.366，更多近端人声在低相关性时被保护，不进入残余消除 |

**P0-4：提高自适应参考搜索的最小相关性阈值**

| 配置项 | 当前值 | 改为 |
|--------|-------|------|
| `ADAPTIVE_REF_MIN_CORR_Q15` | 1500(0.046) | **8000(0.244)** |

| 项 | 内容 |
|----|------|
| 文件 | `sdkconfig` 第1028行（或 `live_aec.c` 第128行默认值） |
| 原因 | 1500(0.046) 太低了，几乎任何噪声都会被当作"最佳偏移"。这导致 AEC 频繁切换到错误的参考延迟，滤波器发散产生尖刺。8000(0.244) 要求至少 24.4% 的相关性才切换 |

**P0-5：降低参考丢失时的衰减**

| 配置项 | 当前值 | 改为 |
|--------|-------|------|
| `REF_MISSING_ATTENUATE_Q15` | 2048(6.25%) | **8192(25%)** |

| 项 | 内容 |
|----|------|
| 文件 | `sdkconfig` 第1023行 |
| 原因 | 参考丢失时信号被压到 6.25%，用户说话完全听不见。25% 保留一定衰减但不至于压死人声。有双麦提示时会自动提升到 8192，无提示时 2048 过低 |

**P0-6：提高播放时 quiet_gate 门限**

| 项 | 当前值 | 改为 |
|----|-------|------|
| `quiet_avg` | 90 | **180** |
| `quiet_peak` | 420 | **700** |

| 项 | 内容 |
|----|------|
| 文件 | `main/conversation/audio_cleaner.c` 第506-514行 |
| 原因 | 90/420 的门限对于 AEC 残留回声 (avg≈100-300) 形同虚设。180/700 可以滤除大部分残留回声 |

## 七、改动汇总

| 级别 | 数量 | 涉及文件 | 预估行数 |
|------|------|---------|---------|
| P0 | 6项 | `audio_cleaner.c` + `sdkconfig`（5个值） | ~70行 |
| P1 | 4项 | `nuwax_ai_partner_main.c` | ~30行 |
| P2 | 2项 | `sdkconfig`（2个值） | ~5行 |

**P0 是必须实施的**，解决"人声被完全压没+尖刺"两个严重问题。
P0-1（禁止softref二次运行）是**当前最优先的单一点**，单一改动就能解决最大的过度消除问题。

## 八、实施后预期效果

| 现象 | 当前 (S19) | P0 实施后 |
|------|-----------|----------|
| 人声 | 完全被压没 | 人声保留 40-60%（软参考二次消除被禁止，raw_mix 恢复部分人声） |
