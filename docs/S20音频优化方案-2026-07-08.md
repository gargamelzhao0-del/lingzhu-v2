## 二、S19 问题的真实根因（按优先级）

### 🔴 根因1：audio_cleaner softref 在 live_aec 输出上做二次消除，且线性抵消发生在近端保护之前

**代码路径：** `audio_cleaner.c:291-315`

```
process_softref_echo 执行顺序：
  1. 读取软件参考（第254行）
  2. 检查 ref 是否活跃（第276行）
  3. 检查 speech_protected（第287行）← 这是近端保护
  4. 计算相关性（第295行）
  5. 如果相关且增益非零 → apply_softref_linear_cancel（第315行）← 先抵消
```

**问题：** 第315行的线性抵消发生在先，后续的 nearend_guard（第302行）检查在后。但即使 nearend_guard 跳过了线性抵消，第330行的 echo_gate（衰减至 25%-12.5%）依然可能被执行。结果是 softref 在 live_aec 已经处理过的信号上再次做回声消除，人声被二次衰减。

**S19 数据佐证：** softref_linear=32, softref_gate=217，说明大量帧经过了 softref 处理。

### 🔴 根因2：nearend_blend raw_mix=0，人声被 AEC 压掉后缺少稳定恢复

- `NEAREND_RAW_MIX_Q15=0`
- `STRONG_NEAREND_RAW_MIX_Q15=0`
- 只有 `HINT_STRONG_RAW_MIX_Q15=8192`（25%）在有强双麦提示时有效
- S19 中 `nearend_blend_chunks=16`，触发极少

**问题：** 普通近端和强近端场景下 raw_mix=0，代码直接 return（`live_aec.c:780`）。被 AEC 衰减的人声没有恢复通路。

### 🟡 根因3：双麦信息没有有效转化为人声保护

| 数据 | 值 | 含义 |
|------|-----|------|
| mic2_speech_like_frames | 393 | MIC2 检测到大量语音特征 |
| dual_mic_voice_like | 0 | 但 voice_like 为 0 |

**问题：** MIC2 数据被读取并分析，但分析结果（`dual_mic_features`）没有转化为有效的近端保护信号。`dual_mic_aec_hint` 的 guard 条件过于严格（需要同时满足 MIC1 能量、MIC2 能量、差值、空间平衡等多条件），导致 `nearend_hint` 未被触发 → `nearend_blend` 和 `dual_restore` 都得不到 hint 增强。

### 🟡 根因4：自适应参考搜索可能引入尖刺

`ADAPTIVE_REF_ENABLE=y`，`MIN_CORR_Q15=1500`（0.046）

**问题：** 阈值过低导致几乎任何弱相关都会被当作"最佳偏移"，AEC 可能切换到错误的参考延迟 → 滤波器发散 → 尖刺。但需要更稳定性的约束，不仅仅是抬高阈值。

### ✅ 不是根因（从 S19 数据排除）

| 排除项 | 依据 |
|--------|------|
| 上传丢帧 | sent=786, dropped=0 |
| 参考丢失 | ref_missing=0, ref_missing_attenuated=0 |
| VAD 门控 | 问题出在上传前的音频处理，不是 VAD 判定 |

## 三、S20 优化方案（分步实施，每步可验证）

### Step 1 — softref 在近端保护时跳过线性抵消（关键修复）

**目标：** 保留 softref 对无人场景的设备声抑制，但在 `speech_protected` / `nearend_hint` / `dual_mic_hint` 时提前跳过线性抵消和 echo gate。

**改动：** `main/conversation/audio_cleaner.c` 第287-340行

```c
// 当前逻辑（简化）：
if (speech_protected) {
    cleaner->stats.softref_nearend_guard_frames++;
    return level;  // ← 跳过后续所有处理
}

// 改为：
if (speech_protected) {
    cleaner->stats.softref_nearend_guard_frames++;
    return level;  // speech_protected 时跳过，当前代码已有此逻辑
}
// 重点：进入线性抵消前，增加 nearend_hint 检查
if (cleaner->nearend_hint_active) {
    cleaner->stats.softref_nearend_hint_skip_frames++;
    return level;
}
```

**关键逻辑链：** 主循环 `nuwax_ai_partner_main.c:2952-2975` 已经计算了 `dual_mic_aec_hint_active`，可以在调用 `audio_cleaner_process` 时将 hint 状态传入。cleaner 收到 hint 后跳过 softref 的线性抵消和 echo gate。

**验证：** S19 验收中 `mic2_speech_like=393`，如果传入 hint，softref 应跳过大部分帧的处理。

### Step 2 — 小幅开启 nearend_blend raw_mix

**目标：** 近端恢复从 0 开始小幅开启，安全起步，不把设备播报声混回来。

| 配置项 | 当前值 | 改为 |
|--------|-------|------|
| `NEAREND_RAW_MIX_Q15` | 0 | **1024**（3.125%） |
| `STRONG_NEAREND_RAW_MIX_Q15` | 0 | **2048**（6.25%） |

**理由：**
- 工程师建议从 **1024/2048** 起，而非报告中建议的 2048/4096
- 1024 是代码默认值（`live_aec.c:46`），是一个安全起点
- 强近端 2048 配合 hint 增强可以更有效地恢复人声
- `HINT_STRONG_RAW_MIX_Q15=8192(25%)` 保持不变，作为双麦提示时的强恢复通道

### Step 3 — 给自适应参考加稳定性约束

**目标：** 减少尖刺，但不是简单抬高阈值。

**改动方案：**

**方案 A（推荐）：** 增加"连续确认"约束——自适应参考搜索找到的最佳偏移必须在连续 N 帧（如 3-5 帧）中都被选为最佳，才实际切换。

**方案 B（备选，不改代码只改配置）：** 提高 `MIN_CORR_Q15` 从 1500 到 8000，同时要求新偏移的相关系数必须比当前偏移高至少 `CORR_IMPROVEMENT_THRESHOLD`（例如 2000）。相当于"新偏移必须明显优于当前偏移"。

**代码位置：** `live_aec.c:891-896`
```c
if (metrics.corr_q15 > best_corr) {
    best_corr = metrics.corr_q15;
    best_offset = offset;
    best_copied = copied;
    best_is_probe = true;
}
```
当前逻辑是只要大于就替换。建议改为：
```c
if (metrics.corr_q15 > best_corr + CORR_IMPROVEMENT_THRESHOLD) {
```

### Step 4 — 将双麦 hint 传入 audio_cleaner（配合 Step 1）

**改动：** `nuwax_ai_partner_main.c`

在调用 `nuwax_audio_cleaner_process` 时，将当前帧的 `dual_mic_aec_hint_active` 状态传入 cleaner：

```c
// 当前调用（第3017行附近）：
nuwax_audio_cleaner_process(&audio_cleaner, s_audio_samples, samples_read,
                            playback_active, speech_protect_hint, &clean_result);

// 改为（新增参数或通过 cleaner 状态设置）：
nuwax_audio_cleaner_set_nearend_hint(&audio_cleaner, dual_mic_aec_hint_active);
nuwax_audio_cleaner_process(&audio_cleaner, s_audio_samples, samples_read,
                            playback_active, speech_protect_hint, &clean_result);
```

**`audio_cleaner.c` 新增函数：**
```c
void nuwax_audio_cleaner_set_nearend_hint(nuwax_audio_cleaner_t *cleaner, bool hint) {
    if (cleaner) {
        cleaner->nearend_hint_active = hint;
    }
}
```

### Step 5 — 放宽 dual_mic_aec_hint 的 guard 条件

**目标：** 将 MIC2 的语音特征（S19 中 `mic2_speech_like=393`）转化为实际的 nearend_hint。

**位置：** `nuwax_ai_partner_main.c` 第2928-2950行

当前 `dual_mic_aec_preserve_hint()` 需要同时满足：
1. MIC1 avg>=320 && peak>=1100
2. MIC2 avg>=250 && peak>=800  
3. diff avg>=350 && diff peak>=1000
4. balance <= 28672 或 diff_energy_ratio >= 16384

**放宽建议：** 当 `dual_mic.voice_like` 为 true 时（即使空间条件不完全满足），也产生一个弱 hint（`weak_nearend_hint`），该 hint 至少能触发 `nearend_blend` 的普通混合（而非强混合）。

## 四、S20 实施步骤总表

| 步骤 | 内容 | 涉及文件 | 风险等级 | 验证方式 |
|------|------|---------|---------|---------|
| Step 1 | softref 在 nearend_hint 时跳过线性抵消 | `audio_cleaner.c` | 低 | 对比 S19 验收 WAV，人声 RMS 应有提升 |

| Step 5 | 放宽 dual_mic_aec_hint guard | `nuwax_ai_partner_main.c` | 中 | 对比 step1-4 前后人声保留量 |

## 五、不做的事

| 事项 | 原因 |
|------|------|
| P0-3 残余取消近端保护阈值 | 非 S19 主因，暂不动 |
