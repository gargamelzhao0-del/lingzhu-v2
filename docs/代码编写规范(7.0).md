# Nuwax AI Partner 代码编写规范(7.0)

更新时间: 2026-06-16
状态: 配套 `7.0工作计划(定稿)` 发布,适用于 7.0 全部新增/改造代码,旧代码改动随手向本规范靠拢。
适用范围: ESP32-S3 固件(`NuwaxAIPartner/main`、`components`、`lib`、`test`)与 Node.js 云端(`cloud-gateway`)。
立场: 本规范从本工程**已发生的真实教训**抽象而来,不是通用模板。每条尽量给出工程内的来由。

---

## 0. 总则

### 0.1 强制度分级
- **MUST(必须)**:违反即评审打回,不得合入。
- **SHOULD(应当)**:默认遵守,偏离须在 PR 描述写明理由。
- **MAY(可选)**:推荐做法,自行裁量。

### 0.2 质量优先级(冲突时按此排序)
**正确性 > 实时性/资源安全 > 可测试性 > 可维护性 > 性能 > 行数/简洁**。
> 来由:6.3 重构确立"看八维度质量,不看行数门槛"。**禁止以"行数没超"或"行数更少"作为质量论据。** 减少耦合、提高内聚、可测试性,优先于把文件改短。

### 0.3 本工程不可动摇的既定边界
1. 对外音频接口是**纯 PCM 契约**(`nuwax_*_read_pcm16` / `write_pcm16`),换芯片不得外溢到下游。
2. 硬件差异封死在 **board profile + audio_board** 内,上层不得出现具体芯片型号分支。
3. 任何高风险能力(codec/AFE/AEC/full-duplex/打断分层/battery/IMU)**必须有 feature flag**,可独立关闭回退。
4. 构建走 `build-opus-firmware.ps1`,**不直接 `idf.py`**(含空格路径会链接失败);改 sdkconfig 必须**同步改 `sdkconfig.defaults` 与本地 `sdkconfig`**(构建脚本拷后者作基底)。

## 1. 分层架构与依赖方向(MUST)

7.0 端侧分层,**依赖只能从上往下,严禁反向或跨层**:

```text
L5 app / conversation_fsm / interrupt_engine        (业务策略,不碰寄存器)
L4 service: audio_service / session_protocol / diagnostics
L3 abstraction: audio_board / afe_processor          (能力抽象,出 PCM/事件)
L2 driver: es7210 / es8311 / bq27220 / bmi270 / display(ST77916) / touch(CST816S/CST816-family)
L1 platform: i2c_bus_manager / i2s / gpio / board_profile(引脚与能力常量)
L0 HAL: ESP-IDF / esp_codec_dev / esp-sr / lvgl
```

规则:
- **MUST** 上层只依赖下层的**头文件接口**,不依赖其实现细节;下层**绝不**包含上层头文件(无反向依赖)。
- **MUST** L5/L4 业务层**不得**出现 `gpio_set_level`、`i2s_*`、`es8311_*`、寄存器地址、具体 GPIO 数字。出现即分层泄漏。
- **MUST** 跨层数据用**明确的结构体 + 所有权约定**传递(见 §6.4),不用全局可变状态偷渡。
- **SHOULD** 每层有清晰的"对上契约"头文件(如 `audio_board.h` 暴露 `audio_board_caps_t` 与 `read/write_pcm16`,不暴露 ES7210 寄存器)。

> 反面教训:6.3 的 `nuwax_ai_partner_main.c` 体量过大(God file,半双工闸门、cancel、auto-followup 都挤在内)。7.0 新增逻辑**MUST** 落到对应层的独立模块,**不得**继续往 main 堆状态、协议和触摸分发;`main` 只保留最薄的入口与编排。

## 2. 硬件/接口抽象(MUST)

### 2.1 Board profile
- **MUST** 所有引脚、I2C 地址、采样率、能力布尔集中在 `board/esp_vocat_v1_0_pins.h` 与 `audio_board_caps_t`;业务代码引用**符号常量**,严禁散落魔数 GPIO。
- **MUST** 旧硬件保留为独立 `legacy` profile,通过 `choice NUWAX_BOARD` 选择,默认不隐式切换;启动**打印** board 名与关键 GPIO。

### 2.2 Codec / 音频抽象
- **MUST** ES7210/ES8311/PA/I2S 的初始化与生命周期**只在 `audio_board` 内**;`mic_input`/`speaker_output` 向 audio_board 申请能力,不再自持 `i2s_new_channel`。
- **MUST** 对上仍出 `read_pcm16/write_pcm16`;内部多通道(MIC1/MIC2/REF)对上层透明,**通过 caps 标志**(`has_ref`/`full_duplex`/`channels`)协商,不靠 `#ifdef 芯片型号`。
- **MUST** codec 路线(esp_codec_dev vs 手写寄存器)切换**不改变** audio_board 对上接口(P0-G2 兜底的前提)。
- **SHOULD** 抽象接口用"能力查询 + 操作"两段式:先 `audio_board_get_caps()`,再按 caps 决定是否走多通道/AEC,避免上层假设硬件。

### 2.3 接口契约稳定性
- **MUST** 跨模块公共头文件的函数签名变更视为破坏性改动,需在 PR 标注并同步所有调用方与 host 测试。
- **MUST(NA 协议向后兼容)** 端云"NA"22 字节二进制帧头**长度不可变**;新增上下文按定稿 G4 策略实现:轻量布尔走 `flags`/`reserved` 位 + hello capability 协商;结构化字段(`turn_id`/`playback_id`)走并行 JSON 控制帧;确需扩头则**新增 frame version=2 且端云同时支持 v1/v2**,旧端按 v1 解析不得错位。改动 NA 帧的 PR 必须附 v1/v2 兼容测试。
- **SHOULD** 新接口先想"能否被 fake 替身在 host 上测"(见 §10)。不可测的接口通常是抽象没切干净。

## 3. 低耦合 / 高内聚(MUST/SHOULD)

- **MUST** 单一职责:一个 `.c` 一个清晰主题;采集、播放、AFE、编码、发送、状态机、打断判定**各自成模块**,不互相内联。
- **MUST** 头文件最小暴露:只导出必要符号;内部函数 `static`;内部结构体放 `.c` 或 `priv_include/`。
- **MUST** LVGL widget 句柄遵守单一所有者:创建对象的模块负责生命周期,其他模块只允许通过 `const` 句柄 bundle 借用,**不得**把同一批指针再缓存成另一份模块私有 static 或 bind 后复制别名。
- **SHOULD** 模块间通过**事件/队列/回调**解耦,不直接读对方内部状态(如打断引擎不直接读 speaker 队列内部,改用 `has_pending()` 这类查询接口)。
- **SHOULD** 圈复杂度高、参数 >5、嵌套 >3 层的函数应拆分;但拆分以**降耦合/可测**为目的,不为凑行数(见 0.2)。
- **MUST(改名安全)** 用整词/符号级替换重命名,**先查该标识符是否是更长标识符的子串**;`replace_all` 子串会误伤(本工程踩过)。改名后编译 + host 测试双确认。

## 4. 命名 / 文件组织 / include(MUST)

- **MUST** C 端公共符号统一 `nuwax_` 前缀 + snake_case;类型 `_t` 结尾;宏与编译期常量全大写;Kconfig `CONFIG_NUWAX_*`。
- **MUST** 文件名小写下划线,与主类型/职责同名(`audio_board.c/.h`、`es7210_adc.c/.h`)。
- **SHOULD** include 顺序:① 本模块自身头 ② C 标准库 ③ ESP-IDF/FreeRTOS ④ 第三方组件 ⑤ 本工程其它模块;每组内字母序;**禁止**在头文件里 include 仅实现需要的头(减少传递依赖)。
- **SHOULD** 每个 `.h` 顶部一句话写清"本模块对上提供什么能力、属于哪一层"。
- 云端 JS:`camelCase` 函数/变量、`PascalCase` 类、`UPPER_SNAKE` 常量;沿用现有 `cloud-gateway.js` 风格。

## 5. 实时系统设计规范(MUST——音频/采集/播放路径红线)

> 全双工下采集/播放/AFE/编码/发送并行,**实时路径任何一处长阻塞都会 underrun/overrun**。本节为硬红线。

### 5.1 任务与优先级
- **MUST** 明确每个 FreeRTOS 任务的优先级、栈大小、所在核、唤醒源,并在代码注释/文档登记。基准:capture/playback > AFE fetch > Opus encode > WS send > UI;**音频实时任务高于 UI**。
- **SHOULD** 重 AFE/编码任务**绑核**(参考固件 AFE pin core1),把音频与 LVGL 渲染分核,减少争用。
- **MUST** 任务栈用 high-watermark 实测定值(纳入 G5 资源预算),不拍脑袋。

### 5.2 实时路径禁忌
- **MUST NOT** 在采集/播放/AFE/ISR 路径中:动态 `malloc/free`、阻塞式日志、持有可能长占的锁、做文件/网络同步 IO、`vTaskDelay` 兜底掩盖时序问题。
- **MUST** 实时缓冲区**预分配**(启动时一次),运行期只复用;ring/queue 容量上限固定(纳入 G5)。
- **MUST** 队列/ring 满时有**明确策略**(丢最旧 + 计数 + 降级),**禁止**无界增长或静默丢弃;丢弃必须可观测(计数 + 限频日志)。

### 5.3 ISR 规则
- **MUST** ISR 只做最小工作 + `FromISR` 通知任务;不调用非 ISR-safe API,不打日志,不分配内存。
- **SHOULD** 触摸/IMU 中断走"ISR 置标志 → 任务处理"模式。

### 5.4 时钟与同步(全双工特有)
- **MUST** 采集与播放共享 I2S 时钟域(单 I2S TX-STD+RX-TDM,共享 MCLK/BCK/WS),AEC reference 与麦克风**严格同步**(收发采样漂移 **<1%**,与定稿 P2-2/G3⑧ 同口径);采样率全链路 16k 统一。
- **MUST** REF 的 TDM slot 序在驱动中**固定且日志可识别**(P2-5),不靠运行期猜测。

### 5.5 打断的实时性
- **MUST** 打断"先本地静音,再等云端清理":`interrupt_confirmed` 后立即本地 mute,不等 cancel ack(用户感知优先)。
- **MUST** 打断/取消后旧 turn 的 audio frame **stale drop 可计数**;新旧 turn 用 `turn_id/playback_id` 严格区分。

## 6. 内存规范(MUST)

- **MUST** 显式选择 internal vs PSRAM:DMA 缓冲、实时小热缓冲、对延迟敏感的 LVGL draw buffer 用 **internal**(`MALLOC_CAP_INTERNAL`/`DMA`);大只读资产、模型、非实时大缓冲用 PSRAM。
  > 来由:6.3 性能根因之一是 **LVGL draw buffer 误落 PSRAM** → 渲染慢;阈值修正为 32KB。**MUST** 关键缓冲分配后**断言/日志其落位**,不假设。
- **MUST** 优先用 `heap_caps_malloc` 指定 caps;通用分配器遵循工程"internal 优先"策略(P3-2 已确立)。
- **MUST** 谁分配谁释放;跨模块移交所有权必须在接口注释写明(见 6.4);长生命周期对象启动期分配、关闭期释放,soak 不增长(P8 门禁)。
- **MUST** 记录并守住 internal heap largest / DMA heap / PSRAM largest 下限(G5);触线降级。

### 6.4 所有权约定(MUST 在接口注释声明三选一)
`owns`(被调方接管,负责释放)/ `borrows`(调用期内有效,被调方不得留存)/ `copies`(被调方自存副本)。多通道音频帧、PCM 缓冲跨任务传递时尤其要标。

## 7. 并发与同步(MUST)

- **MUST** 共享可变状态必须有同步;优先**单一所有者 + 消息传递**,其次细粒度锁。
- **MUST** 沿用 **owner-lock 模式**:如 mic 资源用 `s_mic_owner_lock` + owner 枚举(WAKE_DETECTOR vs CONVERSATION_CAPTURE 互斥),避免两路同时开同一 I2S。新增共享硬件资源沿用此模式。
- **MUST** 触摸路径也遵守单一所有者:如果 `app_shell` 已负责手势分发,就保持 LVGL pointer indev 关闭;不要让 LVGL indev 和业务手势任务同时消费同一 CST816 硬件路径。
- **MUST** `failed to lock LVGL for touch event=...` 这类日志是锁范围过大或锁顺序不稳的信号,不是调大超时阈值的理由。优先缩短临界区、把音频/网络/IO 移出锁外,必要时丢弃低价值触摸事件。
- **MUST NOT** 在持有 **LVGL 锁**时调用音频/网络阻塞操作;反之亦然(避免优先级反转拖垮音频)。锁的获取顺序全局一致,防死锁。
- **MUST** 状态写入集中、加保护:状态机迁移走单一 `set_state()`,带必要的 defer/守卫(参考现有半双工闸门),不在多处裸改状态。
- **SHOULD** 临界区尽量短,只保护数据不保护 IO。

## 8. 错误处理与降级(MUST)

- **MUST** C 端用 `esp_err_t` 贯穿并向上传播;`ESP_ERROR_CHECK` 只用于**启动期不可恢复**初始化,运行期路径必须捕获并降级,**不得**让其 abort 整机。
- **MUST** 每个高风险能力有 **feature flag** 与**明确降级路径**(codec 失败→legacy;AEC ref 不健康→禁 L3;全双工资源触线→candidate-only→半双工)。降级是设计的一部分,不是事后补丁。
- **MUST** 外设/网络失败进入**可恢复**状态(明确 error/recovery),不死机、不无限重试(P8-2 故障注入验收)。
- **SHOULD** 错误信息含足够定位上下文(模块/操作/错误码),但遵守 §9 脱敏。
- 云端:**MUST** `cancelTurn` 走真 abort(`AbortController` 中止在飞 LLM SSE / TTS HTTP),不只软黑名单。

## 9. 日志与可观测(MUST)

- **MUST** 每模块固定 `TAG`;分级正确(ERROR/WARN/INFO/DEBUG);默认发布等级不刷屏。
- **MUST(脱敏)** 日志**禁止**输出 token、密钥、WS URL 凭证、用户隐私音频/文本原文。
  > 来由:6.x 做过日志脱敏(log redaction)。新增日志默认按"会被截图外发"对待。
- **MUST(实时限频)** 采集/播放/AFE 路径**禁止逐帧日志**;只输出统计值(RMS/VAD/队列水位)并限频,避免日志拖垮音频任务。
- **MUST** 统一诊断字段命名以**定稿 §14.2 为唯一权威表**(含端·音频/端·打断时序/端·硬件/云 四组,打断时序时间戳 `near_end_candidate_ts/interrupt_confirmed_ts/local_mute_ts/stale_drop_effective_ts` 等用于算 p95);全链路一致,支撑"先证据后调参"。
- **SHOULD** 关键缓冲落位、board profile、能力协商结果在启动期各打一行,便于现场定位。

## 10. 可测试性(MUST/SHOULD)

- **MUST** 纯逻辑(状态机迁移、打断分层判定、回声/语义判别、协议帧解析/构造、VAD 策略)与硬件/IO **分离**,可在 **host 上单元测试**。
  > 来由:工程已有 `test/host/` 纯逻辑单元测试框架。新增策略逻辑**MUST** 配 host 测试,不依赖真机才能验。
- **MUST** 硬件依赖通过接口注入,host 测试用 **fake/stub** 替身(fake codec/fake mic/fake ws),覆盖正常 + 边界 + 故障路径。
- **SHOULD** 打断引擎、协议兼容(v1/v2 帧)、stale drop、turn 区分等高风险逻辑做**表驱动测试**(多场景用例表),并随回归跑。
- **SHOULD** 云端沿用现有 `test-*.js`(cancel-turn、streaming-tts、audio-utils…)扩充;改并发/真 abort 必须补回归用例。
- **MUST** 验收指标可复现:固定样本库(开发档 ≥50/50/30,见定稿 §14),不靠主观听感。

## 11. 可维护性(MUST/SHOULD)

- **MUST** 注释解释"为什么"(时序、硬件约束、降级原因),不复述"做什么";密度与命名风格**匹配周边代码**。
- **MUST** 公共接口有头注释:能力、所有权、线程上下文(可在哪个任务/ISR 调)、失败语义。
- **SHOULD** 复杂时序/状态迁移配 ASCII 图或指向定稿对应章节。
- **MUST** 每个 P 阶段产出阶段记录(沿用 `docs/*阶段记录*` 习惯):改了什么、为什么、验证证据、回退点。
- **SHOULD** TODO/FIXME 带责任人与条件,不留无主悬置。

## 12. Kconfig 与 feature flag(MUST)

- **MUST** 新能力先加 `CONFIG_NUWAX_*` 开关,默认值保守(高风险默认关或灰度);开关覆盖 codec/AFE/AEC/full-duplex/interrupt-level/battery/IMU。

## 13. 配置与构建(MUST)

- **MUST** 构建用 `build-opus-firmware.ps1`(IDF v6.0 环境),不直接 `idf.py`(空格路径链接失败)。
- **MUST** 改 sdkconfig 同步改 `sdkconfig.defaults`(声明式,git 跟踪)与本地 `sdkconfig`(脚本拷贝作基底),两处一致。
- **MUST** 维持性能基线:`COMPILER_OPTIMIZATION_PERF`(-O2)+ `ESP_DEFAULT_CPU_FREQ_MHZ_240`;不得无理由回退到 -Og/160MHz。
  > 来由:6.3 先暴露出 **draw buffer 落 PSRAM** 这一一级根因,再叠加 DEBUG 编译等级 + 160MHz 放大渲染慢;改 O2+240 并把 buffer 放回 internal 后 render 中位 88→37ms。
- **MUST** 性能排查顺序固定:先查 buffer 落点(internal vs PSRAM),再查编译等级与 CPU 频率,最后才动渲染算法和 dirty 区域;不要把第一性问题藏在 UI 代码重写里。
- **SHOULD** 构建脚本对关键项(Opus 开、PCM16 关、WS/token、board、VAD 参数)做 post-build 校验(现脚本已有,扩展勿删)。

## 17. 6.3 / P4 / P5 真实教训索引

- **主控拆分**:`main` 只能是编排层,不是业务、协议、触摸、状态机和缓存的长期居所。6.3 的 God file 证明“先堆进去跑起来”会很快变成拆不动的总线。
- **LVGL 所有权**:创建 widget 的模块拥有它,其它模块只借用句柄 bundle。`bind` 后再缓存一份 static、让多模块共同持有同一对象,属于共享可变所有权,应直接禁止。
- **触摸/LVGL 锁**:触摸路径只有一条,锁只保护最小临界区。`failed to lock LVGL for touch event=...` 不是可接受常态,而是要缩短锁内工作、移出 IO 的信号。
- **改名安全**:重命名必须先验证是否命中更长标识符,不要用子串替换碰运气。改名后要做编译与 host 测试双确认。
- **构建路径**:固定走 `build-opus-firmware.ps1`,临时工作区放 `TEMP`,BuildDir 保持简单目录名,不要把构建/清理/临时文件散落在工程目录里。
- **性能真根因**:先看 buffer 在哪里,再看编译等级和 CPU 频率。6.3 已经证明,把 draw buffer 放在 PSRAM 里,再好的渲染逻辑也会先输在内存带宽上。
