## 明确保留的限制

**BP03 临界电量自动关机尚未启用。** 本轮修复了电压判断基础、低电提示和正常关机协调，但没有把现有 3400mV 告警阈值当作自动断电阈值。仍需这块板和当前电芯的实测阈值、持续时间及 SD 最坏落盘时间。已向用户询问这些数据；缺少标定时不能声称“电量耗尽前一定能保存完整录音”。

OTA 启动确认仍保留必要硬件健康与有界等待/回滚；这次只分离新升级的百分比门槛，没有取消镜像身份、云端确认和本地健康检查。没有证明外部稳定供电时，电池不存在不会自动放行升级。

正常关机不能保证紧急长按、直接拔电或坏卡情况下零损失。强制长按 5 秒后松手的应急关机语义保留。普通关机若资源始终无法收尾会继续等待，不能把超时当作文件已安全关闭。

I²C 新统计是总线级累计指标，尚不是按设备划分的完整性能画像。本轮没有实机帧率、功耗或启动速度对比。

## 关键实现细节

1. 关机 PREPARING 与 OTA/配网 owner 使用同一原子字裁决，避免先检查后又进入升级；最终硬件关机失败时恢复准备状态，避免重开业务入口。
2. 补传 start 的判断、context 发布和关机门禁用同一 `s.lock` 串行化；瞬时 cancel 清除不会重新开放准入。
3. SD 最终屏障同时取得 admission / writer_gate / state 锁，覆盖“队列最后一个项目已取走、writer_busy 尚未发布”的交接窗口，并检查未关闭的 FILE。所有等待为本次返回后下轮继续，未在主线程等整个网络上传。
4. 电压安全组和 SOC/容量模型分离，旧完整读取接口继续以返回码表明整份数据是否成功；新部分读取接口仅由已适配的电池服务使用。
5. 配置验证重试与普通遥测由单一电池任务执行，最多三次额外尝试；OTA/配网保护存在时延后，不冒险进入配置写入。
6. 摸头触发、表情资源、OTA 动画资源和正式云端协议没有改版。

## 验证

新增 `tools/test-board-power-boundaries.py`：提取并执行生产函数体，外设接口使用可控桩，验证：

- OTA/配网/电池维护与普通关机的准入顺序，以及最终关机失败后 gate 恢复。
- 安全组成功、后续寄存器超时；FCC 异常；0mV；电池状态读取失败；24 秒过期边界。
- 未验证 SOC 拒绝新升级，可信 SOC 的 29%/30% 边界，以及启动确认与升级准入分离。
- 电池停止超时、重复调用、另一停止者持锁、状态锁忙、仅一次任务删除。
- 补传未退出、writer dequeue 交接、FILE 未关闭都阻止关机；瞬时 cancel 清除不能解除持续门禁。

主机故障注入不是电气测试，也不是 FreeRTOS 两核时序穷举证明。
