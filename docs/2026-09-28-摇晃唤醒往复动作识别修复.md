# 摇晃唤醒往复动作识别修复

## 问题与证据

原 `sample_is_active()` 使用相邻三轴加速度变化绝对值之和 >=700 mg **或**三轴角速度绝对值之和 >=150 度/秒作为运动条件，`shake_observe()` 累计1500 ms活动后触发，允许300 ms间隙保留累计量，没有来回换向要求或整体动作截止时间。

使用原实际函数模拟复现：加速度不变、单向转动160度/秒，1500 ms即可触发；每250 ms一次活动采样，也会在7500 ms累计触发。它们只能证明代码误判路径存在，不能替代用户本次动作的传感器记录。

## 实现

新策略位于 `main/board/shake_motion_policy.h`，由原 `shake_detector_task` 调用。保留50 ms轮询、原QMI范围和ODR、3072字节PSRAM任务栈、任务优先级、共享I2C管理、触摸/摇晃交互锁及回调。每次采样处理固定大小状态，无动态分配、新任务或额外I2C访问。

1. 用时间常数400 ms的低通估计重力/缓慢变化分量，得到动态加速度；这不是完整的姿态融合，快速姿态变化仍可能产生残差。
2. 动态向量达到450 mg时开启候选，固定本次运动的单位方向；后续使用在该方向上的有符号投影。支持三轴和斜向，不把无关方向的动作相加计数。
3. 只有正负交替跨过450 mg门槛才增加有效半波数，不要求采样点恰好落在零点。至少4个交替半波，动作跨度至少500 ms，且须在1500 ms整体窗口内完成。相邻交替半波间隔100–500 ms，过快反弹重置候选、过慢或整体超时重新识别。
4. 陀螺仪不再单独触发，仅用于判断触发后的稳定状态及诊断。
5. 候选确认后，无论共享交互锁是否允许发出事件，本地均抑制重复触发。至少4秒冷却后，还须连续300 ms满足动态幅度<=150 mg、角速度总和<=45度/秒，再重新识别；抑制期间不累计候选。
6. 调度漏采、读取失败或端到端读取耗时>=50 ms时停止本次判定；短间隙保留已有有效半波，恢复首帧只重建基线、不计峰。有效观测间隔>150 ms时清空候选；固定动作窗口仍会使旧证据过期。不因传感器故障解除触发后抑制。过慢读取后重新安排下一次轮询，禁止补读追赶。

没有改变上层对话打断、表情处理和交互事件释放流程。短暂故障不抹掉所有有效证据，但缺失数据和恢复首帧不算新的半波；长期或频繁采样故障仍可能影响慢摇命中率，应先分析采样健康日志。

## 测试

`main/shake_motion_policy_host_check.c` 直接使用生产策略。`tools/test-shake-gap.py` 还提取实际采样任务循环进行故障注入。

- 650 mg合成往复波形：1.25/2/3 Hz，三轴与斜向，4种起始相位，共48种组合均能触发。
- 单向转动、同向稀疏颠簸、单次拿起倾斜、200 mg轻微摆动、0.4 Hz缓慢摆动、单次冲击反弹等合成样例不触发。
- 覆盖少于4个半波、锁定方向、1500 ms边界、半波间隔、重复时间戳、计数回绕、NAN、长采样间隙和故障恢复。
- 连续摇动只触发一次；冷却后仍在转动不能解除抑制；稳定后可再次触发。
- 实际任务循环覆盖12种场景：读取错误、调度延迟、反复长间隙、陀螺仪单独运动、短促零散运动、共享锁拒绝、故障后恢复、过慢成功读取、两次独立动作等。
- 10项策略和3项任务反向变异检查防止关键保护被移除。

这些是程序及合成输入验证，不是实机误触发率或儿童动作成功率的测量。较强且规律的携带颠簸仍可能与主动摇晃相似，必须实机复测。
