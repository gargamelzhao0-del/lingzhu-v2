# SD 卡离线音频归档与恢复上传交接文档

历史协议：下文的在线镜像、能力协商及逐文件上传描述不适用于当前 SD 场次测试固件。当前云端对接以 [SD 会议监控场次上传协议](SD会议监控场次上传协议.md) 为准，设备流程见 [功能逻辑与异常处理](SD会议监控功能逻辑与异常处理.md)。

## 1. 范围

在线会议、监控和实时音频协议保持不变。本次云端仅新增 SD 离线归档接收、断点续传、校验和归档存储。

设备行为：在线实时上传并异步写 SD；断网写 SD；恢复网络后新数据实时上传，旧 `.ready` 文件后台补传。

## 2. 能力声明

现有认证成功响应增加：

```json
{"offline_audio":{"supported":true,"protocol_version":1,"archive_only":true}}
```

未同时满足三个条件时，设备不补传且不删除本地文件。

## 3. 文件格式

SD 文件状态：

```text
*.part   正在写入，禁止上传
*.ready  已封存，允许补传
```

文件结构：

```text
96 字节 NWXOFF1 Header
多个 [4 字节记录长度 + NA v1 PCM16 帧]
32 字节 NWXEND1 Footer
```

NA v1 帧为现有在线音频帧，默认 PCM16、16 kHz、单声道、20 ms，包含 `sequence`、`timestamp_ms`、`flags` 和 PCM 数据。Footer 包含 `frame_count`、`payload_bytes`、`crc32`、`complete`。

## 4. 补传时序

```text
offline_audio_begin
→ offline_audio_begin_ack
→ NWXCH1 Binary Frame（逐片）
→ offline_audio_chunk_ack
→ offline_audio_commit
→ offline_audio_commit_ack
→ 删除对应 .ready
```

补传使用正式 WebSocket 的后台任务，不得阻塞实时会议或监控音频。

## 5. Begin

设备发送：

```json
{"type":"offline_audio_begin","mode":"archive_only","request_id":"begin_001","segment_id":"segment_001","total_bytes":524288,"crc32":305419896}
```

云端回复：

```json
{"type":"offline_audio_begin_ack","mode":"archive_only","request_id":"begin_001","ok":true,"next_offset":0}
```

`next_offset` 为云端已可靠保存的连续字节数。断点续传必须从该位置继续。

## 6. NWXCH1 分片

Binary Frame 为 `64 字节 NWXCH1 Header + 最多 8064 字节归档内容`。头部字段（小端序）：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 6 | `NWXCH1` |
| 8 | 4 | version=`1` |
| 12 | 4 | 文件 offset |
| 16 | 4 | payload 长度 |
| 20 | 40 | chunk request_id |
| 64 | N | 归档内容 |

云端持久化后回复：

```json
{"type":"offline_audio_chunk_ack","mode":"archive_only","request_id":"chunk_001","ok":true,"next_offset":8128}
```

## 7. Commit

设备发送：

```json
{"type":"offline_audio_commit","mode":"archive_only","request_id":"commit_001","segment_id":"segment_001","total_bytes":524288,"crc32":305419896}
```

云端校验文件长度、NWXOFF1/NWXEND1、记录长度、frame_count、payload_bytes 和 CRC32 后回复：

```json
{"type":"offline_audio_commit_ack","mode":"archive_only","request_id":"commit_001","ok":true}
```

设备只有收到 `ok:true` 才删除 `.ready`。

## 8. 云端处理规则

- 幂等键：`device_id + session_id + segment_id`；
- 重复 Begin 返回已保存的 `next_offset`；
- 重复 Chunk 不得重复追加；
- 重复 Commit 在长度和 CRC 一致时返回成功；
- 失败、超时、断线或 CRC 错误不得要求设备删除文件；
- `archive_only` 只进入归档存储，不触发 ASR、会议转写、监控事件、告警、TTS 或计费；
- 单个归档分段失败不得关闭正式 WebSocket；
- 云端按归档内 sequence 和 timestamp 处理，不按网络到达顺序重排。

错误示例：

```json
{"type":"offline_audio_chunk_ack","mode":"archive_only","request_id":"chunk_001","ok":false,"next_offset":0,"error_code":"offset_invalid"}
```
