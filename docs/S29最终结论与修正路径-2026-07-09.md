## 二、五大问题根因（按优先级）

### 🔴 问题1：采集链路未保持实时16kHz — 基础架构缺失

**严重度：致命。** 这是所有问题的前置条件。采集主循环不是独立实时任务，导致：
- WAV 14.60s 对应墙钟 23.4s → 实时性 **62%**
- 音频时间轴压缩 → 人声变调 → “加速感”
- 所有试听结论不可靠，因为时间轴错误

**代码验证：**
- 主循环 `nuwax_ai_partner_main.c:2770` 是同步循环：读I2S → AEC → cleaner → VAD → 编码 → 入队 → 命令排空，全部串行
- 没有独立高优先级 I2S 采集 task + ringbuffer
- `main/audio_reliable_capture.c`（M1 可靠采集环形缓冲，32帧×30ms=960ms）**存在但未被编译引用**（`main/CMakeLists.txt` 未包含）

**验证方法：** WAV采样数/采样率=14.60s，墙钟~23.4s，实时性=14.60/23.4=62%

### 🔴 问题2：AEC 参考不稳定 — 软件参考对齐漂移

**严重度：致命。** AEC 几乎失效，导致回音和设备声残留。

**代码验证：**
- `CONFIG_NUWAX_VOCAT_SLOT2_AEC_REF_ENABLE=0` → 硬件参考未启用
- `adaptive_last_offset=1440` → 软件参考对齐偏移 1440 样本（90ms @16kHz），远超正常范围
- `ref_inactive_preserved=452` → 约一半的 chunk 参考信号不活跃，AEC 走 `append_ref_inactive_chunk` 分支

**`live_aec.c:1259-1294` 的 `append_ref_inactive_chunk`：**
```c
int32_t atten_q15 = (int32_t)CONFIG_NUWAX_LIVE_AEC_REF_INACTIVE_ATTENUATE_Q15;  // =2048=6.25%
// 有 strong_nearend_preserve_hint 时才提升
if (aec->strong_nearend_preserve_hint && ...) {
    atten_q15 = CONFIG_NUWAX_LIVE_AEC_REF_INACTIVE_HINT_ATTENUATE_Q15;  // =8192=25%
}
if (atten_q15 >= 32768) {
    append_bypass_chunk(aec);  // 不衰减
    return;
}
// 否则衰减到 6.25%
```

**后果：** 参考不活跃 → 麦克风信号衰减到 6.25% → 人声被压没。同时由于 AEC 未工作，回声残留。

### 🔴 问题3：human-first 保护误判设备声为人声

**严重度：严重。** 保护机制反向工作，把设备声保护下来，把人声压掉。

**代码验证（`nuwax_ai_partner_main.c`）：**

`dual_mic_human_first_hint_active` 的判定条件：
```c
// 需要 MIC1 avg>=120 && peak>=500
// 需要 MIC2 avg>=300 && peak>=1000
// 需要 diff avg>=180 && diff peak>=700
// 需要 balance <= 26000
// 6帧 hangover
```

S29 无人基线中 `dual_mic_human_first_hint_active=461` → 设备播报声本身就满足了这些条件，导致保护误触发。

**保护机制的实际效果：**
- `audio_cleaner.c:500`：有 `nearend_hint` 时跳过 softref 线性消除 → **设备声被保留**
- `audio_cleaner.c` 后续播放残留门禁要求 `!speech_protected` → **设备声穿透上传**

**后果：** 设备声被“保护”下来，真人声被 AEC ref_inactive 压掉 → “设备还在、人声很小、整体回音”

### 🟡 问题4：ref_inactive 衰减与保护策略矛盾

**严重度：高。** AEC 的两条分支逻辑互相矛盾。

| 分支 | 逻辑 | 效果 |
|------|------|------|
| ref active + human hint | 跳过 softref | 设备声被保护 |
| ref inactive（~50%帧） | 衰减到 6.25% | 人声被压没 |

**同一帧中两者叠加：**
1. human hint 保护了设备声 → 设备声不被消除
2. ref inactive 把人声衰减到 6.25% → 人声消失
3. 上传音频中：设备声被保留，人声消失

### 🟡 问题5：“可靠采集/可靠播放”原型未进入固件

**代码验证：**
- `main/audio_reliable_capture.c` — M1 可靠采集（32帧环形缓冲，960ms）
- `main/audio_reliable_playback.c` — M1 可靠播放
- `main/filter_conservative.c` — M2 帧过滤器
- `main/state_cmd_fast.c` — M1 状态命令

**以上全部存在但未编译**（`main/CMakeLists.txt` 无引用）。

## 三、修正路径（按顺序，不可跳跃）

### Step 1 — 先修实时采集（基础，必须先做）

**目标：** 采集实时性从 62% 提升到 95%+，WAV 时长与墙钟一致。

| # | 改动内容 | 涉及文件 | 预估行数 |
|---|---------|---------|---------|
| 1.1 | 新建独立高优先级 I2S 采集任务（prio 8-9），仅做 I2S read + ringbuffer push | `audio_reliable_capture.c` 改造 | ~150行 |
| 1.2 | 主循环改为从 ringbuffer pop 帧，不做 I2S 阻塞读 | `nuwax_ai_partner_main.c` | ~50行 |
| 1.3 | ringbuffer 深度 32-64 帧（960-1920ms），超时保护 | `audio_reliable_capture.c` | ~30行 |
| 1.4 | 加入 `main/CMakeLists.txt` 编译 | `CMakeLists.txt` | 1行 |

**验收标准：** 实时性 >= 95%（WAV时长/墙钟 >= 0.95），sent 不变

### Step 2 — 再修 AEC/参考对齐（核心）

**目标：** AEC 参考对齐稳定，ref_inactive 帧数从 50% 降到 10% 以下。

| # | 改动内容 | 涉及文件 | 预估行数 |
|---|---------|---------|---------|
| 2.1 | 自适应参考搜索增加稳定性约束：新偏移必须连续 N 帧(3-5)都被选中才切换 | `live_aec.c:891-896` | ~20行 |
| 2.2 | 降低自适应参考最小相关阈值 | `sdkconfig`: `MIN_CORR_Q15=1500` | 1行 |
| 2.3 | 增大自适应参考搜索步长（提高搜索效率） | `sdkconfig`: `STEP=320` | 1行 |
| 2.4 | ref_inactive 时不再默认强衰减：`REF_INACTIVE_ATTENUATE_Q15=2048→16384(50%)` | `sdkconfig` | 1行 |

**验收标准：** ref_inactive_preserved 从 452 降到 < 100

### Step 3 — 最后重做 human-first 判据（精细化）

**目标：** human hint 只在真正人声时触发，不在设备播报时误触发。

| # | 改动内容 | 涉及文件 | 预估行数 |
|---|---------|---------|---------|
| 3.1 | human hint 增加 AEC ref 相关性约束：ref 活跃时 MIC 信号高 → 更可能是人声 | `nuwax_ai_partner_main.c` | ~20行 |
| 3.2 | 降低 MIC1/MIC2 能量门槛，但提高双麦差异要求 | `nuwax_ai_partner_main.c` | ~10行 |
| 3.3 | human hint 与 AEC ref_inactive 状态互斥：ref_inactive 时不产生 strong hint | `nuwax_ai_partner_main.c` | ~10行 |
| 3.4 | 移除 `nearend_blend_dual_evidence()` guard（或放宽阈值） | `live_aec.c:792-795` | ~5行 |

**验收标准：** 无人基线中 human hint 触发次数从 461 降到 < 50

## 五、不做的事

| 事项 | 原因 |
|------|------|
| 继续调 raw_mix / nearend_blend 参数 | 采集实时性不先修复，所有调参结论不可靠 |
| 调整 VAD 门控（P1 播放门控） | 当前问题不是 VAD 门控，是 AEC 参考和采集实时性 |
| 启用硬件参考 AEC | 当前硬件参考（slot2）健康度未通过验收，启用后可能更差 |
| 全量关闭 softref | softref 在参考稳定的场景有效，不应全量关闭 |
| 继续真人试听 | 采集时间轴错误 → 试听结论持续误导。先修实时性 |

---

## 六、最终结论

**S29 效果极差的根因是：采集实时性不足（62%）+ AEC 参考不稳定（50%帧ref_inactive）+ human-first 保护误判（无人基线461次触发）。**

| 现象 | 根因 | 优先级 |
|------|------|--------|
| 音频加速感 | **采集实时性仅 62%**，时间轴压缩 | 🔴 Step 1 |
| 人声极小 | ref_inactive 衰减到 6.25% | 🔴 Step 2 |
| 回音严重 | AEC 参考漂移 1440 样本，AEC 失效 | 🔴 Step 2 |
| 设备声较大 | human hint 误判保护设备声 | 🔴 Step 3 |

**修正顺序不可跳跃：** 先 Step 1（实时采集）→ 再 Step 2（AEC参考）→ 最后 Step 3（human-first）。在 Step 1 完成前，任何调参和试听都会因时间轴错误而得出误导性结论。
