### S29 失败复盘（2026-07-09 用户主观验收后）

- 用户反馈：
  - 人声非常小。
  - 整体声音充满回音。
  - 设备播报声仍较大。
  - 整个音频听起来像加速。
- 精确问题 1：验收 WAV 时间轴被压缩。
  - WAV header：16 kHz / mono / 16 bit。
  - WAV data：233600 samples = 14.60 s。
  - 串口：`I2S microphone stream start` 在约 `1004734 ms`，`I2S microphone stream done` 在约 `1028144 ms`。
  - 真实窗口约 23.4 s，但最终只有 14.6 s 音频，等效采样率约 10 kHz。
  - `timeouts=0`、`sent=730`、`dropped=0`、`queue_full=0`，说明不是网络队列丢帧，而是采集/处理主循环没有维持 20 ms 节拍。
- 精确问题 2：当前“可靠采集”原型未进入构建。
  - `audio_reliable_capture.c`、`audio_reliable_playback.c`、`filter_conservative.c`、`state_cmd_fast.c` 文件存在。
  - `main/CMakeLists.txt` 未引用这些文件，当前固件仍走 `nuwax_ai_partner_main.c` 的同步采集主循环。
- 精确问题 3：S29 human-first 误把大量设备声当成人声保护。
  - no-human 基线已有 `dual_mic_human_first_hint=245`、`dual_mic_human_first_hint_active=461`。
  - human 测试为 `dual_mic_human_first_hint=437`、`dual_mic_human_first_hint_active=585`。
  - 当前 human-first 只要 MIC2 满足 `nuwax_mic_level_is_speech()` 就触发，设备播报残留同样可能满足该条件。
- 精确问题 4：softref 清洗被保护门绕开。
  - `softref_active=284`，但 `softref_linear=0`。
  - `softref_guard=266`，说明软件参考存在时也大量被 nearend guard 直接跳过，没有做线性抵消。
  - `speech_protected=657/730` 使后续 `playback_unprotected_gate` 基本失效。
- 精确问题 5：live AEC 参考有效覆盖不足且对齐不稳定。
  - `slot2_aec_ref_enabled=0`，硬件 ref 没参与。
  - live AEC summary：`processed=459`、`ref_inactive_preserved=452`，约一半 chunk 没有有效参考。
  - `ref_inactive_preserved` 分支实际会按 ref inactive 衰减路径输出，不是真正保真人声。
  - `adaptive_last_offset=1440`、`adaptive_offset_abs_sum=288800`，说明 software ref 对齐大幅偏移/跳动，容易产生回音感和设备声残留。
- 结论：
  - S29 不应继续作为调参基线。
  - 下一版优先级必须改为：
    1. 先修实时采集，保证验收 WAV 与真实墙钟时间一致（目标 48-52 fps，16 kHz 不压缩）。
    2. 再修 ref 策略：ref inactive 时不允许继续重压用户声；software ref 对齐必须稳定。
    3. 最后收窄 human-first：MIC2 speech-like 不能单独作为人声保护条件，必须结合双 mic 空间差异、ref 相关性和设备声判据。
