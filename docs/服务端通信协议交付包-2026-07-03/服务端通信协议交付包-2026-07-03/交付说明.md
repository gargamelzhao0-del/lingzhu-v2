## 交付目标

本交付包用于服务端工程师在不依赖 ESP32 设备端源码的情况下，实现与当前 Nuwax AI Partner 7.0 设备端的基础通信闭环:

- WebSocket 握手和 `X-Bridge-Token` 鉴权
- JSON text message 解析和下发
- `NA` 二进制音频帧解析
- 设备音频上行
- 服务端 PCM16 mono 音频下行播放
- `text_response`、`playback_begin`、`NA END`、`playback_end`
- 基础设备命令和 ack

## 使用顺序

1. 先阅读 `docs/2026-07-02-设备端服务端通信协议规范.md`。
2. 用 `docs/protocol/schemas/nuwax-device-protocol.schema.json` 校验 JSON message。
3. 用 `docs/protocol/fixtures/na/*.bin` 测试服务端 `NA` parser。
4. 服务端启动后，用 `tools/fake-device/fake-device-conformance.js` 模拟设备联调。

## fake-device 基础联调

```powershell
node .\tools\fake-device\fake-device-conformance.js --url ws://127.0.0.1:8799/api/device/ws
```

如果服务端需要 token:

```powershell
node .\tools\fake-device\fake-device-conformance.js --url ws://127.0.0.1:8799/api/device/ws --token <token>
```

如果要求服务端完整返回播放链路:

```powershell
node .\tools\fake-device\fake-device-conformance.js --url ws://127.0.0.1:8799/api/device/ws --expect-playback
```

## 关键约束

- 服务端下行 WebSocket payload 不得超过 16 KiB。
- 服务端下行 binary message 必须且只能包含一个 PCM16 mono `NA` 播放帧。
- 下行最后一个音频帧必须带 `NA END`；`playback_end` JSON 不能替代 `NA END`。
- `sample_rate`、`frame_duration_ms` 必须以设备 `hello.audio_params` 为准，不能照抄示例值。
- 普通 `listen` 可能不携带 `audio_session_id`，`listen stop` 的 `mode` 也不保证和 `start` 一致；服务端应关闭当前连接上的 active audio session。
