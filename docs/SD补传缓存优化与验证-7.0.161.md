# SD 补传缓存优化与验证：7.0.161

日期：2026-10-22。基线：7.0.160。继续使用本机 SD 音频测试网关。

## 修复

上一轮设备录制 617.82 秒、30,891 帧，5 个文件全部上传并确认。主要额外耗时之一是 6 次文件／场次结束选择累计 14.52 秒。

根因是首次上传文件时，通过通用索引写入函数保存“已尝试上传”标记。这个函数会清空场次选择缓存。每个文件上传完成后，需要重新扫描历史目录；会议与监控轮转时，还可能先扫描一次没有待上传数据的模式。

本轮增加专用的尝试标记写入操作：

- 在同一个文件句柄内读取当前有效索引，只更新尝试标记，保存新的 CRC 记录并检查同步和关闭结果。
- 保留场次排序、空模式提示和扫描位置；清除单次选择快照及旧 ACK 证明，避免使用过期状态。
- 写入、同步或关闭失败时返回失败，保留音频，后续按原恢复流程重试。
- 新建场次、封存文件、缺失记录、结束、完成、身份变化及延后重试等操作仍正常使缓存失效。

文件删除仍要求云端确认和本地 ACK 持久化成功。没有降低持久化要求、提高任务优先级、增加传输窗口或放宽超时。

## 发送端检查

当前发送端已经使用批量 TCP 写入和按字掩码复制。本轮保留其行为，增加每文件一次的分项日志：

```text
offline mask detail word_bytes=... scalar_bytes=... copy_ms=... random_ms=... timing=wall_including_preemption
```

`word_bytes` / `scalar_bytes` 表示按字复制与逐字节回退分别处理的字节数。`copy_ms` / `random_ms` 分别统计掩码复制和随机掩码生成的墙钟耗时，都可能包含任务抢占，不能直接视为纯 CPU 运算时间。没有新增网络消息或热循环逐帧日志。

最终 Xtensa ELF 的单帧、批量发送路径均通过检查：掩码操作保留按字加载、异或和存储，没有退化为逐字调用 memcpy。
