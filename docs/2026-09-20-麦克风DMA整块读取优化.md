# 麦克风 DMA 整块读取优化

日期：2026-09-20。用户已授权先实施采集优化，覆盖先前“八部分完成后再修改”的工作顺序；其他部分仍待分析。

## 修改范围

- `main/mic_input.c`：VOCAT 的 mono、MR、双麦、双麦加参考四个读取接口统一调用整块读取器。
- `main/mic_input.h`：增加软件余量字节数和偏移，随麦克风对象一起移交。
- `main/mic_dma_reader.inc`：按配置的 DMA 块（当前 240 点、四槽、1,920 字节）读取，业务帧消费后的余量由设备自己的缓冲保存。
- `main/mic_dma_reader_host_check.c`、`tools/run-mic-dma-reader-host-checks.ps1`：使用生产读取器的主机契约检查。

SDK 源码、采样率、DMA 描述符数量、业务帧格式及上传协议未因本次实现修改。去直流和增益算法保持原实现，不在本轮调整。

## 修复目标与前后差异

旧路径向 SDK 请求 320 点，可能在 240 点 DMA 块中留下未读尾部。当前本地 SDK 在接收队列接近满时可能切换缓冲，跳过尾部但不触发队列溢出回调。

新路径按 240 点整块请求，正常对齐状态下不把业务帧的余量留在驱动内。首次交付 320 点时读取 480 点，多出的 160 点留在软件缓冲。下一次读取先使用余量，再补充整块；四个通道保持交织顺序，之后由原接口提取需要的通道。

| 项目 | 原路径 | 修改后 |
| --- | --- | --- |
| 未消费的业务余量 | 可能留在 SDK 当前 DMA 块内 | 保存到应用拥有的缓冲 |
| 320 点压力模型 | 队列接近满时构造出跳过 160 点 | 同一模型连续读取 12 帧，没有跳样 |
| 部分超时 | 交付可用的部分采样 | 仍交付可用部分，不强制填零 |
| 硬读取错误 | 返回错误 | 返回错误并不复用本次暂存余量 |
| 已检测溢出 | 不交付受断点影响的数据 | 同时清空软件余量，避免跨断点拼接 |
| 离线转在线直接移交 MIC | 移交原对象 | 余量跟随对象移交，不额外丢弃 |
| 正常释放再初始化 | 重建读取状态 | 清除余量，避免旧模式数据泄漏 |

启动排空、读取前发现溢出、读取期间发现溢出、释放麦克风均清理余量。原有溢出恢复及任务所有权机制保留。

## 代价与适用边界

- 每个活跃 VOCAT 麦克风实例多分配 1,920 字节缓冲；仍优先 PSRAM，失败时沿用原 8-bit heap 回退策略。结构体另增两个 `size_t`。
- 不新增任务或队列；会增加小量余量搬移以及 I2S API 调用次数，CPU 成本尚未实测。
- 为得到完整 DMA 块，未对齐的业务帧在理想无积压状态下可能多等待小于 15 ms。超时仍允许返回部分数据；总循环用剩余时间预算，不能视为对 RTOS 调度延迟的硬实时保证。
- 该措施针对业务读取粒度导致的驱动尾部残留，不保证任意过载、断电或硬件异常下零丢样，也没有修复所有音频问题。
- 主机模型不等同于真实 FreeRTOS/DMA 并发，历史实机是否曾发生此类丢样仍未证明。
- 本次不是补传提速修改，不宣称提升 KiB/s。
