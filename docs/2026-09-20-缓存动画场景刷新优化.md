# 缓存动画场景刷新优化（cached-scene-v6）

## 依据

上一轮 `net-style-v5` 实机日志：切页 20 次，中位数 12.3 FPS；进入二级页面每次仅 3～4 帧，耗时中位数 366 ms。样式缓存已经启用，但缓存动画仍通过 LVGL 的覆盖搜索、对象刷新、祖先及兄弟节点处理。20 行分块会反复执行这些工作。单缓冲还需要等待传输完成。

同一日志的测试网关连接在 3 秒后超时，但错误进入 `device_error_report` 持久化流程，触发暂停唤醒和 NVS 整理。25～27 秒、91～92 秒出现这条链路。它是额外干扰源，不是全部低帧率的解释。

## 修改

1. 为 LVGL display 增加可选的完整活动屏幕绘制回调。回调在分块缓冲所有权已取得后运行；未处理时完整保留普通刷新路径。有前一屏参与转场时不调用该回调。顶部层、系统层、绘制任务提交、传屏队列、完成信号和最终帧交接仍由 LVGL 处理。
2. 灵珠菜单仅在缓存、冻结背景、覆盖范围和层级满足条件时使用该回调。每帧在布局更新后的 `RENDER_START` 检查一次样式和遮挡状态；每个分块直接绘制黑色背景，仅与分页栏相交的分块刷新分页栏。既有 flush 合成器继续填入缓存卡片、二级页面和冻结背景。
3. 有可见的后置屏幕控件（例如 OTA 覆盖信息）、缓存失效、测试页面、非默认旋转或不符合条件的样式时，回到普通路径。新路径不分配帧缓冲，不强制恢复低内存下释放的第二块内部缓冲。
4. 新增 `ui refresh ... cached_parts=N`，统计真实走缓存场景路径的分块数，避免只从“缓存已分配”推断优化生效。启动标记为 `profile=cached-scene-v6`。
5. WebSocket 配置增加仅本地记录连接诊断的选项，只由独立 SD 测试网关启用。其 DNS、TCP、TLS 和握手失败保留串口日志、返回错误和原有退避，不再进入正式云端诊断 NVS 队列。正式云端默认行为及上传过程中其他错误处理保留。

## 验证方法

- 原生 fixture 对命中新路径的每帧关闭回调重画，逐像素比较；仍执行局部刷新/全量刷新、缓存/实时绘制、点击、反向切换、最终帧交接和二维码检查。
- 在动画中加入可见屏幕兄弟控件，验证自动回退；加入顶部层覆盖控件，对比两条路径的结果。
- 网络故障注入验证：测试端点超时不进入持久诊断，正式端点仍产生诊断；连接超时、取消、套接字释放和 OTA 等待退出继续回归。
- 最终 ELF 验证 RGB565 路径、开机资源及既有音频相关链接保护。

原生 fixture 使用模拟时间，其日志 FPS 不代表 ESP32 实机性能。构建和逐像素一致性通过，只能证明实现和这些回归场景正确；实际 FPS 与长期稳定性仍需烧录回归。

## 烧录后检查

- 启动出现 `style_cache=1 profile=cached-scene-v6`。
- 缓存可用的切页和二级页面动画期间 `cached_parts` 应大于零。静态页面或回退场景为零是正常现象。
- 对比 `page ... fps`、`navigation ... frames/elapsed_ms`、`cover_us/tree_us/owner_wait_us`，不能用静态页面的零 FPS 或表情主页的 40 FPS 替代动画指标。
- 测试网关关闭时仍会出现约 3 秒 TCP 超时及退避；这些连接失败本身不应再引发错误队列持久化和唤醒暂停。其他需要持久化的事件仍可能操作 Flash。
- 连续操作下拉、左右切页、二维码/设备信息进入返回、快速反向操作，并检查 OTA 覆盖信息及网络状态更新，无花屏、残影、点击丢失或重启。
