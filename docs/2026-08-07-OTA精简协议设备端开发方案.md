# OTA 精简协议设备端开发方案

> 日期：2026-08-07  
> 状态：协议已确定，设备端改造已实施，等待完整构建与真机验收  
> 工程：`NuwaxAIPartner-v2`

## 1. 目标

在不改变 `hello` 的前提下，把 OTA 业务协议精简为单一事务键 `update_id`，删除云端不需要的硬件元数据、发布序号、进度与取消消息，同时保留以下可靠性能力：

- 每次启动只进行一次逻辑版本报告；
- OTA 指令幂等，不能重复启动下载；
- 严格防降级；
- 下载大小和 SHA-256 校验；
- A/B 分区、断电保护和 Bootloader 回滚；
- staged、committed、failed、rolled_back 结果可靠确认；
- OTA 期间音频、配网、关机和 UI 互锁保持有效；
- 下载进度继续在本地 UI 显示。

## 2. 目标协议

### 2.1 设备启动报告

```json
{
  "type": "firmware_report",
  "report_id": "fw_0123456789abcdef",
  "device_id": "NX-AABB-CCDD-EEFF",
  "device_secret": "device-runtime-secret",
  "reset_reason": "power_on",
  "firmware": {
    "firmware_type": "NuwaxAIPartner_V2",
    "version": "7.0.48",
    "image_sha256": "6c65363081d4641a725fe2505968dd82c72e71e8bac0db367b065f5128eaa25e"
  }
}
```

设备从当前动态云端配置读取 `device_secret`，只在 WSS 消息中使用，不打印、不持久化额外副本，并在发送后清零临时缓冲区。

### 2.2 云端下发

```json
{
  "type": "device_command",
  "command": "ota_update",
  "update_id": "ota_7000047_001",
  "url": "https://firmware.example.com/NuwaxAIPartner-7.0.49.bin",
  "version": "7.0.49",
  "size_bytes": 2007552,
  "image_sha256": "a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3a3"
}
```

### 2.3 设备接受确认

```json
{
  "type": "ota_ack",
  "update_id": "ota_7000047_001",
  "accepted": true
}
```

### 2.4 设备结果

```json
{
  "type": "ota_result",
  "update_id": "ota_7000047_001",
  "ok": false,
  "message": "https_read_stalled"
}
```

### 2.5 云端结果确认

```json
{
  "type": "ota_result_ack",
  "update_id": "ota_7000047_001",
  "ok": false
}
```

`ota_progress` 和 `device_command/ota_cancel` 从正式协议删除。

## 3. 当前代码不能直接删字段的原因

当前 `release_sequence` 同时参与清单校验、下载前防降级、pending NVS 事务、新镜像身份匹配和 accepted sequence 提交。如果只从 JSON 解析器删除该字段，旧固件可能完成下载并切换分区，但新固件启动后发现 pending sequence 与自身编译身份不匹配，最终触发错误回滚。

当前 `request_id` 还用于 OTA 上下文持久化、结果重发和 ACK 关联。直接删除会破坏结果确认闭环。

因此必须按以下顺序改造，不能只删 JSON 字段。

## 4. 设备端实施步骤

### 4.1 清单模型

修改 `nuwax_ota_manifest_t` 和解析器：

- 正式必填仅保留 `update_id/url/version/size_bytes/image_sha256`；
- `type/command` 由外层命令分发器校验；
- `version` 使用严格 SemVer；
- URL、大小、SHA 和重复关键字段继续严格校验；
- 旧云端附带的删除字段在滚动升级兼容期可以忽略，但设备自身永不依赖这些值；
- 新设备和新云端的发送端严格只产生精简字段。

### 4.2 唯一事务键

- 对外只使用 `update_id`；
- 内部短期将原 `request_id` 缓冲区写成同一个 `update_id`，避免立即迁移 NVS 布局；
- 所有 command、report context、重发和 ACK 匹配最终只比较 `update_id`；
- 相同 `update_id + version + size + SHA` 视为幂等重投；
- 相同 `update_id` 但镜像身份不同必须拒绝。

### 4.3 防降级与发布序号

云端 `release_sequence` 删除后，设备执行两层检查：

1. 下载前比较 `ota_update.version` 与当前运行版本，目标必须严格更高。
2. 下载完成后校验镜像描述中的 project/version、实际大小和 SHA-256。

pending 新镜像身份改为：

```text
target_partition_address
version
image_size
image_sha256
update_id
```

pending 身份匹配不再依赖云端 release sequence。新镜像通过启动健康门并 `mark_app_valid` 后，使用新镜像自身编译的 `NUWAX_OTA_FIRMWARE_RELEASE_SEQUENCE` 更新本地 accepted sequence。云端发布序号仍可保留为服务器内部排序字段，但不参与设备协议。

### 4.4 NVS 兼容和掉电恢复

- 保持当前 v1/v2/v3 pending record 的读取兼容；
- 新记录可以继续沿用现有结构大小，原 sequence 槽写入本地兼容值，不能再作为 pending 镜像匹配条件；
- 旧记录仍按旧规则验证，避免升级固件后误接受损坏记录；
- 新记录必须通过版本、目标分区、大小、SHA 和 update ID 共同匹配；
- `mark_app_valid` 前断电时仍由 Bootloader pending-verify/rollback 机制保护；
- `mark_app_valid` 后 NVS 提交失败时保留可恢复上下文，下次启动继续提交，不能回滚已经确认有效的镜像。

### 4.5 ACK、结果与重传

- `ota_ack` 只生成 `type/update_id/accepted`；
- `ota_result` 只生成 `type/update_id/ok/message`；
- `ota_result_ack` 只校验 `type/update_id/ok` 和当前 WebSocket connection epoch；
- 云端发送 ACK 即代表已经持久化，设备不再要求 `persisted:true`；
- ACK 超时继续重发完全相同的 result；
- staged 结果确认后才允许按现有策略重启；
- committed/rolled_back 结果上下文必须跨重启和重连保存，直到收到匹配 ACK。

### 4.6 取消与本地进度

- 删除 WebSocket `ota_cancel` 分发和取消 ACK；
- 云端无法在设备接受后主动取消升级；
- 保留内部 abort/cancel 能力给下载失败、系统停机和异常清理使用，但不暴露为云端协议；
- 删除 `ota_progress` 网络发送；
- 保留 transport stats、百分比计算和 UI callback，本地显示逻辑不变；
- 云端超时只进入待对账，不得自动重复下发同一个 update ID。

## 5. 状态机目标

```text
IDLE
  -> COMMAND_ACCEPTED
  -> QUIESCING
  -> DOWNLOADING
  -> VERIFYING
  -> STAGED
  -> REBOOTING
  -> PENDING_VERIFY
  -> COMMITTED

COMMAND_ACCEPTED..VERIFYING -> FAILED -> IDLE
PENDING_VERIFY              -> ROLLED_BACK -> IDLE
```

约束：

- OTA 活跃期间只允许一个 owner；
- OTA 接受后立即阻止会议、监控、配网和关机竞争；
- UI 可以显示进度，但不能驱动 OTA 核心状态迁移；
- WebSocket 断线不终止 Flash 写入，结果在重连后补报；
- 任何失败都必须释放音频/电源互锁并恢复正常业务；
- 只有进入 BLE 配网的系统路径可以主动停止云端连接，OTA 自身不主动断开连接。

## 7. 分步验证

每一步都必须先通过对应验证再继续：

1. 清单 Parser 主机测试：最小合法消息、缺字段、重复字段、错误 SemVer、HTTP URL、错误大小和错误 SHA。
2. release policy 测试：升级、同版本、降级、预发布版本和 NVS accepted sequence 恢复。
3. pending transaction 测试：新旧记录兼容、分区/版本/大小/SHA 不匹配、断电恢复。
4. 协议测试：精简 ACK/result/result ACK，旧多余字段不会成为逻辑依赖。
5. 状态机测试：重复 update ID、冲突 update ID、网络断开、ACK 丢失、下载失败、SHA 失败。
6. 全部 ESP-IDF host checks 与协议 Schema 校验。
7. ESP-IDF 完整构建并记录固件 size/SHA。
8. 真机故障注入：下载前断网、写入中断电、staged 后断电、新镜像健康失败、结果 ACK 丢失。

## 8. 完成标准

- 新云端只按精简协议即可完成升级；
- 设备不再依赖云端 release sequence、板型和构建元数据；
- 云端收不到进度消息，设备 UI 仍持续显示进度；
- 云端发送 `ota_cancel` 不属于正式协议且不会影响进行中的升级；
- 下载或校验失败后旧固件正常运行；
- 新固件异常时可以自动回滚；
- 断电发生在任意 OTA 阶段都至少保留一个可启动固件；
- 所有 OTA 终态可跨连接可靠补报并由精简 ACK 收敛；
- 对话、会议、监控、配网、休眠、唤醒和关机功能在 OTA 结束后全部恢复。
