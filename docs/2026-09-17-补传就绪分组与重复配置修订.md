# 补传就绪分组与重复配置修订

## 实测基线

上一轮 `meeting_20260917_76f279a7_319374`：8 个文件，6,690,328 字节，网关首个 begin 到最终 commit 共 15.694 秒，端到端 **416.307 KiB/s**；窗口内约 460.496 KiB/s。同样数据达到 500 KiB/s，需在 13.067 秒内完成，即总耗时还需减少约 16.7%。

较早八小时离线部分：959,157,786 字节，40 分 17.765 秒，约 **387.415 KiB/s**。不能用短片段速度代表长时间补传，也不能只计窗口内发送耗时。

最近一轮完整约 1 MiB 文件，平均预读等待约 146.6 ms，ACK 等待约 228 ms。固定等待四帧才发送，会把部分 SD 读取和网络发送串行化；每个 ACK 后无条件休眠一个 tick，也会重复让步。读、发送、采音保护时间有重叠，不能简单相加估算收益。

## 本轮实现

| 项目 | 行为 |
| --- | --- |
| 按就绪数据分组 | 预读发布一帧后即可发送；采音保护等待结束后重新读取发布进度，一次合并已经就绪的 1–4 帧，不主动等待凑满四帧 |
| 保持帧边界 | 单帧仍为 8064 字节，只有窗口尾帧可更短；offset、请求标识、窗口结束标记和重试内容保持原规则 |
| ACK 后调度 | 成功 ACK 等待不足一个 tick 时继续休眠一个 tick；已等待至少一个 tick 时省去这次额外休眠。64 KiB／20 ms 工作预算保持有效 |
| 音量重复持久化 | 在 Flash 保护前读取 NVS，已保存相同音量则跳过写入和唤醒任务停启；比较持久值而非当前运行值 |
| 写入失败重试 | 失败提交标记为不确定，下次即使读到暂存值也再次提交；保留 Flash 保护与 NVS 空间恢复 |
| 并发音量保存 | 原子互斥保护读取与提交；冲突调用保持既有尽力持久化语义并记录 deferred，当前运行音量仍已应用。不新增后台保存队列 |

协议、云端接口、会议／监控会话关联不变。预读窗口在持久化 ACK 前不复用，最终 commit ACK 前不删除文件，部分发送失败仍断开连接再续传。

保持读取优先级 6、发送优先级 5、最大 128 KiB 窗口、双缓冲、1 MiB PSRAM 预算、16 KiB 内部 DMA 空闲余量、采音积压 60 ms 暂停／30 ms 恢复，以及原有崩溃保护。本轮不扩大缓冲或提高优先级。静态内存差异见快照 `build-result.json`。

## 验证与限制

- 编译生产补传循环，覆盖就绪 1／2／3／4 帧、首帧不等待四帧、任意偏移续传、立即／延迟 ACK、16,896 个头部变异、CRC、超时、抢占、连接变化、低内存、读任务退出和资源释放。
- 生产 WebSocket 路径覆盖 192 组编码与 320 组竞争调度；隔离 TCP 网关验证合帧／拆帧、短写恢复、重复窗口、commit 和归档逐字节一致。
- 直接提取生产音量持久化函数，验证去重、读失败、提交失败、Flash 保护失败、NVS 空间恢复及并发进入。
- 完整构建性能版和 UART 诊断版，核验最终 ELF 的掩码代码、RNNT 修复调用点和 BIN 内嵌 ELF SHA。烧录快照携带源码摘要和测试日志。

**主机回归与构建不等于实机达标。本轮尚无 500 KiB/s 实测结果，也不能据此认定此前重启问题已根治。** 小分组减少等待，但可能增加 socket 调用；实际收益需结合新统计判断，不能预先保证。

先对比约 5 分钟离线会议，恢复网络、退出会议后完整补传；保留启动 SHA、完整串口日志和网关数据。通过后再进行八小时长测，并在补传期间操作 UI、开始／结束会议和监控，验证抢占及恢复。

新日志 `tx_batch_policy=ready_prefix` 标识本轮发送策略；`groups_1..groups_4` 表示成功发送的分组次数（含重试），`ack_yields`／`ack_yields_saved` 分别表示强制让步和省去重复让步次数。对比 `first_payload_ms`、`data_wait_ms`、`calls`、`write_ms`、采音保护等待、队列丢帧、堆检查及 UI 响应。

达标按整个目标会话的首个 begin 到最后 commit 计算，包含文件切换和重试；同时校验文件 CRC、帧数、序号连续性及无重复，不能以局部窗口峰值代替：

```powershell
node tools/protocol/audit-offline-session.js runtime-logs/sd-replay-test-20260911/archives SESSION EXPECTED_FRAMES tmp/session-acceptance.json GATEWAY_LOG 500
```

若小分组明显增加写调用却未降低总耗时，应依据统计调整合并策略；若采音或内存保护等待上升，优先处理资源竞争，不放宽稳定性阈值。
