# 500 KiB/s 阶段目标：消除掩码循环的逐字 ROM 调用

本轮已完成代码修订、主机回归及两种配置的整机构建。尚未烧录或实测，500 KiB/s 是验收目标，不是已经达到的结果。

## 可确认的瓶颈及修改

ESP-IDF 实际使用 `-fno-builtin-memcpy`。原 `ws_mask.h` 对齐路径虽然以 32 位字异或，但取出/存回每个字都使用普通 `memcpy`。上一版最终 ELF 的循环中可直接看到两次 `callx8` 调用 ROM `memcpy`，即每 MiB 对齐数据约 524288 次调用，此外还有帧头准备等少量调用。

本轮仅将掩码内部三个固定 4 字节复制改为 GCC 显式 `__builtin_memcpy`。保留原对齐检查、尾部逐字节处理和 C 别名规则；未全局解除 IDF 的 memcpy 编译限制。32 位路径现在直接生成读取、异或、写入指令，不再把每个字搬到栈上交给 ROM 复制。

这降低编码本身的 CPU/内存访问成本，也可能减轻同核 SD 预读和其他任务的竞争；实际端到端收益还取决于 SD、TCP、唤醒推理和显示负载，不能按删除调用数直接推算倍数。

本轮没有扩大缓冲、降低 16 KiB 内部空闲准入余量、提高任务优先级、停止唤醒功能或修改协议。原双缓冲、40 MHz 自检/回退、CRC、ACK 保留和断点续传均保留。Wi-Fi 配置写 Flash 保护及 RNNT 修复保留，之前的 Cache/MMU 重启仍需持续验证。

## 验证证据

- `tools/test-ws-mask-codegen.py` 使用 Xtensa GCC 15.2、`-O2 -fstrict-aliasing -fno-builtin-memcpy` 编译实际头文件；将 builtin 换回普通 memcpy 作为负向对照，重现 18 处 memcpy 重定位，新版为 0。
- 对两版最终 ELF 的发送函数反汇编，按 DWARF 的 `ws_mask.h` 来源范围检查：包含 32 位读写及异或指令，没有函数调用。检查结果绑定最终 ELF SHA。
- 主机发送回归采用同样的优化/别名/禁用普通 memcpy 内联参数；覆盖 26 种长度、源/目标四种对齐、四种掩码相位，校验源数据及目标哨兵；240 组实际发送路径交错、短写、TLS、连接代次和重连用例通过。
- 离线录音、ACK 重试、CRC、分段发布、低内存及 SD 失败回归通过。模拟 8 小时容量测试不是实机 8 小时验证。
- 最终 ELF 的两个 RNNT 补丁调用点继续验证通过。
- 与各自上一版相比，性能版代码减少 804 字节，诊断版减少 812 字节，静态内部 RAM 占用均不增加。不同配置之间仍有约 4.1 KiB 的诊断常驻内存差异。

500 KiB/s 按同一次补传所有归档字节总和，除以网关首次 `offline begin` 至最后 `offline commit` 的墙钟时间验收，不用单片瞬时速度或只扣发送时间的指标代替。以上轮 5983702 字节计算，目标耗时不超过 11.687 秒，上轮为 18.859 秒。

同时要求网关 CRC 正确、帧序号连续、无重复，设备最终 ACK 后删除，录音/唤醒无新增丢帧。对比 `encode_ms`、`send_ms`、`sd_read_ms`、读取容量、压力等待及 UI 帧率。补传结束后继续待机至少 30 分钟；一次短测达速不能证明重启已根治或长期稳定。
