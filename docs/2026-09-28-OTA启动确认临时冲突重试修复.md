# OTA 启动确认临时冲突重试修复（7.0.102）

## 问题与证据

测试日志包含 7.0.99 → 7.0.101 → 回滚 7.0.99 → 再次升级 7.0.101，共三次软件重启。首次新固件在约 13.7 秒完成云端连接，24.4 秒完成真实镜像哈希及固件上报，但启动确认未继续，121.352 秒报 validation_timeout，123.422 秒回滚。第二轮约 23.4 秒完成 staged ACK、标记有效和 committed ACK。

代码存在可复现的漏重试路径：OTA 控制器消费 cloud-ready 事件后，读取待确认事务需要获取共享 Flash 保护；其他任务暂时持有保护时返回 ESP_ERR_INVALID_STATE。原流程只对哈希忙的 ESP_ERR_NOT_FINISHED 恢复事件，未处理元数据读取阶段的冲突。固件上报任务稍后完成哈希不会重新触发 OTA 确认。

故障注入已复现该路径。原设备日志未打印这次返回码和保护持有者，所以无法仅凭日志确定当时竞争的具体任务。

## 修复

`main/nuwax_ota_new/nuwax_ota_device.c` 在控制器事件入口增加 `process_cloud_ready_with_retry`。调用原有完整验证流程后，对 INVALID_STATE、TIMEOUT、NOT_FINISHED 检查是否允许保留事件：

- 新固件仍在待确认状态。
- 云端仍处于认证状态。
- 未有确认或回滚决策占用。
- 原始启动验证期限尚未到达。
- 没有已有待处理事件（避免覆盖新事件）。

符合条件时保留原 ready_ms，交由原控制器循环继续处理，不增加任务、队列或动态内存。无命令时原循环通过 100ms 队列等待限制重试频率；不延长原 120 秒总期限。恢复后仍必须完成真实哈希校验、staged 持久化 ACK、标记固件有效、committed ACK。

INVALID_STATE 也可能表示持续状态错误，因此只将其作为期限内的重试机会；绝不视为校验成功。CRC/版本错误不由此入口安排暂时错误重试。已确认、断开认证、回滚中的状态不会由此入口新增重试。

新增限频诊断：`OTA boot validation retry revision=boot-retry-v1 err=... attempt=...; original deadline retained`。首次保留事件记录一次，之后同类重试诊断间隔至少 5 秒。等待重试期间不再每轮扫描任务栈/堆或重复打印通用失败信息，完成或最终失败后保留资源诊断。

## 保留行为

SD 卡未插入时的初始化失败本轮不修改。语音唤醒阈值 0.09、摇晃往复动作识别、OTA 最低电量 5%、现有显示及对话功能保持当前配置；正式云端路由保持启用。

升级版本为 7.0.102，发布序号 7000102，用于从已确认的 7.0.101 正常升级，避免同版本重复发布导致版本策略拒绝。

## 回归覆盖

`tools/test-ota-identity-cache.py` 直接提取生产验证函数及新入口进行主机故障注入：

- 哈希前读取 NVS 遇到 INVALID_STATE / TIMEOUT，保留事件；冲突解除并由另一任务完成哈希后，继续确认且复用真实摘要。
- 读取运行分区状态临时失败后恢复。
- staged ACK 后、标记有效前再次发生元数据冲突，恢复后完成确认。
- 连续冲突不续期，到期限仍回滚。
- 未认证、已确认及回滚决策占用时不新增重试。
- 错误摘要仍拒绝，原有哈希失败、ACK 失败、哈希/ACK 期间超时保护继续测试。
- 删除冲突重试、丢失原哈希忙重试、绕过期限的错误变体均应被测试拒绝。

主机测试不替代实机 OTA 回归。新版本实际重启次数、云端 ACK 和长时间对话表现需实机确认。

## 实机验收

保持不插 SD 卡，从当前已确认的 7.0.101 升级至 7.0.102。正常预期为一次 OTA 软件重启，然后出现 `OTA boot identity verified`、`OTA running image confirmed valid; rollback cancelled` 和 `OTA boot verification finished committed_ack=1 audio_blocked=0`。升级确认后的 WebSocket 状态刷新属于主动重连，不是设备重启。

如发生短暂冲突，应看到 boot-retry-v1 日志，并在原期限内自动继续；持续错误仍应回滚。请保留升级前、下载、重启和启动后至少 3 分钟完整日志。
