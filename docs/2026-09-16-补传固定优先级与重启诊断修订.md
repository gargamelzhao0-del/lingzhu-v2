# 补传固定优先级与重启诊断修订

本轮先撤回有调度副作用的优化，并生成独立、可取证的测试固件。Cache/MMU 重启的首次非法访问尚未定位；本次不能宣称已经根治重启，也没有新的实机吞吐成绩。

## 已落实

1. 预读任务保持优先级 5，不再每次 SD 读取升至 6、随后降回 5。当前 FreeRTOS 实现降低当前任务优先级会请求重新调度；原逻辑将这项成本放大到每个读取片段。继续采用工作量预算和录音压力检查保证让出 CPU。
2. 保留双缓冲、ACK 前保留数据、断点续传、CRC 校验、分段直接掩码编码、40 MHz 自检及错误后 20 MHz 回退。协议、请求标识与音频会话规则没有改变。
3. 修订独立诊断配置：UART ELF 转储、最多 8 个任务、独立 2048 字节内部转储栈；按 SDK 要求将每核 ISR 栈设为 2096 字节。关闭转储调试字符串和全 DRAM 抓取，限制常驻开销。UART 转储仍依赖故障现场内存可读，不能保证所有 Cache 故障都可完整导出。
4. 新增可选 `NUWAX_WAKE_WORD_HEAP_CHECKS`，仅诊断配置启用。在 MultiNet 初次创建前后、重建时销毁/创建边界，以及任务已停止后的重新启用清理前后检查堆结构。检查失败打印阶段并中止，避免继续使用已知损坏的堆。它是定位手段，不是修复；不检查每帧推理、不扫描每个上传片段，也不启用全局堆填充。检查正常不能排除对象内部越界或失效指针。
5. 保留内部空闲内存至少 16 KiB 的临时 DMA 缓冲准入与分配后复核；诊断占用增加时允许自动缩小缓冲或回退，不以压低保护余量换速度。
6. 补齐 Wi-Fi 管理器重连配置的 Flash 保护：`esp_wifi_set_config()` 在驱动使用 `WIFI_STORAGE_FLASH` 时也会涉及 NVS，原调用绕过了 `wifi_nvs_open()` 的停止保护。现在必须先成功停止唤醒任务才调用驱动，并在成功/失败返回时配对释放保护。这是保护覆盖缺口；没有日志证明该调用发生在本次崩溃时，不能据此宣布根因已消除。

## 重启证据边界

最新故障是补传任务退出约 192 秒后的 Cache/MMU fault，Core 1 涉及 MultiNet 推理及 Xtensa 异常保存，任务栈位于 PSRAM。现有日志没有首次 MMU 失败地址或完整转储。此前 RNNT 增容修复已出现在匹配的 ELF 内，不能把本次故障直接解释为旧修复未烧入，也不能仅凭 PSRAM 栈认定根因。

已有 Flash/NVS 保护与任务停止流程仍保留。本次不凭猜测缩小唤醒栈、扩大内部常驻缓冲，或定时重建模型掩盖故障。

## 速度判断

上轮 session 309152 网关实测约 280.5 KiB/s，之前对照约 361.5 KiB/s；读取任务和发送任务的压力等待同时增加。撤回逐次优先级变化是消除已知调度成本，不代表已经实测恢复基线。

单窗隔离观测的发送速度约 425 KiB/s、读取约 455 KiB/s，说明不能仅扩大 ACK 窗口就承诺 800 KiB/s。达到目标还需要降低发送侧编码、内存访问与调度成本，并验证读写并行时的争用。上述单窗成绩不是芯片速度上限；优先取得稳定、同条件的剖析数据再决定下一项优化。

诊断版占用更多内部内存，因此必须结合 `internal_bytes/fallback_bytes`、读取尺寸、压力等待、编码及写入耗时解释速度，不能将全部差异都归因于优先级修订。

## 验证及测试

主机回归覆盖离线录音、补传 ACK 丢失重试、断点续传、取消/连接代次变化、低内存回退、CRC、SD 错误处理；另有 ROM CRC 路径、240 组 WebSocket 并发交错、Wi-Fi 配置停止失败/驱动错误/嵌套保护及并发恢复测试，以及 RNNT 补丁及 SDK 源码指纹检查。主机模拟的 8 小时容量验证不等同于实机 8 小时录音。

构建结果、固件 SHA、镜像清单和内存变化记录随独立快照归档。未烧录、未占用设备串口。默认速度构建目录保留原配置；本轮使用下列明确的诊断快照路径，避免误烧旧版本。

性能对照版（没有 UART 转储或堆检查）另存为 `C:\tmp\nuwax-replay-fixed-priority-20260916`，用于诊断结束后的同内存预算对照；代码包含同样的优先级修订及 Wi-Fi 配置保护。当前重启尚未定位，先使用诊断版。

两版均已构建通过，最终 ELF 内两个 RNNT 修复调用点验证通过。与上一轮相比，性能版静态内部 RAM 占用不变，链接报告的镜像体积减少 176 字节；诊断版静态 DIRAM 增加 4196 字节，镜像增加 8512 字节。这里是链接统计，不是实机剩余堆测量；SDK 同时自动启用了 core dump 所需的任务入口包装。

启动 ELF SHA 前缀：诊断版 `a154764b5823`，性能版 `0eec17f780d7`。完整 SHA、六份镜像及源文件哈希见各快照的 `build-result.json`。
