# SD 恢复调度与离线采集修复

## 本轮问题与修复

设备日志会话为 `meeting_20260914_76f279a7_274814`。在线初始 278 帧、离线 25404 帧、恢复在线 1039 帧，共 26721 帧。SD 接纳计数没有拒绝，但重连期间出现一次麦克风 DMA discontinuity；这意味着仅靠帧序号连续、CRC 正确，不能证明物理采音完全无缺口。

1. `nuwax_offline_audio_storage_busy()` 遗漏介质恢复标志，调度层以为空闲，启动层却返回 `ESP_ERR_NOT_FINISHED` 并设置重试标志。下一次调度又清除退避截止时间，形成毫秒级重试循环。现将恢复标志纳入忙状态，且消费重试标志时保留截止时间，覆盖忙状态检查后的竞争窗口。退避仍有最大 30 秒上限。
2. 云端连接任务原先在新连接 epoch 同步调用 SD 恢复；目录扫描不受锁等待超时的完整约束，可能阻塞保活。现只唤醒存储 supervisor，由其执行恢复及周期探测。
3. 离线采集原先在核心 0、优先级 5，与重连工作竞争。现为核心 1、优先级 12，PSRAM 栈和内部栈回退使用相同调度参数。该变更降低重连抢占风险，是否消除实机 DMA 溢出仍需烧录验证；未扩大内部 RAM 中的 DMA 缓冲。
4. 归档 CRC 从逐位运算改成 16 项半字节表，减少每字节运算量，不分配额外堆内存。CRC 多项式、初值、增量调用语义、文件格式和线上协议不变。FAT 目录查找、创建、重命名仍可能较慢，现有缓冲和慢操作日志继续保留；本次没有测得优化后的实机耗时。

本次没有改变 `request_id` / `audio_session_id` 的协议规则，也没有开发用户可见 SD 状态。
