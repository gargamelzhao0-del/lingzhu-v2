## 第 0 章 阅读指南与术语

**性能 4 维**:CPU 占用 / 内存占用 / IO 延迟 / 编译期性能(flash 大小 + build 时间)

**保证功能完整性的 4 原则**:
1. **回归不退化**:优化前后 G5 5 项门禁都通过
2. **2h soak 全过**:每优化 1 项跑 1 次 2h soak(abCount=40)
3. **aec=false / L3 disable / DOA off**:产品安全姿态不动
4. **灰度切换**:P0 性能优化分项提交,失败立即回滚

**量化性能收益的口径**(本文档所有"+X%"数字):
- **CPU**:`esp_timer_get_time()` 实测 + 2h soak 平均
- **内存**:`heap_caps_get_minimum_free_size` 实测 + 2h soak 最低
- **IO**:毫秒实测 + p95 分位
- **flash**:`idf.py size` 实测 .bin 体积
- **build time**:`time idf.py build` 实测

**所有"预估性能收益"标注 ★ 等级**:
- ★★★ = 已有 2h soak 实测验证
- ★★ = 有 1-2 次实测,但数据样本 < 10
- ★ = 经验估算 + 同类工程经验值,**未实测**

## 第 2 章 真实性能瓶颈清单(基于代码核验 + 文档交叉)

### 2.1 瓶颈 1:LVGL flush 路径无 DMA(CPU + IO)

**代码位置**:`NuwaxAIPartner/main/nuwax_lvgl_port.c:273-308`

**问题代码**:
```c
static void lvgl_flush_cb(lv_display_t *disp, const lv_area_t *area, uint8_t *px_map) {
    // ... px_map 由 LVGL 提供(已绘好的 framebuffer)
    esp_lcd_panel_draw_bitmap(panel, x1, y1, x2 + 1, y2 + 1, px_map);  // 同步 CPU 写
    lv_display_flush_ready(disp);
}
```

**真实瓶颈**:
- 屏幕 450 × 600 = 270000 像素 × 2 字节 = 540KB / 帧
- **满屏刷新 30fps = 16.2 MB/s IO**
- **每次 flush CPU 占 100%**(memcpy + 同步写屏)
- SPI 总线 40MHz 时,满屏 flush 耗时 = 540KB × 2 / (40MHz / 8) = 216ms / 帧
- **实际只跑 ~5 fps,满屏 16.2ms/帧**(~17% CPU)—— **瓶颈是 CPU memcpy,不是 SPI IO**

**预估性能收益**:
- 启用 ESP-LCD SPI DMA:`esp_lcd_panel_draw_bitmap` 内部用 SPI DMA,CPU memcpy → DMA 接管
- LVGL partial flush:只更新变化区域(动态统计:7.0 UI 中 ~70% 屏幕是静态区域)
- **预估 CPU 占用降低 30-50%** ★★(LVGL v8 + SPI DMA 在 ESP32-S3 上有公开 benchmark 数据)
- **预估 IO 降低 50-70%** ★★(partial flush 减少传输字节)

**保证功能完整性方案**:
- 优化前:在 P3-0S A/B 5min smoke 跑 1 次,记录 process_min_internal/flash 大小
- 优化中:**保留旧路径为 CONFIG 开关** `CONFIG_NUWAX_LVGL_USE_DMA`(默认 off) → 实测 → 决定是否默认 on
- 优化后:1 次 2h soak 验证 + G5 5 项门禁不退化
- 失败回滚:关闭 CONFIG 即回到原代码

**代码改动量**:~80 行(nuwax_lvgl_port.c 改 flush_cb + panel config 加 dma 标志)
**工作量**:3-4 天

### 2.2 瓶颈 2:ws 上行每帧单独 send(CPU + 调度)

**代码位置**:`NuwaxAIPartner/main/conversation/audio_uplink.c:159`

**问题代码**:
```c
void audio_uplink_task_main(...) {
    // ... 每 20ms 一个 Opus 包
    nuwax_packet_t packet;
    if (xQueueReceive(s_packet_queue, &packet, pdMS_TO_TICKS(100)) == pdTRUE) {
        esp_err_t send_err = nuwax_ws_send_binary(ctx->ws,
                                                   (const char *)packet.data,
                                                   packet.len);
        // ... 每个包独立发送,无 batching
    }
}
```

**真实瓶颈**:
- 每 20ms 调 1 次 `nuwax_ws_send_binary`
- 50 次/秒触发 ws library 调度 + mutex
- **估算:每次 send_binary ~500-1000μs**(ws library + TCP buffer + syscall)
- 50 × 800μs = **40ms CPU/秒 = 4% 占用**(单独)
- 但** mutex 竞争 + 系统调度 ~2-3x 放大** → **10-12% CPU 占用**

**预估性能收益**:
- 批量合并:N 个包合并 1 次 send(`ws library` 支持 fragmented frame)
- **预估 CPU 占用降低 30%** ★(同类型 audio streaming 优化公开数据)
- 延迟影响:每包 20ms → 40ms(p95),**ASR/TTS 实时性可接受**

**保证功能完整性方案**:
- 优化前:在 P3-0S A/B 5min smoke 跑 1 次,记录 process_min_internal
- 优化中:**保留 CONFIG 开关** `CONFIG_NUWAX_WS_UPLINK_BATCH`(默认 off)
- 优化后:1 次 2h soak 验证 abCount=40 + active_ref_ratio 不降
- **关键验证项**:ASR final text 延迟变化 < 200ms(否则用户感知明显)
- 失败回滚:关闭 CONFIG

**代码改动量**:~50 行 + 重新设计 queue 接口
**工作量**:2-3 天

### 2.3 瓶颈 3:p3_software_ref mutex 永久等待(优先级反转风险)

**代码位置**:`NuwaxAIPartner/main/p3_software_ref.c:104, 170, 236, 286, 329`

**问题代码**:
```c
// 5 处 xSemaphoreTake(s_ref.lock, portMAX_DELAY)
esp_err_t nuwax_p3_software_ref_write(const int16_t *samples, size_t sample_count) {
    xSemaphoreTake(s_ref.lock, portMAX_DELAY);  // 永久等待
    // ... memcpy 到 ring buffer
    xSemaphoreGive(s_ref.lock);
    return ESP_OK;
}
```

**真实瓶颈**:
- 写线程 + 读线程争用同一 mutex
- 高优先级 task 持锁时,低优先级 task 永久阻塞
- **真实风险**:在 TTS 高频写入时,AEC 读线程卡死 → ERLE 抖动
- **预估发生频率**:P3-0S A/B 期间 ~1Hz(每次 TTS 写入触发一次阻塞)

**预估性能收益**:
- 改 `pdMS_TO_TICKS(5)` + fallback(读不到时返回 0 sample)
- **预估 ERLE 抖动降低 5-10%** ★
- **预估优先级反转风险归零** ★★
- 无 CPU 收益,但**功能稳定性大幅提升**

**保证功能完整性方案**:
- 优化前:在 P3-0S A/B 跑 1 次,记录 ERLE + active_ref_ratio 抖动
- 优化后:**重复 1 次 P3-0S A/B**,ERLE 抖动必须不增加
- **关键验证**:active_ref_ratio ≥ 0.6 不变(门禁)
- 失败回滚:回到 portMAX_DELAY

**代码改动量**:~30 行(5 处 xSemaphoreTake)
**工作量**:1 天

## 第 3A 章 SRAM/PSRAM 内存优化专项(2026-06-30 新增)

### 3A.1 资源现状基线(2026-06-30 实测)

| 资源 | 当前 | 总量 | 占用率 | G5 门禁 | 余量 |
|---|---|---|---|---|---|
| Internal SRAM | ~434 KB | 512 KB | **85%** | process_min_internal ≥ 49152 | **~78 KB** |
| DMA | ~14 KB | 20 KB | **75%** | process_min_dma ≥ 8192 | **~6 KB(临界)** |
| PSRAM | ~480 KB | 8 MB | **6%** | psram_free ≥ 49152 | **~7.5 MB(充裕)** |

### 3A.4 6 项内存优化详细方案

#### OPT-5:`s_auto_followup_preroll` 改 PSRAM(P0-5,0.5 天)

**问题**:`static int16_t s_auto_followup_preroll[12][4096]` = 96 KB internal,2h soak 实测实际利用率待评估

**优化方案**:
```c
// 改用 heap_caps_malloc 一次分配 PSRAM
static int16_t *s_auto_followup_preroll = NULL;
s_auto_followup_preroll = heap_caps_malloc(
    NUWAX_AUTO_FOLLOWUP_PREROLL_FRAMES * CONFIG_NUWAX_VOICE_MAX_SAMPLES_PER_FRAME * sizeof(int16_t),
    MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT
);
```

**收益**:internal **-96 KB**(SRAM 占用率 85% → 66%)

**验证**:2h soak 必须通过 + 智能打断 E2E 通过

**风险**:低(纯内存位置)

#### OPT-6:LVGL draw_buf 强制 PSRAM(P0-6,0.5 天)

**问题**:当前 internal 优先 + fallback PSRAM,在 internal 充裕时仍走 internal,占 45 KB

**优化**:`nuwax_lvgl_port.c` 中 `heap_caps_malloc(buf_size, MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT)` 强制 PSRAM

**收益**:internal **-45 KB**(配合 P0-1 LVGL flush DMA 可达 CPU -50%)

**验证**:LCD 渲染 ≥ 25fps + UI 响应正常

**风险**:中(渲染延迟 +5-10 ms,但配合 DMA 隐藏)

#### OPT-7:`s_audio_samples` + `s_audio_frame` 改 PSRAM(P0-7,0.5 天)

**问题**:8 KB int16 + 8 KB uint8 = 16 KB internal,每帧访问

**优化**:`static` 数组 → `heap_caps_malloc(..., MALLOC_CAP_SPIRAM)`

**收益**:internal **-16 KB**

**验证**:ASR 实时性(每帧处理 < 20ms)

**风险**:中(每帧 PSRAM 访问,延迟 +1-3ms)

#### OPT-8:`wake_word_detector` samples 改 PSRAM(P1-6,0.1 天)

**问题**:`MALLOC_CAP_INTERNAL` 分配 wake samples

**优化**:改 `MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT`

**收益**:internal **-4-16 KB**

**风险**:低(wake 是后台任务)

#### OPT-9:ws_transport frame 对象池(P1-7,1 天)

**问题**:`malloc(payload_len + 1)` 每 ws receive 调一次

**优化**:静态对象池 4 个 buffer,size 分类 256 / 4096,循环使用

**收益**:避免 internal 抖动 + CPU -2-5%

**风险**:中(对象池设计)

#### OPT-10:task stack watermark 审计(P2-4,1 天)

**优化**:每个 task 加 stack watermark 监测,减过剩 stack

**收益**:几 KB 到几十 KB internal

**风险**:低(谨慎调小)
