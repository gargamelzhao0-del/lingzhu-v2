## 3. 主要缺口与代码证据

### 3.1 底座

商家 `main/boards/CyberVoc-Board-V2_0/base_control.cc` 实现 UART1 初始化、心跳及插入/校准事件处理。`cybervoc_tools.cc` 的 `self.cyber_base.set_action` 支持摇头、缓慢摇头、环顾、蹭头、校准、左右转及归位。协议实现位于 `components/espressif2022__cybervoc_base_control`。

本地 `main/board/uart_driver.c` 已定义底座串口 TX43/RX44，115200 波特率；业务侧未发现完整底座协议接入。`main/mcp_server.c` 虽定义条件发布的 `self.servo.head_shake`，但 `main/nuwax_ai_partner_main.c` 中 `.servo_head_shake = NULL`。

补齐需要：协议驱动、心跳/离座处理、校准状态机、动作互斥、超时处理及上层回调。原理图证明主板提供底座接口，不能据此认定用户实物底座中的电机、控制器和固件均已匹配。

### 3.2 双麦声源定位

商家 `audio_analysis.cc` 使用音频分析结果处理 DOA，并调用 `cyber_base_control_set_angle()`；`cybervoc_tools.cc` 提供 `self.cyber_base.set_audio_mode`。本地未发现对应运行链路。

MIC1/MIC2 是声源定位所需的双麦输入；MIC3 是回声参考候选链路，两者用途不同。MIC3 不可用不等于双麦定位不可用，但声源定位也不能替代 AEC。应先验证双麦同步、实际间距及角度误差，再接底座动作。

商家 `base_control.cc` 和 `CyberVoc.cc` 的相关流程会关闭 AEC 后启用 DOA 跟随；不能直接把两套功能移植后假定可同时稳定运行。

### 3.3 4G

商家 `main/boards/common/dual_network_board.cc` 在 Wi-Fi 与 ML307 之间选择网络，保存配置后重启切换，并非会话不中断的自动蜂窝接管。

本地 `main/board/uart_driver.c` 已有 TX6/RX5、GPIO15 供电控制和 `nuwax_4g_at_probe()`。该探测只验证 AT 应答并清理串口；`hardware_selftest.c` 可按配置调用。主程序启动时关闭 4G 供电，未发现 ML307 产品网络传输链路。

补齐需要模块/SIM 实物确认、注册与 APN、网络传输接入、重连和切换策略。不能只打开供电或通过 AT 自检就认为设备已有 4G 联网能力。

### 3.4 实体绿灯

本地 `main/board/led_driver.c` 提供 LEDC 控制，`led_status.c` 提供状态优先级；排除模块自身和头文件后，LED API 调用只见于 `hardware_selftest.c`。因此正常联网、播放、休眠等状态尚未驱动此灯。

商家 V2.0 板级类未发现 `GetLed()` 覆盖，公共 `Board::GetLed()` 返回 `NoLed`。此项属于原理图上的硬件潜力，并不是已经证明商家完整实现而二开遗漏的功能。该灯也不同于充电芯片直接控制的指示灯。

### 3.5 AEC 与实时打断

当前 `tmp/sdkconfig.test-panel` 中 `CONFIG_NUWAX_LIVE_AEC_ENABLE`、`CONFIG_NUWAX_VOCAT_SLOT2_AEC_REF_ENABLE` 及软件/硬参考 A/B 开关均未启用。测试栏中的占位按钮不能视为功能已开启。

应先验收采样槽位、参考信号、扬声器播放与参考延迟，再验证双讲和误打断。商家代码中的实时模式和打断分支能说明实现意图，不能证明这套硬件上的实际识别效果。详见同目录《2026-09-14-商家V2.0实时对话与打断审计.md》。

## 4. 不应误判为遗漏的部分

- 本地已有 QMI8658A 摇晃检测；姿态、跌落等可以扩展，但本次未证明商家已实现这些应用。
- 本地已有头部触摸、电池服务、电源保持/关机及屏幕触摸，不应重新开发一套。
- 充电电路自身工作的能力不等于必须新增软件充电控制。
- USB/BOOT 接口存在，不等于商家已实现 USB 声卡、U 盘等产品功能。
- 商家的番茄钟、睡眠闹钟工具属于软件功能差异，不属于主板硬件未使用。
- 本地板级头文件仍使用 `esp_vocat_v1_0_pins.h` 名称，但内容标注苗伴 2.0；应核对实际引脚，不能仅凭文件名判定板型不匹配。

## 5. 建议顺序

1. 以实时对话为目标时，优先验证双麦/参考采样及播放链路，避免在未通过声学验收前开放自动打断。
2. 有底座产品需求时，先完成底座协议和安全停止/超时，再加 DOA 跟随；二者分开验收。
3. 绿灯运行状态接入可单独完成，改动范围相对小；不涉及暂缓开发的用户可见 SD 状态。
4. 4G 在确定模块、SIM 和产品切换策略后独立实施，不能直接照搬商家重启切网行为作为无缝恢复方案。
