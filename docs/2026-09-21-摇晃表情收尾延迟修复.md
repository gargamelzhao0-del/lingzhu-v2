# 摇晃表情收尾延迟修复

本轮日志中摇晃表情约显示 16 秒：34.266 秒插入，35.246 秒提交交互后锁定；38.686 秒接收到云端播放结束，40.056 秒扬声器已完成播放，但主业务线程到 50.236 秒才处理结束消息，50.816 秒完成聆听表情切换。48.176 秒发生诊断 NVS 空间整理，50.116 秒完成错误上报。已确认结束事件处理延迟，NVS 同步持久化是代码中实际存在的阻塞路径；原日志没有函数耗时，不能将全部延迟精确归因给 NVS。

## 实施

- `nuwax_device_error_report_service()` 仅从 RAM 发送限时上报，不再先同步执行 NVS 快照写入。
- 所有诊断快照写入统一经过主线程空闲检查：仅休眠/空闲状态，且没有活跃对话、视觉回合、播放收尾、触摸/摇晃交互、采集、会议/监控、通知、OTA、配网隔离、待处理云端及扬声器事件时允许执行。SD 采集/补传限制继续保留。
- 连续对话期间延后诊断持久化，不延后实时 RAM 上报。该期间尚未持久化且未被云端接收的诊断，在突然掉电时可能丢失；不会影响音频归档和协议。
- 使用现有扬声器事件时间戳记录排队耗时；超过 250 ms 输出 `speaker owner event delayed ... queue_ms=...`。空闲诊断持久化超过 100 ms 输出 `idle diagnostic persistence slow elapsed_ms=...`。
- 保留原有摇晃回复表情锁定和按 epoch/generation 校验的收尾逻辑。并未把已提交摇晃回复强制截断为 3 秒，也没有越过物理播放完成和云端结束确认提前开启麦克风。正常收尾进入聆听时立即解除摇晃表情。
