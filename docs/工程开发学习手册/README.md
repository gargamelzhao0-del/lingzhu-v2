# Nuwax AI Partner：从硬件到产品的开发学习手册

这是一部围绕真实工程编写的中文教材。它从 C 语言、嵌入式硬件和任务调度讲起，逐步解释声音如何被采集、识别、上传、播放和归档，以及配网、界面、电源和 OTA 如何共同运行。教材同时保留开发中走过的弯路，教读者用证据区分现象、原因和猜测。

**初版：2026-10-03；最近复核：2026-10-09；当前默认应用版本：7.0.113。** 工作树包含尚未提交的修改，因此 Git 提交号不能单独代表本教材对应的代码。关键源文件摘要和配置摘录见 [证据清单](evidence/source-manifest.json) 与 [配置快照](evidence/config-snapshot.json)。本书不是“整个产品已无缺陷”的验收声明，也不把主机测试通过写成实机长期稳定性保证。

## 怎样使用这本书

需要重新做出整机时，先读 [重建主线](30-rebuild.md)，再用 [逐项功能接线索引](31-feature-wiring.md) 确认范围。零基础读者在这条主线中遇到不熟悉的基础，再回到对应章节，并完成第 23 章的实验。有 C/RTOS 经验的读者先读第 00、02、07 章，再选择业务章节。维护者优先阅读第 21、22、24 章，了解验证方法、历史故障和当前边界。

每章尽量回答五个问题：它解决什么问题；数据经过哪里；谁拥有资源；失败时如何收尾；如何验证。正文中的代码片段如果标注“教学示意”，就不是可以直接覆盖生产代码的补丁。精确协议以现行协议文档及实现为准，正文不另造第二套协议。

技术阅读版为原有 30 章补充学习目标、知识路径图和场景自测，重点扩写资源交接、音频帧、会话恢复、持久化、补传吞吐与整帧发送。开发经历作为解释设计约束的案例，技术实现是阅读主线。

在知栈中，正文带虚线的术语可点击查看定义、工程用法和易混点；说明从右侧打开，关闭后继续原位置阅读。三个分步示意分别说明缓冲归还、断网后的身份延续和归档提交，不执行固件、不模拟实测性能。普通 Markdown 阅读器可能将 `zhizhan-demo` 显示为文本围栏，紧邻的表格和解释保留完整学习信息。

可按章节阅读，也可使用生成的 [连续阅读版](全册.md)。[文档校验报告](evidence/document-validation.json) 记录本次交付的链接、代码围栏和文件检查结果；[维护工具](maintain_handbook.py) 可以重新生成连续阅读版并校验文档。

## 交付范围

覆盖当前产品主要运行链路、配置开关、驱动接口、业务状态机、协议、诊断、测试和已记录的故障经验。第三方库从“本工程怎样使用和约束它”讲解，不逐行重写 ESP-IDF、LVGL 或识别模型内部实现。外部正式云服务、APP 与专有模型训练源码不在本仓库，涉及它们的结论会注明证据边界。

教材修订与固件发布分开。本轮修改教材并同步知栈源码中的内置资料，不修改固件业务实现，不烧录或发布固件。手机已安装的知栈不会因电脑上的正文变化而自动获得新版资料；需要后续应用交付及内置资料更新。历史测试结果在正文中按历史证据引用；本次文档检查以校验报告为准。

## 后续怎样更新

修改分章 Markdown，然后在工程根目录执行：

```powershell
python docs/工程开发学习手册/maintain_handbook.py
```

这会重建连续阅读版、检查本地链接与 JSON 示例、运行三个教学示例，并比较已保存的源文件摘要及脱敏配置白名单。缺少证据、配置消失或配置值变化会报错/告警；章节必须连续编号且出现在目录中。只有人工重新核对了新源码与正文后，才用 `--refresh-evidence --review-date 2026-10-09` 更新证据基线，日期替换成实际人工复核日期。刷新摘要本身不代表内容已经适配。维护工具不调用编译、烧录或网络服务。
