# 解绑与凭据失效后的 BLE 配网恢复

更新日期：2026-09-11，描述当前工作树。解绑不等于 Wi-Fi 密码失效；不清除已保存
的 Wi-Fi 或未确认 SD 归档。当前配置仍通过保存恢复记录并重启进入 BLE 配网模式。

## 云端错误处理

- `type=error` 的 `code` 或 `error` 为 `DEVICE_NOT_BOUND`、
  `DEVICE_SECRET_INVALID`、`DEVICE_AUTH_FAILED`：按连接 epoch 申请重新绑定。
- `hello` 中明确 `ok=false` 且携带上述设备错误码：同样进入重新绑定。
- `AUTH_FAILED`、`UNAUTHORIZED` 的 error 消息，以及正式 WebSocket 握手
  HTTP 401/403：转入配网协调器，不继续按普通断网策略反复使用旧凭据。
- 超时、DNS/TLS 故障、服务器临时错误和格式错误的 hello 不等同于解绑；
  保留一般网络恢复策略。日志中的自由文本不用于推断解绑。
- 迟到的旧连接错误不能触发当前连接重新绑定。HTTP 拒绝发生于应用 epoch
  发布之前，由连接 owner 单独保存并消费重新绑定请求。

## 手动配网与录音接管

点击配网不再因会议、监控、离线录音或归档活动直接被拒绝。请求先建立配网
隔离标志，阻止新连接和录音恢复。活动会议/监控由原采集 owner 在控制轮询中
关闭连接并执行正常退出；SD 关闭通过异步请求，等待已准入帧排空封存。
连接 owner 清除离线恢复租约后暂停，切换期间不会再启动离线录音。

worker 确认音频、归档和补传用户退出后才继续。超时仍回报失败并保留恢复路径，
不能带着活动 FILE 重启。OTA、通知播放和电源转换的原有互斥仍然保留。

## 界面与连接取消

- 新增 `provisioning_starting`，启动阶段显示“启动中”，不允许重复点击切换目标。
- `provisioning_active` 只在 BLE 启动成功后发布，届时显示“运行中”并展示二维码。
- TLS 连接使用 IDF 异步接口，轮询中检查配网取消请求；总连接预算仍为 15 秒。
  HTTP 升级响应按单字节、100 ms 等待片检查取消，总握手预算不变。
- IDF 内部 DNS 解析仍可能同步等待，不能宣称所有网络条件下均即时取消；
  未加密测试 TCP 路径的 connect 也保留原行为。正式设备使用 WSS。

## 验证

新增协议回归覆盖设备密钥失效、error 字段兼容、hello 明确拒绝及重复字段拒绝。
配网、产品、会议、监控及 SD 主机检查通过，ESP-IDF 产品固件构建通过。
主机检查和编译不等于手机与实机联调：仍需验证解绑后 HTTP/JSON 拒绝、监控期间
手动配网、SD 慢卡关闭、启动时连点，以及 TLS 等待期间配网。未执行刷机或 OTA。
