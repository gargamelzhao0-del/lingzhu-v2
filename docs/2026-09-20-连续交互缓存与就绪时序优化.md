# 连续交互缓存与就绪时序优化

针对 f1bbac73 日志中的间歇性卡手和启动体验。本轮承接 `691965d03…` 异步 Wi-Fi 固件。

## 实现

1. **运动期间使用完整已提交缓存。** 删除“页面变脏超过 200 ms 就拒绝缓存”的入口限制。原限制与“仅空闲时重建缓存”组合后，会令连续手势退回完整实时对象树。现在只使用完整提交的页，不读取正在构建的中间数据。动画期间的显示值可以暂时保持上一份快照；脏标记不清除，动画结束后交回实时页面显示最新状态，操作判断仍使用实时状态。
2. **分页图像用于普通回退路径。** 当其他屏幕子对象使场景快速路径退出时，只要几何条件仍满足，就复用该帧分页图像。回退路径不再对每个分块重复 `lv_obj_refr(pager)`。位置、透明度和选中状态改变时仍生成新快照；本轮没有宣称消除了每帧快照开销。快照更新/释放前使解码缓存失效，避免保留旧尺寸或存储指针。
3. **云端就绪立即尝试收敛状态。** `wait_for_cloud_service_ready()` 成功返回前调用原有睡眠状态协调函数。保留活动对话、录音、会议/监控、通知、OTA 和配网的全部占用判断，不抢占这些模式。
4. **首次连接在工作任务就绪后尽早排队。** 模型构建和 AEC 预检完成，且内部可用内存至少 32 KiB、最大内部块至少 16 KiB、最大 DMA 块至少 8 KiB 时，提前提交恢复请求，与最后的本地服务注册重叠；不足时仍由主循环启动。后台工作任务和原退避逻辑不变。

本轮没有将 Wi-Fi 提前到模型构建之前，因此不能承诺将 17 秒联网降到数秒。AP 临时拒绝关联、WPA3 协商和 DHCP 等待也不由本轮显示修改解决。未变更屏幕布局、显示 DMA 配置、任务优先级或看门狗期限。

## 验证

- 原生 LVGL 测试版与正式布局全部通过。场景缓存与普通绘制分别对照 44、53 帧；局部刷新与整屏刷新像素一致；二级页面、模式开关、音量和无缓存回退检查通过。
- 屏幕覆盖对象和顶层覆盖对象测试保留原绘制结果。新增直接对照原始逐块分页遍历，像素一致；测试样本的对象绘制次数分别由 16、12 降到 0。这是主机样本的工作量变化，不是 ESP32 帧率测试。
- 半页构建过程中延迟 500 ms 后仍能启用完整旧缓存，并保留脏标记；新一代六块图像完整提交后才替换旧页。
- 云端就绪状态协调测试覆盖重复就绪、未就绪、对话/音频/通知/独占模式/OTA/配网占用。
- Wi-Fi 异步恢复测试再次通过：连续失败、主备长等待、退避、取消、旧结果丢弃。
