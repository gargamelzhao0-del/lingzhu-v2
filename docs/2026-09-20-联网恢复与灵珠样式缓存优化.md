# 联网恢复与灵珠样式缓存优化

本轮对应 `lingzhu-net-style-v5`。保留黑白菜单、二级页面、点击反馈、开机 Logo、SD 测试网关和原有上传协议。

## 日志依据与边界

上一轮日志显示，首次 Wi-Fi 连接经历多次 reason 4/205/2 失败，约 25.6 秒后结束；随后重新配置 STA 的一次连接约 0.66 秒完成关联，另用约 3.18 秒获得 IP。这支持提前结束无效重试并尝试一次重新配置，但不能证明最初失败一定由密码、路由器或 WPA3 引起。本轮不降低无线认证安全级别，也不将唤醒模型初始化与认证高峰强行并行。

菜单日志的刷新树遍历耗时仍较大，上一轮没有实机证据证明已达到目标帧率。检查实际构建配置发现 `CONFIG_LV_OBJ_STYLE_CACHE` 未启用：`lib/lvgl/src/core/lv_obj_style.c` 中，缺省属性仍需经过 `get_prop_core()` 的样式链搜索。启用 LVGL 自带的样式组缓存后，不存在对应属性组时可跳过这次搜索，继承属性仍走原有父对象查找规则。它不能消除所有绘制、合成、调度和传屏耗时。

测试网关 TCP 连接此前调用阻塞式 `connect()`，连接取消回调在这段时间无法执行；日志中每轮等待约 18 秒。正式云端已经连接时，独立测试网关的等待仍使 `replay_running()` 返回真，因此 OTA 被音频忙碌条件拒绝。测试网关不可达和正式云端连接失败是两个不同的问题。

## 实现

### 显示

- 在默认配置和当前 SD 测试配置中启用 `CONFIG_LV_OBJ_STYLE_CACHE=y`。
- 每个 LVGL 对象增加两个 32 位属性组位图，即 8 字节，不增加帧缓冲。缓存由 LVGL 的样式增删和更新路径维护。
- 保留已有刷新裁剪、缓存展示平面和最后一帧交接逻辑。
- 原生界面检查按完整配置隔离 LVGL 对象文件，并在头文件改变后重编译，避免开关样式缓存引起对象结构 ABI 混用。
- 启动日志增加 `style_cache=1 profile=net-style-v5`，用于确认实际烧录版本。

### Wi-Fi

- 同步连接期间，连续两次暂态认证/关联失败可触发一次重新配置 STA。排除无 AP、明确认证拒绝等原因；成功关联或非暂态失败清除连续失败计数。
- 事件回调只通知，驱动配置仍由原来的连接操作所有者执行，并保留 Flash 操作保护。
- 原始尝试与重新配置共用 30 秒截止时间，不额外扩展一轮完整超时。
- 等待连接期间按最长 100 毫秒的片段检查配网接管、模拟断网和连接意图变化。
- 增加关联完成、等待 DHCP，以及连接总耗时日志。实际获得 IP 的速度仍受路由器和 DHCP 影响。

### 测试网关与 OTA

- 普通 TCP 改为非阻塞连接，以最长 100 毫秒片段等待并检查取消。测试网关 TCP 阶段使用 3 秒预算；其他普通 TCP 调用默认 15 秒。TLS 路径沿用原实现。DNS 解析仍使用现有同步接口，3 秒预算不包含 DNS；当前网关使用数字 IP。
- 网关连接失败后结束本轮工作任务，按 5、10、20、30 秒上限退避；已建立连接后的上传重试机制保留。
- 单独提供 OTA 忙碌判断：正在连接的独立测试网关可以取消，实际 SD 回放、正式补传任务和隔离中的未退出传输仍阻止 OTA。
- OTA 进入活动状态后阻止新的测试补传，取消连接，并最多等待 2.5 秒确认任务退出。退出失败、并发回放或传输隔离均拒绝继续写固件。
- 原有供录音、存储等所有者使用的 `replay_running()` 语义保留。ACK 确认后删除归档的规则及音频协议均未改变。

## 验证

`tools/test-network-join-handoff.py` 提取并编译生产代码，替换时钟、驱动和套接字边界，覆盖：TCP 成功、拒绝、多地址回退、EINTR、限时、取消和套接字关闭；Wi-Fi 事件通知与同步所有者重新配置、最多一次恢复、共享截止时间、取消；OTA 等待退出、退出超时、正在回放、竞争和隔离状态。

另执行原有 Wi-Fi 所有权、WebSocket 帧交错、补传 ACK/窗口回归，以及真实 LVGL 原生界面、二维码解码、触摸锚点、RGB565 像素路径、开机 Logo 和最终 ELF 校验。开关样式缓存的画面需要逐帧一致。原生测试采用模拟时间，不能将其动画日志中的 40 FPS 当作 ESP32 实测帧率。

ESP32-S3 构建及验证结果、源文件摘要、完整 ELF/BIN 和烧录镜像保存在独立目录 `C:/tmp/nuwax-lingzhu-net-style-20260920`；具体结果见目录内 `build-result.json` 和 `verification`。

## 实机回归

1. 检查启动日志出现 `style_cache=1 profile=net-style-v5`。
2. 测试冷启动及网络恢复，记录第一次关联、获取 IP、正式云端上线时间。观察 `Wi-Fi fresh STA retry` 是否触发且每次连接至多一次。
3. 下拉、左右切页、二维码/设备信息进入退出、快速反向操作及音量拖动；比较 `page perf`、`navigation perf` 和 `ui refresh` 指标，确认无残影、花屏和点击丢失。
4. 网关关闭时应约 3 秒结束 TCP 尝试并退避；此时启动 OTA，应先退出补传连接任务再继续。实际上传期间 OTA 仍应拒绝。
5. 网关恢复后确认 SD 归档继续上传。保留长时间运行、内存低水位、唤醒和会议并发测试。

本轮未烧录设备；实际 FPS、首次联网延迟及长期稳定性需要上述实机回归确认。
