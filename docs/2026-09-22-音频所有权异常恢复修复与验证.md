# 音频所有权异常恢复修复与验证

对应模块 02 的 AU01/AU02。固件标识：`20260922-audio-owner-v1`。本轮集中修改初始化、释放和异常恢复路径；不调整音频算法、网络协议、采样参数、播放表情或 UI 动画。

## 1. 改动与效果

| 项目 | 修复前 | 修复后 |
| --- | --- | --- |
| 扬声器关闭失败 | TX 租约已释放，但 initialized 和旧指针仍可使 ready/init 返回成功 | 开始关闭即取消 initialized；逻辑引用释放后清空输出对象，物理关闭错误仍向调用方报告 |
| 物理板级关闭失败 | 保留一个无身份的引用，由旧对象或下一次 init 重试 | 逻辑引用只消费一次；板级保存 pending 硬件清理，下一次 init 先完成清理再创建新一代资源 |
| 旧对象再次关闭 | 可能扣减新一代引用数 | 已消费句柄为空，重复释放无副作用；旧副本或错误 generation/token 返回 INVALID_STATE |
| MIC 异常退出 | 物理关闭失败后保留 vocat_shared_rx，之后仍可能再次扣引用 | 引用消费后清空 MIC；释放全局 MIC owner，让后续初始化可恢复板级状态 |
| 诊断/测试音 | 使用无身份 init/deinit | 全部迁移到引用句柄；诊断将逻辑释放与板级物理重试分开 |
| 自检 | 最后一次 deinit 失败可能仍报告生命周期成功 | 最后释放结果必须成功才能通过 |

正常播放、录音和共享 RX/TX 的工作方式保持一致。异常释放时不再“看似可用”，并不表示硬件故障会被隐藏为成功。

## 2. API 和资源成本

`nuwax_audio_board_init/deinit` 现在接收 `nuwax_audio_board_ref_t *`。结构包含 generation 和 token，必须零初始化，活引用只能移动不能复制。

- init 成功生成一个引用，重复初始化非空引用被拒绝。
- deinit 后 token 为 0：调用方逻辑所有权已经释放；返回错误可能表示物理清理仍 pending。
- deinit 后 token 非 0：释放被拒绝，调用方必须保留清理责任。
- `nuwax_audio_board_retry_teardown()` 仅重试板级 pending 清理，不扣减任何调用方引用；新一代活资源不受它影响。
- 最后一个引用在 RX/TX 租约仍存在时继续拒绝关闭。
- registry 固定 8 个引用，64 字节；另有 4 字节计数器，每个 MIC/speaker/诊断实例增加 8 字节句柄。没有新增任务、音频缓冲或动态 registry 分配。
- ref token 回绕跳过 0 和仍然存活的 token。

板级操作仍通过原有互斥串行执行；验证 registry 仅发生于 init/deinit。播放器 ready 检查增加本地引用/租约判断，不在每帧路径增加板级查询锁。

## 4. 故障注入

执行 `python tools/audit-audio-teardown.py`，覆盖：

1. 正常初始化、重复初始化、输出锁超时后保留所有权。
2. 硬件关闭开始前失败、TX 已删除而 RX 未完成关闭时失败；错误仍返回，旧输出不可用。
3. 持续关闭失败时拒绝创建新输出；恢复成功后旧对象和旧副本不能影响新引用。
4. RX/TX 共存，关闭 TX 不破坏 RX；持有租约时拒绝最后一次板级释放。
5. 错误租约释放被拒绝，仍保留清理责任，但 initialized 必须失效。
6. 引用槽耗尽、重复引用、同代旧副本、初始化失败。
7. MIC 关闭失败→新 owner 初始化→旧 MIC 再次清理。
8. 引用 token 回绕并跳过活 token。

另有四个可编译的故意破坏版本：空引用错误扣数、丢失调用方引用消费、失败输出仍 initialized、遗漏 pending 标记。必须全部在执行阶段被拒绝；编译失败不算有效拦截。

测试直接抽取生产板级 init/deinit/acquire/release、speaker init/deinit/ready 和 MIC deinit。硬件和 FreeRTOS 边界使用桩，不能代替设备真实 I2C/I2S/调度测试。上轮缺陷报告保留在 `docs/audits/2026-09-22-w05/teardown-report.json`，本轮结果单独保存，不覆盖修复前证据。
