# 远程进入配网模式

## 1. 设备命令

当前固件支持：

```json
{
  "type": "device_command",
  "request_id": "bleprov_<unique>",
  "command": "start_ble_provisioning"
}
```

设备 hello 声明：

```json
{
  "features": {
    "remote_ble_reprovision": true
  }
}
```

设备接受后发送匹配的 `device_command_ack`，把当前 STA 配置保存为可回滚
记录，延迟约 500 ms 重启，并进入持续 BLE 配网模式。前 300 秒仅等待 APP；
之后 BLE 继续广播，同时周期性尝试回滚记录中的旧 Wi-Fi，直到新配网提交成功或旧 Wi-Fi 恢复成功。

## 2. 本地模拟器按钮

Real 模式中的“让设备进入配网模式”使用页面内两次点击确认。浏览器只向
loopback Bridge 发送：

```json
{
  "deviceId": "NX-3927-2693-9288",
  "serviceName": "PROV_1467C4"
}
```

联调电脑通过 ESP32-S3 原生 USB 连接设备时，Bridge 优先执行：

```text
POST /api/reprovision
-> COM 端口发送 NUWAX_CTRL start_ble_provisioning
-> 固件返回 NUWAX_CTRL ACK start_ble_provisioning
-> 固件把请求放入与设备菜单相同的可回滚 worker
-> 保存当前 STA 回滚记录，约 500 ms 后重启
-> Bridge 定向等待 serviceName + 冻结 Service UUID
-> 仅在发现精确广播后返回 ble_advertisement_confirmed
```

如果没有可用 ESP USB 串口、设备又仍连接本地测试网关，Bridge 才使用带
内存管理令牌的 `/api/device/command` 作为备用路径。内部
`command_forwarded` 只表示写入设备 socket；对浏览器的成功响应仍要求发现
精确 BLE 广播。浏览器永远拿不到网关管理令牌。

USB 命令属于物理连接的联调能力，由
`CONFIG_NUWAX_PROVISION_USB_CONTROL_ENABLE` 控制；量产发布必须关闭。

## 3. 正式服务限制

设备迁移到正式 WSS 后，本地测试网关不再拥有该 WebSocket。连接在联调电脑
USB 上的开发设备仍可由模拟器按钮触发；这不是生产 APP 的远程能力。

正式 APP 若需要远程触发，正式后端必须提供：

1. 验证 APP 用户登录态。
2. 验证用户对 `deviceId` 的所有权。
3. 限频、审计和重放保护。
4. 向该设备的正式 WSS 转发 `start_ble_provisioning`。
5. 等待匹配 `device_command_ack`，再向 APP 返回接受结果。

APP 禁止直接持有设备 WebSocket 管理权限或直接向设备发送云端命令。

## 4. 离线恢复

正式后端不可用时，设备本地 `Device` 菜单中的 BLE 配网按钮是离线恢复
入口。失败或超时后固件恢复原 Wi-Fi；新 Wi-Fi 达到 GOT_IP 后才清除回滚
记录。
