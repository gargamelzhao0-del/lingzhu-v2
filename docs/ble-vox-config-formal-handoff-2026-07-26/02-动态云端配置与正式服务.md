# 动态云端配置与正式服务

## 1. bind 与 BLE 下发职责

APP 先使用用户登录态调用现有 bind 接口。bind 返回同一 `deviceId` 对应的
最新 `deviceSecret`。APP 不生成、不改写、不写死该密钥，只把它与当前
`gatewayUrl` 原样放入 `vox-config`。

已提供的 `bind` 响应中有 `deviceId` 和 `deviceSecret`，没有 `gatewayUrl`。
`gatewayUrl` 必须来自 APP 的环境配置或另一个后端配置接口。当前正式联调环境值为：

```text
wss://testagent.xspaceagi.com/api/device/ws
```

因此 APP 的合并对象为：

```text
deviceId     = device-info.serialNumber = bind.data.deviceId
deviceSecret = bind.data.deviceSecret
gatewayUrl   = APP 当前环境配置/后端配置
```

模拟器不持有 APP 登录 token，也不调用正式 `bind`。它由测试人员输入
`bind` 已返回的最新密钥，验证的是“APP 取得绑定结果之后”的 BLE 下发、
设备持久化和 WSS 连接链路。

当前协议不包含：

- `credentialId`
- `bundleVersion`
- `signature`
- ECDSA 签名 bundle
- `cloud-config` endpoint

把上述旧字段发给当前固件会导致 endpoint 不存在或请求格式错误。

## 2. 固件保存和连接方式

固件校验：

- `deviceId` 必须等于硬件 UID。
- 生产 URL 必须是 `wss://`；`ws://` 仅允许测试构建。
- `deviceSecret` 为 1..95 个可打印 ASCII 字符（`0x21..0x7E`），可安全用于 `X-Bridge-Token`。
- `gatewayUrl` 只接受 ASCII `ws://`/`wss://`，禁止账号密码、fragment 和 IPv6 literal；显式端口必须为 `1..65535`。

成功配置原子写入 NVS：

```text
namespace: nuwax_cloud
key: active
value: version + deviceId + gatewayUrl + deviceSecret
```

设备连接时发送：

```http
GET /api/device/ws HTTP/1.1
Upgrade: websocket
X-Bridge-Token: <deviceSecret>
```

WebSocket 建立后发送 hello v1，其中：

```json
{
  "type": "hello",
  "version": 1,
  "device_id": "NX-3927-2693-9288",
  "device_secret": "<同一个动态设备密钥>",
  "features": {
    "remote_ble_reprovision": true
  }
}
```

密钥只在 TLS 内传输。固件会清空序列化缓冲区，且不得记录 header、hello
JSON 或密钥。

## 3. 正式服务验收结论

正式地址：

```text
wss://testagent.xspaceagi.com/api/device/ws
```

2026-07-26 真机结果：

- `vox-config` 返回 `ok=true,state=active`。
- `xspaceagi` 获得 IP，达到 `WIFI_READY`。
- 正式 WSS TLS/Upgrade 成功。
- 正式服务接受 `X-Bridge-Token` 和 hello 的动态密钥。
- 设备连续收到应用层 `pong`。
- 本地 8800 测试网关设备数为 0，排除误连本地服务。
- 4/4 连续硬重启均从 NVS 恢复配置并自动重连正式 WSS。

验收使用的真实密钥不在本包中。APP 必须在每次绑定/重新绑定时使用 bind
返回的最新值。

上述真机结果确认了设备到正式 WSS 的动态鉴权链路。Android APP 从
`bind` 取值到 `sendDataToCustomEndPoint("vox-config", ...)` 的端到端验收仍是
首轮 Android Provider 联调门槛，不应由模拟器结果代替。

## 4. 状态展示

模拟器只能查询本地测试网关，因此目标为正式 WSS 时显示
`WIFI_READY / cloud=NOT_OBSERVED` 是预期结果，不表示正式云连接失败。

正式 APP 应从正式后端获得独立的设备在线状态，例如：

```json
{
  "deviceId": "NX-3927-2693-9288",
  "online": true
}
```

后端状态接口未冻结前，APP 不得把本地模拟器的 `NOT_OBSERVED` 转成配网失败。
