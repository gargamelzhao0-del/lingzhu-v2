# 灵珠刷新裁剪深度优化

## 本轮依据

用户 0a0479f2 日志的状态/菜单切换为 6.4～18.7 FPS，中位约 12 FPS。104 秒窗口 render 平均 98.3 ms，draw_other 占 81.0%，缓存合成仅 4.0%。上一轮优化未达到实机流畅目标。draw_other 包含样式、遍历、任务调度及抢占时间，不能当作单纯像素绘制。

## 已落实

1. **缓存动画专用呈现节点**：在抽屉根节点下创建一个无子控件的呈现节点，缓存可用且有冻结表情时参与 LVGL COVER_CHECK。覆盖搜索直接选择该节点，跳过后面的抽屉布局树；绘制黑色底和实时分页条，沿用原 flush 合成器叠加缓存卡片、详情与圆形边界外的冻结表情。分页条使用原对象绘制，不重挂父节点、不复制文字、不增加帧缓存。缓存失效或冻结表情不可用时自动沿原路径绘制；末帧交接后隐藏该节点。
2. **普通控件提前裁剪**：lv_obj_refr 原来先解析透明度、重着色，再由 lv_obj_redraw 判断是否与当前刷新条带相交。现在使用现有 coords 和 ext_draw_size，在确认普通图层后提前排除不相交控件，省掉后续样式解析和函数调用。保留原 rendered 标志语义，旋转/缩放和需要独立图层的控件继续原流程。此优化也作用于静态页面局部刷新。
3. **新增 ui refresh 统计**：parts、culled、cover_us/max、tree_us/max、drain_us/max。cover 是寻找覆盖对象；tree 包含遍历、样式、同步创建/派发任务和软件绘图；drain 是提交 flush 前收尾。计时包含抢占，tree 与 ui sw draw 嵌套，不能相加；culled 也可能包含快照生成期间被剔除的控件。

不增加像素缓冲，不改变屏幕时钟、动画时长或任务优先级，保留内部 RAM 不足时释放第二块绘图缓冲的保护。新增对象及诊断元数据仍有少量内存开销。

## 验证结果与边界

- 原生生产控件测试：测试页版、无测试页版，缓存及内存不足回退均通过；二维码正确解码，白边和不可用时隐藏旧码通过。
- 缓存呈现节点启用/停用逐像素一致；代表性整屏刷新中的可观测 COVER_CHECK 回调从 45 降为 32（24 行主机绘图缓冲）。这不是全部遍历次数，也不是实机 FPS 提升比例。
- 使用优化前的 lv_refr.c 重新编译参考程序，114 张图片逐像素一致，包括切页、详情、返回、动态信息更新、阴影、透明度、图层、旋转及溢出子控件场景。
- 显示 RGB565、缓存复制、圆形合成、触摸交互及最终 ELF 开机资源验证通过；ESP32-S3 构建通过，应用大小 0x38bee0（3,718,880 字节），分区剩余 14%。
- 本轮未烧录，也未测量实机帧率；不能声称已经达到 30/40 FPS。主机动画时钟为模拟时间，不用于性能结论。
