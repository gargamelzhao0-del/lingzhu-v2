## 路由检查依据

1. `test_controls.h` 将页面与模拟断网执行 API 共用总开关。关闭页面不仅隐藏标签，同时关闭第三页创建、翻页目标和测试操作入口；正式布局由原生 LVGL 回归检查。
2. `session_protocol.c` 在正式补传启用后发送 `features.offline_audio_replay_v1=true`。
3. `nuwax_ai_partner_main.c` 的 `HELLO_OK` 分支传递正式云端能力声明和连接 epoch；补传 ACK 在普通业务分发之前进入 `nuwax_offline_audio_handle_protocol_text()`。
4. `service_offline_audio_replay()` 使用 `nuwax_offline_audio_replay_formal_start(ws, epoch)`，不再调用局域网测试 worker。正式 worker 复用此 ws，并检查连接代次、云端能力、存储与音频占用。
5. `offline_audio_spool.c` 只有匹配的 commit ACK 成功、且当前存储条件允许清理时才删除归档。ACK 超时、取消、协议不支持等场景保留本地文件。

新增启动日志，用于实机确认有效配置：

```text
offline replay route=formal_cloud test_panel=0 simulated_network=0
```

## 验证层级

- 正式分支主机调度测试：调用实际生产调度函数，断言传入当前主 WebSocket 与 epoch；涵盖重试、占用与恢复。
- 能力声明测试：完整 v1/archive-only 声明通过；旧云端回复、错误类型、错误版本、缺少字段和损坏 JSON 均拒绝开启正式补传。
- 真实补传函数主机回归：ACK、断点、epoch、取消、CRC、commit 成功删除以及失败保留等；禁用诊断 lane probe。
- 正式双页原生 LVGL 回归：页面像素、交互、二级页面、缓存与无缓存回退。
- `verify-sd-formal-build.py` 检查生成的 `config/sdkconfig.h`、真实正式 worker 符号、测试 UI/worker/font 符号缺失、测试 URL/token 字符串缺失，以及 BIN 内嵌 ELF SHA。对旧测试固件执行验证应拒绝。
- 烧录前校验所有 manifest 镜像与固定快照哈希；错误 ELF/BIN/资源不得打开串口。

构建产物验证不等于正式云端端到端验收。本轮没有烧录，也未用真实设备凭据发起云端补传。

## 云端前提及实机验收

云端需要按 `SD音频补传协议文档.md` 实现 begin/chunk/commit 及 ACK。hello 回复至少包含以下能力字段，并满足正常认证流程：

```json
{
  "type": "hello",
  "ok": true,
  "offline_audio": {
    "supported": true,
    "protocol_version": 1,
    "archive_only": true
  }
}
```

若仍只支持早期在线会议/监控、或只下发业务命令而没有声明上述能力，设备保持正常在线业务，但正式补传不会启动，SD 文件保留。正式路径使用共享云端连接，TLS、云端 ACK 和业务占用可能影响吞吐，不能直接套用独立 LAN 测试网关速度。

烧录后检查：

1. SHA 与固定快照一致；启动 route 日志为 formal_cloud，两个测试标志均为 0。
2. 控制中心只有两页，左右滑动不能进入测试页；二维码、设备信息与会议开关正常。
3. 主连接仍为 App 下发的云端地址；没有连接 8810、`offline replay test scheduled` 或网关重试日志。
4. `formal SD replay capability ... supported=1` 后，应看到 `offline formal replay scheduled`。
5. 用真实断网进行短时会议离线录音，恢复后核对云端 begin/commit ACK、音频序号、CRC 和设备 acknowledged/deleted 日志。无 ACK 时 SD 文件应保留。
